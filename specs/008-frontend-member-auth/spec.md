# Feature Specification: 프론트 회원·인증 화면

**Feature Branch**: `008-frontend-member-auth`

**Created**: 2026-09-07

**Status**: Draft

**Input**: `프로젝트설계/기능명세상세-프론트엔드/phase1-회원/` 의 화면 9건 — 1.1~1.5(비로그인) · 1.7(본인 정보) · 1.8~1.10(관리자)

## 대상 화면

| 화면번호 | 이름 | URL | 표시 | 권한 |
|---|---|---|---|---|
| 1.1 | 로그인 | `/auth/login` | 페이지 | 없음 |
| 1.2 | 회원가입 | `/auth/signup` | 페이지 | 없음 |
| 1.3 | 아이디 찾기 | `/auth/find-id` | 페이지 | 없음 |
| 1.4 | 비밀번호 찾기 | `/auth/find-password` | 페이지 | 없음 |
| 1.5 | 비밀번호 변경 | `/auth/reset-password` | 페이지 | 없음 |
| 1.7 | 본인 정보 | `/member/profile` | 페이지 | 로그인 |
| 1.8 | 회원 목록 | `/admin/members` | 페이지 | 관리자 |
| 1.9 | 회원 추가 | `/admin/members?m=create` | 모달 | 관리자 |
| 1.10 | 회원 수정 | `/admin/members?m=edit&id={id}` | 모달 | 관리자 |

**1.6 권한 없음은 007 이 만든다** — 권한 차단이 착지할 화면이라 인터셉터와 함께 서야 한다.

부르는 API 12건: `MemberSignup` · `MemberLogin` · `MemberFindId` · `MemberFindPassword` · `MemberResetPassword` · `MemberGetMe` · `MemberUpdateMe` · `AdminMemberList` · `AdminMemberCreate` · `AdminMemberGet` · `AdminMemberUpdate` · `AdminMemberDeactivate`

## 이 기능의 핵심 개념

**비로그인 화면과 로그인 후 화면이 레이아웃부터 다르다.** 1.1~1.5 는 사이드바 없는 `auth` 껍데기, 1.7~1.10 은 사이드바가 있는 `main` 껍데기다.

**비밀번호 찾기는 두 화면에 걸쳐 있다.** 1.4 가 아이디·닉네임으로 본인을 확인하고, 1.5 가 새 비밀번호를 받는다. **1.5 의 저장 API 가 아이디·닉네임을 다시 요구하므로** 1.4 에서 확인한 값을 1.5 로 넘겨야 한다 — 넘기지 않으면 사용자가 같은 값을 두 번 입력해야 한다.

**정지와 로그아웃은 다르다.** 관리자의 회원 정지(`AdminMemberDeactivate`)는 계정을 비활성으로 만드는 것이고, 로그아웃(`MemberTokenRevoke`)은 토큰을 무효화하는 것이다. 정지된 계정은 로그인 자체가 `1004` 로 막힌다.

**관리자 화면은 메뉴에서도 보이지 않아야 한다.** 일반 회원에게 URL 을 숨기는 것만으로는 부족하고, 007 의 인터셉터가 직접 접근도 막는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입하고 로그인한다 (Priority: P1) 🎯 MVP

계정을 만들고 로그인해 서비스 안으로 들어간다.

**Why this priority**: 로그인 없이는 화면 25개가 열리지 않는다. 007 이 세운 세션 인증이 실제로 도는 첫 경로이기도 하다.

**Independent Test**: 가입 → 로그인 → 보호 화면 진입 → 로그아웃까지 한 줄로 확인한다. 나머지 화면 없이 완결된다.

**Acceptance Scenarios**:

1. **Given** 가입 화면에서, **When** 아이디·비밀번호·비밀번호 확인·닉네임을 채워 제출하면, **Then** 가입되고 로그인 화면으로 간다
2. **Given** 이미 쓰이는 아이디로, **When** 가입하면, **Then** `2002` 를 받아 그 사유가 폼에 표시된다
3. **Given** 비밀번호와 확인이 다를 때, **When** 제출하면, **Then** `2005` 가 표시되고 입력이 남아 있다
4. **Given** 폰을 하이픈과 함께 입력했을 때, **When** 제출하면, **Then** 숫자만 전송된다
5. **Given** 올바른 아이디·비밀번호로, **When** 로그인하면, **Then** 월별 가계부로 이동하고 이후 화면에서 다시 로그인하지 않는다
6. **Given** 비밀번호가 틀렸을 때, **When** 로그인하면, **Then** `1003` 이 표시되고 **아이디가 맞는지 여부는 드러나지 않는다**
7. **Given** 정지된 계정으로, **When** 로그인하면, **Then** `1004` 로 비활성 계정임이 표시된다
8. **Given** 로그인한 상태에서, **When** 로그아웃하면, **Then** 로그인 화면으로 가고 보호 URL 이 다시 막힌다

---

### User Story 2 - 아이디·비밀번호를 잃어버려도 되찾는다 (Priority: P2)

이메일로 아이디를 찾고, 아이디·닉네임으로 본인을 확인해 새 비밀번호를 정한다.

**Why this priority**: 없으면 사용자가 계정을 영구히 잃는다. 다만 로그인이 서야 의미가 있다.

**Independent Test**: 가입한 계정으로 아이디 찾기·비밀번호 재설정을 끝까지 밟고 새 비밀번호로 로그인되는지 본다.

**Acceptance Scenarios**:

1. **Given** 가입할 때 쓴 이메일로, **When** 아이디를 찾으면, **Then** 그 아이디가 화면에 나온다
2. **Given** 등록되지 않은 이메일로, **When** 찾으면, **Then** `2001` 이 표시된다
3. **Given** 아이디·닉네임이 맞을 때, **When** 비밀번호 찾기를 제출하면, **Then** 비밀번호 변경 화면으로 가고 **아이디·닉네임을 다시 묻지 않는다**
4. **Given** 비밀번호 변경 화면에서, **When** 새 비밀번호를 저장하면, **Then** 같은 화면에 완료 문구가 뜬 뒤 로그인 화면으로 간다
5. **Given** 규칙에 못 미치는 비밀번호로, **When** 저장하면, **Then** `2004` 와 함께 규칙 안내가 표시된다
6. **Given** 새 비밀번호를 정한 뒤, **When** 그 비밀번호로 로그인하면, **Then** 성공한다

---

### User Story 3 - 본인 정보를 고친다 (Priority: P2)

닉네임·이메일·폰·소개를 바꾸고, 원하면 비밀번호도 바꾼다.

**Why this priority**: 로그인 후 가장 먼저 손대는 화면이지만 없어도 가계부는 쓸 수 있다.

**Independent Test**: 값을 바꿔 저장하고 다시 열어 반영됐는지 본다.

**Acceptance Scenarios**:

1. **Given** 본인 정보 화면에서, **When** 화면이 뜨면, **Then** 현재 값이 채워져 있고 **아이디는 고칠 수 없다**
2. **Given** 닉네임을 바꿔, **When** 저장하면, **Then** 저장되고 결과가 화면에 반영된다
3. **Given** 비밀번호 칸을 비운 채, **When** 저장하면, **Then** 비밀번호는 그대로 유지된다
4. **Given** 남이 쓰는 이메일로, **When** 저장하면, **Then** `2003` 이 표시된다

---

### User Story 4 - 관리자가 회원을 관리한다 (Priority: P3)

회원을 찾아보고, 추가하고, 정보를 고치고, 필요하면 정지한다.

**Why this priority**: 관리자 한 명만 쓰는 화면이라 마지막이다.

**Independent Test**: 관리자로 로그인해 목록·검색·페이징을 쓰고 추가·수정·정지를 한 뒤, 일반 권한으로는 같은 URL 이 막히는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리자로 로그인했을 때, **When** 회원 목록을 열면, **Then** 목록·검색·페이징이 동작한다
2. **Given** 일반 권한으로, **When** 사이드바를 보면, **Then** 회원 관리 메뉴가 없고 URL 로 직접 가면 권한 없음 화면이다
3. **Given** 목록에서, **When** 추가 모달을 열어 회원을 만들면, **Then** 목록에 나타난다
4. **Given** 목록에서, **When** 수정 모달을 열면, **Then** 그 회원의 값이 채워져 있다
5. **Given** 회원 하나를, **When** 확인 후 정지하면, **Then** 그 계정으로는 로그인이 `1004` 로 막힌다
6. **Given** 페이지를 넘길 때, **When** 다음 페이지를 누르면, **Then** 겹치는 행 없이 이어진다

---

### Edge Cases

- **1.5 에 직접 URL 로 들어오면?** 아이디·닉네임을 넘겨받지 못했으므로 저장이 `9001` 로 막힌다. 비밀번호 찾기(1.4)로 안내한다.
- **로그인한 채로 1.1·1.2 에 들어가면?** 비로그인 허용 화면이라 열리지만, 이미 로그인한 사용자에게는 의미가 없다 — 월별 가계부로 보낸다.
- **관리자가 자기 계정을 정지하면?** 다음 요청부터 자기도 막힌다. 확인 다이얼로그에서 대상이 본인임을 알린다.
- **가입 직후 로그인 화면에서 아이디가 비어 있으면?** 방금 만든 아이디를 채워 준다 — 사용자가 다시 입력할 이유가 없다.
- **검색어와 페이지를 함께 쓸 때?** 검색어가 바뀌면 첫 페이지로 되돌린다. 그러지 않으면 결과가 적어졌을 때 빈 페이지가 뜬다.

## Requirements *(mandatory)*

### Functional Requirements

**가입·로그인 (US1)**

- **FR-701**: 가입 화면은 아이디·비밀번호·비밀번호 확인·닉네임을 필수로, 이메일·폰·소개를 선택으로 받아야 한다
- **FR-702**: 비밀번호 규칙(8자 이상, 영 대·소문자·특수문자·숫자 중 3종류 이상)을 **입력 전에** 화면에 보여야 한다
- **FR-703**: 폰은 **하이픈 없이 숫자만** 전송해야 한다. 사용자가 하이픈을 넣어도 화면이 걷어낸다
- **FR-704**: 가입이 성공하면 로그인 화면으로 보내고 **방금 만든 아이디를 채워** 둬야 한다
- **FR-705**: 로그인이 성공하면 월별 가계부로 보내야 한다
- **FR-706**: 로그인 실패(`1003`)는 **아이디와 비밀번호 중 무엇이 틀렸는지 드러내지 않아야** 한다. 서버가 하나의 코드로 묶은 이유를 화면이 풀지 않는다
- **FR-707**: 정지된 계정(`1004`)은 비활성 상태임을 알려야 한다
- **FR-708**: 로그아웃은 상단에서 부를 수 있어야 하며, 부르면 로그인 화면으로 보내야 한다. 백엔드 `MemberTokenRevoke` 를 008 이 직접 부르지 않고 **007 의 `POST /auth/logout` 에 보낸다** — 토큰 비활성화와 세션 무효화의 순서(007 FR-621)를 한 곳에서 지켜야 하기 때문이다
- **FR-709**: 이미 로그인한 사용자가 로그인·가입 화면에 들어오면 월별 가계부로 보내야 한다

**찾기·재설정 (US2)**

- **FR-710**: 아이디 찾기는 이메일을 받아 조회된 아이디를 화면에 보여야 한다
- **FR-711**: 비밀번호 찾기는 아이디·닉네임을 받아 확인하고, 성공하면 비밀번호 변경 화면으로 보내야 한다
- **FR-712**: 비밀번호 변경 화면은 **1.4 에서 확인한 아이디·닉네임을 함께 들고** 있어야 한다. 사용자에게 다시 묻지 않는다
- **FR-713**: 비밀번호 변경이 성공하면 **같은 화면에 완료 문구**를 보인 뒤 로그인 화면으로 보내야 한다. 완료 전용 URL 을 따로 두지 않는다
- **FR-714**: 비밀번호 변경 화면에 아이디·닉네임 없이 직접 들어오면 비밀번호 찾기로 안내해야 한다

**본인 정보 (US3)**

- **FR-715**: 본인 정보 화면은 현재 값을 채워 보여야 하며 **아이디는 고칠 수 없어야** 한다
- **FR-716**: 비밀번호 칸을 비워 두면 비밀번호를 바꾸지 않아야 한다 — 보낸 필드만 반영되는 수정 규칙을 따른다
- **FR-717**: 이메일 중복(`2003`)·비밀번호 규칙 위반(`2004`)을 해당 칸 가까이 알려야 한다

**관리자 (US4)**

- **FR-718**: 회원 목록은 아이디·닉네임 검색과 페이징을 제공해야 한다
- **FR-719**: 검색어가 바뀌면 **첫 페이지로 되돌려야** 한다
- **FR-720**: 회원 추가·수정은 목록 위 **모달**이며 부모 URL + `?m=create` · `?m=edit&id={id}` 로 열려야 한다
- **FR-721**: 권한은 **관리자 `1` · 일반 `3`** 두 값으로만 고를 수 있어야 한다
- **FR-722**: 회원 정지는 **확인 다이얼로그**를 거쳐야 하며, 대상이 본인이면 그 사실을 함께 알려야 한다
- **FR-723**: 회원 정지는 로그아웃과 **다른 행위**임을 화면이 드러내야 한다 — 정지된 계정은 다시 로그인할 수 없다
- **FR-724**: 일반 권한 회원에게 회원 관리 메뉴를 보이지 않아야 한다

### 이 기능이 쓰는 에러코드

**새로 정의하는 코드가 없다.** 백엔드가 준 코드를 화면에 맞게 보여줄 뿐이다.

| 코드 | 뜻 | 어느 화면 |
|---|---|---|
| `1003` | 아이디 또는 비밀번호가 틀림 | 1.1 |
| `1004` | 비활성 계정 | 1.1 |
| `2001` | 회원을 찾을 수 없음 | 1.3 · 1.4 · 1.10 |
| `2002` | 아이디 중복 | 1.2 · 1.9 |
| `2003` | 이메일 중복 | 1.2 · 1.7 · 1.9 · 1.10 |
| `2004` | 비밀번호 규칙 위반 | 1.2 · 1.5 · 1.7 · 1.9 · 1.10 |
| `2005` | 비밀번호 확인 불일치 | 1.2 · 1.5 |
| `9001` | 필수 누락·형식 오류·페이징 규칙 위반 | 전부 |

### Key Entities

DB 저장 단위가 없다. 화면이 다루는 것은 백엔드가 돌려주는 회원 정보뿐이다.

- **회원**: 아이디(바꿀 수 없다) · 닉네임 · 이메일 · 폰 · 소개 · 권한(`1` 관리자 / `3` 일반) · 활성 여부. 비밀번호는 화면으로 내려오지 않는다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-701**: 가입에서 로그인까지 **화면 이동 두 번**으로 끝난다
- **SC-702**: 로그인 실패 응답에서 아이디의 존재 여부를 **알아낼 수 없다**
- **SC-703**: 비밀번호를 잊은 사용자가 아이디·닉네임을 **한 번만** 입력하고 재설정을 마친다
- **SC-704**: 폰을 어떤 형식으로 입력해도 저장된 값은 숫자만이다
- **SC-705**: 일반 권한으로는 관리자 화면 3개에 메뉴로도 URL 로도 닿을 수 없다
- **SC-706**: 정지한 회원이 그 즉시 로그인하지 못한다
- **SC-707**: 화면 9개의 실패가 모두 `resCode` 와 서버 메시지로 사용자에게 전달된다
- **SC-708**: 브라우저가 받은 응답 어디에도 비밀번호·JWT 원문이 없다

## Assumptions

- **007 이 이미 서 있다.** 세션 인증·인터셉터·레이아웃·모달 셸·확인 다이얼로그·API 클라이언트를 그대로 쓰며 이 스펙은 화면만 만든다
- **백엔드 002 의 API 16건이 동작한다.** 008 은 그중 12건을 부르고, `MemberTokenValidate`·`MemberTokenRefresh`·`MemberTokenRevoke` 3건은 007 의 세션 계층이 부르며(로그아웃 버튼은 008 이 만들고 호출은 007 이 한다), `HealthCheck` 는 화면이 부르지 않는다. 백엔드 코드와 스키마는 바뀌지 않는다
- **화면기획 프로토타입을 그대로 옮긴다** — `auth-*.html` 다섯, `member-profile.html`, `member-admin-list.html`. 폼 필드 이름은 이미 백엔드 계약에 맞춰져 있다
- **1.6 권한 없음은 007 이 만들어 둔 것을 쓴다**
- **소셜 로그인은 범위 밖이다**(명세의 "이후 버전")
