# Data Model: 프론트 회원·인증 화면

**Feature**: 008-frontend-member-auth | **Date**: 2026-09-11 | **Plan**: [plan.md](./plan.md)

**DB 저장 단위가 없다.** 화면 모듈은 데이터베이스를 모르고(헌장 원칙 I), 회원 정보는 백엔드가
돌려주는 값을 그때그때 받아 화면에 그린다. `sql/schema-moneylogdb.sql` 은 읽지도 바꾸지도 않는다.

여기 적는 것은 **화면이 손에 들고 있는 값**이다. 세 갈래다.

| 갈래 | 사는 곳 | 수명 |
|---|---|---|
| 로그인 세션 | 서버 세션 | 로그인 ~ 로그아웃·만료 (007 이 정의) |
| 비밀번호 재설정 표식 | 서버 세션 | 본인 확인 ~ 재설정 성공 (008 이 정의) |
| 폼과 화면 값 | 요청 하나 | 그 요청 동안만 |

## 1. 로그인 세션 — 007 의 것을 그대로 쓴다

속성 네 개(접근 토큰·재발급 토큰·아이디·권한)와 그 수명은
[007 data-model.md § 로그인 세션](../007-frontend-foundation/data-model.md)이 이미 정했다.
**008 은 여기에 아무것도 더하지 않는다.**

008 이 하는 일은 둘이다.

| 언제 | 무엇을 |
|---|---|
| 로그인이 성공했을 때 (1.1) | 백엔드가 준 토큰 두 개와 아이디·권한을 세션에 담는다 |
| 로그아웃 버튼을 눌렀을 때 (상단바) | 007 의 로그아웃 주소로 보낸다. 토큰 비활성화와 세션 버리기는 007 이 한다 |

**본인 정보를 세션에 담지 않는다.** 닉네임·이메일·폰·소개는 1.7 이 열릴 때마다 백엔드에서 받는다.
세션에 두면 관리자가 그 회원을 고쳤을 때 화면에 옛 값이 남는다.

**1.7 에서 닉네임을 바꿔도 세션은 바뀌지 않는다.** 세션이 들고 있는 것은 아이디와 권한뿐이고 둘 다
본인 수정으로 바뀌지 않는다.

## 2. 비밀번호 재설정 표식 — 008 이 만드는 유일한 상태

**사는 곳**: 서버 세션. 로그인하지 않은 사용자의 세션이다.

**접근 경로**: 한 클래스만 이 속성을 읽고 쓴다. 007 의 로그인 세션과 같은 규율이며, 이름이 여러 곳에
흩어지면 오타 하나가 "비밀번호 찾기가 자꾸 처음으로 되돌아간다"는 증상으로 나타난다.

### 속성

| 속성 | 타입 | 넣는 시점 | 설명 |
|---|---|---|---|
| 확인된 아이디 | string | 1.4 본인 확인 성공 | 1.5 가 저장 요청에 실을 아이디. 사용자에게 다시 묻지 않기 위해 들고 있다 |
| 확인된 닉네임 | string | 1.4 본인 확인 성공 | 1.5 가 저장 요청에 실을 닉네임. 백엔드가 저장 시점에 다시 대조한다 |

### 수명

| 사건 | 표식 |
|---|---|
| 1.4 본인 확인 성공 | 두 값을 담는다 |
| 1.5 조회 | 읽어서 화면에 싣는다. **지우지 않는다** — 규칙에 안 맞는 비밀번호로 실패했을 때 다시 써야 한다 |
| 1.5 저장 성공 | **지운다.** 남겨 두면 뒤로 가기로 같은 화면에 돌아와 다시 바꿀 수 있다 |
| 1.5 에 표식 없이 들어옴 | 1.4 로 안내한다 (FR-714) |
| 세션 만료 | 함께 사라진다 |

### 담지 않는 것

| 담지 않는 것 | 왜 |
|---|---|
| 새 비밀번호 | 세션에 평문이 머무는 시간을 만들지 않는다. 저장 요청에만 실려 나간다 |
| 확인 시각·시도 횟수 | 잠금·만료 정책은 백엔드가 정할 일이고 002 에 없다. 화면이 임의로 만들면 백엔드와 판단이 갈린다 |

## 3. 화면이 주고받는 값

백엔드 응답을 그대로 쓰지 않고 **화면 용도의 값으로 받는다.** 응답에 있지만 화면이 쓰지 않는 항목을
타입에 두면 "이건 어디 쓰나"를 읽는 사람이 매번 되묻게 된다.

### 3.1 회원 — 화면이 보여 주는 것

1.7 본인 정보와 1.8~1.10 관리자 화면이 같은 모양을 쓴다.

| 값 | 타입 | 어디서 오나 | 화면에서 |
|---|---|---|---|
| 아이디 | string | 백엔드 조회 | **고칠 수 없다.** 1.7·1.10 에서 읽기 전용으로 보인다 |
| 닉네임 | string | 백엔드 조회 | 고칠 수 있다 |
| 이메일 | string 또는 없음 | 백엔드 조회 | 고칠 수 있다. 비우면 지운다 |
| 폰 | string 또는 없음 | 백엔드 조회 | 숫자만. 고칠 수 있고 비우면 지운다 |
| 소개 | string 또는 없음 | 백엔드 조회 | 고칠 수 있다. 비우면 지운다 |
| 권한 | number | 백엔드 조회 | `1` 관리자 · `3` 일반. **본인 정보에서는 고칠 수 없고** 관리자 화면에서만 고른다 |
| 활성 여부 | boolean | 백엔드 조회 | **관리자 목록에만 있다.** 본인 조회 응답에는 없거나 항상 참이다 |

**비밀번호는 어느 방향으로도 이 값에 들어오지 않는다.** 백엔드가 내려주지 않고, 화면도 여기 담지
않는다. 새 비밀번호는 저장 요청에만 실린다.

**가입일은 없다.** 백엔드 목록 응답에 그 값이 없어 화면에 열을 두지 않는다(research 12).

### 3.2 폼 — 사용자가 채우는 것

화면마다 받는 칸이 다르므로 폼도 화면별로 나눈다. **하나로 합치지 않는다** — 합치면 어느 화면이
어느 칸을 쓰는지 폼만 보고 알 수 없고, 그 화면이 보내지 않는 칸까지 검증 규칙이 따라붙는다.

| 폼 | 화면 | 칸 |
|---|---|---|
| 로그인 | 1.1 | 아이디 · 비밀번호 |
| 가입 | 1.2 | 아이디 · 비밀번호 · 비밀번호 확인 · 닉네임 · 이메일 · 폰 · 소개 |
| 아이디 찾기 | 1.3 | 이메일 |
| 비밀번호 찾기 | 1.4 | 아이디 · 닉네임 |
| 비밀번호 재설정 | 1.5 | 새 비밀번호 · 새 비밀번호 확인 (아이디·닉네임은 표식에서 온다) |
| 본인 정보 수정 | 1.7 | 닉네임 · 이메일 · 폰 · 소개 · 새 비밀번호 |
| 회원 추가 | 1.9 | 아이디 · 비밀번호 · 닉네임 · 권한 · 이메일 · 폰 · 소개 |
| 회원 수정 | 1.10 | 닉네임 · 권한 · 이메일 · 폰 · 소개 · 새 비밀번호 |

**폰은 어느 폼에서 오든 숫자만 남겨 보낸다**(research 10). 걷어내는 자리는 화면 모듈 한 곳이다.

**빈 칸의 뜻이 칸마다 다르다**(research 7). 새 비밀번호를 비우면 바꾸지 않고, 이메일·폰·소개를
비우면 지운다. 1.7 과 1.10 에 함께 해당한다.

### 3.3 목록 화면의 상태

1.8 회원 목록이 주소에 들고 다니는 값이다. **세션에 두지 않는다** — 세션에 두면 뒤로 가기와 새 탭에서
다른 목록이 뜬다.

| 값 | 기본 | 설명 |
|---|---|---|
| 아이디 검색어 | 없음 | 부분 일치. 닉네임 검색어와 함께 넣으면 **둘 다** 맞는 회원만 나온다 |
| 닉네임 검색어 | 없음 | 부분 일치. 위와 같다 |
| 쪽 번호 | 0 | 0 부터 센다. 백엔드가 요구하는 조회 시작점은 007 의 환산기가 만든다 |
| 한 쪽 개수 | 007 기본값 | 바뀌면 007 의 환산기가 첫 쪽으로 되돌린다 |

**검색 폼은 쪽 번호를 싣지 않는다**(research 6). 새 검색은 언제나 쪽 번호 없는 요청이 되어 첫 쪽에서
시작한다.

## 4. 상태 변화 — 비밀번호 재설정 흐름

두 화면에 걸쳐 있고 중간 상태가 세션에 있으므로 여기만 흐름을 적는다.

```
1.4 비밀번호 찾기
 │  아이디·닉네임 입력
 ├─ 확인 실패 (회원 없음·비활성) ─→ 1.4 에 그대로 머물며 사유를 보인다
 └─ 확인 성공
        │ 표식에 아이디·닉네임을 담는다
        ↓
1.5 비밀번호 변경
 ├─ 표식 없이 직접 들어옴 ─→ 1.4 로 안내 (FR-714)
 ├─ 저장 실패 (규칙 위반·확인 불일치) ─→ 1.5 에 머문다. 표식은 그대로 둔다
 └─ 저장 성공
        │ 표식을 지운다
        ↓
   완료 문구를 같은 화면에 보인 뒤 1.1 로그인으로
```

**실패해도 표식을 지우지 않는 것이 요점이다.** 지우면 규칙에 안 맞는 비밀번호를 한 번 넣은 사용자가
1.4 부터 다시 해야 한다.
