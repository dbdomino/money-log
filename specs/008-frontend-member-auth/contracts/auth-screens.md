# Contract: 비로그인 화면 다섯 (1.1~1.5)

**Feature**: 008-frontend-member-auth | **관련 FR**: 701~714

전부 007 의 **로그인 전 껍데기**를 쓰고, 007 의 비로그인 허용 목록에 이미 들어 있다.

| 화면 | 주소 | 부르는 API | 성공하면 |
|---|---|---|---|
| 1.1 로그인 | `/auth/login` | `MemberLogin` | 월별 가계부 |
| 1.2 회원가입 | `/auth/signup` | `MemberSignup` | 로그인 화면 (아이디를 채워서) |
| 1.3 아이디 찾기 | `/auth/find-id` | `MemberFindId` | 같은 화면에 결과 |
| 1.4 비밀번호 찾기 | `/auth/find-password` | `MemberFindPassword` | 비밀번호 변경 화면 |
| 1.5 비밀번호 변경 | `/auth/reset-password` | `MemberResetPassword` | 같은 화면에 완료 → 로그인 |

**다섯 API 는 전부 인증 없이 부른다.** 007 클라이언트의 비인증 통로를 쓴다 — 만료된 토큰을 실어
보내면 로그인조차 만료로 거절된다.

---

## 1. 화면마다 조회와 제출이 한 쌍이다

| 주소 | 조회(GET) | 제출(POST) |
|---|---|---|
| `/auth/login` | 폼을 그린다 | 로그인한다 |
| `/auth/signup` | 폼을 그린다 | 가입한다 |
| `/auth/find-id` | 폼을 그린다 | 아이디를 찾아 같은 화면에 보인다 |
| `/auth/find-password` | 폼을 그린다 | 본인을 확인하고 1.5 로 보낸다 |
| `/auth/reset-password` | 표식을 확인하고 폼을 그린다 | 비밀번호를 바꾼다 |

브라우저가 보내는 것은 **GET 과 POST 뿐**이다. 백엔드가 요구하는 메서드로 옮기는 일은 화면 모듈이
한다(research 8).

---

## 2. 1.1 로그인

### 조회

| 상황 | 결과 |
|---|---|
| 로그인하지 않았다 | 폼을 그린다 |
| **이미 로그인했다** | 월별 가계부로 보낸다 (FR-709) |
| 가입 직후 넘어왔다 | 아이디 칸에 **방금 만든 아이디**를 채운다 (FR-704) |
| 세션이 끝나 밀려났다 | 007 이 실어 보낸 안내 문구를 보인다 (research 14) |

### 제출

성공하면 백엔드가 준 토큰 두 개와 아이디·권한을 **007 의 로그인 세션에 담고** 월별 가계부로 보낸다.
세션 식별자를 새로 만드는 일은 007 의 세션 계층이 한다.

| 실패 | 보이는 것 |
|---|---|
| `1003` | 폼 **상단**에만. 아이디 칸에도 비밀번호 칸에도 붙이지 않는다 (FR-706) |
| `1004` | 비활성 계정임을 분명히 알린다 (FR-707) |
| `9001` | 폼 상단 |

화면 아래에 가입·아이디 찾기·비밀번호 찾기로 가는 길을 둔다.

---

## 3. 1.2 회원가입

### 칸

| 칸 | 필수 | 비고 |
|---|:---:|---|
| 아이디 | ✅ | |
| 비밀번호 | ✅ | **규칙을 입력 전에 칸 아래에 적는다** (FR-702) |
| 비밀번호 확인 | ✅ | |
| 닉네임 | ✅ | |
| 이메일 | ❌ | |
| 폰 | ❌ | 숫자만 보낸다. 하이픈은 화면 모듈이 걷어낸다 (FR-703) |
| 소개 | ❌ | |

**비밀번호 규칙 문구는 `_공통.md` 의 것을 그대로 쓴다** — 8자 이상, 영 대·소문자·특수문자·숫자 중
3종류 이상. 화면이 문구를 새로 쓰면 백엔드가 규칙을 고쳤을 때 화면만 옛 안내를 보인다.

### 조회

이미 로그인한 사용자는 월별 가계부로 보낸다 (FR-709).

### 제출

성공하면 **로그인 화면으로 보내며 방금 만든 아이디를 함께 넘긴다.** 사용자가 같은 값을 두 번
입력할 이유가 없다.

| 실패 | 붙는 곳 |
|---|---|
| `2002` 아이디 중복 | 아이디 칸 |
| `2003` 이메일 중복 | 이메일 칸 |
| `2004` 비밀번호 규칙 위반 | 비밀번호 칸 |
| `2005` 비밀번호 확인 불일치 | 비밀번호 확인 칸 |
| `9001` | 폼 상단 |

실패하면 **비밀번호 두 칸을 뺀 나머지가 그대로 남는다**(form-failure.md §3).

---

## 4. 1.3 아이디 찾기

이메일 한 칸을 받아 조회한 아이디를 **같은 화면에** 보인다. 결과 전용 주소를 만들지 않는다.

| 항목 | 내용 |
|---|---|
| 결과 | 백엔드가 돌려준 아이디. **일부가 가려져 올 수 있다** |
| 가림 여부 | 백엔드가 함께 알려 준다. 가려진 값이면 그 사실을 화면에 적는다 |
| `2001` | 그 이메일로 가입된 회원이 없다는 안내 |
| `9001` | 이메일 형식 오류 |

**가려진 아이디를 화면이 풀지 않는다.** 가리는 판단은 백엔드가 한다.

결과 아래에 로그인으로 가는 길을 둔다.

## 5. 1.4 비밀번호 찾기

아이디와 닉네임으로 본인을 확인한다. **비밀번호 칸이 없다** — 이 화면은 확인만 한다.

| 결과 | 다음 |
|---|---|
| 확인 성공 | 아이디·닉네임을 **재설정 표식에 담고** 1.5 로 보낸다 (FR-711) |
| `2001` 불일치 | 1.4 에 머물며 안내. 아이디와 닉네임 중 무엇이 틀렸는지 백엔드가 가르지 않으므로 화면도 가르지 않는다 |
| `1004` 비활성 | 정지된 계정임을 알린다 |
| `9001` | 폼 상단 |

화면에 "확인되면 비밀번호 변경 화면으로 갑니다"를 미리 적는다. 두 단계라는 것을 시작할 때 알리는
편이 낫다.

## 6. 1.5 비밀번호 변경

### 조회

| 상황 | 결과 |
|---|---|
| 표식이 있다 | 폼을 그린다. **확인된 아이디를 화면에 보여 준다** — 누구의 비밀번호를 바꾸는지 알아야 한다 |
| **표식이 없다** | 비밀번호 찾기로 안내한다 (FR-714) |

표식이 없을 때 폼을 그리고 저장에서 실패시키지 않는다. 사용자가 비밀번호를 고른 뒤에 "처음부터
다시 하세요"를 보게 된다.

### 칸

| 칸 | 필수 | 어디서 |
|---|:---:|---|
| 아이디 | — | **표식에서.** 사용자가 입력하지 않는다 |
| 닉네임 | — | **표식에서.** 사용자가 입력하지 않는다 |
| 새 비밀번호 | ✅ | 규칙 문구를 칸 아래에 적는다 |
| 새 비밀번호 확인 | ✅ | |

앞의 둘은 화면에 숨은 값으로 싣고 저장 요청에 함께 보낸다. **백엔드가 저장 시점에 다시 대조하므로**
값을 바꿔도 남의 비밀번호를 바꿀 수 없다.

### 제출

| 결과 | 다음 |
|---|---|
| 성공 | **표식을 지우고**, 같은 화면을 완료 상태로 그린다. 완료 문구와 「로그인으로」 버튼을 함께 둔다 (FR-713) |
| `2004` 규칙 위반 | 1.5 에 머문다. **표식은 그대로 둔다** — 지우면 1.4 부터 다시 해야 한다 |
| `2005` 확인 불일치 | 위와 같다 |
| `2001` 불일치 | 표식의 값이 더는 맞지 않는다. 1.4 로 안내한다 |
| `9001` | 폼 상단 |

완료 화면은 잠시 뒤 로그인으로 옮겨 간다. **버튼을 함께 두는 것이 중요하다** — 자동 이동이 막힌
환경에서 사용자가 갇히지 않게 한다.

## 7. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 가입 성공 → 로그인 화면 주소로 가고 아이디가 채워져 있다 | FR-704 · SC-701 |
| 로그인 성공 → 월별 가계부 주소로 가고 세션에 토큰이 담긴다 | FR-705 |
| `1003` 안내가 아이디 칸에 붙지 않는다 | FR-706 · SC-702 |
| 하이픈을 넣어 가입해도 백엔드로 나간 폰은 숫자만이다 | FR-703 · SC-704 |
| 로그인한 채 `/auth/login`·`/auth/signup` → 월별 가계부 | FR-709 |
| 1.4 성공 → 1.5 에서 아이디·닉네임을 **묻지 않는다** | FR-712 · SC-703 |
| 표식 없이 `/auth/reset-password` → 1.4 로 안내 | FR-714 |
| 1.5 실패 후에도 표식이 살아 있어 다시 시도할 수 있다 | data-model §4 |
| 1.5 성공 후 표식이 사라진다 | data-model §2 |
| 세션 만료로 밀려난 사용자가 1.1 에서 사유 문구를 본다 | research 14 |
