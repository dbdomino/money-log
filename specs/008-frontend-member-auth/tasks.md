## Path Conventions

Spring Boot 멀티모듈이다. 저장소 루트 기준 경로를 쓴다.

- 프론트 메인: `app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/`
- 프론트 템플릿: `app-mod/money-app/src/main/resources/templates/`
- 프론트 시험: `app-mod/money-app/src/test/java/com/dbdomino/moneylog/front/`
- 화면 상세 명세: `프로젝트설계/기능명세상세-프론트엔드/phase1-회원/`
- 화면기획 산출물(원본): `프로젝트설계/화면기획/proto/`

**의존성을 더하지 않는다.** 007 이 남긴 `common-mod`·웹·타임리프·검증 넷으로 충분하다. 루트 `build.gradle` 을 손대지 않는다.

**백엔드와 DB 를 건드리지 않는다.** `app-mod/money-backend-app` 과 `sql/schema-moneylogdb.sql` 의 diff 가 비어 있는 것이 이 기능의 전제다.

## 007 을 고치지 않는다

008 이 007 의 공통 코드를 고치기 시작하면 009~012 도 그렇게 하고, 공통 기반이 화면별 사정을 하나씩 알게 된다. 필요한 착지 변경은 **컨트롤러 안의 선언**으로 해결한다 — 컨트롤러 지역 선언이 공통 선언보다 먼저 잡히는 것이 프레임워크의 규칙이다.

**예외가 하나 있다.** 007 의 결함이 드러나면 그쪽을 고친다. 지금 아는 후보는 세션 만료 안내 문구의 전달 경로 하나이며 T030 이 그것을 확인한다.

## Implementation Strategy

### MVP 범위

**Phase 1 + Phase 2 + Phase 3(US1)** 이 최소 인도 단위다. 여기까지면 사용자가 계정을 만들고 로그인해 서비스 안으로 들어간다 — 007 이 세운 세션 인증이 처음으로 실제로 돈다.

착지할 월별 가계부는 010 이 만들므로 MVP 시점의 로그인은 **주소까지만** 간다. 그것으로 세션 인증이 도는지는 확인된다.

### 그다음

| 순서 | 스토리 | 왜 이 순서인가 |
|---|---|---|
| 2 | US2 찾기·재설정 | 없으면 사용자가 계정을 **영구히 잃는다** |
| 3 | US3 본인 정보 | 로그인 후 가장 먼저 손대는 화면이지만 없어도 가계부는 쓸 수 있다 |
| 4 | US4 관리자 | 관리자 한 명만 쓰는 화면이다 |

US2 와 US3 은 둘 다 P2 라 순서를 바꿔도 된다. 위 순서는 "없으면 사용자가 잃는 것"의 크기로 정했다.

### 병렬 인도

네 스토리가 서로 독립이므로 Phase 2 이후 사람이 나뉘면 스토리별로 갈라 받을 수 있다. 겹치는 파일은 없고, 공통 장치(T006~T010)는 그 전에 서 있다.
