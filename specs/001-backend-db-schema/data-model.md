# Data Model: 001-backend-db-schema

**재작성**: 2026-08-31 — spec 재작성 + clarification 4건 반영.

대상 스키마: PostgreSQL 18 `moneylogdb.moneylog`. 근거 결정은 [research.md](./research.md), 요구사항은 [spec.md](./spec.md).

## 공통 규칙

모든 테이블에 예외 없이 적용된다. 아래 각 테이블 정의에서는 **반복하지 않는다.**

| 항목 | 규칙 | 근거 |
|------|------|------|
| 기본키 | `idx BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`. **`tbl_user`만 `id_key`** | FR-008 |
| 소유자 | `id_key BIGINT NOT NULL REFERENCES tbl_user(id_key) ON DELETE RESTRICT`. `tbl_user` 자신은 제외 | FR-002 |
| 감사 | `created_at TIMESTAMPTZ NOT NULL`, `updated_at TIMESTAMPTZ NOT NULL`, `created_by BIGINT NOT NULL`, `updated_by BIGINT NOT NULL` — FK 없음 | FR-004, research §3 |
| 금액 | `BIGINT` (원 단위 정수) | FR-005 |
| 시각 | `TIMESTAMPTZ` | research §6 |

`created_by`/`updated_by`는 그 행을 만들거나 고친 회원의 `id_key`이며, 소유자 `id_key`와 다를 수 있다.

**예외 1개** — `tbl_user.created_by`는 NULL 허용(회원가입은 자기 자신을 만드는 행위라 INSERT 시점에 `id_key`가 없다). NULL = 본인 가입, 값 있음 = 그 관리자가 추가.

## 1. `tbl_user` — 회원

Spec: FR-010 ~ FR-014, FR-020 · Entity #1

|------|------|------|------|

| `nickname` | VARCHAR(20) | NOT NULL | 닉네임 2~20자 |
| `email` | VARCHAR(100) | NULL | 이메일. 값이 있으면 전역 유일(부분 유니크) |

| `active` | BOOLEAN | NOT NULL, DEFAULT true | 활성 여부. 관리자 정지 시 false |

**UNIQUE**: `(user_id)` · `(email) WHERE email IS NOT NULL`

**규칙**
- 비활성화는 이 행이나 그 회원의 가계부 데이터를 지우지 않는다(FR-014)
- 회원 물리 삭제 경로가 없으므로 모든 자식 FK는 RESTRICT로 충분하다

## 2. `tbl_user_session` — 회원 세션

Spec: FR-015 ~ FR-018, FR-019a · Entity #2 · `_공통.md § 회원 세션`

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `session_id` | UUID | NOT NULL, UNIQUE | 세션 식별자. Access Token JWT 클레임 `sid`에 담긴다 |
| `access_token_hash` | VARCHAR(100) | NULL | 현재 Access Token 해시. 폐기 시 NULL |
| `refresh_token_hash` | VARCHAR(100) | NULL | 현재 Refresh Token 해시. 폐기 시 NULL |
| `access_expires_at` | TIMESTAMPTZ | NOT NULL | Access 만료 시각 |
| `refresh_expires_at` | TIMESTAMPTZ | NOT NULL | Refresh 만료 시각 |
| `revoked` | BOOLEAN | NOT NULL, DEFAULT false | JWT 비활성화 여부 |
| `last_accessed_at` | TIMESTAMPTZ | NULL | 마지막 API 인증 성공 시각 |

**UNIQUE**: `(session_id)` · **`(id_key) WHERE revoked = false`** ← 활성 세션 1건 강제(FR-017)

**규칙**
- 폐기 = 두 해시를 NULL로 하고 `revoked = true`. **행을 지우지 않는다**(FR-016)
- 토큰 재발급은 같은 행의 두 해시·두 만료 시각을 갱신한다. 새 행을 만들지 않는다(FR-018)
- 폐기 행은 무기한 보존한다(FR-019a)
- 세션의 `created_at`이 명세의 "세션(로그인) 생성 시각"을 겸한다

## 5. `tbl_user_expend_group` — 지출유형

Spec: FR-020, FR-034 ~ FR-037 · Entity #5

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `name` | VARCHAR(30) | NOT NULL | 유형 이름. 회원 안에서 유일 |
| `in_use` | BOOLEAN | NOT NULL, DEFAULT true | 사용 여부 |
| `default_group` | BOOLEAN | NOT NULL, DEFAULT false | 시스템 기본 유형 여부. 가입 시 생성분은 true |
| `icon_filename` | VARCHAR(255) | NULL | 아이콘 파일명 (예: `user01_식비.png`). 없으면 NULL |
| `deleted` | BOOLEAN | NOT NULL, DEFAULT false | 삭제 표시 |

**UNIQUE**: `(id_key, name)` — 삭제 표시된 행도 포함해 유일(research §5)

**INDEX**: `(id_key, in_use, deleted)` ← 2.13 사용 중 유형 목록

**규칙**
- 삭제는 `deleted = true`로만 바꾼다(FR-037). 아이콘 파일은 남긴다

- 고정지출·목표금액·통계가 이 유형을 가리키는 것은 삭제 차단 조건이 **아니다**

- 가입 시 10종 생성: 식비·교통·주거·통신·쇼핑·장보기·의료·교육·문화·기타. 전부 `default_group = true`, `in_use = true`, `icon_filename` 채움(FR-020)

## 6. `tbl_user_expense` — 월별 지출 내역

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `payment_method_idx` | BIGINT | NOT NULL, FK → `tbl_user_payment_method(idx)` RESTRICT | 지출 수단 |
| `payment_method_name` | VARCHAR(50) | NOT NULL | **등록 당시** 수단 이름(스냅샷) |
| `amount` | BIGINT | NOT NULL, CHECK > 0 | 금액(원) |
| `payment_date` | DATE | NOT NULL | 결제일 |
| `place` | VARCHAR(100) | NOT NULL | 장소 |
| `content` | VARCHAR(255) | NOT NULL | 내용 |
| `expend_group_idx` | BIGINT | NOT NULL, FK → `tbl_user_expend_group(idx)` RESTRICT | 지출유형 |
| `expend_group_name` | VARCHAR(30) | NOT NULL | **등록 당시** 유형 이름(스냅샷) |
| `installment_group_id` | BIGINT | NULL | 할부 그룹 식별자. 시퀀스 `seq_installment_group` |
| `installment_index` | INT | NULL, CHECK >= 1 | 할부 회차 번호(1부터) |
| `installment_total` | INT | NULL, CHECK >= 2 | 총 할부 개월 수 |

**INDEX**: `(id_key, payment_date)` · `(installment_group_id, payment_date)`

**규칙**
- 할부 3개 컬럼이 **모두 NULL이면 일시불**, 모두 채워지면 할부다(FR-043)
- 할부 등록은 개월 수만큼의 행을 한 트랜잭션에 만들고 같은 `installment_group_id`를 공유한다. 일부 실패 시 전체 롤백(FR-044)
- 중도상환 = `WHERE installment_group_id = ? AND payment_date > CURRENT_DATE` 물리 삭제. 오늘·과거 회차는 남는다(FR-045)
- 이름 스냅샷은 참조가 바뀔 때만 새 참조의 현재 이름으로 갱신한다(FR-042). 원본 이름만 바뀐 경우 과거 건은 그대로
- 삭제는 물리 삭제(FR-047). 같은 날짜·금액·수단 중복 허용 — 업무 유일 제약 없음(FR-048)
- **고정지출 행은 이 테이블에 들어오지 않는다**(FR-052)
- 엑셀 일괄 등록은 이 테이블과 `tbl_user_income`에만 행을 만든다. 업로드 이력을 저장하지 않는다(FR-049)

| `content` | VARCHAR(255) | NOT NULL | 내용 |
| `expend_group_idx` | BIGINT | NOT NULL, FK → `tbl_user_expend_group(idx)` RESTRICT | 지출유형 |

- 값을 바꿔도 이미 만들어진 월별 내역은 **미래 달 + `modified = false`** 인 것만 따라간다(FR-058). 애플리케이션 로직

## 9. `tbl_user_fixed_expense_monthly` — 월별 고정지출 내역

Spec: FR-052 ~ FR-060 · Entity #9

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `fixed_expense_idx` | BIGINT | NOT NULL, FK → `tbl_user_fixed_expense(idx)` **CASCADE** | 어느 고정지출의 그 달 내역인가 |
| `year` | INT | NOT NULL | 연 |
| `month` | INT | NOT NULL, CHECK 1~12 | 월 |
| `amount` | BIGINT | NOT NULL, CHECK > 0 | **그 달** 금액 |
| `payment_date` | DATE | NOT NULL | **그 달** 결제일. 말일 보정이 끝난 완전한 날짜 |
| `content` | VARCHAR(255) | NOT NULL | 그 달 내용 |
| `payment_method_idx` | BIGINT | NOT NULL, FK → `tbl_user_payment_method(idx)` RESTRICT | 그 달 수단 |
| `expend_group_idx` | BIGINT | NOT NULL, FK → `tbl_user_expend_group(idx)` RESTRICT | 그 달 지출유형 |
| `modified` | BOOLEAN | NOT NULL, DEFAULT false | 그 달 값을 사용자가 직접 고쳤는지 |

**UNIQUE**: `(fixed_expense_idx, year, month)` ← 그 달 1건 강제(FR-053)

**INDEX**: `(id_key, year, month)`

**규칙**
- **생성 시점**: 그 연·월을 **처음 조회할 때** 관리 행에서 복사해 INSERT(lazy). 4.5와 4.8 **양쪽 모두**에서 일어난다(FR-054)
- **동시 요청**: UNIQUE + `INSERT ... ON CONFLICT DO NOTHING`으로 행이 늘어나지 않는다(FR-054)
- **결제일 확정**: `payment_day_of_month`가 그 달 말일보다 크면 말일로 보정해 **저장**한다. 조회할 때마다 다시 계산하지 않는다(FR-055)
- **생성 범위**: 관리 행의 적용 기간 안인 연·월만. `year*12+month`가 시작~종료 사이(FR-056)
- **단건 수정**: 금액·결제일·내용·수단만 바꾸고 `modified = true`로 표시. 이름·지출유형은 이 경로로 바꾸지 않는다(FR-057)
- **이름 스냅샷 없음.** 조회 시 원본 현재 이름(FR-053)
- 별도의 "월별 예외" 테이블은 만들지 않는다 — 이 행 자체가 그 달의 값이다

**수동 재작성(FR-060)이 이 테이블에 하는 일** — 지정한 연·월 하나에 대해 한 트랜잭션:

| 대상 | 처리 |
|------|------|
| 적용 기간에 걸리는데 행이 없는 고정지출 | INSERT (`createdCount`) |
| 행이 있고 `modified = false` | 관리 값으로 UPDATE (`updatedCount`) |
| 행이 있고 `modified = true` | 기본 보존(`keptCount`). `overwriteModified=true`면 UPDATE 후 `modified = false`로 되돌림 |
| 적용 기간이 그 연·월을 더는 포함하지 않는 행 | DELETE (`deletedCount`) |

| `saved_at` | TIMESTAMPTZ | NOT NULL | 저장 시각. 재저장 시 갱신. 응답 `savedAt` |
| `income_total` | BIGINT | NOT NULL | 월 소득 합계 |
| `expense_total` | BIGINT | NOT NULL | 월 지출 합계 (일반+할부+고정) |
| `fixed_amount` | BIGINT | NOT NULL | 고정지출 합계 |
| `regular_amount` | BIGINT | NOT NULL | 일반·할부 지출 합계 |
| `fixed_percent` | NUMERIC(5,2) | NOT NULL | 고정 비율 0.00~100.00 |
| `regular_percent` | NUMERIC(5,2) | NOT NULL | 일반 비율 0.00~100.00 |

**UNIQUE**: `(id_key, year, month)` ← 재저장해도 행이 늘지 않음(FR-074)

**규칙**
- 재저장은 이 행을 UPDATE하고 상세 3종을 지웠다 다시 넣는다. `saved_at`을 갱신한다
- 저장 당시 값을 그대로 보존한다. 이후 원본이 바뀌어도 변하지 않는다(FR-075)
- **저장본 존재 = `source: SAVED`**. `view=live` 요청은 이 테이블을 읽지도 쓰지도 않고 즉석 계산만 한다(FR-079)
- `view=live`인데 저장본이 있으면 `saved_at`만 꺼내 응답에 싣는다(5.5 명세)

## 14. `tbl_user_statistics_expend_group` — 통계 지출유형별 요약

Spec: FR-076 ~ FR-078a · Entity #14

| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| `statistics_idx` | BIGINT | NOT NULL, FK → `tbl_user_statistics(idx)` **CASCADE** | 소속 스냅샷 |
| `expend_group_idx` | BIGINT | NOT NULL, **FK 없음** | 지출유형 대리키. 값으로만 보관 |
| `expend_group_name` | VARCHAR(30) | NOT NULL | **저장 당시** 유형 이름(한글) |
| `amount` | BIGINT | NOT NULL | 유형별 지출 합계 |
| `target_amount` | BIGINT | NOT NULL | 적용된 목표금액 (월별 ?? 기본) |
| `usage_rate` | NUMERIC(6,2) | NOT NULL | 사용률 %. `target = 0`이면 0 |
| `status` | VARCHAR(10) | NOT NULL, CHECK IN ('UNDER','OK','OVER') | 90% 미만 / 90~110% / 110% 초과 |

**UNIQUE**: `(statistics_idx, expend_group_idx)`

**규칙**
- **참조 무결성 제약을 두지 않는다**(FR-078a). 원본 유형이 사라져도 이 행은 남고, 화면은 `expend_group_name`으로 복원한다
- 응답 `expendGroupId`는 저장된 `expend_group_idx` 값을 그대로 내려준다 — 실재하지 않을 수 있다
- 지출이 **0원인 유형은 저장하지 않는다**(FR-076)
- `status` 기준이 나중에 바뀌어도 이미 저장된 행은 다시 계산하지 않는다

`usage_rate`가 `NUMERIC(6,2)`인 이유: 사용률은 100%를 넘을 수 있고(`OVER`), 목표 대비 1000% 같은 값도 표현 가능해야 한다.

## 관계도

```text
tbl_user (id_key)
├── tbl_user_session                    (id_key)  UNIQUE(id_key) WHERE NOT revoked
├── tbl_user_login_history              (id_key)
├── tbl_user_payment_method             (id_key)  ←──┐
├── tbl_user_expend_group               (id_key)  ←┐ │
├── tbl_user_expense                    (id_key)  ─┴─┤  + installment_group_id (시퀀스)
├── tbl_user_income                     (id_key)  ───┤
├── tbl_user_fixed_expense              (id_key)  ─┬─┘
│   └── tbl_user_fixed_expense_monthly  (id_key)  ─┘  CASCADE ← fixed_expense_idx
├── tbl_user_expend_target_default      (id_key)  → expend_group
├── tbl_user_expend_target_monthly      (id_key)  → expend_group
└── tbl_user_statistics                 (id_key)
    ├── tbl_user_statistics_weekly              CASCADE
    ├── tbl_user_statistics_expend_group        CASCADE  (expend_group_idx = 값만)
    └── tbl_user_statistics_payment_method      CASCADE  (payment_method_idx = 값만)
```

실선 화살표는 FK, 괄호 안은 소유자 컬럼이다. 통계 상세 2종의 유형·수단 참조만 FK가 없다.

## JPA 매핑 메모

- 스키마는 Entity에 하드코딩하지 않고 `hibernate.default_schema=moneylog`로 제어한다(헌장 기술 제약)
- 감사 4컬럼은 `@MappedSuperclass` 공통 상위 클래스 + `AuditingEntityListener`로 상속시킨다. `AuditorAware<Long>`이 `SecurityContext`의 `id_key`를 공급한다
- `tbl_user`만 PK 이름이 다르므로 공통 상위 클래스에 PK를 넣지 않는다 — PK는 각 Entity가 선언한다
- Entity는 API·화면에 노출하지 않는다(헌장 II). 본 기능은 Entity·Repository까지만 만든다
- 부분 유니크 인덱스와 CHECK는 Hibernate가 만들지 못하므로 보조 DDL로 적용한다(research §8, [contracts/naming-and-constraints.md](./contracts/naming-and-constraints.md))
