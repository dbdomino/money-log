# Contract: 월별 가계부 (5.1)

**Feature**: 010-frontend-ledger-expense-income | **관련 FR**: 901~907 · 918~921

| 항목 | 값 |
|---|---|
| 주소 | `/ledger` |
| 껍데기 | 007 의 **로그인 후** 레이아웃 |
| 사이드바 활성 메뉴 | `ledger` |
| 권한 | 로그인 |
| 부르는 API | `LedgerMonthlyList` |

**로그인 직후 착지하는 화면이다.** 008 이 로그인 뒤 이 주소로 보내며, 여기가 모달 넷(3.1~3.4)의
부모다.

---

## 1. 한 목록에 네 종류

### 열

| 열 | 값 |
|---|---|
| 일자 | 결제일 `YYYY-MM-DD` |
| 구분 | **뱃지.** 지출 · 할부 · 소득 · 고정지출 |
| 수단 | 수단 이름 |
| 유형 | 지출유형 이름. **소득은 빈 칸** |
| 내용 | 내용. 장소가 있으면 함께 보인다 |
| 금액 | 원 단위. 오른쪽 정렬 |
| 관리 | 행 종류에 따라 다르다 (§3) |

**뱃지가 먼저 온다.** 종류를 알아야 그 행에 왜 빈 칸이 있는지 읽힌다 — 소득에는 지출유형이
없고, 소득·고정지출에는 장소가 없다.

**할부 행은 회차를 함께 보인다.** 「3/12」처럼 적어 같은 내용이 달마다 반복되는 이유를
알린다. 적지 않으면 사용자는 같은 지출이 여러 번 들어간 줄 안다.

### 비는 칸을 채우지 않는다

**응답에 없는 것이 정상이다.** 「없음」 같은 말을 넣으면 "비어 있는 값"과 "없는 항목"이
구분되지 않는다(`FR-906`).

### 이름을 다시 조회해 덮어쓰지 않는다

**고정지출 행만 조회 시점 현재 이름**이고 나머지는 등록 당시 스냅샷이다(`FR-905`). 수단 이름을
바꾼 뒤 열면 고정지출 행만 새 이름으로 보이는데 **버그가 아니라 설계다**.

화면이 이 차이를 숨기려고 이름을 맞추면 **과거 기록이 사후에 바뀐다.** 가계부가 해서는 안
되는 일이다.

**사용자에게 설명하지 않는다.** 목록에 주석을 달면 읽기 어려워진다. 이 규칙은 문서에 남기고
화면은 조용히 지킨다.

## 2. 상단 요약

| 값 | 어디서 |
|---|---|
| 지출 합계 | 백엔드가 준 값 그대로 |
| 소득 합계 | 백엔드가 준 값 그대로 |
| 잔액 | 화면이 두 값을 뺀다 |

**필터와 무관하다**(`FR-904` · `SC-903`). 화면이 목록을 다시 더해 맞추지 않는다.

필터를 걸면 목록의 합과 상단 합계가 달라지는데 **그것이 의도다** — 합계는 화면 상단의 요약이고
필터는 아래 목록을 좁히는 도구다. 맞추려 하면 "필터를 걸었는데 이번 달 지출이 줄어드는"
화면이 되고, 사용자는 자기가 쓴 돈이 줄었다고 읽는다.

**거래가 없는 달은 합계가 0 이고 빈 목록임을 함께 알린다**(`FR-907`). 목록만 비어 있으면
사용자는 불러오지 못한 것으로 읽는다.

## 3. 행이 열 수 있는 것

| 종류 | 수정 | 삭제 | 중도상환 |
|---|:---:|:---:|:---:|
| 지출 | ✅ | ✅ | ❌ |
| 할부 | ✅ | ✅ | **✅** |
| 소득 | ✅ | ✅ | ❌ |
| 고정지출 | **❌** | **❌** | ❌ |

**고정지출 행은 읽기만 한다**(`FR-917`). 만들고 고치는 것은 011 이며, 여기서 지우면 그 달
내역만 사라질지 설정 전체가 사라질지 사용자가 알 수 없다 — **되돌릴 수 없는 동작의 범위가
불분명한 버튼**이다.

**대신 고정지출 화면으로 가는 길을 둔다.** 왜 이 행만 버튼이 없는지 적지 않으면 화면이
고장 난 것으로 읽힌다.

**중도상환 버튼은 할부 행에만 그린다**(`FR-922`). 일반 지출 행에 두면 사용자는 자기 지출이
할부인 줄 안다.

## 4. 연·월과 필터

### 주소에 들고 다닌다

| 값 | 기본 |
|---|---|
| 연 · 월 | **이번 달**. 주소에 없으면 **서버 시각**으로 정한다 |
| 수단 · 지출유형 | 없음 |
| 시작일 · 종료일 | 없음. 그 달 안에서 결제일을 더 좁힌다 |
| 검색어 | 없음. **내용과 장소** 두 칸을 본다 |
| 종류 | 없음(전부). **여러 개를 함께** 고를 수 있다 |
| 정렬 기준 · 방향 | **결제일 · 내림차순** |

**정렬 기준은 결제일과 금액 둘뿐이다**(`FR-920`). 백엔드가 그 둘만 받는다 — 수단·지출유형
정렬은 부를 방법이 없어 이 기능의 범위가 아니다(research 12-1).

**화면이 받은 목록을 스스로 다시 정렬하지 않는다.** 지금은 한 달치를 전부 받아 괜찮아 보이지만
그 가정이 화면 코드에 숨고, 쪽 넘기기가 생기는 순간 깨진다.

**세션에 두지 않는다.** 두면 뒤로 가기와 새 탭에서 다른 목록이 뜬다.

**브라우저 시각을 믿지 않는다**(`FR-901`). 시차가 있는 사용자가 다른 달을 본다.

**연·월을 바꿔도 필터가 유지된다**(`FR-921`). 주소 방식에서 저절로 따라온다 — 연·월만 바꾼
주소를 만들면 나머지가 그대로 실린다.

**종류 필터는 여러 값을 보낼 수 있어야 한다.** 백엔드가 콤마로 받는다. 화면이 한 값만 보내면
"지출과 할부만" 같은 조합을 만들 수 없다(`FR-919`).

### 결과가 0건이어도 필터를 풀지 않는다

**사용자가 건 조건이다.** 자동으로 풀면 사용자는 자기가 무엇을 걸었는지 잃는다. 빈 목록임을
알리기만 한다.

### 쪽 넘기기가 없다

한 달치를 전부 받으며 합계도 함께 온다. 007 의 페이징 환산기를 쓰지 않는다 — 쪽을 나누면
합계와 목록의 기준이 갈린다.

**011·012 는 각자 확인한다.** 목록이라고 다 같지 않다.

## 5. 이 화면이 만나는 실패

**새로 정의하는 코드가 없다.** 백엔드가 준 코드를 그대로 옮긴다.

| 코드 | 뜻 | 보이는 곳 |
|---|---|---|
| `3501` | 가계부 조회의 연·월 값 오류 | 목록 안내. **빈 목록과 합계 0 으로** 그린다 |
| `3207` | 정리할 남은 할부가 없음 | 목록 안내 (오류 화면이 아니다) |
| `3202` | 지출을 찾을 수 없음 — 삭제·중도상환 대상 | 목록 안내 |
| `3302` | 소득을 찾을 수 없음 — 삭제 대상 | 목록 안내 |

**이 화면의 실패는 전부 목록의 안내다.** 모달이 없는 자리에서 일어나므로 붙일 칸이 없고,
**오류 화면으로 보내면 목록으로 돌아오는 걸음만 늘어난다.**

**목록 조회가 실패해도 빈 목록과 합계 0 으로 그린다.** 로그인 직후 착지라 여기서 터지면
사용자는 로그인하자마자 오류를 만난다. **백엔드에 닿지 못한 것은 다르다** — 그때는 007 의
오류 화면으로 간다.

모달 안에서 일어나는 실패는
[expense-income-modals.md](./expense-income-modals.md) §6 이 들고 있다.
