## Implementation Strategy

### MVP 범위

**Phase 1 + Phase 2 + Phase 3(US1)** 이 최소 인도 단위다. 여기까지면 사용자가 **평소 한도를
정해 둘 수 있다.**

**다만 US2 를 함께 넣는 쪽이 값이 크다.** 둘 다 P1 이고 서로 독립이며, US1 만 인도하면
**정해 둔 목표를 쓸 곳이 없다** — 목표 대비를 보는 화면이 US2 이기 때문이다.

### 그다음

| 순서 | 스토리 | 왜 이 순서인가 |
|---|---|---|
| 1 | US1 + US2 | 둘 다 P1 이고 독립이다. 목표를 정하고 그 결과를 보는 한 쌍이 완성된다 |
| 2 | US3 월별 목표 | 통계를 보며 "이번 달은 다르게"를 정하는 흐름이다. US2 의 표에 칸을 더한다 |
| 3 | US4 통계 저장 | 과거 월을 보존하는 유일한 방법이다. 쌓인 뒤에 필요해진다 |

**US3 을 US4 보다 앞에 두는 이유**는 US3 이 **매달 쓰는 기능**이고 US4 는 **지난 달을
확정할 때 한 번** 쓰는 기능이기 때문이다.

### 병렬 인도

Phase 2 이후 사람이 둘이면 **한쪽이 US1, 다른 쪽이 US2** 를 맡는다. 패키지가 달라 겹치는
파일이 없다.

셋이면 US2 가 끝난 뒤 **US3 과 US4 로 갈린다.** 둘 다 통계 화면을 넓히지만 자리가 달라 —
US3 은 유형별 표의 칸, US4 는 상단의 배지와 버튼 — 합칠 때 충돌이 적다.

## Notes

- **[P] 는 다른 파일이고 미완 작업에 기대지 않는다는 뜻이다.** 같은 파일을 넓혀 가는 작업에는 붙이지 않았다.
- **007~011 을 하나도 고치지 않는다.** 모달도 확인 다이얼로그도 파일 주고받기도 없어 공통 코드를 건드릴 이유가 없다. T045 가 diff 로 확인한다.
- **"없음"과 "0"이 다르다.** 0 은 "그 달엔 쓰지 않겠다"는 의사 표시이며, 빈 칸과 같게 다루면 그 표시가 사라진다. **기본 목표는 반대로 "없음"이 없다.**
- **화면이 내는 값과 서버 값을 가른다.** 적용 금액과 비중은 화면이 내고, **사용률은 서버 값**이다 — 상한에서 자르는 규칙이 서버에 있고 저장본은 저장 당시 목표 기준이다.
- **같은 화면의 두 표가 반대 규칙을 쓴다.** 유형별은 0원을 빼고 수단별은 남긴다 — **통일하면 한쪽이 계약과 어긋난다.**
- **전역 목표를 만들지 않는다.** 화면이 유형별 목표를 더하면 숫자가 틀리고 판정 기준이 두 개가 된다.
- **조회가 저장을 겸하지 않는다.** 겸하면 열어 보기만 해도 스냅샷이 덮인다.
- **고정 0 을 단정하지 않는다.** 화면은 합계가 0 이라는 것만 알 뿐이라 **두 가능성을 함께** 적는다.
- **에러코드를 새로 정의하지 않는다.** 백엔드가 준 코드를 그대로 옮긴다.
- 화면이 부르는 API 6건의 주소와 칸은 `프로젝트설계/기능명세상세-백엔드/` 의 phase5 가 갖고 있다. 012 는 그것을 소비만 한다.
