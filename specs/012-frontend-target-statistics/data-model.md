# Data Model: 프론트 목표금액·통계 화면

**Feature**: 012-frontend-target-statistics | **Date**: 2026-09-21 | **Plan**: [plan.md](./plan.md)

**DB 저장 단위가 없다.** 화면 모듈은 데이터베이스를 모르고, 목표와 통계는 백엔드가 돌려주는
값을 그때그때 받아 그린다. `sql/schema-moneylogdb.sql` 은 읽지도 바꾸지도 않는다.

**세션에 더하는 상태가 없다.** 009~011 과 같다 — 화면 둘이 전부 한 요청 안에서 끝난다.
쪽 번호·연·월·조회 갈래는 주소에 실린다.

| 갈래 | 사는 곳 | 수명 |
|---|---|---|
| 로그인 세션 | 서버 세션 | 007 이 정의한 그대로. 012 는 읽지도 쓰지도 않는다 |
| 6.1 의 쪽 번호·검색어 | 주소 | 그 요청 동안만 |
| 6.2 의 연·월·조회 갈래 | 주소 | 그 요청 동안만 |
| 폼과 화면 값 | 요청 하나 | 그 요청 동안만 |

---

## 1. 목표금액 행

6.1 과 6.2 가 **같은 값을 함께 쓴다.** 6.1 은 기본을 고치고 6.2 는 월별을 고친다.

| 값 | 타입 | 화면에서 |
|---|---|---|
| 지출유형 식별자 | number | 저장 경로에만 쓰고 화면에 보이지 않는다 |
| 지출유형 이름 | string | **조회 시점 현재 이름** |
| 기본 목표 | number | **언제나 숫자다.** 정한 적 없으면 서버가 `0` 을 준다 |
| 월별 목표 | number **또는 없음** | **정한 적 없으면 없음.** 기본을 복사해 주지 않는다 |
| 적용 금액 | number | **응답에 없다.** 화면이 `월별 ?? 기본` 으로 낸다 |

### 1.1 "없음"과 "0"을 끝까지 가른다

**이 기능에서 가장 놓치기 쉬운 지점이다.**

| 상태 | 월별 칸 | 적용 금액 | 뜻 |
|---|---|---|---|
| 정한 적 없음 | **빈 칸** | 기본을 따른다 | "평소대로" |
| `0` 으로 정함 | **`0`** | **0** | **"그 달엔 쓰지 않겠다"** |

**0 은 의사 표시다.** 빈 칸과 같게 다루면 그 표시가 사라지고, 적용 금액이 기본으로 떨어져
**사용자가 정한 것과 다른 한도**로 통계가 나온다.

**기본 목표는 반대다** — 거기엔 "없음"이 없다. 정한 적 없으면 `0` 이고 화면도 `0` 을 그대로
보인다. **두 칸의 규칙이 다르다는 것을 화면에 설명하지 않는다**: 표에서 빈 칸과 0 이 다르게
보이면 사용자는 설명 없이 읽고, 설명을 달면 표가 읽기 어려워진다.

### 1.2 적용 금액을 내는 자리가 하나다

`월별 ?? 기본` 을 행 타입이 낸다. **템플릿이 두 값을 직접 비교하지 않는다** — 비교가 화면
여러 곳에 흩어지면 한 곳만 고쳤을 때 6.1 과 6.2 가 다른 값을 보인다.

**기본이 언제나 숫자라 결과가 비는 일이 없다.**

## 2. 월별 통계

| 값 | 타입 | 화면에서 |
|---|---|---|
| 연 · 월 | number 둘 | |
| **출처** | string | `저장본` 또는 `즉석 계산`. **배지로 드러낸다** |
| **저장 시각** | string 또는 없음 | 저장본이 없으면 없다. **즉석 계산을 보는 중에도** 저장본이 있으면 온다 |
| 소득 합계 | number | |
| 지출 합계 | number | 일반·할부·고정을 모두 더한 값 |
| 고정 vs 일반 | 객체 | 고정 금액·일반 금액·고정 비율·일반 비율 넷 |
| 주별 지출 | 배열 | 주차·시작일·종료일·금액 |
| 유형별 요약 | 배열 | **0원 유형이 없다** |
| 수단별 요약 | 배열 | **0원 수단이 있다** |

### 2.1 두 표가 반대 규칙을 쓴다

| 표 | 0원 행 | 답하는 질문 |
|---|---|---|
| 유형별 | **없다** | **"무엇에 썼나"** — 쓰지 않은 유형이 행으로 있을 이유가 없다 |
| 수단별 | **있다** | **"어느 수단으로 나갔나"** — 쓰지 않은 수단도 답의 일부다 |

**화면이 통일하지 않는다.** 걸러 내면 수단별에서 정보가 사라지고, 채워 넣으면 유형별에
**서버에 없는 행**이 생긴다.

### 2.2 이름은 받은 값 그대로다

| 조회 갈래 | 이름의 출처 |
|---|---|
| 저장본 | **저장 당시 스냅샷** |
| 즉석 계산 | 지금 이름 |

**화면이 할 일은 양쪽 다 같다 — 받은 값 그대로.** ID 로 원본을 다시 조회하지 않는다.

지출유형을 삭제한 뒤 저장본을 열면 그 행이 **저장 당시 이름으로 남아 있다** — 다시 조회하면
사라졌을 이름이고, 그것이 스냅샷의 목적이다.

010(스냅샷) · 011(현재 이름) · 012(둘 다) 에서 **세 번 같은 결론**이 나왔다.

### 2.3 사용률은 서버 값이다

`금액 ÷ 목표 × 100` 이지만 **화면이 계산하지 않는다.** 서버가 **상한(`9999.99`)에서 자르는
규칙**을 갖고 있고, 저장본의 사용률은 **저장 당시 목표** 기준이다.

**상한에 걸린 값은 그 사실이 드러나게 보인다** — 숫자만 보이면 사용자는 그것이 실제 비율인
줄 안다.

**비중(유형별 금액 ÷ 지출 합계)은 화면이 낸다** — 같은 응답 안의 두 값으로 내며 서버에 그
값도 규칙도 없다.

### 2.4 전역 목표가 없다

**목표는 지출유형별이다.** 상단 요약에 목표·달성률·판정을 두지 않는다 — 화면이 유형별
목표를 더해 만들면 **목표를 정하지 않은 유형이 0 이라 합이 의도보다 작고**, **판정 경계가
화면에 생겨** 서버의 유형별 판정과 기준이 둘로 갈린다.

## 3. 저장 결과

| 값 | 타입 | 뜻 |
|---|---|---|
| 연 · 월 | number 둘 | |
| 저장 시각 | string | |
| 출처 | string | 언제나 `저장본` |
| 문구 | string | 백엔드가 준 그대로 |

**통계 본문이 오지 않는다.** 그래서 저장 뒤 **배지와 시각만 갱신하고 표는 건드리지 않는다.**

**표가 낡았을 수 있다.** 낡은 저장본을 보던 중에 저장하면 새 스냅샷은 **그 시점 계산값**인데
화면의 표는 옛 값이다 — 그래서 **「저장한 값 보기」 링크**를 함께 둔다. 화면이 자동으로 다시
조회하지는 않는다.

---

## 4. 화면의 상태 — 주소에 들고 다닌다

**세션에 두지 않는다.** 두면 뒤로 가기와 새 탭에서 다른 값이 뜬다.

### 6.1 기본 목표

| 값 | 기본 | 설명 |
|---|---|---|
| 쪽 번호 | 첫 쪽 | 007 의 환산기가 시작점으로 바꾼다 |
| 검색어 | 없음 | 지출유형 이름 부분 일치 |
| 연 · 월 | **이번 달** | 화면에 고르는 칸이 없다 — 목록 API 가 필수로 받아 넘길 뿐이다 |

**연·월을 화면에 두지 않는 이유**는 6.1 이 **기본만 다루는 화면**이기 때문이다. 월별 값은
읽기로만 보이고 고치는 곳은 6.2 다 — 연·월 선택을 두면 사용자가 **여기서도 월별을 고칠 수
있다고 읽는다.**

### 6.2 월별 통계

| 값 | 기본 | 설명 |
|---|---|---|
| 연 · 월 | **이번 달** | 주소에 없으면 **서버 시각**으로 정한다. **2000~2100** 으로 제한 |
| 조회 갈래 | 기본(저장본 우선) | 「최신 계산 보기」일 때만 즉석 계산 |

**브라우저 시각을 믿지 않는다** — 010·011 과 같다. 시차가 있는 사용자가 다른 달을 본다.

**모르는 조회 갈래는 기본으로 떨어뜨린다.** 007 이 모달 값을 화이트리스트로 판정한 것과 같은
판단이며, **화면이 만드는 링크는 두 가지뿐**이다.

---

## 5. 두 값의 독립 — 기본과 월별

```
기본 목표                     월별 목표 (그 달)
   │                              │
   ├─ 6.1 에서 고친다              ├─ 6.2 에서 고친다
   │                              │
   ├─ 바꿔도 ─────✗─────────────→ 저장된 월별 값은 그대로다
   │                              │
   └─ 월별이 없는 달에만 ─────────→ 적용 금액이 된다
```

**둘은 독립이다.** 기본을 바꿔도 **이미 저장된 월별 값은 변하지 않는다**(`SC-1203`) —
011 의 고정지출 수정이 미래 달로 번지던 것과 **다르다.**

| | 011 고정지출 | **012 목표금액** |
|---|---|---|
| 기준값을 바꾸면 | **미래 달로 번진다** | **아무 달도 바뀌지 않는다** |
| 그 달 값을 정했으면 | 보존된다 | 그대로다 |
| 지난 달을 맞추려면 | 반영을 누른다 | **그 달에서 다시 정한다** |

**번지는 것이 없어 되돌릴 수 없는 전이도 없다.** 012 에는 확인 다이얼로그가 하나도 없다 —
목표를 덮어써도 그 달 하나이고, 통계 저장은 다시 저장하면 갱신된다.
