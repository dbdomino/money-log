# Feature Specification: 프론트 목표금액·통계 화면

**Feature Branch**: `012-frontend-target-statistics`

**Created**: 2026-09-07

**Status**: Draft

**Input**: `프로젝트설계/기능명세상세-프론트엔드/phase6-목표-통계/` 의 화면 2건 — 6.1(기본 목표금액) · 6.2(월별 통계)

## 대상 화면

| 화면번호 | 이름 | URL | 표시 |
|---|---|---|---|
| 6.1 | 기본 목표금액 | `/targets/default` | 페이지 |
| 6.2 | 월별 통계 | `/statistics` | 페이지 |

전부 **로그인** 권한이고 모달이 없다. 부르는 API 6건: `ExpendTargetList` · `ExpendTargetGet` · `ExpendTargetDefaultUpsert` · `ExpendTargetMonthlyUpsert` · `StatisticsMonthlyGet` · `StatisticsMonthlySave`

## 왜 화면 둘을 한 스펙에 묶었나

**월별 목표금액을 통계 화면에서 입력한다.** 6.1 은 기본 목표만, 6.2 는 그 달 목표를 그 달 통계와 나란히 놓고 고친다 — 사용자가 "이 달 얼마나 썼나"를 보면서 "그럼 이 달 한도를 얼마로 할까"를 정하기 때문이다. 두 화면이 **같은 목록 API** 를 쓰고 저장만 갈린다.

## 이 기능의 핵심 개념

**목표금액은 두 층이다.** 기본은 "평소 이만큼", 월별은 "이 달만 다르게"다. **둘은 독립**이라 기본을 바꿔도 저장된 월별 값은 변하지 않는다.

**"없음"과 "0원"이 다르다.** 월별 값이 없으면 기본을 따르고, 0원으로 정했으면 **그 달엔 쓰지 않겠다**는 뜻이라 0 이 그대로 적용된다. 화면이 빈 칸과 0 을 같게 다루면 이 의사 표시가 사라진다.

**적용 금액은 화면이 계산한다.** 서버는 기본과 월별 두 값만 준다. 화면이 `월별 ?? 기본` 으로 낸다 — 기본은 없으면 0 이라 결과가 비는 일이 없다.

**통계는 저장본과 즉석 계산 두 갈래다.** 기본 조회는 저장본이 있으면 저장본, 없으면 지금 계산이다. `view=live` 는 저장본을 무시하고 지금 계산하되 **저장하지는 않는다**. 저장은 「통계 저장」 버튼의 명시적 행위다.

**저장본은 불변이다.** 저장한 뒤 그 달 지출을 고쳐도, 지출유형을 삭제해도, 목표금액을 바꿔도 저장본은 그대로다. 최신으로 맞추려면 다시 저장한다.

**연도 범위가 005 와 다르다.** 목표·통계는 **2000~2100** 이고 가계부·고정지출은 1900~9999 다. 이 화면의 연도 선택은 좁은 쪽에 맞춘다.

**한 번도 열지 않은 달은 고정지출 합계가 0 이다.** 통계 조회는 월별 고정지출 내역을 만들지 않는다 — 011 의 화면이나 가계부를 먼저 열어야 채워진다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 지출유형별 기본 목표를 정한다 (Priority: P1) 🎯 MVP

평소 쓸 한도를 지출유형마다 정해 둔다.

**Why this priority**: 목표가 없으면 통계의 "목표 대비"가 전부 0 으로 나와 표가 절반만 의미를 갖는다.

**Independent Test**: 목표를 정하고 다시 열어 반영됐는지 본다. 통계 화면 없이 완결된다.

**Acceptance Scenarios**:

1. **Given** 기본 목표 화면에서, **When** 화면이 뜨면, **Then** **사용 중인 지출유형만** 보이고 각각의 기본 목표가 채워져 있다
2. **Given** 목표를 정한 적 없는 유형은, **When** 보면, **Then** **`0`** 으로 보인다 — 빈 칸이 아니다
3. **Given** 한 유형의 금액을 넣어, **When** 저장하면, **Then** 저장되고 다시 열어도 그 값이다
4. **Given** 이미 값이 있는 유형에, **When** 다시 저장하면, **Then** 덮어써지고 행이 늘지 않는다
5. **Given** 1억을 넘는 금액을, **When** 저장하면, **Then** `3602` 와 함께 **0~1억** 범위가 안내된다
6. **Given** `0` 을, **When** 저장하면, **Then** **성공한다** — 유효한 값이다
7. **Given** 사용 안 함으로 바꾼 유형은, **When** 목록을 보면, **Then** **없다**
8. **Given** 목록이 여러 페이지일 때, **When** 이름으로 검색하면, **Then** 그 유형만 남고 전체 건수도 함께 줄어든다

### User Story 2 - 그 달 통계를 본다 (Priority: P1)

연·월을 골라 소득·지출 합계, 주별·유형별·수단별 지출, 목표 대비를 본다.

**Why this priority**: 이 기능이 사용자에게 주는 것 자체다. 목표 없이도 합계는 볼 수 있어 US1 과 독립이다.

**Independent Test**: 거래가 있는 달을 열어 여섯 값과 세 표가 나오는지 본다.

**Acceptance Scenarios**:

1. **Given** 통계 화면에서 연·월을 고르면, **When** 조회하면, **Then** 소득·지출 합계와 고정 vs 일반 비율이 보인다
2. **Given** 주별 지출을, **When** 보면, **Then** 주차와 기간이 함께 보이고 **지출이 0원인 주도 행이 있다**
3. **Given** 유형별 요약을, **When** 보면, **Then** **그 달 지출이 0원인 유형은 없다**
4. **Given** 수단별 요약을, **When** 보면, **Then** **지출이 0원인 사용 중 수단도 있다** — 유형별과 반대다
5. **Given** 목표가 있는 유형은, **When** 보면, **Then** 사용률과 상태(절약·적정·초과)가 색으로 구분된다
6. **Given** 목표가 0 인 유형은, **When** 보면, **Then** 사용률이 **0** 이고 절약으로 분류된다
7. **Given** 지출이 한 건도 없는 달을, **When** 열면, **Then** 여섯 값이 0 이고 유형별 표가 비어 있다
8. **Given** 월별 고정지출 내역을 한 번도 열지 않은 달을, **When** 열면, **Then** 고정지출 합계가 0 이며 **그 이유와 채우는 방법**이 안내된다

### User Story 3 - 그 달만 목표를 다르게 정한다 (Priority: P2)

통계를 보면서 그 달의 유형별 목표를 따로 정한다.

**Why this priority**: 기본 목표(US1)로도 통계는 돌아간다. 다만 "이번 달은 여행이라 식비를 늘린다" 같은 조정이 여기서 일어난다.

**Independent Test**: 통계 화면에서 월별 목표를 넣고 사용률이 그 값 기준으로 다시 계산되는지 본다.

**Acceptance Scenarios**:

1. **Given** 통계 화면의 유형별 표에서, **When** 월별 목표 칸에 값을 넣어 저장하면, **Then** 그 달 목표가 저장된다
2. **Given** 월별 목표를 저장한 뒤, **When** 기본 목표 화면을 열면, **Then** **기본은 바뀌지 않았다**
3. **Given** 기본을 바꾼 뒤, **When** 이미 저장한 월별 값을 보면, **Then** **그대로다**
4. **Given** 월별 목표를 정한 적 없는 유형은, **When** 보면, **Then** 그 칸이 **비어 있고**(0 이 아니다) 적용 금액은 기본을 따른다
5. **Given** 월별 목표를 `0` 으로 저장하면, **When** 보면, **Then** 그 칸이 **`0`** 이고 적용 금액도 0 이다 — 기본으로 떨어지지 않는다
6. **Given** 다른 달을 열면, **When** 보면, **Then** 그 달의 월별 목표는 따로다

---

### User Story 4 - 통계를 확정해 남긴다 (Priority: P2)

지난 달 통계를 스냅샷으로 저장해 나중에 원본이 바뀌어도 그대로 보게 한다.

**Why this priority**: 과거 월을 보존하는 유일한 방법이다. 조회(US2)가 먼저 서야 한다.

**Independent Test**: 저장한 뒤 원본 지출을 고치고 다시 열어 저장본이 그대로인지, `view=live` 는 달라지는지 본다.

**Acceptance Scenarios**:

1. **Given** 통계 화면에서, **When** 「통계 저장」을 누르면, **Then** 저장되고 **저장 시각과 저장본 배지**가 즉시 화면에 반영된다 — 다시 조회하지 않는다
2. **Given** 저장한 뒤, **When** 그 달을 기본 조회하면, **Then** **저장본**이 보인다
3. **Given** 저장 후 그 달 지출을 고치면, **When** 기본 조회하면, **Then** 저장본은 **그대로다**
4. **Given** 같은 상황에서, **When** 「최신 계산 보기」를 누르면, **Then** 지금 값이 보이고 **저장 시각도 함께** 보인다
5. **Given** 「최신 계산 보기」로 본 뒤, **When** 다시 기본 조회하면, **Then** 저장본이 **변하지 않았다**
6. **Given** 저장본과 최신이 다를 때, **When** 화면을 보면, **Then** **갱신하려면 다시 저장하라**는 안내가 보인다
7. **Given** 다음 달을, **When** 저장하려 하면, **Then** `3604` 로 거절되고 미래 월은 저장할 수 없음이 안내된다
8. **Given** **이번 달**을, **When** 저장하면, **Then** **성공한다**
9. **Given** 지출유형을 삭제한 뒤, **When** 저장본을 보면, **Then** 그 유형 행이 **저장 당시 이름으로 남아 있다**

### Edge Cases

- **연도 선택에 1999 나 2101 이 있으면?** 고를 수 없어야 한다. 서버가 `3603` 으로 거절하는데 사용자는 화면에서 고른 값이 왜 막히는지 알 수 없다.
- **사용률이 아주 클 때?** 서버가 `9999.99` 에서 자른다. 화면은 받은 값을 그대로 보이되 상한에 걸렸음이 드러나게 표시한다.
- **저장본이 있는 달의 목표를 바꾸면?** 저장본의 목표·사용률·상태는 저장 당시 값이라 바뀌지 않는다. 최신은 「최신 계산 보기」로 본다.
- **`view` 에 이상한 값이 URL 로 들어오면?** `3603` 이다. 화면이 만드는 링크는 두 값만 쓴다.
- **기본 목표 화면에서 연·월은 왜 필요한가?** 목록 API 가 연·월을 필수로 받는다. 기본만 보는 화면이라도 **이번 달**을 넘겨 응답 형태를 하나로 유지한다.
- **삭제 표시됐지만 사용 중인 유형은?** 목표 목록에 나온다 — 목록이 보는 것은 사용 여부뿐이다.

## Requirements *(mandatory)*

### Functional Requirements

**기본 목표 (US1)**

- **FR-1101**: 기본 목표 화면은 **사용 중인 지출유형만** 보여야 한다
- **FR-1102**: 기본 목표가 없는 유형은 **`0`** 으로 보여야 한다. 빈 칸으로 두지 않는다
- **FR-1103**: 금액은 **0~100,000,000** 이며 범위 밖은 `3602` 로 거절됨을 입력 전에 안내해야 한다
- **FR-1104**: **`0` 저장은 성공**이며 오류로 다루지 않아야 한다
- **FR-1105**: 목록은 이름 부분 일치 검색과 페이징을 제공해야 하며, **전체 건수도 사용 중 유형만** 센다
- **FR-1106**: 목록 API 가 연·월을 필수로 받으므로 기본만 보는 화면도 **이번 달**을 넘겨야 한다

**통계 조회 (US2)**

- **FR-1107**: 연·월 선택은 **2000~2100** 으로 제한해야 한다. 그 밖의 값을 고를 수 있게 두지 않는다
- **FR-1108**: 소득 합계·지출 합계와 고정 vs 일반 비율 네 값을 보여야 한다
- **FR-1109**: 주별 지출은 주차와 **기간(시작·종료일)**을 함께 보여야 하며 0원인 주도 행으로 남겨야 한다
- **FR-1110**: 유형별 요약은 **0원 유형이 없고**, 수단별 요약은 **0원 행이 있다**. 화면이 둘을 같은 규칙으로 다루지 않아야 한다
- **FR-1111**: 목표 대비 상태(절약·적정·초과)를 **색과 문구**로 구분해야 한다
- **FR-1112**: 사용률이 상한(`9999.99`)에 걸린 경우 그 사실이 드러나게 표시해야 한다
- **FR-1113**: 유형·수단 이름은 **저장 당시 스냅샷**이며 원본이 사라져도 그대로 보여야 한다. ID 로 원본을 다시 조회하지 않는다
- **FR-1114**: 고정지출 합계가 0 인 달은 **월별 내역을 아직 열지 않아서**임을 알리고 채우는 방법을 안내해야 한다

**월별 목표 (US3)**

- **FR-1115**: 통계 화면의 유형별 표에서 **그 달 목표를 바로 입력**할 수 있어야 한다
- **FR-1116**: 월별 목표를 저장해도 **기본 목표는 바뀌지 않아야** 한다
- **FR-1117**: 월별 목표가 없는 유형의 칸은 **비어 있어야** 한다. `0` 으로 채우지 않는다
- **FR-1118**: 월별 목표 `0` 은 그대로 적용되어야 한다. 기본으로 떨어뜨리지 않는다
- **FR-1119**: 적용 금액은 화면이 **월별 ?? 기본** 으로 내야 한다

**통계 저장 (US4)**

- **FR-1120**: 「통계 저장」은 명시적 버튼이어야 한다. 조회가 저장을 겸하지 않는다
- **FR-1121**: 저장 응답의 **저장 시각과 저장본 표시를 즉시 화면에 반영**해야 한다. 저장 후 다시 조회하지 않는다
- **FR-1122**: 기본 조회는 저장본이 있으면 저장본, 없으면 지금 계산이며 **어느 쪽인지 배지로** 드러내야 한다
- **FR-1123**: 「최신 계산 보기」는 저장본을 무시하고 지금 계산하되 **저장본을 바꾸지 않아야** 한다
- **FR-1124**: 「최신 계산 보기」에서 저장본이 있으면 **저장 시각을 함께** 보여 사용자가 둘을 나란히 비교할 수 있어야 한다
- **FR-1125**: 저장본이 최신과 다를 수 있음을 알리고 **다시 저장하는 것이 갱신 방법**임을 안내해야 한다
- **FR-1126**: 미래 월은 저장할 수 없음(`3604`)을 알리되 **이번 달은 저장할 수 있어야** 한다

### 이 기능이 쓰는 에러코드

**새로 정의하는 코드가 없다.**

| 코드 | 뜻 | 화면 |
|---|---|---|

| `3602` | 목표금액이 0~1억 밖 | 6.1 · 6.2 |
| `3603` | 연·월 범위 오류(2000~2100) 또는 조회 구분 값 오류 | 6.1 · 6.2 |
| `3604` | 미래 월 저장 시도 | 6.2 |
| `9001` | 페이징 규칙 위반 | 6.1 |

### Key Entities

- **목표금액 행**: 지출유형 · **현재** 이름 · 기본 목표(항상 숫자) · 월별 목표(없으면 비어 있음). 적용 금액은 화면이 낸다
- **월별 통계**: 소득·지출 합계 · 고정 vs 일반 비율 · 주별·유형별·수단별 요약 · 출처(저장본/즉석) · 저장 시각. 상세의 이름은 **저장 당시 스냅샷**이다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-1201**: 목표를 정한 적 없는 유형이 화면에서 `0` 으로 보이고 빈 칸으로 보이지 않는다
- **SC-1202**: 월별 목표를 정하지 않은 칸과 `0` 으로 정한 칸이 **화면에서 구분된다**
- **SC-1203**: 기본을 바꿔도 저장된 월별 값이 화면에서 변하지 않는다
- **SC-1204**: 연도 선택에서 2000~2100 밖을 고를 방법이 없다
- **SC-1205**: 유형별 표에 0원 유형이 없고 수단별 표에는 0원 수단이 있다
- **SC-1206**: 저장 직후 **재조회 없이** 저장본 배지와 시각이 화면에 반영된다
- **SC-1207**: 「최신 계산 보기」를 여러 번 눌러도 저장본이 바뀌지 않는다
- **SC-1208**: 저장본과 최신이 다른 상황에서 사용자가 **갱신 방법**을 화면에서 안다
- **SC-1209**: 이번 달은 저장되고 다음 달은 거절되며, 사용자가 그 경계를 안다
- **SC-1210**: 고정지출 합계가 0 인 달에서 사용자가 **왜 0 인지**와 채우는 방법을 안다

## Assumptions

- **007 이 이미 서 있다.** 페이징 환산·API 클라이언트·레이아웃을 그대로 쓴다
- **009 가 이미 서 있다.** 지출유형이 있어야 목표를 정할 수 있다
- **010·011 이 있으면 통계가 의미를 갖는다.** 거래와 고정지출이 없으면 합계가 전부 0 이라 화면 검증은 되지만 값이 비어 보인다
- **백엔드 006 의 API 6건이 동작한다.** 백엔드 코드와 스키마는 바뀌지 않는다
- **화면기획 프로토타입을 그대로 옮긴다** — `target-default.html` · `statistics-monthly.html`
- **차트는 표로 대체할 수 있다.** 주별·비율을 그림으로 그리는 것은 선택이며, 값이 표로 읽히면 요구사항을 만족한다
- **모달이 없다.** 두 화면 모두 풀페이지이며 입력은 표 안에서 일어난다
