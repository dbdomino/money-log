# Contract: 기본 목표금액 (6.1)

**Feature**: 012-frontend-target-statistics | **관련 FR**: 1101~1106

| 항목 | 값 |
|---|---|
| 주소 | `/targets/default` |
| 껍데기 | 007 의 **로그인 후** 레이아웃 |
| 사이드바 활성 메뉴 | `targets` |
| 권한 | 로그인 |
| 표시 | **페이지.** 모달이 없다 |
| 부르는 API | `ExpendTargetList` · `ExpendTargetDefaultUpsert` |

**평소 쓸 한도를 지출유형마다 정해 두는 화면이다.** 목표가 없으면 통계(6.2)의 "목표 대비"가
전부 0 으로 나와 표가 절반만 의미를 갖는다.

---

## 1. 목록

### 열

| 열 | 값 |
|---|---|
| 지출유형 | 이름. **조회 시점 현재 이름** |
| **기본 목표** | **입력 칸.** 여기서 고친다 |
| 이번 달 목표 | **읽기 전용.** 정한 적 없으면 **빈 칸** |
| 관리 | 저장 |

**사용 중인 지출유형만 나온다**(`FR-1101`). 사용 안 함으로 바꾼 유형은 목록에서 사라지며,
**전체 건수도 사용 중만** 센다(`FR-1105`).

**삭제 표시됐지만 사용 중인 유형은 나온다** — 목록이 보는 것은 사용 여부뿐이다.

### 프로토타입과 세 곳이 다르다

| 프로토타입 | 이 화면 | 왜 |
|---|---|---|
| 상단에 **전역 「기본 목표 금액」 입력 폼** | **없다** | 백엔드에 **그런 저장 단위가 없다.** 목표는 지출유형별이라 그대로 두면 **저장할 곳이 없는 칸**이 남는다 |
| 유형별 표가 **전부 텍스트** | **기본 목표가 입력 칸** | 기본 목표를 **정하는 화면**인데 입력할 자리가 없다 |
| 페이징이 안내 문구뿐 | **007 의 환산기**로 쪽을 넘긴다 | 「사용 중 유형만 · totalCount 6」은 쪽 이동이 아니다 |

**「이번 달 목표」 열은 읽기로 둔다.** 목록 응답이 그 값을 주므로 보일 수는 있지만 **고치는
곳은 6.2** 다(`FR-1115`) — 여기에 입력 칸을 두면 같은 값을 고치는 자리가 둘이 된다.

### 쪽 넘기기와 검색

**007 의 페이징 환산기**를 쓴다 — 008(관리자 회원)·011(고정지출)에 이어 세 번째다. 시작점이
개수의 배수가 아니면 목록이 통째로 실패하므로 **쪽 번호에서만** 시작점을 만든다.

**이름 부분 일치 검색**을 제공하며, 검색하면 **전체 건수도 함께 줄어든다**(`FR-1105`).

### 연·월을 화면에 두지 않는다

목록 API 가 연·월을 **필수로** 받으므로 화면이 **이번 달을 넘긴다**(`FR-1106`). 다만 **고르는
칸을 두지 않는다.**

**6.1 은 기본만 다루는 화면이기 때문이다.** 연·월 선택을 두면 사용자가 **여기서도 월별을
고칠 수 있다고 읽는다** — 월별 값은 읽기로만 보인다.

---

## 2. "없음"과 "0"이 다르다

| 칸 | 정한 적 없으면 | `0` 으로 정했으면 |
|---|---|---|
| **기본 목표** | **`0`** (서버가 그렇게 준다) | `0` |
| **이번 달 목표** | **빈 칸** | **`0`** |

**기본 목표에는 "없음"이 없다**(`FR-1102` · `SC-1201`). 서버가 미설정을 `0` 으로 주며 화면도
`0` 을 그대로 보인다 — **빈 칸으로 두지 않는다.**

**월별 목표에는 있다.** 없으면 비워 두고 기본을 복사하지 않는다 — 복사하면 **사용자가 그
값을 정한 것처럼 보이고**, 저장을 누르는 순간 "따라가던 값"이 "고정된 값"이 된다.

**`0` 저장은 성공이다**(`FR-1104`). 오류로 다루지 않는다 — 유효한 값이고 "이 유형에는 쓰지
않겠다"는 뜻이다.

---

## 3. 저장

| 항목 | 내용 |
|---|---|
| 부르는 곳 | **행마다 있는 「저장」** |
| 보내는 방법 | `POST`. 화면 모듈이 백엔드의 수정 요청으로 옮긴다 |
| 보내는 값 | 그 행의 **기본 목표 한 칸** |
| 범위 | **0 ~ 100,000,000**. 입력 전에 화면이 적는다(`FR-1103`) |

### 행마다 저장한다

**「전체 저장」을 만들지 않는다.** 백엔드가 유형 하나씩 받으므로 한 번에 보내면 화면이
**N번 부르는 반복**을 갖게 되고, **트랜잭션이 없어 중간에 실패하면 일부만 저장된 상태**가
된다 — 사용자는 어디까지 저장됐는지 알 수 없다.

**바꾸지 않은 행을 덮어쓰지도 않는다.** 전체 폼으로 묶으면 건드리지 않은 값까지 실려 나간다.

### 덮어쓰기지 추가가 아니다

이미 값이 있는 유형에 다시 저장하면 **덮어써지고 행이 늘지 않는다.**

---

## 4. 실패가 붙는 칸

008 의 규약을 따른다 — 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 폼 상단.

| 코드 | 뜻 | 붙는 칸 |
|---|---|---|
| `3602` | 목표금액이 **0~1억 밖** | **그 행의 금액 칸.** 범위를 함께 적는다 |
| `3601` | **사용하지 않는 유형**에 목표를 정하려 함 | 그 행. 목록을 다시 그리며 안내 |
| `3103` | 지출유형이 없거나 타인 것 | 그 행. 목록을 다시 그리며 안내 |
| `9001` | 페이징 규칙 위반 | 목록 안내 |

### `3601` 은 목록이 낡았다는 뜻이다

화면이 목록을 받은 뒤 그 유형이 **사용 안 함으로 바뀐** 경우다. 사용자가 잘못한 것이 아니라
**보고 있던 목록이 낡은 것**이므로, 그 사실과 함께 목록을 다시 그린다.

### `3602` 는 입력 전에 막는다

범위를 **입력 칸 가까이 먼저 적고**(`FR-1103`), 입력 칸에도 최소·최대를 건다. **화면이 막는
것과 서버가 막는 것은 서로를 대신하지 않는다** — 주소로 직접 올 수 있다.

## 5. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| **사용 중인 유형만** 보인다 | FR-1101 |
| 기본 목표가 없는 유형이 **`0`** 으로 보인다(빈 칸이 아니다) | FR-1102 · SC-1201 |
| 월별 목표가 없는 칸이 **비어 있다**(0 이 아니다) | FR-1117 · SC-1202 |
| **`0` 저장이 성공**한다 | FR-1104 |
| 범위(0~1억)가 **입력 전에** 적혀 있다 | FR-1103 |
| `3602` 가 **그 행의 금액 칸**에 붙고 범위가 함께 보인다 | §4 |
| 목록이 **007 의 페이징 환산기**를 쓰고 시작점이 개수의 배수다 | FR-1105 |
| 이름 검색이 실리고 **전체 건수도 함께 줄어든다** | FR-1105 |
| 목록 요청에 **이번 달**이 실린다 | FR-1106 |
| 화면에 **연·월 선택 칸이 없다** | §1 |
| **전역 「기본 목표 금액」 입력이 없다** | research 7 |
| 「이번 달 목표」 열이 **읽기 전용**이다 | §1 |
| 저장이 **행마다** 나가고 한 번에 여러 건을 보내지 않는다 | research 16 |
| 이미 값이 있는 유형에 다시 저장하면 **행이 늘지 않는다** | §3 |
