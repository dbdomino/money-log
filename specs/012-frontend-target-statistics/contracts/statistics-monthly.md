# Contract: 월별 통계 (6.2)

**Feature**: 012-frontend-target-statistics | **관련 FR**: 1107~1126

| 항목 | 값 |
|---|---|
| 주소 | `/statistics` · 연·월은 `?year=&month=` · 최신 계산은 `&view=live` |
| 껍데기 | 007 의 **로그인 후** 레이아웃 |
| 사이드바 활성 메뉴 | `statistics` |
| 권한 | 로그인 |
| 표시 | **페이지.** 모달이 없다 |
| 부르는 API | `StatisticsMonthlyGet` · `StatisticsMonthlySave` · `ExpendTargetList` · `ExpendTargetMonthlyUpsert` |

**그 달을 보면서 그 달 목표를 정하는 화면이다.** 사용자가 "이 달 얼마나 썼나"를 보며 "그럼
이 달 한도를 얼마로 할까"를 정하기 때문에 월별 목표 입력이 여기 있다.

---

## 1. 목표 목록을 함께 부른다

**통계 응답의 유형별 요약에는 `target` 하나만 온다** — 월별이 우선 적용된 뒤의 합쳐진 값이라
**어느 쪽에서 온 값인지 알 수 없다.**

그래서 이 화면은 **통계와 목표 목록 둘을 부른다.** 월별 칸에 무엇을 보일지 정하려면
**"월별로 정한 0"과 "기본에서 따라온 0"을 갈라야** 하기 때문이다.

| 부르는 것 | 무엇에 쓰나 |
|---|---|
| 통계 | 합계·비율·주별·유형별·수단별·출처·저장 시각 |
| 목표 목록 | **유형별 표의 월별 칸과 기본 값** |

**목표 목록은 한 번에 200건을 부른다.** 기본 유형이 10개이고 200을 넘는 지출유형은 유형별
표 자체가 읽을 수 없는 규모다.

**전체 건수가 그보다 크면 표 위에 알린다** — 받지 못한 유형의 월별 칸이 비어 보여 **「정한
적 없음」으로 읽히기 때문**이다. 조용히 자르면 **빈 칸의 뜻이 흔들린다.**

## 2. 연·월

| 항목 | 값 |
|---|---|
| 기본 | **이번 달.** 주소에 없으면 **서버 시각**으로 정한다 |
| 범위 | **2000~2100** (`FR-1107` · `SC-1204`) |
| 입력 | 연과 월을 **각각** 받는다 |

**005 와 범위가 다르다.** 가계부(010)·고정지출(011)은 1900~9999 이고 목표·통계는 2000~2100
이다 — **이 화면은 좁은 쪽에 맞춘다.**

고를 수 있는데 저장에서 거절당하면 **사용자는 화면에서 고른 값이 왜 막히는지 알 수 없다.**

**범위 밖이 주소로 실려 오면 이번 달로 떨어뜨린다.** 조회 갈래와 같은 판단이며(§5),
007 이 모달 값을 화이트리스트로 판정한 것과 같다 — 북마크를 잘못 저장했거나 주소를 오타로
친 사용자를 막을 이유가 없다.

**한 칸짜리 연월 입력을 쓰지 않는다.** 백엔드가 연·월을 정수 두 칸으로 받고, 한 칸으로
받으면 **쪼개는 자리가 또 하나의 규칙**이 된다 — 011 에서 같은 이유로 정수 네 칸을 그대로
두기로 했다.

**브라우저 시각을 믿지 않는다** — 시차가 있는 사용자가 다른 달을 본다.

## 3. 상단 요약 — 넷이다

| 값 | 어디서 |
|---|---|
| 소득 합계 | 백엔드 값 그대로 |
| 지출 합계 | 백엔드 값 그대로. 일반·할부·고정을 모두 더한 값 |
| 고정 금액 · 비율 | 백엔드 값 그대로 |
| 일반 금액 · 비율 | 백엔드 값 그대로 |

### 목표·달성률·판정을 두지 않는다

프로토타입 상단에 그 셋이 있는데 **백엔드가 전역 목표를 주지 않는다.** 목표는 지출유형별이고
판정도 유형별이다.

화면이 유형별 목표를 더해 만들면 문제가 둘이다.

| 문제 | 내용 |
|---|---|
| 숫자가 틀린다 | 목표를 정하지 않은 유형은 0 이라 **합이 의도보다 작고** 달성률이 부풀려진다 |
| 규칙이 두 개가 된다 | **판정 경계가 화면에 생겨** 서버의 유형별 판정과 기준이 갈린다 |

**목표·사용률·상태는 유형별 표에만 둔다.**

### 고정 vs 일반을 수단별 표에 섞지 않는다

프로토타입이 수단별 표 아래에 「고정 합계」·「일반 합계」 행을 섞어 두었다. **상단 요약으로
옮긴다** — 수단이 아닌 행이 수단 표에 있으면 사용자가 **「고정 합계」를 수단 이름으로 읽는다.**

### 고정이 0 일 때 단정하지 않는다

**통계 조회는 월별 고정지출 내역을 만들지 않는다.** 한 번도 열지 않은 달은 고정 합계가 0 이다.

**화면이 아는 것은 합계가 0 이라는 것뿐이다** — 정말 고정지출이 없는 달인지, 내역을 아직
만들지 않은 달인지 **가를 방법이 없다.**

그래서 **두 가능성을 함께 적고** 011 의 화면(또는 가계부)으로 가는 길을 준다
(`FR-1114` · `SC-1210`). 한쪽으로 단정하면 **절반의 사용자에게 틀린 말**이 된다.

## 4. 세 표

### 주별 지출

| 열 | 값 |
|---|---|
| 주차 | 1부터 |
| **기간** | 시작일 ~ 종료일 |
| 금액 | 그 주 지출 합계 |

**표로 그린다. 차트를 두지 않는다** — 스펙이 "차트는 표로 대체할 수 있다"로 정했고
**차트 라이브러리는 의존을 더한다.**

**기간이 표에 맞는다.** 「2026-07-01 ~ 2026-07-05」 같은 값은 차트 축에 담기 어렵고,
**첫 주가 짧은 이유**(1일이 월요일이 아니면 1일부터)가 기간을 보여야 읽힌다.

**0원인 주도 행으로 남긴다**(`FR-1109`). 빼면 주차가 건너뛰어 「1주·3주」처럼 보이고 사용자는
데이터가 빠진 것으로 읽는다.

### 유형별 요약

| 열 | 값 |
|---|---|
| 지출유형 | 이름. **받은 값 그대로** |
| 금액 | 그 달 지출 |
| 비중 | **화면이 낸다** — 금액 ÷ 지출 합계 |
| 기본 목표 | 목표 목록에서 |
| **이번 달 목표** | **입력 칸.** 여기서 고친다 |
| 적용 금액 | **화면이 낸다** — 월별 ?? 기본 |
| 사용률 | **서버 값 그대로** |
| 상태 | 절약 · 적정 · 초과. **색과 문구로** 구분(`FR-1111`) |

**0원 유형이 없다.** 쓰지 않은 유형이 행으로 있을 이유가 없다.

### 수단별 요약

| 열 | 값 |
|---|---|
| 수단 | 이름. 받은 값 그대로 |
| 금액 | 그 달 지출 |

**0원 수단이 있다.** 그 달 지출이 있는 수단 전부와, **사용 중인 지출용 수단**이 함께 온다 —
"이 카드는 이번 달에 안 썼다"도 답의 일부다.

**백엔드가 주지 않는 「구분」 열을 두지 않는다**(일반+할부/일반/고정). 화면이 추측해 채우면
**틀린 분류가 표에 남는다.**

### 두 표를 통일하지 않는다

| 표 | 0원 행 | 답하는 질문 |
|---|---|---|
| 유형별 | **없다** | **"무엇에 썼나"** |
| 수단별 | **있다** | **"어느 수단으로 나갔나"** |

**통일하면 한쪽이 계약과 어긋난다**(`FR-1110` · `SC-1205`). 걸러 내면 수단별에서 정보가
사라지고, 채워 넣으면 유형별에 **서버에 없는 행**이 생긴다.

## 5. 조회는 두 갈래다

| 갈래 | 주소 | 무엇을 보나 |
|---|---|---|
| 기본 | 갈래를 싣지 않는다 | **저장본이 있으면 저장본, 없으면 지금 계산** |
| 최신 계산 보기 | `&view=live` | **저장본을 무시하고 지금 계산.** 저장하지 않는다 |

### 출처를 배지로 드러낸다

지금 보는 것이 **저장본인지 즉석 계산인지** 배지로 보인다(`FR-1122`). 같은 화면이 두 가지
값을 보일 수 있으므로 **어느 쪽인지 모르면 숫자를 믿을 수 없다.**

**저장본이 있으면 저장 시각을 함께 보인다** — **즉석 계산을 보는 중에도** 그렇다
(`FR-1124`). 둘을 나란히 비교하려면 시각이 있어야 한다.

### 저장본이 최신과 다를 수 있다

그 사실을 알리고 **갱신 방법이 다시 저장하는 것**임을 적는다(`FR-1125` · `SC-1208`).
적지 않으면 사용자는 저장본을 고치는 길을 찾다 포기한다.

**「최신 계산 보기」를 여러 번 눌러도 저장본이 바뀌지 않는다**(`FR-1123` · `SC-1207`).

### 모르는 갈래는 기본으로 떨어뜨린다

화면이 **아는 값 둘만** 백엔드로 넘긴다. 주소에 모르는 값이 실려 오면 **기본 조회로**
떨어뜨린다 — 007 이 모달 값을 화이트리스트로 판정한 것과 같은 판단이며, 북마크를 잘못
저장했거나 주소를 오타로 친 사용자를 막을 이유가 없다.

**화면이 만드는 링크는 두 가지뿐이다.**

## 6. 저장 둘 — 성격이 다르다

### 월별 목표 저장

| 항목 | 내용 |
|---|---|
| 부르는 곳 | 유형별 표의 **행마다 있는 「저장」** |
| 보내는 값 | 그 행의 **이번 달 목표 한 칸** |
| 범위 | **0 ~ 100,000,000** |

**행마다 저장한다** — 6.1 과 같은 이유다(백엔드가 유형 하나씩 받고, 한 번에 보내면 부분 저장
상태가 생긴다).

**기본 목표는 바뀌지 않는다**(`FR-1116` · `SC-1203`). 둘은 독립이다.

**`0` 은 그대로 적용된다**(`FR-1118`). 기본으로 떨어뜨리지 않는다 — **"그 달엔 쓰지 않겠다"**는
의사 표시다.

**정한 적 없는 칸은 비워 둔다**(`FR-1117` · `SC-1202`). 기본을 복사하지 않는다.

### 통계 저장

| 항목 | 내용 |
|---|---|
| 부르는 곳 | 화면 상단의 **「통계 저장」** |
| 보내는 값 | 연 · 월 |
| 경계 | **이번 달은 저장된다. 다음 달은 거절된다**(`FR-1126` · `SC-1209`) |

**조회가 저장을 겸하지 않는다**(`FR-1120`). 겸하면 **열어 보기만 해도 스냅샷이 덮이고**,
과거 월을 보존하려 만든 기능이 열어 볼 때마다 무너진다.

#### 저장 뒤 다시 조회하지 않는다

저장 응답에는 **시각·출처·문구만** 오고 **통계 본문이 오지 않는다.** 그래서 **배지와 시각만
갱신한다**(`FR-1121` · `SC-1206`).

**그런데 표가 낡았을 수 있다.** 낡은 저장본을 보던 중에 저장하면 새 스냅샷은 **그 시점
계산값**인데 화면의 표는 옛 값이다 — 배지만 갱신하고 끝내면 **표는 옛 값인데 "방금 저장"이라
적힌** 화면이 된다.

그래서 **「저장한 값 보기」 링크를 함께 둔다.** 화면이 자동으로 다시 조회하지는 않고
**사용자가 고른다.**

## 7. 실패가 붙는 칸

| 코드 | 뜻 | 붙는 칸 |
|---|---|---|
| `3602` | 목표금액이 **0~1억 밖** | **그 행의 금액 칸.** 범위를 함께 적는다 |
| `3601` | **사용하지 않는 유형**에 목표를 정하려 함 | 그 행. 화면을 다시 그리며 안내 |
| `3103` | 지출유형이 없거나 타인 것 | 그 행 |
| `3603` | **연·월 범위 오류** 또는 조회 갈래 값 오류 | 화면 상단 안내. **연 범위(2000~2100)를 함께** 적는다 |
| `3604` | **미래 월 저장 시도** | 저장 버튼 가까이. **이번 달은 된다**는 것을 함께 적는다 |

### `3604` 는 경계를 함께 적는다

"미래 월은 저장할 수 없습니다"만 적으면 사용자는 **이번 달도 안 되는 줄 안다**. **이번 달은
저장된다**는 것을 함께 적어야 경계가 읽힌다(`SC-1209`).

### `3603` 은 두 가지를 겸한다

연·월 범위 오류와 조회 갈래 값 오류가 같은 코드다.

**`3603` 은 이 화면에서 거의 나지 않는다.** 연·월도 조회 갈래도 **화면이 앞에서
떨어뜨리기** 때문이다 — 범위 밖 연·월은 **이번 달로**, 모르는 조회 갈래는 **기본 조회로**
간다(§2 · §5). 그래서 이 화면이 만드는 요청에는 그 값이 실리지 않는다.

**그래도 다루는 이유**는 **백엔드가 범위를 바꿀 수 있고**, 화면이 막는 것과 서버가 막는 것은
서로를 대신하지 않기 때문이다 — 011 에서 세운 것과 같다. **서버 문구를 그대로 보인다.**

## 8. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 연·월 선택이 **2000~2100** 으로 제한된다 | FR-1107 · SC-1204 |
| 연·월이 없으면 **서버 시각의 이번 달**이다 | §2 |
| 상단 요약이 **넷**이고 **목표·달성률·판정이 없다** | research 7 |
| 소득·지출 합계와 고정·일반 비율이 **백엔드 값 그대로**다 | FR-1108 |
| 주별이 **표**이고 주차·**기간**·금액이 보인다 | FR-1109 |
| **0원인 주도 행으로** 남는다 | FR-1109 |
| 유형별에 **0원 유형이 없고** 수단별에 **0원 수단이 있다** | FR-1110 · SC-1205 |
| 수단별 표에 **고정/일반 합계 행이 없다** | research 8 |
| 상태가 **색과 문구**로 구분된다 | FR-1111 |
| 사용률이 **서버 값 그대로**이고 화면이 계산하지 않는다 | research 2 |
| **상한에 걸린 사용률**이 그 사실과 함께 보인다 | FR-1112 |
| 이름을 **다시 조회하지 않는다** — 받은 값 그대로 | FR-1113 |
| **고정 0** 일 때 두 가능성과 채우는 길이 보인다 | FR-1114 · SC-1210 |
| 유형별 표에 **이번 달 목표 입력 칸**이 있다 | FR-1115 |
| 월별 목표를 저장해도 **기본이 바뀌지 않는다** | FR-1116 · SC-1203 |
| 월별 목표가 없는 칸이 **비어 있다**(0 이 아니다) | FR-1117 · SC-1202 |
| 목표를 **전부 받지 못했으면** 표 위에 그 사실이 보인다 | §1 |
