# 목표금액 계약: 두 층 구조와 `null` vs `0`

**Feature**: `006-backend-target-statistics` | **Date**: 2026-09-02 | **Phase**: 1

5.1~5.4의 계약이다. 이 문서의 핵심은 **두 층이 독립이라는 것**과
**두 필드의 미설정 표현이 의도적으로 다르다는 것** 둘이다.

---

## 1. 두 층

```text
기본 목표금액            "식비는 평소 40만원"
  tbl_expend_target_default    (회원 × 지출유형 당 1건)

월별 목표금액            "2026-12 식비만 60만원"
  tbl_expend_target_monthly    (회원 × 연·월 × 지출유형 당 1건)

           적용 금액 = 월별 값 ?? 기본 값
```

**둘은 독립이다**(FR-505).

| 동작 | 결과 |
|---|---|
| 기본을 바꾼다 | 이미 저장된 월별 값은 **변하지 않는다** |
| 월별을 저장한다 | 기본은 **변하지 않는다** |
| 기본을 정한다 | 월별로 **복사되지 않는다** |

복사하지 않는 것이 중요하다. 복사해 두면 "이 달은 기본을 따른다"와 "이 달은 마침 기본과
같은 값으로 정했다"가 구분되지 않는다.

---

## 2. `null` vs `0` — 의도된 비대칭

**이 기능에서 가장 틀리기 쉬운 규칙이다.**

| 필드 | 행이 없으면 | 뜻 |
|---|---|---|
| `monthlyTargetAmount` | **`null`** | "기본값을 쓰겠다" |
| `defaultTargetAmount` | **`0`** | "한도를 정한 적 없다" |

### 왜 월별에만 두 상태가 필요한가

| 월별 값 | 뜻 | 적용 금액 |
|---|---|---|
| `null` (행 없음) | 기본값을 쓰겠다 | 기본 값 |
| `0` (0으로 저장) | **그 달엔 쓰지 않겠다** | `0` |
| `400000` | 그 달은 40만원 | `400000` |

`null`과 `0`이 다른 결과를 낸다. 기본에는 이 구분이 필요 없다 —
"미설정"과 "0으로 설정" 둘 다 한도 없음으로 동작한다.

### 이 비대칭이 적용 금액을 항상 숫자로 만든다

```text
적용 금액 = 월별 ?? 기본

  월별이 null  →  기본으로 떨어진다
  기본은 절대 null 이 아니다 (없으면 0)
  ⟹ 적용 금액은 절대 null 이 되지 않는다
```

**`tbl_statistics_expend_group.target_amount`가 NOT NULL이라 이게 필요하다**(덤프 확인).
통계 저장 시 적용 금액을 그 컬럼에 넣어야 하는데 `null`이면 저장이 실패한다.

**대칭으로 만들면 깨진다.** `defaultTargetAmount`도 `null`로 하면 적용 금액이 `null`이 될 수
있고 통계 저장이 불가능해진다. FR-507에 이 문장을 명시적으로 넣은 이유다.

### 응답에서 두 값을 별도 필드로 내린다

```json
{ "expendGroupId": 1, "expendGroupName": "식비",
  "defaultTargetAmount": 400000,
  "monthlyTargetAmount": null,
  "appliedTargetAmount": 400000 }
```

**세 필드가 다 필요하다.** 적용 금액만 주면 화면이 "이 달은 따로 정한 것인가 기본을
따르는 것인가"를 구분할 수 없다 — 목표금액 화면이 그걸 보여줘야 한다.

`monthlyTargetAmount`가 `null`일 때 **필드를 생략하지 않는다.** Jackson이 `null` 필드를
빼지 않도록 확인한다 — 프론트가 `'monthlyTargetAmount' in obj`로 분기하면 생략과 `null`이
다른 결과를 낸다. `003`의 `iconUrl`(SC-209)과 같은 주의점이다.

---

## 3. 금액 범위 (FR-504)

**0 ~ 100,000,000원.** 벗어나면 `3602`.

`ck_target_default_amount`·`ck_target_monthly_amount` CHECK이 DB에도 같은 범위로 걸려 있다
(덤프 확인). 애플리케이션 검증은 **DB 오류(`9000`)로 새는 것을 막기 위한** 선검사다.

**`0`은 유효한 값이다.** 월별에서 "그 달엔 쓰지 않겠다"를 표현하는 값이다.

---

## 4. upsert (5.3·5.4)

**`PATCH`이고 행이 없으면 만들고 있으면 갱신한다**(FR-512).

```text
1. expendGroupId 로 지출유형 조회 (본인 소유?)   없음·타인 → 3103
2. in_use = false 인가                               → 3601
3. (5.4만) year·month 범위                           → 3603
4. targetAmount 가 0 ~ 100,000,000 밖                → 3602
5. upsert
   └ 유니크 위반은 흡수하거나 재시도한다
```

**1번과 2번의 순서가 중요하다.** 남의 유형 ID로 접근했는데 그게 마침 `in_use=false`라면
`3601`이 아니라 `3103`이어야 한다 — 존재 여부를 노출하지 않는다.

### 동시 요청

DB가 유일성을 강제한다.

| 테이블 | 유니크 제약 |
|---|---|
| `tbl_expend_target_default` | `ux_target_default (id_key, expend_group_idx)` |
| `tbl_expend_target_monthly` | `ux_target_monthly (id_key, year, month, expend_group_idx)` |

두 요청이 같은 순간 "없음"을 보면 하나가 유니크 위반으로 실패한다.
`005`의 lazy 생성처럼 **충돌을 흡수**하거나 재시도한다 — 사용자에게는 둘 다 성공으로 보여야 한다.

**`5.4`의 실패 표에 `3103`이 없는 것은 표기 누락으로 본다.** Path에 `expendGroupId`가 있으므로
같은 검증이 필요하다. 5.3과 같게 처리한다.

## 5. 사용하지 않는 유형 (`3601`)

| API | `in_use=false`인 유형 |
|---|---|
| 5.1 목록 | **제외**하고 돌려준다 |
| 5.2 단건 조회 | **`3601`로 거절** |
| 5.3 · 5.4 변경 | **`3601`로 거절** |

**`3601`은 006이 정의하는 코드다.** `003`의 FR-212가 이 거절 조건을 만들지만
코드 정의는 006에 넘겼다 — 003의 에러코드 표에 그렇게 적혀 있다.

**삭제 표시(`deleted=true`)는 조건이 아니다.** `in_use`만 본다. 삭제 표시된 유형의
목표금액 행은 유지되고(FR-511), 그 유형이 `in_use=true`인 채로 삭제 표시만 됐다면
목록에 나온다.

## 6. 목록(5.1)의 규칙

| 항목 | 값 |
|---|---|
| `year` · `month` | **필수** Query |
| `offset` · `limit` | **필수** Query. 위반은 `9001` |
| `expendGroupName` | 선택. **부분 일치** 검색 |
| 모집단 | **사용 중(`in_use=true`) 유형만** |
| `totalCount` | **사용 중 유형만** 센다 |
| 부가 필드 | `year` · `month` (`list`와 같은 레벨) |

**연·월이 필수인 이유**(Edge Case): 기본 목표만 보는 화면도 조회 연·월을 넘긴다.
모드 분기를 두지 않아 응답 형태가 하나로 유지된다 — 응답에 `monthlyTargetAmount`가
항상 있으려면 어느 달인지 알아야 한다.

**`totalCount`가 사용 중 유형만 세는 것**을 놓치기 쉽다. 목록이 필터돼 있는데
전체 건수만 필터를 안 걸면 페이지 수가 맞지 않는다.

---

## 7. 목표금액은 월 단위 한도 (FR-508)

일·주 단위가 아니다. 통계의 사용률 계산이 **그 달 지출 ÷ 그 달 적용 금액**이므로
단위가 맞아야 한다.

주별 통계(`tbl_statistics_weekly`)에는 목표금액이 없다 — 주 단위 한도라는 개념이 없다.

---

## 8. 이름은 현재 이름이다

목표금액 응답의 `expendGroupName`은 **조회 시점에 원본에서 읽은 현재 이름**이다.

`tbl_expend_target_default`·`tbl_expend_target_monthly`에 이름 컬럼이 **없다**(덤프 확인).

`005`의 고정지출 설정과 같은 성격이다 — **지금 유효한 설정**이지 과거 기록이 아니다.
반면 통계 상세는 스냅샷을 저장한다 → [statistics-snapshot.md](./statistics-snapshot.md).

한 기능 안에서 두 규칙이 공존하지만 대상이 다르므로 헷갈릴 여지는 적다 —
목표금액 API(5.1~5.4)는 현재 이름, 통계 API(5.5·5.6)는 스냅샷이다.
