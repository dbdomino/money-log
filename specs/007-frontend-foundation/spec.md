# Feature Specification: 프론트 공통 기반 — 화면 모듈 재구성

**Feature Branch**: `007-frontend-foundation`

**Created**: 2026-09-07

**Status**: Draft

**Input**: 화면 모듈을 헌장 원칙 I 에 맞게 다시 세운다. 데이터베이스에 직접 붙어 있던 구조를 걷어내고 데이터를 백엔드 API 로만 얻는 모듈로 만든다. 화면 31개가 올라설 **공통 기반**이며 개별 화면은 008~012 가 맡는다.

**이 문서는 무엇이 달라지는지만 적는다.** 그것을 어떤 수단으로 만드는지 — 라이브러리·클래스·파일 이름, 주소, 코드 값, 호출 메서드 — 는 [plan.md](./plan.md)·[contracts/](./contracts/)·[quickstart.md](./quickstart.md) 에 있다.

## 이 기능이 다루는 범위

**화면을 만드는 기능이 아니다.** 화면 31개가 공통으로 밟는 바탕을 세운다.

| 구분 | 007 | 008~012 |
|---|---|---|
| 백엔드 호출 | 백엔드로 나가는 **단일 통로** · 응답 해석 · 호출 규칙 · 실패의 공통 표시 | 화면별 호출 시점·필드 |
| 목록 | **페이지 번호를 백엔드가 요구하는 조회 구간으로 바꾸는 공통 환산** | 화면별 필터·정렬 |
| 아이콘 | **화면 모듈 주소로 이미지 중계** | 받은 주소로 아이콘 표시 |
| 인증 | 세션 보관 · 인증 정보 부착 · 자동 재발급 · 진입 판정 | 로그인·로그아웃 **화면** |
| 레이아웃 | 로그인 전·후 두 껍데기 · 사이드바 · 모달 셸 · 확인 다이얼로그 | 그 안의 본문 |
| 정적 자원 | 디자인 토큰 · 공통 스타일 · 모달 동작 이식 | 화면별 마크업 |
| 주소 | 루트 주소 · 구 주소 연결 | 화면 주소 31개 |
| 화면 | **1.6 권한 없음** 1개 | 나머지 30개 |

**1.6 권한 없음만 여기서 만든다.** 권한 차단이 착지할 화면이 없으면 진입 판정을 완성할 수 없고, 이 화면은 API 를 부르지 않아 다른 화면과 성격이 다르다. 008 은 1.1~1.5·1.7~1.10 아홉 개를 맡는다.

**화면 상세 명세(`프로젝트설계/기능명세상세-프론트엔드/`)의 골격 채우기는 각 스펙이 자기 범위만 한다.** 007 은 `_공통.md` 와 1.6 문서를 채운다.

## 지금 상태 — 원칙 I 을 어기고 있다

화면 모듈은 아직 전부 레거시다.

| 발견 | 내용 |
|---|---|
| 저장 단위 모델 12종 | `Member`·`Expend`·`Card` 등. 백엔드가 쓰는 테이블과 이름도 구조도 다른 **구 테이블**을 가리키며, 접근·변환 코드가 함께 딸려 있다 |
| 의존 | 데이터베이스 접근 수단과 드라이버를 **직접 끌어 쓴다** |
| 설정 | 기동할 때 데이터베이스에 **직접 붙는다** |
| 화면 | 남아 있는 것은 샘플 4개뿐이고 모두 구 테이블을 전제한다 |
| 시험 | 2개 파일이 **저장소 첫 커밋부터 깨져 있다**. 시험 설정이 기동 설정을 덮어쓰면서 데이터베이스 접속 정보가 사라져 기동 자체가 실패한다 |

헌장 원칙 I 은 화면 모듈이 **백엔드 API 호출로만** 데이터를 얻도록 정한다. 프론트가 DB 에 직접 붙으면 API 계약이 우회되어 **권한·검증·로깅이 무력화된다** — 백엔드가 002~006 에서 세운 소유자 판정과 실패 처리가 전부 우회 가능해진다.

## 이 기능의 핵심 개념

**화면 모듈은 DB 를 모른다.** 데이터는 전부 백엔드 API 로 얻는다. DB 를 꺼도 화면 모듈은 기동해야 하고, 백엔드를 끄면 데이터를 얻을 길이 없어야 한다 — 우회로가 남아 있지 않다는 뜻이다.

**토큰은 서버 세션에 산다.** 화면이 서버에서 그려지고 백엔드 호출도 서버가 하므로, 토큰이 브라우저에만 있으면 서버가 백엔드에 인증 정보를 실을 수 없다. 브라우저로 내려가는 것은 **세션을 가리키는 식별자뿐**이고 토큰 원문은 내려가지 않는다.

**봉투는 한 곳에서만 푼다.** 백엔드는 성공과 실패를 **같은 형태의 봉투**에 담아 답하고, 실패해도 통신 자체는 성공으로 표시된다(헌장 원칙 III). 화면마다 이 봉투를 각자 풀면 어느 화면 하나가 응답 코드 확인을 빠뜨렸을 때 **실패가 성공으로 읽히고 빈 화면이 정상처럼 뜬다.**

**봉투에 예외가 둘 있다.** 지출유형 아이콘 조회(003 의 2.10)와 엑셀 양식 다운로드(004 의 3.11)는 본문이 **파일 그 자체**다. 무조건 봉투로 읽으면 이 둘이 깨진다.

**화면은 페이지와 딥링크 모달 둘뿐이다.** 목록·허브는 풀페이지, 등록·수정·상세는 **부모 주소에 모달 식별자를 덧붙인 딥링크**로 여는 모달이다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 화면이 DB 대신 백엔드 API 를 본다 (Priority: P1) 🎯 MVP

화면 모듈에서 DB 로 가는 길을 없애고, 데이터를 백엔드 API 로만 가져온다. 백엔드가 준 응답 봉투를 한 곳에서 풀어 값 또는 실패 사유를 화면에 넘긴다.

**Why this priority**: 헌장 원칙 I 위반을 걷어내는 것이 이 기능의 존재 이유다. 그리고 이 통로가 없으면 008~012 의 어떤 화면도 데이터를 얻을 수 없다.

**Independent Test**: DB 를 내린 채 화면 모듈을 기동해 정상적으로 뜨는지 보고, 백엔드를 올린 상태에서 호출 하나를 보내 값이 오는지·실패 사유가 그대로 전달되는지 확인한다. 화면 없이 완결된다.

**Acceptance Scenarios**:

1. **Given** DB 가 내려가 있을 때, **When** 화면 모듈을 기동하면, **Then** 정상 기동한다
2. **Given** 백엔드가 성공 봉투를 돌려줄 때, **When** 화면 모듈이 API 를 부르면, **Then** 봉투 안의 값이 그대로 전달된다
3. **Given** 백엔드가 실패 봉투(정수 4자리 응답 코드)를 돌려줄 때, **When** 화면 모듈이 API 를 부르면, **Then** 그 **응답 코드와 안내 문구**가 화면으로 전달되고 **성공으로 읽히지 않는다**
4. **Given** 백엔드가 꺼져 있을 때, **When** 화면이 데이터를 필요로 하면, **Then** 사용자가 서버에 닿지 못했음을 읽을 수 있고 **빈 값이 정상처럼 뜨지 않는다**
5. **Given** 아이콘·엑셀 양식처럼 본문이 파일인 응답일 때, **When** 화면 모듈이 그것을 받으면, **Then** 봉투 해석을 거치지 않고 **파일 그대로** 전달된다

### User Story 2 - 로그인 상태가 유지되고 권한이 지켜진다 (Priority: P1)

로그인하면 그 상태가 서버 세션에 남아 이어지는 화면에서 다시 로그인하지 않아도 된다. 로그인하지 않았거나 권한이 없으면 해당 화면에 들어갈 수 없다.

**Why this priority**: 화면 31개 중 25개가 로그인을 요구하고 3개가 관리자를 요구한다. 이 판정이 없으면 어떤 화면도 안전하게 열 수 없다.

**Independent Test**: 세션에 토큰을 심은 상태와 비운 상태로 보호 주소에 들어가 결과가 갈리는지 확인한다. 로그인 **화면**(008) 없이 완결된다 — 005·006 이 아직 없는 API 대신 데이터를 직접 심어 시험한 것과 같은 방식이다.

**Acceptance Scenarios**:

1. **Given** 세션이 비어 있을 때, **When** 로그인이 필요한 화면 주소에 들어가면, **Then** 로그인 화면으로 보내진다
2. **Given** 세션에 유효한 토큰이 있을 때, **When** 같은 주소에 들어가면, **Then** 그 화면이 열린다
3. **Given** 일반 권한으로 로그인했을 때, **When** 관리자 전용 주소에 들어가면, **Then** 권한 없음 화면으로 보내진다
4. **Given** 로그인하지 않았을 때, **When** 관리자 전용 주소에 들어가면, **Then** **권한 없음이 아니라 로그인 화면**으로 보내진다
5. **Given** 세션의 접근 토큰이 만료됐을 때, **When** 화면이 API 를 부르면, **Then** 재발급이 자동으로 일어나 사용자는 **다시 로그인하지 않고** 그 화면을 본다
6. **Given** 다른 곳에서 로그인해 이 세션이 무효가 됐을 때, **When** 화면이 API 를 부르면, **Then** 세션이 지워지고 로그인 화면으로 보내진다
7. **Given** 로그인한 상태에서, **When** 로그아웃하면, **Then** 세션이 지워지고 보호 주소가 다시 막힌다
8. **Given** 어떤 화면이든, **When** 브라우저가 받은 응답을 살펴보면, **Then** **인증 토큰 원문**이 들어 있지 않다

### User Story 3 - 모든 화면이 같은 껍데기를 쓴다 (Priority: P2)

로그인 전 화면과 로그인 후 화면이 각각 정해진 레이아웃을 쓰고, 사이드바·모달·확인 다이얼로그가 화면마다 다시 만들어지지 않는다.

**Why this priority**: 008~012 가 각자 껍데기를 만들면 화면 31개의 생김새와 모달 동작이 갈린다. 다만 US1·US2 없이는 그 껍데기 안에 넣을 것이 없다.

**Independent Test**: 껍데기만 쓰는 화면(1.6 권한 없음)과 모달 셸이 붙은 시험용 화면을 열어 레이아웃·사이드바 활성 표시·모달 열고 닫기가 동작하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인 후 화면일 때, **When** 화면을 열면, **Then** 사이드바가 함께 뜨고 **그 화면에 해당하는 메뉴가 활성으로** 표시된다
2. **Given** 일반 권한으로 로그인했을 때, **When** 사이드바를 보면, **Then** 회원 관리 메뉴가 **보이지 않는다**
3. **Given** 부모 페이지가 열려 있을 때, **When** 모달 딥링크가 붙은 주소로 들어가면, **Then** 해당 모달이 열린 채로 뜬다
4. **Given** 모달이 열려 있을 때, **When** 취소·닫기·Esc·딤 클릭 중 무엇이든 하면, **Then** 모달이 닫힌다
5. **Given** 어떤 화면이든, **When** 정의되지 않은 모달 식별자를 딥링크에 넣으면, **Then** 모달이 열리지 않고 **부모 페이지만** 정상으로 뜬다

---

### User Story 4 - 옛 주소로 들어와도 화면에 닿는다 (Priority: P3)

루트 주소와 이전에 쓰던 화면 주소로 들어와도 지금의 화면으로 보내진다.

**Why this priority**: 사용자가 북마크·링크로 들어오는 경로를 살린다. 다만 새 주소만 써도 앱은 완결되므로 마지막이다.

**Independent Test**: 루트와 구 주소 목록에 차례로 들어가 각각 정해진 곳으로 보내지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 상태에서, **When** 루트 주소로 들어가면, **Then** 월별 가계부 화면으로 보내진다
2. **Given** 로그인하지 않았을 때, **When** 루트 주소로 들어가면, **Then** 로그인 화면으로 보내진다
3. **Given** 구 등록 주소(예: 수단 등록의 옛 경로)로 들어갔을 때, **When** 화면이 응답하면, **Then** 부모 목록 화면 + 해당 **모달 딥링크**로 보내진다

### Edge Cases

- **재발급 직후에도 인증 만료가 또 오면?** 다시 재발급하지 않는다. 한 번만 시도하고, 그래도 실패하면 세션을 지우고 로그인으로 보낸다 — 재시도를 열어 두면 백엔드가 계속 만료로 답할 때 무한 왕복이 된다.
- **세션은 살아 있는데 백엔드 토큰이 죽었을 때?** 세션 존재만으로 통과시키지 않는다. 백엔드가 **인증 만료·세션 무효**로 답하는 순간 세션을 지운다.
- **백엔드 토큰은 살아 있는데 세션이 만료됐을 때?** 토큰을 잃은 것이므로 미로그인으로 본다. 백엔드에는 세션이 남아 있지만 화면 모듈이 그것을 꺼낼 방법이 없다.
- **한 화면이 API 를 여러 번 부르는데 그중 하나가 인증 만료면?** 그 호출에서 재발급이 일어나고 새 토큰이 세션에 반영되어 뒤이은 호출이 새 토큰을 쓴다.
- **백엔드가 봉투가 아닌 것을 돌려줄 때?** 아이콘·엑셀 두 호출은 의도된 예외라 파일로 다루고, 그 밖의 응답이 봉투가 아니면 실패로 본다.
- **관리자 전용 주소에 미로그인으로 들어오면?** 로그인 판정이 먼저다 — 권한 없음 화면은 "로그인은 했는데 권한이 모자란" 경우에만 보인다. 순서가 뒤집히면 미로그인 사용자에게 그 주소가 실재한다는 사실이 드러난다.
- **DB 가 꺼져 있으면?** 화면 모듈은 정상 기동한다. DB 를 모르기 때문이다.

## Requirements *(mandatory)*

### Functional Requirements

**화면 모듈의 경계 (US1)**

- **FR-601**: 화면 모듈은 **데이터베이스와 그 접근 수단을 일절 의존하지 않아야** 한다. 저장 단위 모델·접근 코드·변환 코드를 자체로 두지 않는다
- **FR-602**: 화면 모듈의 모든 데이터는 백엔드 API 호출로만 얻어야 한다. DB 로 가는 우회로를 남기지 않는다
- **FR-603**: 백엔드 응답 봉투는 **한 곳에서만** 해석해야 한다. 화면과 화면을 그리는 코드가 각자 풀지 않는다
- **FR-604**: **응답 코드가 성공이 아니면** 실패로 보고 그 코드와 안내 문구를 화면으로 전달해야 한다. 실패를 성공으로 읽지 않는다
- **FR-605**: 본문이 파일인 응답 2건(지출유형 아이콘 조회·엑셀 양식 다운로드)은 봉투 해석을 거치지 않고 **파일 그대로** 전달해야 한다
- **FR-606**: 백엔드에 닿지 못하면(연결 거부·응답 지연) 사용자에게 그 사실을 알려야 하며, 화면이 빈 값으로 조용히 뜨지 않아야 한다
- **FR-607**: 화면 모듈은 새 에러코드를 정의하지 않는다. 백엔드가 준 코드를 그대로 전달한다
- **FR-608**: 깨져 있던 화면 모듈의 레거시 시험을 정리해 모듈 시험이 통과해야 한다
- **FR-609**: 백엔드가 기능별로 정한 **호출 규칙을 그대로 지켜야** 한다 — 조회·생성·수정·삭제마다 값을 싣는 자리가 정해져 있고, 수정은 보내지 않은 항목을 그대로 유지한다. 규칙을 벗어난 호출 수단은 검증으로 막는 것이 아니라 **아예 제공하지 않는다**
- **FR-610**: 목록 화면이 쓸 **페이징 환산을 공통으로** 제공해야 한다. 백엔드는 페이지 번호가 아니라 조회 시작점과 개수를 받고 시작점은 항상 개수의 배수여야 하는데, 어긋나면 목록이 통째로 실패한다. 어긋난 값이 만들어질 경로를 두지 않고, 한 쪽에 담는 개수가 바뀌면 첫 페이지로 되돌린다. 화면마다 이 계산을 따로 두지 않는다
- **FR-611**: 지출유형 아이콘을 **화면 모듈 주소로** 내려줘야 한다. 화면은 백엔드 주소가 아니라 화면 모듈 주소로 아이콘을 걸고, 화면 모듈이 백엔드에서 받아 그대로 내보낸다 — 브라우저가 백엔드를 직접 부르지 않는다는 결정(§Assumptions)의 결과다
- **FR-612**: 실패를 화면에 알리는 방식은 **공통 처리에 맡겨야** 한다. 화면마다 실패를 따로 붙잡아 제각각 안내하지 않는다 — 화면 31개가 같은 실패를 다르게 보여주면 사용자가 무엇이 잘못됐는지 배울 수 없다

**세션 인증 (US2)**

- **FR-613**: 로그인 성공 시 **접근 토큰·재발급 토큰**과 판정에 쓸 회원 정보(아이디·권한)를 **서버 세션에** 담아야 한다
- **FR-614**: 백엔드 호출마다 세션의 접근 토큰을 **인증 정보로 실어야** 한다. 보호 화면에 들어올 때 그 토큰이 아직 유효한지 백엔드에 확인한다
- **FR-615**: **인증이 만료됐다는 응답**을 받으면 세션의 재발급 토큰으로 재발급을 **한 번** 시도하고, 성공하면 새 토큰으로 세션을 덮어쓴 뒤 원래 요청을 다시 불러야 한다
- **FR-616**: 재발급이 실패하거나 **세션이 무효라는 응답**을 받으면 세션을 무효화하고 로그인 화면으로 보내야 한다
- **FR-617**: 재발급 재시도는 **한 번뿐**이어야 한다. 재발급 직후 요청이 또 인증 만료로 답해도 다시 재발급하지 않는다
- **FR-618**: 비로그인 허용 주소(화면 1.1~1.6)를 제외한 모든 화면 주소는 세션에 토큰이 없으면 로그인 화면으로 보내야 한다
- **FR-619**: 관리자 전용 주소(화면 1.8~1.10)는 로그인했으나 권한이 관리자가 아니면 권한 없음 화면으로 보내야 한다
- **FR-620**: 미로그인 상태로 관리자 전용 주소에 접근하면 권한 없음이 아니라 **로그인 화면**으로 보내야 한다. 로그인 판정이 권한 판정보다 먼저다
- **FR-621**: 로그아웃은 백엔드에서 **토큰을 비활성화한 뒤 세션을 무효화**해야 한다
- **FR-622**: **인증 토큰 원문**을 로그·응답 본문·화면에 남기지 않아야 한다
- **FR-623**: 세션이 만료되어 토큰을 잃으면 미로그인으로 보고 로그인 화면으로 보내야 한다

**공통 껍데기 (US3)**

- **FR-624**: 로그인 전용 레이아웃과 로그인 후 레이아웃 두 가지를 두고, 모든 화면이 둘 중 하나를 써야 한다
- **FR-625**: 로그인 후 레이아웃은 사이드바를 포함하고 현재 화면에 해당하는 메뉴를 **활성으로** 표시해야 한다
- **FR-626**: 일반 권한 회원에게 회원 관리 메뉴를 **보이지 않아야** 한다
- **FR-627**: 등록·수정·상세는 부모 페이지 위에 뜨는 모달이어야 하며 **부모 주소 + 모달 식별자** 딥링크로 열려야 한다
- **FR-628**: 모달은 취소·닫기·Esc·딤 클릭 중 무엇으로도 닫혀야 한다
- **FR-629**: 삭제·회원 정지·할부 중도상환의 확인은 **공통 확인 다이얼로그** 하나를 써야 한다
- **FR-630**: 정의되지 않은 **모달 식별자**는 모달을 열지 않고 부모 페이지만 보여야 한다. 오류 화면으로 보내지 않는다
- **FR-631**: 화면기획의 디자인 토큰·공통 스타일·모달 동작을 화면 모듈의 정적 자원으로 이식해 전 화면이 같은 것을 써야 한다
- **FR-632**: 권한 없음 화면(1.6)을 만들어 FR-619 의 착지점으로 삼아야 한다

**주소 정리 (US4)**

- **FR-633**: 루트 주소는 로그인했으면 월별 가계부로, 아니면 로그인 화면으로 보내야 한다
- **FR-634**: 구 화면 주소는 부모 페이지 + 해당 **모달 딥링크**로 보내야 한다

### 이 기능이 반응하는 백엔드 응답

**새로 정의하는 코드가 없다.** 화면 모듈은 백엔드가 준 코드를 전달만 한다. 실제 코드 값은 002~006 이 확정했고 [contracts/api-client.md](./contracts/api-client.md) 가 화면 모듈의 반응과 함께 적는다.

| 백엔드가 답한 것 | 화면 모듈의 반응 |
|---|---|
| 성공 | 봉투 안의 값을 화면에 넘긴다 |
| 인증 실패·접근 토큰 만료 | 재발급을 1회 시도하고, 실패하면 세션을 무효화한 뒤 로그인 화면으로 보낸다 |
| 다른 곳 로그인으로 세션 무효 | 재발급하지 않고 세션을 무효화한 뒤 로그인 화면으로 보낸다 |
| 그 밖의 업무·검증 실패 | 받은 코드와 안내 문구를 화면에 표시한다 |
| 응답이 오지 않음(연결 거부·응답 지연) | 코드 없이 서버에 닿지 못했음을 표시한다. 목록·상세를 빈 값으로 그리지 않는다 |

**실패해도 통신 자체는 성공으로 표시된다**(헌장 원칙 III). 통신 성패로 업무 성패를 가르면 전부 성공으로 읽힌다.

### Key Entities

DB 저장 단위가 없다. 화면 모듈이 들고 있는 상태는 세션 하나뿐이다.

- **로그인 세션**: 백엔드가 발급한 **접근 토큰·재발급 토큰**과, 화면 표시·권한 판정에 쓸 회원 아이디·권한. 브라우저에는 세션 식별자만 나가고 토큰은 서버에만 있다. 로그아웃·재로그인·세션 만료로 사라진다

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-601**: DB 를 내린 상태에서 화면 모듈이 정상 기동한다 — 화면 모듈이 DB 를 모른다는 증거다
- **SC-602**: 화면 모듈에서 데이터베이스로 가는 경로가 **하나도 남아 있지 않다** — 백엔드를 내리면 어떤 화면도 데이터를 얻지 못한다
- **SC-603**: 전 모듈 시험이 한 번에 통과한다 — 저장소 첫 커밋부터 깨져 있던 레거시 시험이 정리되어, 모듈을 나눠 돌리지 않아도 된다
- **SC-604**: 로그인이 필요한 화면 주소 **전부**를 미로그인으로 열면 예외 없이 로그인 화면으로 보내진다 — 007 시점에는 보호 화면이 아직 없으므로 **공개 허용 목록 밖의 주소**로 판정하고, 전수 확인은 화면이 다 선 012 완료 시점에 한다
- **SC-605**: 관리자 전용 주소 **전부**를 일반 권한으로 열면 예외 없이 권한 없음 화면으로 보내진다 — SC-604 와 같이 007 시점은 **관리자 주소 규칙**으로 판정하고 전수 확인은 012 시점이다
- **SC-606**: 접근 토큰이 만료된 상황에서 사용자가 **다시 로그인하지 않고** 하던 일을 이어서 한다
- **SC-607**: 브라우저가 받은 어떤 응답에도 **인증 토큰 원문**이 들어 있지 않다
- **SC-608**: 백엔드가 꺼져 있을 때 사용자가 **그 사실을 읽을 수 있고**, 데이터가 없는 화면을 정상으로 오해하지 않는다
- **SC-609**: 백엔드 실패 응답의 **코드가 화면까지 바뀌지 않고** 도달한다
- **SC-610**: 모달 딥링크로 들어온 주소가 모달이 열린 화면을 보여주고, 정의되지 않은 값이면 부모 페이지가 정상으로 뜬다

## Assumptions

- **백엔드 002~006 은 이미 서 있다.** API 56건이 동작하며 007 은 그것을 소비만 한다. 007 이 직접 부르는 것은 세션 계층의 **토큰 검증·토큰 재발급·토큰 비활성화 3건**이고(FR-614·615·621), 나머지는 008~012 가 부른다. 로그아웃은 008 이 화면(버튼)을 만들고 백엔드 호출은 007 의 세션 계층이 한다 — 토큰 비활성화와 세션 무효화의 순서를 한 곳에서 지켜야 하기 때문이다. 백엔드 코드와 데이터베이스 구조는 바뀌지 않는다
- **화면기획 산출물을 그대로 쓴다.** 디자인 토큰·공통 스타일·모달 동작은 이미 완성돼 있어 새로 설계하지 않고 경로만 맞춰 이식한다
- **브라우저가 백엔드를 직접 부르지 않는다.** 서버 세션 결정의 결과이며, 그래서 백엔드에 브라우저의 직접 호출을 받기 위한 설정을 더하지 않는다
- **브라우저에서 도는 스크립트는 토큰을 모른다.** 모달을 열고 닫는 것 같은 화면 조작만 하고 API 를 부르지 않는다
- **레거시 화면 4개는 버린다.** 남아 있는 샘플은 구 테이블을 전제한 것이라 살릴 것이 없다
- **한 사용자가 한 브라우저에서 쓴다.** 회원당 활성 세션 1건이라는 백엔드 규칙과 맞물려, 다른 곳에서 로그인하면 이쪽 세션은 **세션 무효 응답**으로 정리된다
