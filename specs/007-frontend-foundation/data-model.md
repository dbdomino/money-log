# Data Model: 프론트 공통 기반 — 화면 모듈 재구성

**Feature**: 007-frontend-foundation | **Date**: 2026-09-08 | **Plan**: [plan.md](./plan.md)

## DB 저장 단위가 0개다

이 문서에 테이블이 없는 것이 **정상이고, 그것이 이 기능의 결과물**이다.

`money-app` 은 지금 Entity 12개와 Repository 5개로 구 테이블(`tbl_member`·`tbl_expend`·
`tbl_payment_Method` 등)을 직접 읽고 쓴다. 007 은 그 길을 없앤다. 작업 후 화면 모듈이
들고 있는 상태는 **`HttpSession` 하나**뿐이고, 그 밖의 모든 데이터는 요청이 끝나면 사라진다.

`sql/schema-moneylogdb.sql` 은 **읽지도 바꾸지도 않는다**(원칙 VI). 화면 모듈이 DB 를 떠나는
작업이라 스키마 영향도가 구조적으로 0 이다.

## 없애는 저장 단위

| 지금 있는 것 | 개수 | 무엇을 가리켰나 |
|---|---|---|
| Entity | 12 | `Member`·`Card`·`Expend`·`ExpendFix`·`ExpendGroup`·`PaymentMethod`·`Ammount`·`ExpendStatistics`·`ExpendStatisticsDetail`·`LoginHistory`·`SystemStat` + `superclass/CuDate` |
| Repository | 5 | JPA·직접 구현이 섞여 있다(`MemberRepository` 가 두 개 — `repository/` 와 `repository/itf/`) |
| MyBatis Mapper | 9 | Entity 와 같은 이름의 구 테이블 매핑 |
| DTO | 12 | 위 Entity 를 그대로 옮긴 것 |

**백엔드가 쓰는 `tbl_user_*` 와 이름도 구조도 다르다.** 001 이 `tbl_user_<자원명>` 규칙을 세울
때 레거시 이름과 겹치지 않게 한 이유가 이것이다 — 두 스키마가 한 DB 에 공존하고 있었다.
007 이 프론트 쪽을 걷어내면 구 테이블을 가리키는 코드가 저장소에서 사라진다.

**구 테이블 자체는 이 기능이 지우지 않는다.** DB 에 남아 있어도 화면 모듈이 참조하지 않으므로
원칙 I 은 만족된다. 실제 DROP 여부는 운영 판단이며 007 의 범위가 아니다.

## 유일한 저장 단위 — 로그인 세션

**저장 위치**: `money-app` 의 `HttpSession`(서버 메모리). 브라우저에는 `JSESSIONID` 만 나간다.

**접근 경로**: `LoginSession` **한 클래스만** 이 세션 속성을 읽고 쓴다. 컨트롤러·인터셉터·
클라이언트가 `session.getAttribute("accessToken")` 을 직접 부르지 않는다 — 속성 이름이 여러 곳에
흩어지면 오타 하나가 "로그인이 안 풀리는" 증상으로 나타난다.

### 속성

| 속성 | 타입 | 넣는 시점 | 설명 |
|---|---|---|---|
| `accessToken` | string | 로그인 성공 · 재발급 성공 | 백엔드 호출에 `Authorization: Bearer` 로 붙일 JWT. **브라우저로 내려가지 않는다.** 로그·HTML·모델 어디에도 원문을 싣지 않는다 |
| `refreshToken` | string | 로그인 성공 · 재발급 성공 | Access 가 `1001` 일 때 재발급에 쓸 JWT. 재발급이 **새 값을 함께 주므로**(Rotation) Access 와 항상 같이 갱신한다 |
| `memberId` | string | 로그인 성공 | 로그인 아이디. 화면 상단 표시와 로그 식별에 쓴다. 백엔드 `tbl_user.id_key`(대리키)가 아니라 **사용자가 입력한 아이디**다 |
| `role` | int | 로그인 성공 | 권한. `1` 관리자 · `3` 일반. 관리자 전용 URL 판정(FR-619)과 사이드바 메뉴 노출(FR-626)이 이 값 하나를 본다 |

`memberId`·`role` 을 **JWT 에서 꺼내 쓰지 않는다.** 프론트가 JWT 를 파싱하면 서명 검증
책임이 따라온다. 두 값은 로그인 응답(`MemberLogin`)과 검증 응답(`MemberTokenValidate`)이
평문 필드로 주므로 그것을 담는다.

### 담지 않는 것

| 담지 않는 것 | 왜 |
|---|---|
| 닉네임·이메일·전화 등 프로필 | 화면이 필요할 때 `MemberGetMe`(1.7)로 조회한다. 세션에 두면 다른 곳에서 수정한 값과 어긋난다 |
| 토큰 만료 시각(`expiresIn`) | 프론트가 만료를 **미리 판정하지 않는다.** 판정은 백엔드가 하고 프론트는 `1001` 을 받아 대응한다(FR-615). 시계 차이로 프론트만 만료라고 믿는 상태를 만들지 않는다 |
| 목록 필터·페이지 | 화면 상태는 URL 쿼리에 둔다. 세션에 두면 뒤로 가기·새 탭에서 다른 화면이 뜬다 |
| 마지막으로 본 화면 | 로그인 후 착지는 FR-633 이 "월별 가계부"로 고정했다 |

### 수명

| 사건 | 세션 | 백엔드 토큰 |
|---|---|---|
| 로그인 성공 | 속성 4개를 담는다 | 발급됨 (기존 세션은 백엔드가 폐기 — 회원당 1건) |
| 재발급 성공 (`1001` 후) | `accessToken`·`refreshToken` **둘 다** 덮어쓴다 | 새 쌍 발급, 옛 Refresh 폐기 |
| 재발급 실패 (`1005` 등) | `invalidate()` | — |
| `1006` 수신 (다른 곳 로그인) | `invalidate()` | 이미 폐기됨 |
| 로그아웃 | `MemberTokenRevoke` **먼저**, 그다음 `invalidate()` | 비활성화 |
| 세션 타임아웃 (30분) | 컨테이너가 파기 | **살아 있다.** 화면이 꺼낼 방법이 없을 뿐 |

마지막 행이 spec Edge Cases 의 "백엔드 토큰은 살아 있는데 세션이 만료됐을 때"다. 그 토큰은
회수하지 못하고 만료(Access 1일)를 기다린다 — 프론트가 토큰을 잃었으므로 `Revoke` 를 부를
수단도 없다. 다음 로그인이 백엔드에서 그 세션을 폐기한다(회원당 활성 세션 1건).

**로그아웃의 순서가 중요하다.** 세션을 먼저 비우면 `Revoke` 에 쓸 Access 토큰이 사라져
백엔드 JWT 가 살아남는다(FR-621).

## 요청 하나 동안만 사는 것

세션이 아니라 **요청 스코프**에 잠깐 존재하고 사라지는 값들이다. 저장 단위가 아니지만,
"어디에 사나"를 적어 두지 않으면 세션에 넣으려는 시도가 나온다.

| 값 | 어디에 | 설명 |
|---|---|---|
| 백엔드 응답의 `data` | 컨트롤러 지역 변수 → 뷰 모델 | 화면을 그리고 버린다. 캐시하지 않는다 |
| 재발급 시도 여부 | `BackendApiClient.call()` 지역 플래그 | **호출 하나당 한 번**을 잠근다(FR-617). 요청 전체가 아니라 호출 단위인 이유는 research 6 |
| 실패 코드·메시지 | `BackendApiException` → `@ControllerAdvice` → 모델 | 백엔드가 준 값 그대로. 화면 모듈이 코드를 만들지 않는다(FR-607) |
| 페이징 환산 결과 | `Paging` 값 객체 | `page`·`limit` 에서 `offset` 을 만든다. 만들어진 뒤 불변 |
| 열 모달 id | 모델 `openModal` | `?m=` 이 화이트리스트에 있을 때만 채워진다. 없으면 **키 자체를 넣지 않는다**(FR-630) |

## 아이콘은 저장하지 않는다

FR-611 의 프록시는 백엔드에서 받은 바이트를 **그대로 흘려보낸다.** 화면 모듈에 파일로
쓰거나 메모리에 캐시하지 않는다.

캐시를 두면 두 가지가 따라온다. ① 아이콘이 바뀌었을 때 무효화 시점을 007 이 정해야 하는데,
아이콘을 바꾸는 화면은 009 다. ② 회원별로 갈라 담아야 한다 — 파일명이
`{id_key}_{expendGroupId}.{확장자}` 라 다른 회원 것과 섞이지는 않지만, 캐시가 있으면
**권한 검사를 건너뛴 경로**가 생긴다. 지금 구조에서는 매 요청이 백엔드를 거치므로
백엔드의 소유자 판정이 그대로 걸린다.

재요청을 줄이는 것은 브라우저 캐시(`Cache-Control`)에 맡긴다 — 백엔드 `_공통.md` 가 이미
그렇게 정했고, 헤더 값은 아이콘을 실제로 쓰는 009 가 정한다(research §미해결).
