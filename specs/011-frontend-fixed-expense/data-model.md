# Data Model: 프론트 고정지출 화면

**Feature**: 011-frontend-fixed-expense | **Date**: 2026-09-20 | **Plan**: [plan.md](./plan.md)

**DB 저장 단위가 없다.** 화면 모듈은 데이터베이스를 모르고, 설정과 내역은 백엔드가 돌려주는
값을 그때그때 받아 그린다. `sql/schema-moneylogdb.sql` 은 읽지도 바꾸지도 않는다.

**세션에 더하는 상태가 없다.** 009·010 과 같다 — 화면 다섯이 전부 한 요청 안에서 끝난다.
쪽 번호와 연·월은 주소에 실린다.

| 갈래 | 사는 곳 | 수명 |
|---|---|---|
| 로그인 세션 | 서버 세션 | 007 이 정의한 그대로. 011 은 읽지도 쓰지도 않는다 |
| 목록의 쪽 번호 | 주소 | 그 요청 동안만 |
| 월별 내역의 연·월 | 주소 | 그 요청 동안만 |
| 폼과 화면 값 | 요청 하나 | 그 요청 동안만 |

---

## 1. 저장 단위가 둘이다

**이 기능의 모양을 정하는 사실이다.** 하나는 "매달 이만큼 나간다"는 기준값이고, 다른 하나는
"그 달에 실제로 잡힌 값"이다.

| | 고정지출 설정 | 월별 고정지출 내역 |
|---|---|---|
| 무엇인가 | **기준값**. 지금 유효한 설정 | **그 달에 잡힌 값** |
| 다루는 화면 | 4.2~4.5 | 4.6 |
| 식별자 | `fixedExpenseId` | `fixedExpenseId` + **연 + 월** |
| 고치면 | **미래 달로 번진다**(직접 고치지 않은 것만) | **그 달에서 끝난다** |
| 만들어지는 때 | 사용자가 등록할 때 | **그 달을 처음 열 때 서버가 만든다** |
| 지우면 | **내역이 지난 달 것까지 함께 사라진다** | (따로 지우지 않는다) |

**화면이 둘을 같은 말로 부르지 않는다.** 설정의 금액은 「기본 금액」, 내역의 금액은 「그 달
금액」이다 — 같은 「금액」으로 적으면 사용자는 하나로 읽고, **"고쳤는데 지난달이 안 바뀐다"를
버그로 신고한다.**

---

## 2. 고정지출 설정

| 값 | 타입 | 화면에서 |
|---|---|---|
| 식별자 | number | 주소와 요청 경로에만 쓰고 화면에 보이지 않는다 |
| 이름 | string | 목록에서 이 값으로 구분한다 |
| 수단 식별자 | number | 선택 칸의 현재 값 |
| 수단 이름 | string | **조회 시점 현재 이름.** 저장된 값이 아니다 |
| 지출유형 식별자 | number | 선택 칸의 현재 값 |
| 지출유형 이름 | string | 위와 같은 규칙 |
| 기본 금액 | number | 원 단위 정수. **그 달 금액과 다른 값이다** |
| 매달 결제일 | number | 1~31 |
| 내용 | string | |
| 적용 시작 연 · 월 | number 둘 | **정수 두 칸.** 문자열이 아니다 |
| 적용 종료 연 · 월 | number 둘 | 위와 같다 |

### 2.1 이름을 저장하지 않는다

**010 과 정반대다.** 지출·소득은 등록 당시 이름을 스냅샷으로 남겨 화면이 **덮어쓰면 안 됐고**,
고정지출은 이름 컬럼 자체가 없어 **화면이 옛 이름을 들고 있으면 안 된다.**

| | 지출·소득 (010) | 고정지출 (011) |
|---|---|---|
| 이름의 출처 | **등록 당시 스냅샷** | **조회 시점 현재 값** |
| 수단 이름을 바꾸면 | 과거 기록은 그대로 | **이 설정도 새 이름으로 보인다** |
| 화면이 할 일 | 받은 값 그대로 | **받은 값 그대로** |

**화면이 할 일은 양쪽 다 같다** — 받은 값을 그대로 보인다. 다르게 보이는 결과가 나오는 것이
정상이며, 010 의 가계부 목록에서 **고정지출 행만 현재 이름이었던 것**이 이 차이다.

### 2.2 적용 기간은 정수 네 칸이다

| 기능 | 형식 | 예 |
|---|---|---|
| 010 할부 등록 | 문자열 한 칸 | `"2026-01"` |
| **011 고정지출** | **정수 네 칸** | `2026` · `1` · `2026` · `12` |

**한쪽 규칙을 다른 쪽에 옮기면 등록이 형식 오류로 막힌다.** 폼 타입이 네 칸을 그대로 들고
있게 해 옮기다 틀릴 자리를 없앤다.

**화면이 쪼개거나 합치지 않는다.** 입력 칸도 넷이고 보내는 값도 넷이다.

## 3. 월별 고정지출 내역

| 값 | 타입 | 화면에서 |
|---|---|---|
| 고정지출 식별자 | number | 연·월과 **함께** 한 행을 가리킨다 |
| 연 · 월 | number 둘 | |
| 고정지출 이름 | string | 관리 테이블의 **현재** 값 |
| 그 달 금액 | number | **설정의 기본 금액과 다를 수 있다** |
| 그 달 결제일 | string | `YYYY-MM-DD`. 매달 결제일이 그 달 말일보다 크면 **말일로 보정된 값** |
| 그 달 내용 | string | |
| 그 달 수단 (식별자·이름) | number · string | 이름은 현재 값 |
| 그 달 지출유형 (식별자·이름) | number · string | 이름은 현재 값 |
| **직접 수정 여부** | boolean | **「수정됨」 뱃지의 근거**이며 반영이 보존할지 정하는 값 |

### 3.1 「수정됨」이 반영의 전제다

**구분이 없으면 반영을 누를 때 무엇이 보존되는지 알 수 없다.** 「직접 수정분도 되돌리기」가
무엇을 되돌리는지도 이 표시를 봐야 이해된다.

**되돌릴 수 있는 표시다.** 반영으로 다시 설정 값이 될 수 있으므로 위험을 알리는 색을 쓰지
않는다 — 009 의 「삭제됨」과 다른 점이다.

### 3.2 그 달 행은 열어 볼 때 만들어진다

```
4.6 을 연다
   │
   ├─ 그 달 행이 있다 ─→ 그대로 보인다
   │
   └─ 없다 ─→ 서버가 적용 기간에 걸리는 설정을 펼쳐 만들고, 그 목록을 돌려준다
```

**화면은 그 달을 열 뿐이고 만들라고 따로 요청하지 않는다.** 만드는 규칙(적용 기간·말일 보정)이
백엔드에 있고, 화면이 따로 요청하면 같은 판단이 두 곳에 생긴다.

**한 번도 열지 않은 달은 통계(012)의 고정지출 합계가 0 이다.** 그 달을 채우려면 4.6 이나
가계부를 먼저 연다.

### 3.3 한 건 수정으로 바꿀 수 있는 것

| 칸 | 그 달에서 |
|---|---|
| 그 달 금액 · 결제일 · 내용 · 수단 | **고칠 수 있다** |
| 고정지출 이름 · 지출유형 | **여기서 바꾸지 않는다** — 설정(4.5)에서 바꾼다 |

**결제일은 그 달 안이어야 한다.** 밖의 날짜를 넣으면 거절되며 화면이 그 사실을 먼저 적는다.

**아직 만들어지지 않은 달은 고칠 수 없다.** 그때의 실패는 **먼저 그 달을 열라**는 안내로
이어진다(`FR-1017`).

---

## 4. 월 요약

| 값 | 타입 | 설명 |
|---|---|---|
| 그 달 합계 | number | **그 달 전체 기준.** 필터와 무관하다 |

**010 에서 정한 것과 같은 규칙이다.** 합계는 화면 상단의 요약이고 필터는 아래 목록을 좁히는
도구다 — 화면이 목록을 다시 더해 맞추지 않는다.

백엔드가 두 API 에 같은 규칙을 둔 이유도 같다: **다르게 두면 구현이 반드시 한쪽을 틀린다.**

---

## 5. 반영 결과

| 값 | 타입 | 뜻 |
|---|---|---|
| 추가 | number | 적용 기간에 걸리는데 내역이 없던 것 |
| 갱신 | number | 직접 고치지 않아 설정 값으로 다시 맞춘 것 |
| 삭제 | number | 적용 기간이 그 달을 더는 포함하지 않는 것 |
| 보존 | number | **직접 고친 행이라 손대지 않은 것** |

**넷을 다 보인다.** 「보존」이 특히 중요하다 — 그 숫자가 **직접 고친 값이 살아남았다는
증거**이고, 되돌리기를 켰을 때 0 이 되는 것으로 무엇이 달랐는지 읽힌다.

반영 응답에는 **재작성 후 목록과 합계도 함께** 온다. 화면은 그것으로 갱신하고 다시 조회하지
않는다.

---

## 6. 화면의 상태 — 주소에 들고 다닌다

**세션에 두지 않는다.** 두면 뒤로 가기와 새 탭에서 다른 목록이 뜬다.

| 값 | 기본 | 설명 |
|---|---|---|
| 쪽 번호 | 첫 쪽 | 007 의 환산기가 시작점으로 바꾼다. **사용자가 시작점을 직접 넣는 칸을 두지 않는다** |
| 열 모달 | 없음 | 등록·상세·수정·월별 넷 중 하나 |
| 대상 식별자 | 없음 | 상세·수정·**월별의 단건 수정**에 쓴다 |
| 월별의 연 · 월 | **이번 달** | 주소에 없으면 **서버 시각**으로 정한다 |

**브라우저 시각을 믿지 않는다** — 010 에서 정한 것과 같다. 시차가 있는 사용자가 다른 달을
본다.

**모달을 겹치지 않는다.** 월별 내역의 한 건을 고칠 때 같은 모달을 **편집 상태로** 다시 연다 —
007 의 모달 스크립트는 Esc 가 전부 닫는 구조라, 겹치면 사용자가 고치던 값이 사라진다.

---

## 7. 되돌릴 수 없는 전이 둘

```
고정지출 설정
   │
   ├─ 기본값 수정 ─→ 미래 달 중 직접 고치지 않은 내역이 함께 바뀐다
   │                 지난 달·이번 달과 직접 고친 달은 그대로
   │
   └─ 삭제 ─→ 설정이 사라지고 ★ 월별 내역이 지난 달 것까지 함께 사라진다 ★
              되돌릴 수 없다

그 달 내역
   │
   ├─ 한 건 수정 ─→ 그 달만 바뀌고 「수정됨」이 붙는다
   │
   ├─ 반영 ─→ 설정 기준으로 다시 만든다. 「수정됨」 행은 보존된다
   │
   └─ 반영 + 되돌리기 ─→ ★ 직접 고친 값이 사라지고 전부 설정 값이 된다 ★
                          기본은 꺼져 있고 확인을 한 겹 더 받는다
```

**★ 둘이 확인 다이얼로그를 갖는다.** 범위가 다르므로 **문구도 다르다** — 하나는 "지난 달
기록까지", 다른 하나는 "직접 고친 값"이다.
