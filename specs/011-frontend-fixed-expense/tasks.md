## Dependencies & Execution Order

### Phase 의존

```
Phase 1 (Setup — 명세 선행 개정 · 스펙 품질 게이트)
   ↓  코드보다 반드시 먼저 (원칙 V)
Phase 2 (Foundational — 설정 · 내역 · 반영 결과 · 연월 주소 · 모델 담기)
   ↓  여기가 끝나기 전에는 어떤 스토리도 시작할 수 없다
Phase 3 US1 (P1) 🎯 MVP ── 고정지출 설정 관리
   ↓
   ├─ Phase 4 US2 (P1) ── 변경 범위 안내   (US1 의 수정 모달에 붙는다)
   └─ Phase 5 US3 (P2) ── 월별 내역
          ↓
       Phase 6 US4 (P2) ── 반영   (US3 의 모달 안에 있다)
   ↓

```

### 스토리 사이의 의존

| 스토리 | 다른 스토리에 의존하나 |
|---|---|
| US1 설정 관리 | 없다. Phase 2 만 있으면 완결된다 |
| US2 변경 범위 안내 | **US1 이 필요하다.** 안내를 붙일 수정 모달이 먼저 서야 한다 |
| US3 월별 내역 | **코드로는 Phase 2 만 있으면 된다** — 컨트롤러가 다르고 응답을 세워 시험한다. 다만 **손으로 밟으려면 US1 로 설정을 만들어야** 그 달에 행이 생긴다 |
| US4 반영 | **US3 이 필요하다.** 반영 버튼이 그 모달 안에 있다 |

**US2 와 US3 은 서로 독립이다.** US1 이 끝난 뒤 나란히 갈 수 있다 — US2 는 수정 모달의 문구이고 US3 은 다른 컨트롤러다.

**US2 가 작지만 P1 인 이유**는 이 기능에서 **가장 오해하기 쉬운 지점**이기 때문이다. 코드는 몇 줄이지만 없으면 사용자가 지난달이 안 바뀐 것을 버그로 신고한다.

## Implementation Strategy

### MVP 범위

**Phase 1 + Phase 2 + Phase 3(US1)** 이 최소 인도 단위다. 여기까지면 **010 이 읽기만 하던 고정지출 행을 사용자가 만들 수 있다** — 가계부에 네 종류가 모두 화면에서 생긴다.

US2 를 함께 넣는 것도 방법이다. 코드가 몇 줄이고 **US1 의 수정 모달에 문구를 더하는 일**이라, 둘을 묶으면 "고쳐도 지난달이 안 바뀐다"는 신고를 처음부터 막는다.

### 그다음

| 순서 | 스토리 | 왜 이 순서인가 |
|---|---|---|
| 2 | US2 변경 범위 안내 | 코드가 가장 작고, 없으면 US1 을 쓴 사용자가 바로 혼란을 겪는다 |
| 3 | US3 월별 내역 | 설정이 쌓이면 "이번 달만 달랐다"를 다루게 된다 |
| 4 | US4 반영 | US3 의 모달이 있어야 버튼을 놓을 자리가 생기고, US2 가 낸 문제의 답이다 |

**US2 를 US3 보다 앞에 두는 것이 이 목록의 판단이다.** 크기로는 US3 이 본체지만, US2 없이 US1 만 인도하면 **사용자가 겪는 첫 혼란을 그대로 두는 것**이 된다.

### 병렬 인도

Phase 2 이후 사람이 둘이면 **US1 을 함께 끝낸 뒤 한쪽이 US2, 다른 쪽이 US3→US4** 를 맡는다. US2 는 템플릿의 한 자리이고 US3 은 다른 컨트롤러라 겹치는 파일이 `list.html` 하나뿐이다 — **US2 는 수정 모달, US3 은 월별 모달**로 자리가 달라 합칠 때 충돌이 적다.

## Notes

- **[P] 는 다른 파일이고 미완 작업에 기대지 않는다는 뜻이다.** 같은 파일을 넓혀 가는 작업에는 붙이지 않았다.
- **007~010 을 하나도 고치지 않는다.** 010 이 007 의 실패 예외를 고쳐야 했던 것과 달리 필요한 것이 전부 서 있다. T047 이 diff 로 확인한다.
- **저장 단위가 둘이다.** 설정의 「기본 금액」과 그 달의 「그 달 금액」을 같은 말로 부르지 않는다 — 하나로 읽히면 "고쳤는데 지난달이 안 바뀐다"가 버그로 신고된다.
- **적용 기간은 정수 네 칸이다.** 010 의 할부가 문자열 한 칸이라 같은 저장소 안에서 형식이 갈린다 — 폼 타입이 네 칸을 그대로 들고 있게 해 옮기다 틀릴 자리를 없앤다.
- **이름은 현재 값이다.** 010 의 스냅샷과 정반대이며, 화면이 할 일은 양쪽 다 「받은 값 그대로」로 같다.
- **되돌릴 수 없는 것이 둘이고 범위가 다르다.** 삭제는 "지난 달 기록까지", 되돌리기는 "직접 고친 값" — 확인 문구를 따로 쓴다.
- **모달을 겹치지 않는다.** 007 의 Esc 가 전부 닫는 구조라, 겹치면 고치던 값이 사라진다.
- **에러코드를 새로 정의하지 않는다.** 백엔드가 준 코드를 그대로 옮기며, **`3401` 은 두 가지를 겸해 폼 상단**에 둔다.
- 화면이 부르는 API 10건의 주소와 칸은 `프로젝트설계/기능명세상세-백엔드/` 의 phase2·phase4 가 갖고 있다. 011 은 그것을 소비만 한다.
