# Quickstart: 프론트 고정지출 화면

**Feature**: 011-frontend-fixed-expense | **Date**: 2026-09-20 | **Plan**: [plan.md](./plan.md)

이 문서는 **실행하고 검증하는 절차**다. 구현 순서는 `tasks.md` 가 낸다.

## 0. 착수 전

### 선행 기능

| 선행 | 왜 필요한가 |
|---|---|
| 007 (프론트 공통 기반) | 백엔드 호출 통로·모달 껍데기·확인 다이얼로그·**페이징 환산기**를 그대로 쓴다 |
| 008 (프론트 회원·인증) | **로그인이 서 있어야 이 화면들이 열린다.** 폼 실패 착지 규약도 008 의 것이다 |
| 009 (프론트 수단·지출유형) | **지출용 수단과 지출유형이 있어야 고정지출을 만들 수 있다.** 목록+모달 규약도 009 의 것이다 |
| 010 (프론트 가계부) | 선행은 아니지만 **결과가 그쪽에 나타난다** — 고정지출 행이 가계부 목록에 섞여 보인다 |
| 003·005 (백엔드) | 고정지출 8건은 005, 사용 중 목록 2건은 003 이다 |
| `화면기획/proto/` | `fixed-expense-list.html` 을 옮긴다 — **다만 4.6 은 거의 새로 만든다** |

**010 이 없어도 011 은 선다.** 다만 만든 고정지출이 가계부에 어떻게 보이는지는 010 으로
확인한다.

## 1. 실행

화면과 백엔드를 함께 띄운다. **백엔드에는 PostgreSQL 이 필요하다.**

```bash
./gradlew :app-mod:money-backend-app:bootRun   # :8081
./gradlew :app-mod:money-app:bootRun           # :8080
```

로컬 기동에는 환경변수 둘이 필요하다 — `JWT_SECRET`(32바이트 이상)과 `ICON_STORAGE_DIR`.

**먼저 009 에서 지출용 수단과 지출유형을 만들어 둔다.** 없으면 등록 모달의 선택 칸이 비어
있다.

## 2. 손으로 밟아 보는 경로

### US1 — 고정지출 설정을 관리한다

| # | 하는 것 | 기대 |
|---|---|---|
| 1 | 사이드바에서 「고정지출 설정 목록」을 연다 | 목록이 뜨고 **상태 필터가 없다** |
| 2 | 등록 모달을 연다 | 수단·유형 칸에 **사용 중인 것만** 나온다 |
| 3 | 적용 기간 칸을 본다 | **연과 월이 각각 따로** 네 칸이다 |
| 4 | 전부 채워 저장한다 | 목록에 나타나고 **적용 기간 열**이 보인다 |
| 5 | 결제일에 32 를 넣어 저장한다 | 거절되고 **1~31** 임이 안내된다 |
| 6 | 종료 연월을 시작보다 앞서게 해 저장한다 | 거절되고 사유가 **폼 상단**에 보인다 |
| 7 | 009 에서 소득용 수단을 만든 뒤 그것을 고른다 | 거절되고 **「지출용 수단을 고르라」**가 보인다 |
| 8 | 상세 모달을 연다 | 값이 읽기 전용으로 보인다 |
| 9 | 009 에서 수단 이름을 바꾼 뒤 목록을 다시 연다 | **새 이름**이다 — 010 의 지출 행과 반대다 |
| 10 | 행을 11건 이상 만들어 다음 쪽을 누른다 | **겹치는 행 없이** 이어진다 |
| 11 | 삭제를 누른다 | 확인에 **월별 내역도 함께 사라진다**가 적혀 있다 |

### US2 — 기준값을 고치면 어디까지 따라오는지 안다

| # | 하는 것 | 기대 |
|---|---|---|
| 1 | 수정 모달을 연다 | **저장 전에** 「미래 달 중 직접 고치지 않은 내역에만 반영된다」가 보인다 |
| 2 | 같은 안내를 읽는다 | **4.6 의 반영으로 가는 길**이 함께 있다 |
| 3 | 금액을 바꿔 저장한 뒤 **미래 달** 내역을 연다 | 새 금액이다 |
| 4 | **지난 달** 내역을 연다 | **옛 금액 그대로**다 |
| 5 | 어떤 달을 직접 고친 뒤 설정을 또 바꾼다 | 그 달은 **바뀌지 않는다** |

### US3 — 그 달 내역을 보고 한 건만 고친다

| # | 하는 것 | 기대 |
|---|---|---|
| 1 | 「월별 내역」 버튼을 누른다 | **화면 상단에 하나** 있고 행마다 있지 않다 |
| 2 | 모달이 열린다 | 주소가 `?m=monthly` 이고 **대상 식별자가 없다** |
| 3 | 한 번도 안 연 달을 고른다 | 빈 목록이 아니라 **설정에서 펼쳐진 행들**이 보인다 |
| 4 | 결제일이 31 인 고정지출을 2월에 본다 | **말일로 보정된 날짜**가 그대로 보인다 |
| 5 | 한 행의 금액을 고쳐 저장한다 | 그 행이 갱신되고 **「수정됨」**이 붙는다 |
| 6 | 편집 중 Esc 를 눌러 본다 | 모달이 **겹쳐 있지 않다** — 목록 모달이 닫힌다 |
| 7 | 다른 달을 연다 | 그 달은 **바뀌지 않았다** |
| 8 | 결제일을 그 달 밖으로 고친다 | 거절되고 **그 달 안이어야 함**이 안내된다 |
| 9 | 상단 합계를 본다 | **그 달 전체 합계**다 |
| 10 | 적용 기간에 걸리는 것이 없는 달을 연다 | 「이 달에 해당하는 고정지출이 없습니다」 |

### US4 — 그 달 내역을 설정 기준으로 다시 만든다

| # | 하는 것 | 기대 |
|---|---|---|
| 1 | 모달이 열린 직후 체크박스를 본다 | 「직접 수정분도 되돌리기」가 **꺼져 있다** |
| 2 | 「고정지출 반영」을 누른다 | 확인 다이얼로그가 뜬다 |
| 3 | 확인한다 | **추가·갱신·삭제·보존 건수 넷**이 보이고 목록이 갱신된다 |
| 4 | 직접 고친 행을 본다 | **보존됐다.** 「수정됨」이 그대로다 |
| 5 | 체크박스를 켜고 반영을 누른다 | 확인 문구가 **달라진다** — 「직접 수정한 값이 사라진다」 |
| 6 | 확인한다 | 전부 설정 값이 되고 **보존 건수가 0** 이다 |
| 7 | 지난 달에서 반영을 눌러 본다 | US2 가 못 맞춘 지난 달이 **설정 값으로 맞춰진다** |

### 010 과 맞물리는 지점

| # | 하는 것 | 기대 |
|---|---|---|
| 1 | 가계부(010)의 같은 달을 연다 | 고정지출 행이 **고정지출 뱃지**로 섞여 보인다 |
| 2 | 그 행의 관리 열을 본다 | **수정·삭제가 없고** 이 화면으로 오는 길이 있다 |
| 3 | 009 에서 수단 이름을 바꾼 뒤 가계부를 다시 연다 | **고정지출 행만** 새 이름이다 |

### 007~010 을 하나도 고치지 않는다

010 은 007 의 실패 예외를 고쳐야 했다(엑셀 행 오류가 구조로 와서). **011 은 그럴 일이 없다.**

| 011 이 필요로 하는 것 | 어디 있나 |
|---|---|
| 쪽 넘기기 | 007 의 **페이징 환산기**. 008 이 이미 쓰고 있다 |
| 모달 넷 | 007 의 모달 껍데기 + 009 의 여는 조각 |
| 확인 다이얼로그 둘 | 007 의 공통 다이얼로그. 본문은 화면이 넘긴다 |
| 구조를 가진 실패 | **없다.** 011 의 실패는 전부 코드와 문구 하나다 |
| 파일 주고받기 | **없다** |

확인:

```bash
git status --short -- app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/client \
                      app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/session \
                      app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/web \
                      app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/support \
                      app-mod/money-app/src/main/resources/templates/layout \
                      app-mod/money-app/src/main/resources/templates/fragments \
                      app-mod/money-app/src/main/resources/static \
                      app-mod/money-app/src/main/java/com/dbdomino/moneylog/front/ledger \
                      app-mod/money-app/src/main/resources/templates/ledger
# → 비어 있어야 한다
```

**「수정됨」 뱃지가 009 의 상태 뱃지 조각으로 되는지 먼저 본다.** 되면 그것을 쓰고, 색 규칙이
맞지 않으면(되돌릴 수 있는 표시라 위험 색을 쓰지 않는다) **011 이 조각을 새로 더한다** —
공통 조각을 고치지는 않는다.
