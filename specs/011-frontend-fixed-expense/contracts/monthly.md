# Contract: 월별 고정지출 내역 (4.6)

**Feature**: 011-frontend-fixed-expense | **관련 FR**: 1011~1021

| 항목 | 값 |
|---|---|
| 주소 | `/fixed-expenses?m=monthly` · 연·월 이동은 `&y={연}&mm={월}` · 단건 수정은 `&id={식별자}` 를 더한다 |
| 부모 페이지 | 4.2 `/fixed-expenses` |
| 껍데기 | 007 의 **로그인 후** 레이아웃 |
| 사이드바 활성 메뉴 | `fixed-list` |
| 권한 | 로그인 |
| 부르는 API | `FixedExpenseMonthlyList` · `FixedExpenseMonthlyUpdate` · `FixedExpenseMonthlySync` · `PaymentMethodListActive` |

**그 달 전체를 보는 화면이다.** 특정 고정지출 하나를 여는 것이 아니라서 **모달 값에 대상
식별자를 붙이지 않는다**(`FR-1012`) — 단건 수정에 들어갈 때만 `id` 가 붙는다.

---

## 1. 설정이 아니라 그 달에 잡힌 값이다

| | 4.2~4.5 설정 | **4.6 이 화면** |
|---|---|---|
| 무엇인가 | 매달 이만큼 나간다는 **기준값** | **그 달에 실제로 잡힌 값** |
| 금액의 이름 | 「기본 금액」 | **「그 달 금액」** |
| 고치면 | 미래 달로 번진다 | **그 달에서 끝난다** |

**같은 「금액」으로 적지 않는다.** 하나로 읽히면 사용자는 "고쳤는데 지난달이 안 바뀐다"를
버그로 신고한다.

### 프로토타입에서 옮길 것이 거의 없다

프로토타입의 `modal-fx-monthly` 는 **연·월·금액 세 칸짜리 단건 수정 폼**이다. 확정 계약의
이 화면은 **그 달 목록 + 단건 수정 + 반영 버튼 + 되돌리기 체크박스**다.

**가져오는 것은 모달 껍데기뿐이고 나머지는 새로 만든다.** 프로토타입이 만들어질 때는 월별
내역이 "설정 하나의 그 달 금액을 덮어쓰는 일"로 보였고, 확정 계약에서 성격이 달라졌다.

---

## 2. 목록

### 열

| 열 | 값 |
|---|---|
| 이름 | 고정지출 이름. 관리 테이블의 **현재** 값 |
| 수단 | 그 달 수단 이름. 현재 값 |
| 유형 | 그 달 지출유형 이름. 현재 값 |
| 결제일 | `YYYY-MM-DD`. **말일로 보정된 값일 수 있다** |
| 그 달 금액 | 원 단위. 오른쪽 정렬 |
| **상태** | **「수정됨」 뱃지.** 직접 고친 행에만 |
| 관리 | 수정 |

### 「수정됨」이 반영의 전제다

**구분이 없으면 반영을 누를 때 무엇이 보존되는지 알 수 없다**(`FR-1013` · `SC-1004`).
「직접 수정분도 되돌리기」가 무엇을 되돌리는지도 이 표시를 봐야 이해된다.

**되돌릴 수 있는 표시라 위험을 알리는 색을 쓰지 않는다** — 009 의 「삭제됨」과 다른 점이다.
반영으로 다시 설정 값이 될 수 있다.

### 결제일이 보정될 수 있다

매달 결제일이 31 인데 그 달이 30일까지면 **서버가 말일로 맞춘다.** 화면은 **받은 날짜를
그대로** 보이고 스스로 계산하지 않는다.

### 그 달 대상이 없을 때

「이 달에 해당하는 고정지출이 없습니다」를 보인다(`FR-1016`). **적용 기간이 그 달을 포함하지
않으면 나오지 않는다**는 것이 이유이며, 빈 목록만 두면 사용자는 불러오지 못한 것으로 읽는다.

## 3. 연·월과 조회

### 주소에 들고 다닌다

| 값 | 기본 |
|---|---|
| 연 · 월 | **이번 달.** 주소에 없으면 **서버 시각**으로 정한다 |

**브라우저 시각을 믿지 않는다** — 010 에서 정한 것과 같다. 시차가 있는 사용자가 다른 달을 본다.

**연·월이 바뀌면 다시 조회한다**(`FR-1011`). 세션에 두지 않으므로 뒤로 가기와 새 탭에서도
같은 달이 뜬다.

### 조회가 쓰기를 겸한다

그 연·월의 내역이 없으면 **서버가 만들어 저장한 뒤** 목록에 넣는다. `GET` 인데 부작용이 있는
유일한 호출이다.

**화면은 그 달을 열 뿐이고 만들라고 따로 요청하지 않는다.** 빈 목록을 받아 "만들까요?"를
묻지 않는다 — 만드는 규칙이 백엔드에 있고, 화면이 따로 요청하면 같은 판단이 두 곳에 생긴다.

**한 번도 열지 않은 달은 통계(012)의 고정지출 합계가 0 이다.** 012 와 맞물리는 지점이다.

### 상단 합계

**필터와 무관하게 그 달 전체 기준**이다(`FR-1015`). 010 에서 정한 것과 같은 규칙이며,
백엔드가 두 API 에 같은 규칙을 둔 이유도 같다 — **다르게 두면 구현이 반드시 한쪽을 틀린다.**

**화면이 목록을 다시 더해 맞추지 않는다.**

## 4. 단건 수정

| 칸 | 그 달에서 |
|---|---|
| 그 달 금액 · 결제일 · 내용 · 수단 | **고칠 수 있다** |
| 고정지출 이름 · 지출유형 | **여기서 바꾸지 않는다** — 4.5 에서 바꾼다 |

**결제일은 그 달 안이어야 한다**(`FR-1014`). 화면이 그 사실을 칸 가까이 먼저 적고, 밖의
날짜는 서버가 거절한다.

**수단 선택 목록은 등록과 같은 사용 중 목록(지출용)** 으로 채운다.

### 모달을 겹치지 않는다

주소에 대상과 연·월을 실어(`?m=monthly&id={식별자}&y={연}&mm={월}`) **같은 모달을 편집
상태로** 다시 연다.

**007 의 모달 스크립트는 겹친 모달을 가정하지 않는다** — Esc 가 전부 닫는 구조라, 겹치면
위의 것만 닫으려 해도 둘 다 닫히고 **사용자가 고치던 값이 사라진다.**

주소에 싣는 것은 009·010 과 같은 방식이라 새로 배울 것이 없고, 실패 착지도 같은 주소로
돌아오면 된다.

### 저장하면 「수정됨」이 붙는다

그 행이 갱신되고 **직접 수정 표시가 켜진다.** 다른 달은 바뀌지 않는다.

## 5. 반영 (「고정지출 반영」)

**US2 가 만든 "지난 달은 안 따라온다"의 유일한 해결책이다.**

| 항목 | 내용 |
|---|---|
| 부르는 곳 | 월별 내역 모달의 「고정지출 반영」 |
| 확인 | 007 의 공통 확인 다이얼로그 (`FR-1018`) |
| 보내는 방법 | `POST`. 연·월과 되돌리기 여부를 싣는다 |

### 무엇이 일어나나

| 대상 | 처리 |
|---|---|
| 적용 기간에 걸리는데 내역이 없는 것 | **추가** |
| 내역이 있고 직접 고치지 않은 것 | 설정 값으로 **갱신** |
| 내역이 있고 **직접 고친 것** | **보존** (되돌리기를 켜면 갱신) |
| 적용 기간이 그 달을 더는 포함하지 않는 것 | **삭제** |

### 결과를 넷 다 보인다

**추가 · 갱신 · 삭제 · 보존** 건수를 보이고 목록을 갱신한다(`FR-1019`).

**「보존」이 특히 중요하다** — 그 숫자가 **직접 고친 값이 살아남았다는 증거**이고, 되돌리기를
켰을 때 0 이 되는 것으로 무엇이 달랐는지 읽힌다.

**응답에 재작성 후 목록과 합계가 함께 온다.** 화면은 그것으로 갱신하고 다시 조회하지 않는다.

### 되돌리기는 안전장치가 두 겹이다

| 겹 | 장치 |
|---|---|
| 1 | 「직접 수정분도 되돌리기」 체크박스가 **기본 꺼짐**(`FR-1020`) |
| 2 | 켠 채 누르면 **확인 문구가 달라진다** — **"직접 수정한 값이 사라진다"**(`FR-1021`) |

**한 겹이면 실수로 켠 것을 알아챌 자리가 없다**(`SC-1005`).

**모달이 열릴 때마다 꺼진 상태로 시작한다.** 이전에 켰던 것이 남아 있으면 다음 반영에서
모르고 지나간다.

## 6. 실패가 붙는 칸

| 코드 | 뜻 | 붙는 칸 | 화면 |
|---|---|---|---|
| `3401` | 금액·결제일·수단 오류 · 바꿀 필드 없음 · **수단 용도 불일치** | **편집 폼 상단** | 4.6 |
| `3402` | 고정지출을 찾을 수 없음 | 목록 안내 | 4.6 |
| `3403` | 연·월 값 오류 | 목록 안내. **빈 목록과 합계 0 으로** 그린다 | 4.6 |
| `3405` | **그 연·월의 내역이 아직 없음** | 목록 안내 + **먼저 그 달을 열라**는 길 | 4.6 |
| `3003` | 수단 없음 · 타인 · 사용 안 함 · 삭제됨 | **수단 칸** | 4.6 |

### `3405` 는 안내로 이어져야 한다

아직 만들어지지 않은 달의 한 건을 고치려 한 경우다. **오류로 끝내지 않고 "먼저 그 달을
열라"는 길을 준다**(`FR-1017`).

그 달을 여는 것(목록 조회)이 곧 만드는 일이므로, **사용자가 할 일은 한 번 더 여는 것뿐**이다.

### `3401` 은 여기서도 상단이다

4.3·4.5 와 같은 이유다 — 값 오류와 수단 용도 불일치를 한 코드가 겸한다. **서버 문구를
그대로 보인다.**

## 7. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 모달 값에 **대상 식별자가 붙지 않는다**(`?m=monthly`) | FR-1012 |
| 단건 수정에 들어갈 때만 `id` 가 붙는다 | §4 |
| 연·월이 없으면 **서버 시각의 이번 달**이다 | §3 |
| 연·월이 바뀌면 **다시 조회한다** | FR-1011 |
| 직접 고친 행이 **「수정됨」으로 구분**된다 | FR-1013 · SC-1004 |
| 상단 합계가 **그 달 전체 기준**이고 목록을 다시 더하지 않는다 | FR-1015 |
| 그 달 대상이 없으면 **안내가 보인다** | FR-1016 |
| 단건 수정이 **금액·결제일·내용·수단만** 싣는다 | FR-1014 |
| 이름·지출유형을 **싣지 않는다** | FR-1014 |
| 결제일이 **그 달 안**이어야 함이 적혀 있다 | FR-1014 |
| **모달을 겹치지 않는다** — 편집도 같은 모달이다 | research 8 |
| 반영이 **확인을 거친다** | FR-1018 |
| 반영 결과로 **네 건수**가 보인다 | FR-1019 |
| 되돌리기 체크박스가 **기본 꺼짐**이다 | FR-1020 · SC-1005 |
| 켠 채 반영하면 **확인 문구가 달라진다** | FR-1021 |
| `3405` 가 **먼저 그 달을 열라**는 안내로 이어진다 | FR-1017 |
| 말일 보정된 결제일을 **그대로** 보인다 | §2 |
