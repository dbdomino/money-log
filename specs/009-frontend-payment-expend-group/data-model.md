# Data Model: 프론트 수단·지출유형 화면

**Feature**: 009-frontend-payment-expend-group | **Date**: 2026-09-12 | **Plan**: [plan.md](./plan.md)

**DB 저장 단위가 없다.** 화면 모듈은 데이터베이스를 모르고(헌장 원칙 I), 수단·지출유형은
백엔드가 돌려주는 값을 그때그때 받아 그린다. `sql/schema-moneylogdb.sql` 은 읽지도 바꾸지도
않는다.

**008 과 달리 세션에 더하는 상태가 없다.** 008 은 두 화면에 걸친 비밀번호 재설정 때문에 표식
하나가 필요했지만, 009 의 화면 여덟은 전부 한 요청 안에서 끝난다.

여기 적는 것은 **화면이 손에 들고 있는 값**이다.

| 갈래 | 사는 곳 | 수명 |
|---|---|---|
| 로그인 세션 | 서버 세션 | 007 이 정의한 그대로. 009 는 읽지도 쓰지도 않는다 |
| 목록 화면의 상태 | 주소 | 그 요청 동안만 |
| 폼과 화면 값 | 요청 하나 | 그 요청 동안만 |

## 1. 화면이 보여 주는 값

백엔드 응답을 그대로 쓰지 않고 **화면 용도의 값으로 받는다.** 응답에 있어도 화면이 쓰지 않는
항목은 타입에 두지 않는다.

### 1.1 지출·소득 수단

2.1 목록과 2.2~2.4 모달이 같은 모양을 쓴다.

| 값 | 타입 | 화면에서 |
|---|---|---|
| 식별자 | number | 주소와 요청 경로에만 쓴다. 화면에 보이지 않는다 |
| 이름 | string | 목록의 첫 열. 고칠 수 있다 |
| 구분 | string | 카드 또는 계좌. **숫자·영문 코드가 아니라 말로 보인다** |
| 용도 | string | 지출용 또는 소득용. 말로 보인다. 등록 시 필수이고 참조가 생기면 못 바꾼다 |
| 사용 여부 | boolean | 「사용」·「사용 안 함」. 되돌릴 수 있는 상태다 |
| 삭제 여부 | boolean | 「삭제됨」. **되돌릴 수 없다.** 사용 여부와 다른 열에 보인다 |
| 카드 유효기간 | string 또는 없음 | `YYYY-MM`. 구분이 계좌면 언제나 없음이다 |

**참조 건수를 담지 않는다.** 백엔드가 목록에 그 값을 주지 않으며, 화면이 세려면 지출·소득·
고정지출을 전부 훑어야 한다(research 9). 용도를 바꿀 수 있는지는 저장해 봐야 안다.

### 1.2 지출유형

2.5 목록과 2.6~2.8 모달이 같은 모양을 쓴다.

| 값 | 타입 | 화면에서 |
|---|---|---|
| 식별자 | number | 주소와 요청 경로에만 쓴다 |
| 이름 | string | 목록의 한 열. **기본 유형이면 고칠 수 없다** |
| 사용 여부 | boolean | 「사용」·「사용 안 함」 |
| 삭제 여부 | boolean | 「삭제됨」. 되돌릴 수 없다 |
| 기본 유형 여부 | boolean | 「기본」·「직접 만듦」. **이름 변경과 삭제를 화면이 미리 막는 근거**다 |
| 아이콘 파일명 | string 또는 없음 | 백엔드가 준 주소에서 **파일명만** 꺼내 둔다(research 2). 없으면 이미지를 걸지 않는다 |

**아이콘 주소 전체를 담지 않는다.** 담으면 그 값이 그대로 `<img>` 에 걸릴 길이 생기고, 그
순간 브라우저가 백엔드를 직접 부르게 된다(`SC-807`). 파일명만 들고 있으면 화면이 쓸 수 있는
주소는 007 의 중계 경로 하나뿐이다.

## 2. 폼 — 사용자가 채우는 것

화면마다 받는 칸이 다르므로 폼도 화면별로 나눈다. 합치면 그 화면이 보내지 않는 칸까지 검증
규칙이 따라붙는다(008 이 같은 이유로 나눴다).

| 폼 | 화면 | 칸 |
|---|---|---|
| 수단 등록 | 2.2 | 이름 · 구분 · 용도 · 사용 여부 · 카드 유효기간 |
| 수단 수정 | 2.4 | 이름 · 구분 · 용도 · 사용 여부 · 카드 유효기간 |
| 지출유형 등록 | 2.6 | 이름 · 사용 여부 · 아이콘 파일 |
| 지출유형 수정 | 2.8 | 이름 · 사용 여부 · 아이콘 파일 |

**상세(2.3·2.7)에는 폼이 없다.** 읽기 전용이며 「수정」이 수정 모달 주소로 넘긴다(research 11).

### 2.1 빈 칸의 뜻

008 이 정한 규칙을 그대로 따른다 — **현재 값이 채워진 채로 뜨는 칸을 비우면 비우라는 뜻**이고,
**비어 있는 것이 기본 상태인 칸을 비우면 건드리지 않은 것**이다.

| 칸 | 비워 두면 | 요청에 |
|---|---|---|
| 아이콘 파일 | **바꾸지 않는다** | **싣지 않는다** (research 3) |
| 카드 유효기간 (구분이 카드) | 비운다 | 비우라는 값으로 싣는다 |
| 카드 유효기간 (구분이 계좌) | — | **언제나 싣지 않는다** (research 10) |
| 이름 · 구분 · 용도 · 사용 여부 | (필수라 비울 수 없다) | 언제나 싣는다 |

아이콘 파일이 008 의 새 비밀번호와 같은 자리다. **둘 다 현재 값이 칸에 채워지지 않은 채
뜬다** — 비밀번호는 보여 줄 수 없어서고 파일은 브라우저가 채울 수 없어서다. 이유는 달라도
"비어 있는 것이 기본 상태"라는 결론은 같다.

### 2.2 값을 고르는 칸은 자유 입력을 두지 않는다

| 칸 | 고를 수 있는 값 |
|---|---|
| 구분 | 카드 · 계좌 두 가지 |
| 용도 | 지출용 · 소득용 두 가지 |
| 사용 여부 | 사용 · 사용 안 함 두 가지 |

008 의 권한 칸과 같은 판단이다. **화면이 고를 수 없는 값을 서버가 받는 일이 없어야 한다** —
그 밖의 값은 형식 오류로 거절되는데, 사용자에게는 자기가 고른 것이 거절된 것으로 보인다.

## 3. 목록 화면의 상태

**주소에 들고 다닌다.** 세션에 두면 뒤로 가기와 새 탭에서 다른 화면이 뜬다.

| 값 | 기본 | 설명 |
|---|---|---|
| 열 모달 | 없음 | 등록 · 상세 · 수정 셋 중 하나. 아는 값이 아니면 열지 않는다 |
| 대상 식별자 | 없음 | 상세·수정에만 쓴다. 없으면 모달을 열지 않는다 |

**쪽 번호가 없다.** 두 목록 모두 백엔드가 조회 구간을 받지 않고 전부 돌려준다(research 4).

**검색어도 없다.** 이 기능의 목록에는 검색이 없다 — 한 사람의 수단과 지출유형은 한 화면에
들어간다.

## 4. 상태 변화 — 삭제 표시

되돌릴 수 없는 전이라 여기만 흐름을 적는다.

```
등록  ── 사용 ────────────┐
          │ 사용 여부를 끈다 │  되돌릴 수 있다
          ↓                 │
      사용 안 함 ───────────┘
          │
          │ 삭제한다 (확인 다이얼로그를 거친다)
          ↓
       삭제됨  ──── 되돌리는 길이 없다
          │
          ├─ 관리 목록: 계속 보인다. 상세만 열 수 있다
          ├─ 지출·소득 입력의 선택 목록: 빠진다 (010·011 이 만든다)
          └─ 이름: 계속 점유된다 (지출유형만 해당)
```

**사용 안 함과 삭제됨을 한 열에 합치지 않는 이유가 이 그림에 있다.** 하나는 되돌아오는
화살표가 있고 하나는 없다.

**삭제된 항목에 수정·삭제를 열지 않는다**(research 6). 다시 삭제하면 거절되고, 고쳐도 선택
목록에 돌아오지 않는다.
