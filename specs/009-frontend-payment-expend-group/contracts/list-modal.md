# Contract: 목록 하나 + 모달 셋

**Feature**: 009-frontend-payment-expend-group | **관련 FR**: 815~818

009 는 이 모양을 **두 벌** 만든다 — 수단(2.1~2.4)과 지출유형(2.5~2.8). 010~012 가 같은 모양을
더 얹으므로 여기서 정한 것이 그 화면들의 기준이 된다.

```
목록 페이지  ─ 주소 하나
  ├─ ?m=create            등록 모달
  ├─ ?m=detail&id={식별자} 상세 모달 (읽기 전용)
  └─ ?m=edit&id={식별자}   수정 모달
```

**모달은 별도 주소를 갖지 않는다.** 부모 목록이 함께 그려지고 그 위에 열린다. 모달을 닫으면
목록이 그대로 남는다.

---

## 1. 서버가 판정하고 스크립트가 연다

007 이 정한 규칙이다. 009 가 더하는 것은 **화면별 값 목록**이다.

| 화면 | 아는 모달 값 |
|---|---|
| 수단 목록 | `create` · `detail` · `edit` |
| 지출유형 목록 | `create` · `detail` · `edit` |

**모르는 값이면 모달을 열지 않고 목록만 보인다.** 오류 화면으로 보내지 않는다 — 북마크가
낡았거나 주소를 잘못 친 것뿐이고 목록은 정상이다.

### 상세·수정은 열리기 전에 값을 가져온다

| 주소 | 서버가 하는 일 |
|---|---|
| `?m=create` | 조회하지 않는다. 새로 만드는 화면이라 가져올 값이 없다 |
| `?m=detail&id={있는 식별자}` | 그 항목을 조회해 모달에 채운다 |
| `?m=edit&id={있는 식별자}` | 그 항목을 조회해 모달에 채운다 |
| `?m=detail` · `?m=edit` (식별자 없음) | **모달을 열지 않는다.** 무엇을 보여 줄지 모른다 |
| 없는 식별자 · 남의 식별자 | **모달 없이 목록만** 보이고 사유를 띄운다 |

여는 일만 브라우저가 하면 **열린 모달이 빈 채로 뜨고** 값을 채우려면 다시 요청해야 한다.

**없는 것과 남의 것을 가르지 않는다.** 백엔드가 한 코드로 묶었고 화면도 풀지 않는다 — 가르면
식별자를 훑어 남의 항목이 실재하는지 알아낼 수 있다.

---

## 2. 목록이 보여 주는 것

### 상태를 두 열로 나눈다

| 열 | 값 | 되돌릴 수 있나 |
|---|---|---|
| 사용 | 「사용」 · 「사용 안 함」 | **그렇다** |
| 상태 | 「정상」 · 「삭제됨」 | **아니다** |

**한 열에 합치지 않는다.** 둘 다 "지금 고를 수 없다"로 보이지만 하나는 되돌아오고 하나는
아니다. 합치면 사용자가 그 차이를 알 수 없다.

**삭제 표시된 항목도 목록에 남는다.** 감추면 "행이 남는다"는 계약이 화면에서 사라지고,
사용자는 지웠다고 믿는데 이름은 계속 점유된다.

### 관리 열의 버튼

| 항목 상태 | 상세 | 수정 | 삭제 |
|---|:---:|:---:|:---:|
| 정상 | ✅ | ✅ | ✅ |
| 삭제됨 | ✅ | ❌ | ❌ |
| 기본 지출유형 (정상) | ✅ | ✅ (이름 칸은 잠김) | ❌ |

**삭제된 항목에 수정·삭제를 열지 않는다.** 다시 삭제하면 거절되고, 고쳐도 선택 목록에
돌아오지 않는다. 누를 수 있는 버튼이 언제나 실패하는 것은 화면의 잘못이다.

**상세는 남긴다** — 삭제된 항목이 어떤 값이었는지 확인할 자리는 있어야 한다.

### 쪽 넘기기가 없다

두 목록 모두 백엔드가 조회 구간을 받지 않고 본인 것을 전부 돌려준다. 007 의 페이징 환산기를
쓰지 않는다.

**010~012 는 다르다.** 가계부·고정지출 목록에는 쪽 넘기기가 있다. 목록이라고 다 같지 않으니
그 화면들은 각자 백엔드 계약을 보고 정한다.

## 3. 상세 모달은 읽기 전용이다

| 항목 | 내용 |
|---|---|
| 입력 칸 | **없다.** 값을 글로 보인다 |
| 바닥 | 「닫기」와 「수정」 둘 |
| 「수정」이 하는 일 | 수정 모달 주소로 **이동한다**. 이 모달 안에서 칸이 열리지 않는다 |

**모달 안에서 모달을 열지 않는다.** 007 의 모달 셸이 겹침을 다루지 않고, 겹치면 Esc 한 번에
어느 것이 닫히는지 규칙이 필요해진다.

주소가 갈리면 화면 상태와 주소가 1:1 이 되어 **뒤로 가기와 새로고침이 예상대로** 동작한다.

## 4. 모달 안의 실패

[008 의 폼 실패 규약](../../008-frontend-member-auth/contracts/form-failure.md)을 그대로
따른다. 009 가 새로 정하지 않는다.

- 착지는 **부모 목록을 다시 그리되 모달을 연 채**다. 닫아 버리면 채운 칸이 전부 사라진다.
- 값은 **요청 파라미터에서 되읽는다.** 단, **파일 칸은 되채울 수 없다** — 브라우저가 파일
  입력에 값을 넣는 것을 허용하지 않는다. 사용자가 파일을 다시 골라야 한다는 것을 안내한다.
- 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 모달 폼 상단이다.

### 009 의 코드가 붙는 칸

008 의 표에는 회원 코드만 있다. 이 기능의 코드는 여기서 정한다.

| 코드 | 뜻 | 붙는 칸 | 화면 |
|---|---|---|---|
| `3001` | 구분 또는 용도 값이 올바르지 않음 | **모달 폼 상단** | 2.2 · 2.4 |
| `3002` | 카드 유효기간 형식 오류 | 유효기간 칸 | 2.2 · 2.4 |
| `3003` | 수단 없음 · 타인 소유 | 목록 안내 (모달 없이) | 2.3 · 2.4 |
| `3004` | 이미 삭제된 수단의 재삭제 | 목록 안내 | 2.1 |
| `3005` | 참조가 있어 용도를 바꿀 수 없음 | **용도 칸** | 2.4 |
| `3101` | 이름 중복 | **이름 칸** | 2.6 · 2.8 |
| `3102` | 아이콘 형식·크기 오류 | **아이콘 칸** | 2.6 · 2.8 |
| `3103` | 지출유형 없음 · 타인 소유 | 목록 안내 (모달 없이) | 2.7 · 2.8 |
| `3105` | 기본 유형의 이름 변경 시도 | 이름 칸 | 2.8 |
| `3106` | 사용 중인 유형의 삭제 시도 | 목록 안내 | 2.5 · 2.7 |
| `3107` | 기본 유형의 삭제 시도 | 목록 안내 | 2.5 · 2.7 |
| `3108` | 이미 삭제된 유형의 재삭제 | 목록 안내 | 2.5 |
| `9001` | 필수 누락 · 형식 오류 | 모달 폼 상단 | 전부 |

**`3001` 이 상단인 이유**는 한 코드가 구분과 용도 두 칸을 함께 가리키기 때문이다. 둘 중 어느
칸인지 코드만으로 가릴 수 없으므로 짐작하지 않는다.

**삭제 실패는 전부 목록 안내다.** 삭제에는 폼이 없고 확인 다이얼로그만 있다. 오류 화면으로
보내지 않는 이유는 관리자가 이미 원하는 상태이거나(재삭제) 대안이 있기 때문이다(사용 중).

## 5. 삭제 확인 다이얼로그

007 의 공통 다이얼로그를 쓰고 **본문은 부르는 화면이 넘긴다**. 되돌릴 수 없는 범위를 아는
쪽이 화면이다.

| 화면 | 본문에 담을 것 |
|---|---|
| 수단 (2.1) | ① 대상 이름 ② **과거 내역의 수단 이름은 그대로 남는다** ③ 되돌릴 수 없고 지출·소득 입력의 선택 목록에서 빠진다 |
| 지출유형 (2.5) | ① 대상 이름 ② **삭제해도 그 이름은 계속 점유된다** ③ 되돌릴 수 없고 선택 목록에서 빠진다 |

**②가 두 화면에서 다르다.** 수단은 과거 기록이 어떻게 되는지가 관심사이고, 지출유형은 같은
이름을 다시 쓸 수 있는지가 관심사다. 같은 문구로 맞추면 둘 다 흐려진다.

**삭제는 `POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는
것만으로 실행된다. 브라우저가 보낼 수 있는 메서드가 둘뿐이라 백엔드의 삭제 요청으로 옮기는
일은 화면 모듈이 한다.

## 6. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 목록에 삭제 표시된 항목이 남고 사용 여부와 다른 열로 보인다 | FR-815 |
| 삭제된 행에 수정·삭제 버튼이 없다 | research 6 |
| `?m=create` 로 들어오면 등록 모달이 열린 채 목록이 뜬다 | FR-816 |
| `?m=edit&id=…` 로 들어오면 **그 항목의 값이 채워진 채** 모달이 열린다 | research 12 |
| 모르는 식별자면 모달 없이 목록이 정상으로 뜬다 | FR-818 |
| 식별자 없이 `?m=edit` 이면 모달을 열지 않는다 | §1 |
| 상세 모달에 입력 칸이 없고 수정으로 가는 길이 있다 | FR-817 |
| 모달 제출 실패가 모달을 연 채로 돌아온다 | §4 |
| 삭제가 `POST` 이고 확인 다이얼로그를 거친다 | §5 |
| 삭제 확인 본문이 두 화면에서 다르다 | §5 |
| 목록 요청에 조회 구간이 실리지 않는다 | research 4 |
