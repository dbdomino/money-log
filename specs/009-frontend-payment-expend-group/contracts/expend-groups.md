## 1. 목록 (2.5)

### 열

| 열 | 값 |
|---|---|
| 아이콘 | 이미지. 없으면 **대체 표시**를 그린다 |
| 이름 | 유형 이름 |
| 구분 | 「기본」 또는 「직접 만듦」 |
| 사용 | 「사용」 또는 「사용 안 함」 |
| 상태 | 「정상」 또는 「삭제됨」 |
| 관리 | 「상세」 · 「수정」 · 「삭제」 |

**구분 열이 화면 동작의 근거다.** 기본 유형은 이름을 바꿀 수 없고 지울 수 없으므로, 왜 그
행만 버튼이 다른지 사용자가 이 열을 보고 안다. 적지 않으면 "어떤 행은 삭제가 되고 어떤 행은
안 되는" 화면이 된다.

**삭제 표시된 유형에도 아이콘이 계속 보인다.** 행이 남으므로 아이콘도 남는다.

---

## 2. 칸 (2.6 등록 · 2.8 수정)

**이름과 사용 여부가 필수이고 아이콘은 선택이다**(FR-806).

| 칸 | 필수 | 비고 |
|---|:---:|---|
| 이름 | ✅ | **기본 유형이면 잠근다** |
| 사용 여부 | ✅ | 사용 · 사용 안 함 두 값. 자유 입력을 두지 않는다 |
| 아이콘 파일 | ❌ | 고르면 저장 전에 미리보기. 비우면 **기존 아이콘을 그대로 둔다** |

**수단(2.2·2.4)보다 칸이 적다.** 지출유형에는 구분·용도에 해당하는 것이 없다 — 기본 유형
여부는 서버가 정하고 사용자가 고르지 않는다.

**아이콘을 지우는 칸이 없다.** 백엔드에 그 동작이 없다. 두면 누를 수 없는 버튼이 된다.

---

## 3. 기본 지출유형

가입할 때 자동으로 생기며 두 가지가 막혀 있다.

| 막힌 것 | 화면이 하는 일 | 서버가 거절하면 |
|---|---|---|
| 이름 변경 | **이름 칸을 잠근다**(읽기 전용) | `3105` 를 이름 칸 가까이 보인다 |
| 삭제 | **삭제 버튼을 그리지 않는다** | `3107` 을 목록 안내로 보인다 |

**화면이 미리 막는 이유**는 목록 응답이 기본 유형인지 알려 주기 때문이다. 알 수 있는 제약을
열어 두고 저장에서 실패시킬 이유가 없다 — `SC-804` 가 "시도할 방법이 화면에 없다"를 요구한다.

**그래도 서버 실패를 함께 다룬다.** 주소를 직접 쳐서 올 수 있다. 화면이 막는 것과 서버가 막는
것은 서로를 대신하지 않는다.

**사용 여부는 기본 유형도 바꿀 수 있다.** 막힌 것은 이름과 삭제 둘뿐이다.

---

## 4. 이름 중복은 삭제된 것까지 센다

| 상황 | 화면이 하는 일 |
|---|---|
| 이름이 겹쳐 거절됨 (`3101`) | **이름 칸 가까이** 안내하며, **삭제 표시된 유형의 이름도 겹침으로 센다**는 것을 함께 적는다 |

적지 않으면 사용자는 **삭제한 것과 이름이 겹칠 리 없다**고 생각한다. 그 상태에서 "이미 쓰이는
이름"만 보면 화면이 잘못됐다고 읽는다.

**수단에는 이름 중복 제약이 없다.** 두 화면의 문구를 같게 맞추지 않는다.

---

## 5. 삭제 (2.5 의 「삭제」)

| 항목 | 내용 |
|---|---|
| 부르는 곳 | 목록 행의 「삭제」. 삭제 표시된 행과 **기본 유형**에는 그리지 않는다 |
| 확인 | 007 의 공통 확인 다이얼로그 |
| 보내는 방법 | `POST`. 화면 모듈이 백엔드의 삭제 요청으로 옮긴다 |

### 확인 본문에 담을 것

1. **대상이 무엇인지** — 유형 이름.
2. **삭제해도 그 이름은 계속 점유된다** — 같은 이름으로 다시 만들 수 없다. 수단의 확인
   본문과 다른 점이며, 지출유형에서 사용자가 가장 자주 부딪히는 사실이다.
3. **되돌릴 수 없고**, 지출 입력의 선택 목록에서 빠진다.

### 실패

| 코드 | 보이는 것 |
|---|---|
| `3106` 사용 중인 유형 | 목록 안내. **「사용 안 함으로 돌리면 새 지출에서 고를 수 없게 됩니다」라는 대안을 함께 제시한다** |
| `3107` 기본 유형 | 목록 안내 |
| `3108` 이미 삭제됨 | 목록 안내 |
| `3103` 유형 없음 | 목록 안내 |

**`3106` 만 대안을 제시한다.** 나머지 셋은 사용자가 할 수 있는 일이 없지만, 이 경우는 목적을
이룰 다른 길이 있다 — 과거 지출은 그 유형을 가리켜야 하므로 지울 수 없지만, 앞으로 쓰지 않게
할 수는 있다. 대안을 적지 않으면 사용자는 막혔다고만 읽는다.

## 6. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 기본 유형의 이름 칸이 잠겨 있다 | FR-811 · SC-804 |
| 기본 유형에 삭제 버튼이 없다 | FR-811 · SC-804 |
| 기본 유형도 사용 여부는 바꿀 수 있다 | §3 |
| `3101` 안내에 **삭제된 이름도 센다**가 적혀 있다 | FR-810 |
| `3106` 안내에 **사용 안 함으로 돌리라는 대안**이 적혀 있다 | FR-812 |
| `3107` · `3108` 이 오류 화면이 아니라 목록 안내로 보인다 | §5 |
| 목록의 구분 열이 기본·직접 만듦을 구분한다 | §1 |
| 삭제 확인 본문에 **이름이 계속 점유된다**가 적혀 있다 | §5 |
| 삭제 표시된 유형에도 아이콘이 보인다 | §1 |
