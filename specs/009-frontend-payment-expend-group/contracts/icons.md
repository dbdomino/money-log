# Contract: 지출유형 아이콘

**Feature**: 009-frontend-payment-expend-group | **관련 FR**: 807 · 808 · 809 · 813 · 814

아이콘은 이 기능에서 **유일하게 파일을 다루는 자리**다. 올리는 길과 보이는 길이 서로 다르고,
둘 다 브라우저가 백엔드를 직접 부르지 않는다.

```
올리기:  브라우저 ──파일──> 화면 모듈 ──파일──> 백엔드
보이기:  브라우저 ──주소──> 화면 모듈 ──인증+조회──> 백엔드 ──바이트──> 브라우저
```

---

## 1. 보이기 — 주소를 바꿔 건다

백엔드가 목록·상세에 실어 주는 것은 **이미지가 아니라 아이콘을 받을 주소**다. 그 주소는
인증을 요구하는데 브라우저의 이미지 태그는 인증을 붙이지 못한다.

| 단계 | 하는 일 |
|---|---|
| ① | 백엔드가 준 주소에서 **파일명만** 꺼낸다 |
| ② | 007 이 만든 화면 모듈의 아이콘 경로에 그 파일명을 붙인다 |
| ③ | 그 주소를 이미지에 건다 |
| ④ | 007 의 중계가 세션의 인증을 실어 백엔드에서 받아 바이트를 흘려보낸다 |

**백엔드 주소를 이미지에 직접 걸지 않는다**(FR-814 · SC-807). 걸면 인증이 붙지 않아 전부
실패하고, 실패가 이미지 깨짐으로만 보여 원인을 짐작하기 어렵다.

**파일명만 꺼내는 이유**는 007 의 중계가 파일명 틀을 검사하기 때문이다. 백엔드가 주소의
앞부분을 바꿔도 화면이 따라 고칠 것이 없다.

### 아이콘이 없으면

| 상황 | 화면 |
|---|---|
| 아이콘 주소가 없음 | **이미지를 걸지 않고** 대체 표시를 그린다 |

빈 주소를 건 이미지는 브라우저가 현재 페이지를 다시 받아 와 깨진 표시를 남긴다. 자리가
비어 보이는 것과 깨진 것은 다르다 — `SC-805` 가 둘 다 깨지지 않을 것을 요구한다.

## 2. 올리기 — 등록과 수정이 다르다

| 화면 | 백엔드가 받는 방식 |
|---|---|
| 등록 (2.6) | 파일을 실은 **생성** 요청 |
| 수정 (2.8) | 파일을 실은 **수정** 요청 |

**007 의 호출 통로에 수정+파일 조합이 없다.** 등록 쪽은 있는데 수정 쪽이 빠져 있다 — 007 이
그 통로를 만들며 "아이콘 업로드(009)가 쓴다"고 적었지만 등록만 보고 수정을 보지 않았다.

**그 통로를 007 에 더한다.** 009 가 자기 통로를 따로 만들지 않는다. 봉투를 푸는 자리가 둘이
되면 어느 한쪽이 응답 코드 확인을 빠뜨렸을 때 실패가 성공으로 읽힌다 —
[research 1](../research.md) 에 근거를 적었다.

### 파일을 고르지 않았으면 그 칸을 아예 싣지 않는다

| 사용자가 | 요청에 | 결과 |
|---|---|---|
| 파일을 골랐다 | 파일 칸을 싣는다 | 아이콘이 바뀐다 |
| 파일을 고르지 않았다 | **파일 칸을 뺀다** | 기존 아이콘이 그대로 남는다 (FR-809) |

**브라우저의 파일 입력은 고르지 않아도 빈 값을 함께 보낸다.** 그것을 그대로 옮기면 0바이트
파일을 올리는 요청이 되어 형식 오류로 거절되고, 사용자에게는 **"이름만 고쳤는데 아이콘이
잘못됐다고 나온다"**로 보인다.

**아이콘을 지우는 길은 없다.** 백엔드에 그 동작이 없다. 파일 칸을 비운 것이 "지우라"는 뜻이
되지 않는다.

## 3. 제약을 입력 전에 알린다

| 항목 | 값 |
|---|---|
| 형식 | `png` · `jpg` · `gif` 세 가지 |
| 크기 | 1MB 이하 |

**이 제약을 파일 칸 아래에 언제나 적는다**(FR-808). 고른 뒤에 알려 주면 사용자는 파일을
찾아 다시 골라야 한다.

**형식은 서버가 파일 내용으로 판정한다.** 확장자만 바꾼 파일은 거절된다. 화면의 파일 선택
필터는 **고르기를 돕는 장치일 뿐** 검사가 아니다 — 그 필터를 통과해도 거절될 수 있다는 것을
사용자가 알 수 있게, 거절 안내에 허용 형식과 크기를 **다시** 적는다.

| 실패 | 보이는 것 |
|---|---|
| `3102` 형식·크기 오류 | **아이콘 칸 가까이.** 허용 형식과 크기를 함께 적는다 (`SC-806`) |

## 4. 저장 전에 미리보기를 보인다

**파일을 고르면 그 자리에서 이미지를 보인다**(FR-807). 서버에 올리기 전이다.

| 누가 | 무엇을 |
|---|---|
| 브라우저 | 고른 파일을 읽어 미리보기를 그린다. **백엔드를 부르지 않는다** |
| 서버 | 아무것도 하지 않는다. 저장 요청이 올 때까지 그 파일을 모른다 |

미리보기는 **화면 조작이지 API 호출이 아니다.** 007 이 "화면 스크립트는 API 를 부르지
않는다"로 정한 선 안에 있다.

**스크립트가 막히면 미리보기만 사라진다.** 파일 선택과 저장은 그대로 동작해야 한다 —
미리보기가 없으면 올릴 수 없는 화면이 되면 안 된다.

---

## 5. 실패로 모달을 다시 그릴 때

**파일 칸은 되채울 수 없다.** 브라우저가 파일 입력에 값을 넣는 것을 허용하지 않는다 —
허용하면 사용자 몰래 파일을 올리는 길이 열리기 때문이다.

| 칸 | 다시 그릴 때 |
|---|---|
| 이름 · 사용 여부 | 사용자가 넣은 값을 되채운다 |
| 아이콘 파일 | **비어 있다.** 다시 골라야 한다는 것을 안내에 적는다 |

적지 않으면 사용자는 이름만 고쳐 다시 저장하고, 아이콘은 올라가지 않은 채로 성공한다.

## 6. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 이미지 주소가 **화면 모듈 경로**이고 백엔드 주소가 응답에 없다 | FR-814 · SC-807 |
| 아이콘이 없는 유형에 이미지 태그를 걸지 않는다 | FR-813 · SC-805 |
| 파일을 고르지 않은 수정 요청에 **파일 칸이 실리지 않는다** | FR-809 · research 3 |
| 파일을 고른 수정 요청에는 실린다 | §2 |
| 제약 문구가 파일 칸 아래에 **입력 전부터** 보인다 | FR-808 |
| `3102` 안내에 허용 형식과 크기가 적혀 있다 | SC-806 |
| 실패로 다시 그릴 때 파일 칸이 비어 있고 그 사실이 안내된다 | §5 |
