## 1. 목록 (2.1)

### 열

| 열 | 값 |
|---|---|
| 이름 | 수단 이름 |
| 구분 | 「카드」 또는 「계좌」. **영문 코드를 그대로 보이지 않는다** |
| 용도 | 「지출용」 또는 「소득용」 |
| 사용 | 「사용」 또는 「사용 안 함」 |
| 상태 | 「정상」 또는 「삭제됨」 |
| 관리 | 「상세」 · 「수정」 · 「삭제」 |

**유효기간 열을 두지 않는다.** 계좌에는 그 값이 없어 절반이 빈 칸이 되고, 빈 칸은 "유효기간을
모르는 카드"로 읽힌다. 유효기간은 상세 모달에서 보인다.

**프로토타입과 다른 점이 둘이다** — 프로토타입에는 상태 열이 없고 관리 열에 삭제 버튼이
없다. 삭제 표시 모델을 사용자가 이해하는 통로가 이 목록뿐이라 둘 다 더한다.

## 2. 칸 (2.2 등록 · 2.4 수정)

| 칸 | 필수 | 고를 수 있는 값 | 비고 |
|---|:---:|---|---|
| 이름 | ✅ | (자유 입력) | |
| 구분 | ✅ | 카드 · 계좌 | 고른 값에 따라 유효기간 칸이 접히고 펴진다 |
| 용도 | ✅ | 지출용 · 소득용 | **한 수단은 한쪽만 갖는다.** 수정에서는 참조가 없을 때만 바뀐다 |
| 사용 여부 | ✅ | 사용 · 사용 안 함 | 끄면 지출·소득 입력의 선택 목록에서 빠진다 |
| 카드 유효기간 | ❌ | `YYYY-MM` | **구분이 카드일 때만** 보이고 실린다 |

**자유 입력을 두지 않는 칸이 셋이다**(구분·용도·사용 여부). 화면이 고를 수 없는 값을 서버가
받는 일이 없어야 한다.

### 유효기간은 표시와 전송을 나눠 다룬다

| 누가 | 무엇을 |
|---|---|
| 브라우저 | 구분에 따라 칸을 **접고 편다**. 입력 중의 편의다 |
| 화면 모듈 | 구분이 계좌면 그 값을 **요청에서 뺀다**. 보장이다 |

브라우저에서만 접으면 스크립트가 막힌 환경에서 값이 그대로 나간다. 백엔드가 계좌일 때 그
값을 무시한다고 적혀 있지만 화면이 그 관대함에 기대지 않는다 — 계약이 "무시한다"에서
"거절한다"로 바뀌면 화면만 깨진다.

## 3. 용도를 바꿀 수 없는 경우 (2.4)

**화면이 미리 막지 않는다.** 참조 건수를 알 방법이 없다 — 목록 응답에 그 값이 없고, 세려면
지출·소득·고정지출을 전부 훑어야 한다.

| 상황 | 화면이 하는 일 |
|---|---|
| 용도를 바꿔 저장했는데 거절됨 (`3005`) | **용도 칸 가까이** 「사용 내역이 있어 용도를 바꿀 수 없습니다」를 보인다 |
| 다시 그릴 때 용도 칸 | **사용자가 고른 값 그대로** 둔다. 원래 값으로 되돌리지 않는다 |

되돌리면 사용자는 자기가 무엇을 바꿨는지 모른 채 저장을 반복한다. 바꾼 것이 눈에 보여야
용도를 원래대로 돌리고 이름만 저장할 수 있다.

**이름만 바꾸려던 사용자가 막히지 않아야 한다.** 용도를 건드리지 않았으면 그 값은 원래
값대로 실려 나가고 백엔드는 변경으로 보지 않는다.

## 4. 삭제 (2.1 의 「삭제」)

| 항목 | 내용 |
|---|---|
| 부르는 곳 | 목록 행의 「삭제」. 삭제 표시된 행에는 그리지 않는다 |
| 확인 | 007 의 공통 확인 다이얼로그 |
| 보내는 방법 | `POST`. 화면 모듈이 백엔드의 삭제 요청으로 옮긴다 |
| 결과 | 목록을 다시 그린다. 그 행의 상태가 「삭제됨」이 된다 |

### 확인 본문에 담을 것

1. **대상이 무엇인지** — 수단 이름.
2. **과거 내역의 수단 이름은 그대로 남는다** — 지출·소득에 등록 당시 이름이 스냅샷으로
   박혀 있어 지워도 과거 기록이 비지 않는다. 이것을 모르면 관리자는 과거 내역이 함께 사라질까
   봐 지우지 못한다.
3. **되돌릴 수 없고**, 지출·소득 입력의 선택 목록에서 빠진다.

| 실패 | 보이는 것 |
|---|---|
| `3003` 수단 없음 | 목록을 다시 그리며 안내 |
| `3004` 이미 삭제됨 | 목록을 다시 그리며 안내. 오류 화면으로 보내지 않는다 |

## 5. 시험으로 고정할 것

| 항목 | 근거 |
|---|---|
| 목록에 구분·용도가 **말로** 보인다 | §1 |
| 구분이 계좌면 유효기간이 요청에 **실리지 않는다** | FR-802 · research 10 |
| 구분이 카드면 유효기간이 실린다 | FR-802 |
| 용도를 고르지 않으면 저장되지 않는다 | FR-801 |
| `3005` 가 용도 칸 가까이 붙고 **고른 값이 그대로 남는다** | FR-803 · §3 |
| 삭제 확인 본문에 **과거 내역 이름이 남는다**가 적혀 있다 | FR-804 |
| `3004` 가 오류 화면이 아니라 목록 안내로 보인다 | FR-805 |
| 삭제 표시된 수단이 목록에 남고 수정·삭제 버튼이 없다 | FR-815 · research 6 |
