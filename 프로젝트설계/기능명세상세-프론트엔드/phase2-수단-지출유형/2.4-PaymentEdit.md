## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 수단 목록(2.1) 행의 「수정」 버튼, 상세 모달(2.3)의 「수정」 버튼, 또는 브라우저가 `?m=edit&id={식별자}` 가 붙은 주소를 직접 여는 경우 셋이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 본인 것만 조회·수정되는 것은 백엔드가 보장한다 |

**모달을 열기 전에 서버가 대상을 조회한다.** 진입 규칙은 상세(2.3)와 같다 — 없는 식별자면 모달 없이 목록만 보이고, 식별자가 없으면 모달을 열지 않는다.

**삭제 표시된 수단에는 이 모달을 열지 않는다.** 목록이 그 행에 「수정」을 그리지 않는다. 고쳐도 지출·소득 입력의 선택 목록에 돌아오지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 수단 목록(2.1)이 평소대로 뒤에 그려진다 |
| 모달 머리 | 제목 「수단 수정」과 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다 |
| 모달 폼 | 칸 다섯을 세로로 놓고 현재 값을 채운다. 유효기간은 구분이 카드일 때만 보인다 |
| 모달 바닥 | 「취소」와 「저장」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이름 | text | 필수 | 현재 이름이 채워진 채로 뜬다 |
| 구분 | select | 필수 | 현재 값이 골라진 채로 뜬다. 「카드」·「계좌」 두 값만 고를 수 있고, 고른 값에 따라 유효기간 칸이 접히고 펴진다 |
| 용도 | select | 필수 | 현재 값이 골라진 채로 뜬다. 「지출용」·「소득용」 두 값만 고를 수 있다. **그 수단을 쓴 거래가 하나라도 있으면 바꿀 수 없다** |
| 사용 여부 | select | 필수 | 현재 값이 골라진 채로 뜬다 |
| 카드 유효기간 | month | 선택 | 현재 값이 채워진 채로 뜬다. **구분이 카드일 때만** 보이고 실린다 |
| 「저장」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /payments/{식별자}` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다. 아무것도 저장하지 않는다 |
| 실패 안내 | 문구 | — | 저장이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 모달 폼 상단에 뜬다 |

**등록(2.2)과 칸이 같다.** 다른 것은 현재 값이 채워져 뜬다는 것과, 나가는 요청이 바뀐 것만 싣는다는 것이다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열리기 전 | `PaymentMethodGet` | GET | 대상 수단의 현재 값을 받아 칸을 채운다 |
| 「저장」 버튼을 눌렀을 때 | `PaymentMethodUpdate` | PATCH | 고친 값을 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 `PATCH` 로 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록 행이나 상세에서 「수정」을 누른다 | **목록을 그리기 전에** 그 수단을 조회해 칸을 채운다 | 값이 채워진 수정 폼이 목록 위에 뜬다 | 조회가 실패하면 **모달 없이 목록만** 보이고 안내를 띄운다 |
| 구분을 카드↔계좌로 바꾼다 | 유효기간 칸을 펴거나 접는다 | 칸이 나타나거나 사라진다 | (해당 없음) |
| 이름만 바꿔 「저장」을 누른다 | 용도를 건드리지 않았으므로 원래 값이 그대로 실려 나가고 백엔드가 변경으로 보지 않는다 | 목록을 다시 그린다. 바뀐 이름이 보인다 | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다 |
| **용도를 바꿔 「저장」을 누르는데 그 수단을 쓴 거래가 있다** | 저장이 거절된다 | (해당 없음) | **용도 칸 가까이** 사유를 보이고, **사용자가 고른 용도를 그대로 둔 채** 모달을 다시 그린다 |
| 구분을 계좌로 바꾸고 저장한다 | 유효기간을 **요청에서 뺀다** | 유효기간이 비워진다 | 위와 같이 모달을 연 채로 다시 그린다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 이름 | 필수. 중복 제약이 없다 |
| 구분 | 필수. 「카드」·「계좌」 두 값만 고를 수 있다 |
| **용도를 못 바꾸는 경우** | **그 수단을 참조하는 지출·소득·고정지출이 하나라도 있으면 바꿀 수 없다.** 바꾸면 과거 지출이 소득 수단을 가리키게 되기 때문이다. 사유는 「사용 내역이 있어 용도를 바꿀 수 없습니다」이며 **용도 칸 가까이** 보인다 |
| **화면이 미리 막지 못하는 이유** | **참조 건수를 알 방법이 없다** — 목록 응답에 그 값이 없고, 세려면 지출·소득·고정지출을 전부 훑어야 한다. 알 수 없는 것을 미리 막으려 하면 틀린 추측으로 막게 되고, 바꿀 수 있는 사용자가 막힌다. 그래서 선택을 열어 두고 거절당하면 사유를 보인다 |
| **실패 후 용도 칸** | **사용자가 고른 값을 그대로 둔다.** 원래 값으로 되돌리면 사용자는 자기가 무엇을 바꿨는지 모른 채 저장을 반복한다. 바꾼 것이 눈에 보여야 용도를 원래대로 돌리고 이름만 저장할 수 있다 |
| 사용 여부 | 필수. 끄면 지출·소득 입력의 선택 목록에서 빠지지만 **되돌릴 수 있다** |
| 카드 유효기간 | 선택. **구분이 카드일 때만** 보이고 실린다. 표시는 브라우저가, 전송은 화면 모듈이 보장한다 |
| 구분·용도 값 오류 | **모달 폼 상단**에 붙인다. 한 코드가 두 칸을 함께 가리켜 어느 칸인지 가릴 수 없다 |
| 유효기간 형식 오류 | **유효기간 칸** 아래에 붙인다 |
| 수단 없음·타인 소유 | 모달 없이 목록만 보이고 안내를 띄운다. 존재 여부를 가르지 않는다 |
| 실패 후 착지 | **모달을 연 채로** 목록을 다시 그린다 |
| 실패 후 입력 유지 | 사용자가 넣은 값을 그대로 되채운다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(2.1)의 템플릿 안에 있다. 별도 주소를 갖지 않는다.
- **삭제 표시된 수단은 고칠 수 없다** — 목록이 그 행에 「수정」을 그리지 않는다.
- 지출유형 수정(2.8)에도 못 바꾸는 칸이 있지만 **성격이 다르다.** 여기는 참조가 있을 때만 막히고 화면이 미리 알 수 없지만, 2.8 의 기본 유형 이름은 **언제나** 막히고 화면이 미리 안다.
