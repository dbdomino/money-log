## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 사이드바의 「지출·소득 수단」 메뉴, 또는 브라우저가 `/payments` 를 직접 여는 경우 둘이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 수단을 연다. 본인 것만 보이는 것은 백엔드가 보장한다 |

**진입 판정은 007 이 한다.** 이 화면이 세션을 다시 확인하지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `payments` 다 |
| 제목·등록 버튼 | 본문 상단에 「지출·소득 수단」과 오른쪽에 「수단 등록」 버튼을 놓는다 |
| 안내 영역 | 표 위에 실패 안내를 놓는다. 삭제 실패와 대상 조회 실패가 여기에 뜬다 |
| 목록 표 | 열 여섯(이름·구분·용도·사용·상태·관리)을 가진 표를 놓는다 |
| 모달 | 등록(2.2)·상세(2.3)·수정(2.4) 모달을 이 화면 위에 띄운다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 「수단 등록」 버튼 | 링크 버튼 | 필수 | 등록 모달을 연다(`?m=create`) |
| 이름 열 | 표 열 | 필수 | 수단 이름. 사용자가 붙인 값이다 |
| 구분 열 | 표 열 | 필수 | 「카드」 또는 「계좌」. **영문 코드를 그대로 보이지 않는다** — `CARD`·`ACCOUNT` 는 화면 밖의 값이다 |
| 용도 열 | 표 열 | 필수 | 「지출용」 또는 「소득용」. 한 수단은 한쪽만 갖는다 |
| 사용 열 | 표 열 | 필수 | 「사용」 또는 「사용 안 함」. **되돌릴 수 있는 상태**다 |
| 상태 열 | 표 열 | 필수 | 「정상」 또는 「삭제됨」. **되돌릴 수 없는 상태**다. 사용 열과 합치지 않는다 |
| 관리 열 | 표 열 | 필수 | 「상세」·「수정」·「삭제」 버튼을 놓는다. **삭제된 행에는 상세만** 놓는다 |
| 「상세」 버튼 | 링크 버튼 | 필수 | 그 수단의 상세 모달을 연다(`?m=detail&id={식별자}`) |
| 「수정」 버튼 | 링크 버튼 | 필수 | 그 수단의 수정 모달을 연다(`?m=edit&id={식별자}`). 삭제된 행에는 그리지 않는다 |
| 「삭제」 버튼 | 제출 버튼 | 필수 | 확인 다이얼로그를 거쳐 삭제 요청을 보낸다. **링크가 아니다.** 삭제된 행에는 그리지 않는다 |
| 실패 안내 | 문구 | — | 삭제나 대상 조회가 실패했을 때만 표 위에 보인다. 응답 코드와 백엔드 문구를 함께 적는다 |

**유효기간 열을 두지 않는다.** 계좌에는 그 값이 없어 절반이 빈 칸이 되고, 빈 칸은 「유효기간을 모르는 카드」로 읽힌다. 유효기간은 상세 모달(2.3)에서 보인다.

**쪽 넘기기가 없다.** 백엔드 목록이 조회 구간을 받지 않고 본인 것을 전부 돌려준다. 한 사람의 수단은 한 화면에 들어간다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때 | `PaymentMethodList` | GET | 본인 수단 전체를 받는다. **삭제 표시된 것까지 함께** 온다 |
| 확인 다이얼로그에서 삭제를 확정했을 때 | `PaymentMethodDelete` | DELETE | 그 수단을 삭제 표시한다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 사이드바에서 「지출·소득 수단」을 누른다 | 목록을 조회한다. 조회 구간을 싣지 않는다 | 행과 상태가 그려진다 | 007 의 오류 화면으로 간다 — 목록을 못 받으면 그릴 표가 없다 |
| 「수단 등록」을 누른다 | 등록 모달을 연 채로 목록을 그린다 | 빈 등록 폼이 모달로 뜬다 | (해당 없음 — 조회가 없다) |
| 「상세」를 누른다 | **목록을 그리기 전에** 그 수단을 조회해 모달에 채운다 | 값이 읽기 전용으로 보인다 | 조회가 실패하면 **모달 없이 목록만** 보이고 안내를 띄운다 |
| 「수정」을 누른다 | 위와 같이 조회해 수정 폼에 채운다 | 값이 채워진 수정 폼이 뜬다 | 위와 같다 |
| 「삭제」를 누른다 | 확인 다이얼로그를 띄운다. 본문은 이 화면이 넘긴다 | 다이얼로그가 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 다이얼로그에서 삭제를 확정한다 | 삭제 요청을 보낸다 | 목록을 다시 그린다. 그 행의 상태가 「삭제됨」이 된다 | 오류 화면으로 보내지 않고 목록을 다시 그리며 안내를 띄운다 |
| 미로그인으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 구분 표시 | 「카드」·「계좌」로 보인다. 영문 코드를 그대로 내보내지 않는다 |
| 용도 표시 | 「지출용」·「소득용」으로 보인다 |
| **사용 여부와 삭제 여부** | **서로 다른 열**에 보인다. 둘 다 「지금 고를 수 없다」로 보이지만 **사용 안 함은 되돌릴 수 있고 삭제됨은 없다.** 한 열에 합치면 사용자가 그 차이를 알 수 없다 |
| 삭제 표시된 행 | **목록에 남는다.** 감추면 「행이 남는다」는 계약이 화면에서 사라지고, 사용자는 지웠다고 믿는데 이름은 과거 내역에 계속 살아 있다 |
| 삭제된 행의 버튼 | **상세만 남기고 수정·삭제를 그리지 않는다.** 다시 삭제하면 백엔드가 거절하고, 고쳐도 지출·소득 입력의 선택 목록에 돌아오지 않는다. 누를 수 있는 버튼이 언제나 실패하는 것은 화면의 잘못이다 |
| 삭제 전송 방식 | **`POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는 것만으로 실행된다 |
| 삭제 확인 본문 | 007 의 공통 확인 다이얼로그를 쓰고 본문은 이 화면이 넘긴다. 아래 「삭제 확인 다이얼로그」 참고 |
| 수단 없음 | 목록을 다시 그리며 안내한다. 오류 화면으로 보내지 않는다 |
| 이미 삭제된 수단의 재삭제 | 목록을 다시 그리며 안내한다. 이미 원하는 상태라 사용자가 할 일이 없는데 오류 화면으로 보내면 돌아오는 걸음만 늘어난다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다. 빈 목록으로 그리지 않는다 — 빈 목록과 「가져오지 못한 목록」이 똑같이 보이면 사용자는 자기 데이터가 없어졌다고 읽는다 |


### 사용 안 함과 삭제됨

표만 보면 둘 다 「지금 고를 수 없다」로만 읽힌다. **한 열에 합치지 않는 이유**가 여기 있다.

| | 사용 안 함 | 삭제됨 |
|---|---|---|
| 되돌릴 수 있나 | **그렇다.** 수정에서 다시 「사용」으로 바꾼다 | **아니다.** 화면에 푸는 길이 없다 |
| 관리 목록에 | 보인다 | 보인다 |
| 지출·소득 입력의 선택 목록에 | 빠진다 | 빠진다 |
| 그 행의 수정·삭제 버튼 | **있다** | **없다** |

**결과가 같아 보여도 사용자가 할 수 있는 일이 다르다.** 합치면 되돌릴 수 있는 것과 없는 것을 구분하지 못해, 되돌릴 수 없는 일을 가볍게 누른다.

### 삭제 확인 다이얼로그

다이얼로그는 문구를 만들지 않고 이 화면이 넘긴다. 세 가지를 담는다.

| 담을 것 | 왜 |
|------|------|
| 대상이 무엇인지 (수단 이름) | 표의 어느 행을 눌렀는지 다이얼로그만 보고 확인할 수 있어야 한다 |
| **과거 내역의 수단 이름은 그대로 남는다** | 지출·소득에 등록 당시 이름이 스냅샷으로 박혀 있어 지워도 과거 기록이 비지 않는다. 이것을 모르면 사용자는 과거 내역이 함께 사라질까 봐 지우지 못한다 |
| **되돌릴 수 없고** 지출·소득 입력에서 고를 수 없게 된다 | 화면에서 삭제를 푸는 길이 없다 |

## 비고

- 화면 구성은 `화면기획/proto/payment-list.html` 을 옮긴다. 프로토타입과 **두 곳이 다르다** — 상태 열이 없고 관리 열에 삭제 버튼이 없다. 그대로 옮기면 **지울 방법이 없는 목록**이 된다.
- 등록(2.2)·상세(2.3)·수정(2.4)은 이 화면 위의 모달이며 별도 주소를 갖지 않는다.
- 지출유형 목록(2.5)과 같은 모양이다. 두 화면이 상태를 **같은 말로** 보여야 사용자가 한 번 배우면 다른 화면에서도 안다.
