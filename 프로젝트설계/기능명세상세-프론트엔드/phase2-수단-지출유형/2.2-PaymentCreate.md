> 화면: `PaymentCreate` · Phase 2 · 화면번호 2.2  
> 인덱스: [README.md](../README.md) · 상태: **완료**

| 항목 | 내용 |

## 목적

- 카드나 계좌를 새 수단으로 등록한다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 수단 목록(2.1)의 「수단 등록」 버튼, 또는 브라우저가 `?m=create` 가 붙은 주소를 직접 여는 경우 둘이다. 어느 쪽이든 **부모 목록이 함께 그려지고 그 위에 모달이 열린다** |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 |

**모달을 여는 판정은 서버가 한다.** 007 의 모달 판정이 주소의 값을 보고 이 화면이 아는 값일 때만 모달을 연 상태로 그린다. 모르는 값이면 모달 없이 목록만 보인다.

**이 모달은 백엔드를 미리 부르지 않는다.** 새로 만드는 화면이라 가져올 값이 없다. 상세(2.3)·수정(2.4)과 다른 점이다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 수단 목록(2.1)이 평소대로 뒤에 그려진다. 모달을 닫으면 그대로 목록이 남는다 |
| 모달 머리 | 제목 「수단 등록」과 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 모달 폼 | 칸 다섯을 세로로 놓는다. 유효기간은 구분이 카드일 때만 보인다 |
| 모달 바닥 | 「취소」와 「등록」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이름 | text | 필수 | 수단 이름. 예: 국민카드, 월급통장. 중복 제약이 없어 같은 이름을 여러 개 만들 수 있다 |
| 구분 | select | 필수 | **「카드」와 「계좌」 두 값만** 고를 수 있다. 자유 입력을 두지 않는다 — 그 밖의 값은 서버가 거절하는데 사용자에게는 자기가 고른 것이 거절된 것으로 보인다. 고른 값에 따라 유효기간 칸이 접히고 펴진다 |
| 용도 | select | 필수 | **「지출용」과 「소득용」 두 값만** 고를 수 있다. **한 수단은 한쪽만 갖는다** — 지출용 수단은 소득 등록에서 고를 수 없다 |
| 사용 여부 | select | 필수 | 「사용」과 「사용 안 함」 두 값. 「사용 안 함」이면 등록은 되지만 지출·소득 입력의 선택 목록에서 빠진다 |
| 카드 유효기간 | month | 선택 | `YYYY-MM` 형식. **구분이 카드일 때만 보이고 실린다.** 계좌면 화면 모듈이 요청에서 뺀다 |
| 「등록」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /payments` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다. 아무것도 저장하지 않는다 |
| 실패 안내 | 문구 | — | 등록이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 모달 폼 상단에 뜬다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「등록」 버튼을 눌렀을 때 | `PaymentMethodCreate` | POST | 칸 다섯을 보내 수단을 만든다. 세션의 인증을 실어 보낸다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록에서 「수단 등록」을 누른다 | 주소에 모달 값을 실어 목록을 다시 열고, 모달 판정이 등록 모달을 연 상태로 그린다 | 빈 등록 폼이 목록 위에 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 구분을 **카드**로 고른다 | 유효기간 칸을 **펼친다** | 유효기간을 넣을 수 있다 | (해당 없음) |
| 구분을 **계좌**로 고른다 | 유효기간 칸을 **접는다** | 칸이 사라진다 | (해당 없음) |
| 용도를 고르지 않고 「등록」을 누른다 | 필수 칸이라 제출되지 않는다. 브라우저가 막지 못한 경우 백엔드가 형식 오류로 거절한다 | (해당 없음) | 그 칸을 채우라는 안내가 뜬다 |
| 칸을 채우고 「등록」을 누른다 | 구분이 계좌면 **유효기간을 요청에서 뺀 뒤** 생성을 부른다 | 목록을 다시 그린다. 만든 수단이 목록에 보인다 | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다. 사용자가 넣은 값을 되채운다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 이름 | 필수. 중복 제약이 없다 |
| 구분 | 필수. 「카드」·「계좌」 두 값만 고를 수 있다 |
| 용도 | 필수. 「지출용」·「소득용」 두 값만 고를 수 있다. **등록 뒤에는 그 수단을 쓴 거래가 생기는 순간 바꿀 수 없다**(2.4 참고) |
| 사용 여부 | 필수 |
| 카드 유효기간 | 선택. `YYYY-MM` 형식이며 **구분이 카드일 때만** 보이고 실린다 |
| **유효기간의 표시와 전송** | **표시는 브라우저가, 전송은 서버가 보장한다.** 브라우저가 구분에 따라 칸을 접고 펴되, 구분이 계좌면 화면 모듈이 그 값을 요청에서 뺀다. 브라우저에서만 접으면 스크립트가 막힌 환경에서 값이 그대로 나간다 |
| 구분·용도 값 오류 | **모달 폼 상단**에 붙인다. 한 코드가 구분과 용도 두 칸을 함께 가리켜 **어느 칸인지 가릴 수 없다** — 짐작해 아무 칸에나 붙이면 사용자가 맞는 칸을 고치고 또 틀린다 |
| 유효기간 형식 오류 | **유효기간 칸** 아래에 붙인다 |
| 필수 누락 | 모달 폼 상단에 붙인다 |
| 실패 후 착지 | **부모 목록으로 튕기지 않고 모달을 연 채로** 목록을 다시 그린다. 모달을 닫아 버리면 사용자가 채운 칸이 전부 사라진다 |
| 실패 후 입력 유지 | 사용자가 넣은 값을 그대로 되채운다 |
| 백엔드 불통 | 모달로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(2.1)의 템플릿 안에 있다. 별도 주소를 갖지 않는다.
- 수정(2.4)과 칸이 같다. 다른 것은 **나가는 요청의 모양**이며, 등록은 전체를 싣고 수정은 바뀐 것만 싣는다.
