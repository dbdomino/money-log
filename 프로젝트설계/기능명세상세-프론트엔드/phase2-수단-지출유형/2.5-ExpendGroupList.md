## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 사이드바의 「지출유형」 메뉴, 또는 브라우저가 `/expend-groups` 를 직접 여는 경우 둘이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 유형을 연다 |

**가입할 때 만들어진 기본 유형이 이미 들어 있다.** 빈 목록으로 시작하지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `expend-groups` 다 |
| 제목·등록 버튼 | 본문 상단에 「지출유형」과 오른쪽에 「유형 등록」 버튼을 놓는다 |
| 안내 영역 | 표 위에 실패 안내를 놓는다. 삭제 실패와 대상 조회 실패가 여기에 뜬다 |
| 목록 표 | 열 여섯(아이콘·이름·구분·사용·상태·관리)을 가진 표를 놓는다 |
| 모달 | 등록(2.6)·상세(2.7)·수정(2.8) 모달을 이 화면 위에 띄운다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 「유형 등록」 버튼 | 링크 버튼 | 필수 | 등록 모달을 연다(`?m=create`) |
| 아이콘 열 | 표 열 | 필수 | 유형의 아이콘 이미지. **화면 모듈 주소로 건다** — 백엔드 주소를 직접 걸면 인증이 붙지 않아 전부 실패한다. **아이콘이 없으면 이미지를 걸지 않고** 대체 표시를 그린다 |
| 이름 열 | 표 열 | 필수 | 유형 이름 |
| 구분 열 | 표 열 | 필수 | 「기본」 또는 「직접 만듦」. **이 열이 화면 동작의 근거다** — 기본 유형만 이름을 못 바꾸고 못 지우므로, 왜 그 행만 버튼이 다른지 사용자가 이 열을 보고 안다 |
| 사용 열 | 표 열 | 필수 | 「사용」 또는 「사용 안 함」. **되돌릴 수 있는 상태**다 |
| 상태 열 | 표 열 | 필수 | 「정상」 또는 「삭제됨」. **되돌릴 수 없는 상태**다. 사용 열과 합치지 않는다 |
| 관리 열 | 표 열 | 필수 | 「상세」·「수정」·「삭제」 버튼을 놓는다. **삭제된 행에는 상세만**, **기본 유형에는 삭제를 빼고** 놓는다 |
| 「상세」 버튼 | 링크 버튼 | 필수 | 그 유형의 상세 모달을 연다(`?m=detail&id={식별자}`) |
| 「수정」 버튼 | 링크 버튼 | 필수 | 그 유형의 수정 모달을 연다(`?m=edit&id={식별자}`). 삭제된 행에는 그리지 않는다 |
| 「삭제」 버튼 | 제출 버튼 | 필수 | 확인 다이얼로그를 거쳐 삭제 요청을 보낸다. **링크가 아니다.** 삭제된 행과 **기본 유형**에는 그리지 않는다 |
| 대체 표시 | 문구·도형 | — | 아이콘이 없는 유형의 아이콘 열에 보인다. 이미지 자리가 깨지지 않게 한다 |
| 실패 안내 | 문구 | — | 삭제나 대상 조회가 실패했을 때만 표 위에 보인다 |

**삭제 표시된 유형에도 아이콘이 계속 보인다.** 행이 남으므로 아이콘도 남는다.

**쪽 넘기기가 없다.** 백엔드 목록이 조회 구간을 받지 않고 본인 것을 전부 돌려준다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때 | `ExpendGroupList` | GET | 기본·직접 만든 유형 전체를 받는다. **삭제 표시된 것까지 함께** 온다 |
| 아이콘을 그릴 때 | `ExpendGroupIconGet` | GET | 이미지 바이너리를 받는다. **화면이 직접 부르지 않는다** — 007 의 중계가 세션의 인증을 실어 대신 부른다 |
| 확인 다이얼로그에서 삭제를 확정했을 때 | `ExpendGroupDelete` | DELETE | 그 유형을 삭제 표시한다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 사이드바에서 「지출유형」을 누른다 | 목록을 조회하고 **아이콘 주소에서 파일명만 꺼내** 화면 모듈 경로로 바꾼다 | 아이콘과 함께 행이 그려진다 | 007 의 오류 화면으로 간다 |
| 아이콘이 없는 유형이 섞여 있다 | 그 행에는 **이미지를 걸지 않고** 대체 표시를 그린다 | 자리가 깨지지 않는다 | (해당 없음) |
| 「유형 등록」을 누른다 | 등록 모달을 연 채로 목록을 그린다 | 빈 등록 폼이 모달로 뜬다 | (해당 없음) |
| 「상세」·「수정」을 누른다 | **목록을 그리기 전에** 그 유형을 조회해 모달에 채운다 | 값이 채워진 모달이 뜬다 | 조회가 실패하면 **모달 없이 목록만** 보이고 안내를 띄운다 |
| 기본 유형의 「수정」을 누른다 | 이름 칸을 **잠근 채로** 모달을 연다 | 이름을 고칠 수 없는 폼이 뜬다 | (해당 없음) |
| 「삭제」를 누른다 | 확인 다이얼로그를 띄운다 | 다이얼로그가 뜬다 | (해당 없음) |
| 다이얼로그에서 삭제를 확정한다 | 삭제 요청을 보낸다 | 목록을 다시 그린다. 그 행의 상태가 「삭제됨」이 된다 | 오류 화면으로 보내지 않고 목록을 다시 그리며 안내를 띄운다 |
| 미로그인으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **사용 여부와 삭제 여부** | **서로 다른 열**에 보인다. 사용 안 함은 되돌릴 수 있고 삭제됨은 없다. 한 열에 합치면 사용자가 그 차이를 알 수 없다 |
| 삭제 표시된 행 | **목록에 남고 아이콘도 계속 보인다.** 감추면 「행이 남는다」는 계약이 화면에서 사라지고, 같은 이름으로 새로 만들려 할 때 중복이라고 거절되는 이유를 알 수 없다 |
| 삭제된 행의 버튼 | **상세만 남긴다.** 다시 삭제하면 백엔드가 거절한다 |
| 기본 유형 | **삭제 버튼을 그리지 않고 이름 칸을 잠근다.** 목록 응답이 기본 유형인지 알려 주므로, 고칠 수 없는 것을 열어 두고 저장에서 실패시킬 이유가 없다. **그래도 백엔드 실패를 함께 다룬다** — 주소를 직접 쳐서 올 수 있고, 화면이 막는 것과 서버가 막는 것은 서로를 대신하지 않는다 |
| 기본 유형의 사용 여부 | **바꿀 수 있다.** 막힌 것은 이름과 삭제 둘뿐이다 |
| 아이콘 주소 | **화면 모듈 경로로 건다.** 백엔드가 준 주소에서 파일명만 꺼내 쓴다 — 백엔드 주소를 그대로 걸면 인증이 붙지 않아 전부 실패하고, 그 실패는 이미지 깨짐으로만 보여 원인을 짐작하기 어렵다 |
| 아이콘 없음 | **이미지를 걸지 않는다.** 빈 주소를 건 이미지는 브라우저가 현재 페이지를 다시 받아 와 깨진 표시를 남긴다 |
| 삭제 전송 방식 | **`POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는 것만으로 실행된다 |
| 사용 중인 유형의 삭제 | 목록을 다시 그리며 안내하고 **「사용 안 함으로 돌리라」는 대안을 함께 제시한다** — 과거 지출이 그 유형을 가리켜야 하므로 지울 수 없지만, 앞으로 쓰지 않게 할 수는 있다. 대안을 적지 않으면 사용자는 막혔다고만 읽는다 |
| 기본 유형의 삭제 시도 | 목록을 다시 그리며 안내한다. 화면이 버튼을 그리지 않으므로 주소로 직접 온 경우다 |
| 이미 삭제된 유형의 재삭제 | 목록을 다시 그리며 안내한다 |
| 유형 없음 | 목록을 다시 그리며 안내한다. **없는 것과 남의 것을 가르지 않는다** |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |


### 사용 안 함과 삭제됨

표만 보면 둘 다 「지금 고를 수 없다」로만 읽힌다. **한 열에 합치지 않는 이유**가 여기 있다.

| | 사용 안 함 | 삭제됨 |
|---|---|---|
| 되돌릴 수 있나 | **그렇다.** 수정에서 다시 「사용」으로 바꾼다 | **아니다.** 화면에 푸는 길이 없다 |
| 관리 목록에 | 보인다 | 보인다 |
| 지출·소득 입력의 선택 목록에 | 빠진다 | 빠진다 |
| 그 행의 수정·삭제 버튼 | **있다** | **없다** |

**결과가 같아 보여도 사용자가 할 수 있는 일이 다르다.** 합치면 되돌릴 수 있는 것과 없는 것을 구분하지 못해, 되돌릴 수 없는 일을 가볍게 누른다.

### 삭제 확인 다이얼로그

007 의 공통 확인 다이얼로그를 쓰고 본문은 이 화면이 넘긴다. 세 가지를 담는다.

| 담을 것 | 왜 |
|------|------|
| 대상이 무엇인지 (유형 이름) | 어느 행을 눌렀는지 다이얼로그만 보고 확인할 수 있어야 한다 |
| **삭제해도 그 이름은 계속 점유된다** | 같은 이름으로 다시 만들 수 없다. 수단(2.1)의 본문과 다른 점이며, 지출유형에서 사용자가 가장 자주 부딪히는 사실이다 |
| **되돌릴 수 없고** 지출 입력에서 고를 수 없게 된다 | 화면에서 삭제를 푸는 길이 없다 |

## 비고

- 화면 구성은 `화면기획/proto/expend-group-list.html` 을 옮긴다. 프로토타입과 **두 곳이 다르다** — 상태 열이 없고 관리 열에 삭제 버튼이 없다.
- 등록(2.6)·상세(2.7)·수정(2.8)은 이 화면 위의 모달이며 별도 주소를 갖지 않는다.
- 수단 목록(2.1)과 같은 모양이다. 두 화면이 상태를 **같은 말로** 보여야 한다.
