## 목적

- 지출유형의 이름·사용 여부를 고치고, 원하면 아이콘을 바꾼다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 지출유형 목록(2.5) 행의 「수정」 버튼, 상세 모달(2.7)의 「수정」 버튼, 또는 브라우저가 `?m=edit&id={식별자}` 가 붙은 주소를 직접 여는 경우 셋이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 본인 것만 조회·수정되는 것은 백엔드가 보장한다 |

**모달을 열기 전에 서버가 대상을 조회한다.** 진입 규칙은 상세(2.7)와 같다.

**기본 유형이면 이름 칸을 잠근 채로 연다.** 목록 응답이 기본 유형인지 알려 주므로, 고칠 수 없는 칸을 열어 두고 저장에서 실패시킬 이유가 없다.

**삭제 표시된 유형에는 이 모달을 열지 않는다.** 목록이 그 행에 「수정」을 그리지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 지출유형 목록(2.5)이 평소대로 뒤에 그려진다 |
| 모달 머리 | 제목 「지출유형 수정」과 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다 |
| 모달 폼 | 칸 셋(이름·사용 여부·아이콘 파일)을 세로로 놓고 현재 값을 채운다 |
| 현재 아이콘 | 아이콘 칸 위에 지금 붙어 있는 아이콘을 보인다. 없으면 대체 표시를 그린다 |
| 미리보기 | 새 파일을 고르면 그 이미지를 보인다 |
| 모달 바닥 | 「취소」와 「저장」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이름 | text | 필수 | 현재 이름이 채워진 채로 뜬다. **기본 유형이면 읽기 전용으로 잠긴다** |
| 사용 여부 | select | 필수 | 현재 값이 골라진 채로 뜬다. **기본 유형도 이 칸은 바꿀 수 있다** |
| 현재 아이콘 | 이미지 | — | 지금 붙어 있는 아이콘. **화면 모듈 주소로 건다.** 없으면 대체 표시 |
| 아이콘 파일 | file | 선택 | **비우면 기존 아이콘을 그대로 둔다.** 고르면 교체된다 |
| 「변경할 때만 고르세요」 안내 | 문구 | 필수 | 아이콘 칸 아래에 언제나 보인다. 비어 있는 것이 정상 상태라는 것을 사용자가 알아야 한다 |
| 아이콘 제약 문구 | 문구 | 필수 | 아이콘 칸 아래에 **입력 전부터** 보인다. 「png·jpg·gif 형식, 1MB 이하」 |
| 미리보기 | 이미지 | — | 새 파일을 고르면 **저장 전에** 보인다. 브라우저가 그리며 백엔드를 부르지 않는다 |
| 「저장」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /expend-groups/{식별자}` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다 |
| 실패 안내 | 문구 | — | 저장이 실패했을 때만 보인다 |

**아이콘을 지우는 자리를 두지 않는다.** 백엔드에 그 동작이 없다 — 두면 누를 수 없는 버튼이 된다. **파일 칸을 비운 것이 「아이콘을 지우라」는 뜻이 되지 않는다.**

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열리기 전 | `ExpendGroupGet` | GET | 대상 유형의 현재 값과 아이콘 주소를 받아 칸을 채운다 |
| 현재 아이콘을 그릴 때 | `ExpendGroupIconGet` | GET | 이미지 바이너리를 받는다. 007 의 중계가 대신 부른다 |
| 「저장」 버튼을 눌렀을 때 | `ExpendGroupUpdate` | PATCH | 고친 값을 보낸다. **파일을 실은 수정 요청**이며, 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록 행이나 상세에서 「수정」을 누른다 | **목록을 그리기 전에** 그 유형을 조회해 칸을 채운다. 기본 유형이면 이름 칸을 잠근다 | 값이 채워진 수정 폼이 뜬다 | 조회가 실패하면 **모달 없이 목록만** 보이고 안내를 띄운다 |
| **이름만 바꾸고 파일은 고르지 않은 채 저장한다** | **파일 칸을 요청에서 빼고** 보낸다 | 이름이 바뀌고 **기존 아이콘이 그대로 남는다** | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다 |
| 새 파일을 고르고 저장한다 | 파일 칸을 실어 보낸다 | 아이콘이 교체된다 | 위와 같이 모달을 연 채로 다시 그린다 |
| 기본 유형의 이름을 바꾸려 한다 | 이름 칸이 잠겨 있어 바꿀 수 없다. 주소로 직접 와 보낸 경우 백엔드가 거절한다 | (해당 없음) | **이름 칸 가까이** 사유를 보인다 |
| 기본 유형의 사용 여부를 바꿔 저장한다 | 사용 여부만 실어 보낸다 | 바뀐다. **이 칸은 기본 유형도 바꿀 수 있다** | 모달을 연 채로 다시 그린다 |
| 이미 쓰이는 이름으로 저장한다 | 백엔드가 거절한다 | (해당 없음) | **이름 칸 가까이** 안내하며 **삭제된 이름도 센다**는 것을 함께 적는다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **빈 칸의 뜻 — 아이콘 파일** | 비우면 **바꾸지 않는다.** 요청에 아예 싣지 않는다. **브라우저의 파일 입력은 고르지 않아도 빈 값을 함께 보내므로**, 그것을 그대로 옮기면 0바이트 파일을 올리는 요청이 되어 형식 오류로 거절된다 — 사용자에게는 「이름만 고쳤는데 아이콘이 잘못됐다고 나온다」로 보인다 |
| 빈 칸의 뜻 — 이름·사용 여부 | 필수라 비울 수 없다. 언제나 요청에 실린다 |
| **기본 유형의 이름** | **언제나 바꿀 수 없다.** 화면이 칸을 잠가 미리 막고, 주소로 직접 온 경우에는 서버가 거절한다. **화면이 막는 것과 서버가 막는 것은 서로를 대신하지 않는다** |
| **화면이 미리 막을 수 있는 이유** | 목록 응답이 **기본 유형인지 알려 주기 때문**이다. 알 수 있는 제약을 열어 두고 저장에서 실패시킬 이유가 없다. 수단의 용도(2.4)와 다른 점이며, 그쪽은 참조 건수를 알 방법이 없어 미리 막지 못한다 |
| 기본 유형의 사용 여부 | **바꿀 수 있다.** 막힌 것은 이름과 삭제 둘뿐이다 |
| **이름 중복의 범위** | **삭제 표시된 유형의 이름도 겹침으로 센다.** 안내에 이 사실을 함께 적고 **이름 칸 가까이** 붙인다 |
| 아이콘 파일 | 선택. **`png`·`jpg`·`gif` 세 형식, 1MB 이하.** 제약을 **입력 전부터** 적고 거절당하면 다시 적는다 |
| 형식 판정 주체 | **서버가 파일 내용으로 판정한다.** 확장자만 바꾼 파일은 거절된다 |
| 아이콘 형식·크기 오류 | **아이콘 칸 가까이** 붙이고 허용 형식과 크기를 함께 적는다 |
| 유형 없음·타인 소유 | 모달 없이 목록만 보이고 안내를 띄운다. 존재 여부를 가르지 않는다 |
| 미리보기 | 새 파일을 고르면 저장 전에 보인다. **스크립트가 막히면 미리보기만 사라지고 선택과 저장은 그대로 동작해야 한다** |
| 실패 후 착지 | **모달을 연 채로** 목록을 다시 그린다 |
| **실패 후 파일 칸** | **비어 있다.** 브라우저가 파일 입력에 값을 넣는 것을 허용하지 않기 때문이다. **다시 골라야 한다는 것을 안내에 적는다** — 적지 않으면 사용자는 이름만 고쳐 다시 저장하고 아이콘은 올라가지 않은 채로 성공한다 |
| 실패 후 나머지 입력 | 이름과 사용 여부는 사용자가 넣은 값을 되채운다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(2.5)의 템플릿 안에 있다. 별도 주소를 갖지 않는다.
- **삭제 표시된 유형은 고칠 수 없다** — 목록이 그 행에 「수정」을 그리지 않는다.
- 등록(2.6)과 칸이 같다. 다른 것은 **빈 파일 칸의 뜻**이며, 여기서는 「기존 아이콘을 그대로 둔다」이다.
- 수단 수정(2.4)에도 못 바꾸는 칸이 있지만 **성격이 다르다.** 여기는 기본 유형의 이름이 **언제나** 막히고 화면이 미리 알지만, 2.4 의 용도는 참조가 있을 때만 막히고 화면이 알 수 없다.
