## 목적

- 지출유형을 새로 만들고 아이콘을 붙인다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 지출유형 목록(2.5)의 「유형 등록」 버튼, 또는 브라우저가 `?m=create` 가 붙은 주소를 직접 여는 경우 둘이다. 어느 쪽이든 **부모 목록이 함께 그려지고 그 위에 모달이 열린다** |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 |

**이 모달은 백엔드를 미리 부르지 않는다.** 새로 만드는 화면이라 가져올 값이 없다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 지출유형 목록(2.5)이 평소대로 뒤에 그려진다 |
| 모달 머리 | 제목 「지출유형 등록」과 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다 |
| 모달 폼 | 칸 셋(이름·사용 여부·아이콘 파일)을 세로로 놓는다 |
| 미리보기 | 아이콘 칸 아래에 고른 파일의 이미지를 보인다. 파일을 고르기 전에는 비어 있다 |
| 모달 바닥 | 「취소」와 「등록」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이름 | text | 필수 | 유형 이름. **같은 회원 안에서 겹칠 수 없고, 삭제 표시된 유형의 이름도 겹침으로 센다** |
| 사용 여부 | select | 필수 | 「사용」과 「사용 안 함」 두 값. 자유 입력을 두지 않는다. 「사용 안 함」이면 등록은 되지만 지출 입력의 선택 목록에서 빠진다 |
| 아이콘 파일 | file | 선택 | 유형을 나타낼 이미지. **고르지 않으면 아이콘 없는 유형이 된다** |
| 아이콘 제약 문구 | 문구 | 필수 | 아이콘 칸 아래에 **입력 전부터** 보인다. 「png·jpg·gif 형식, 1MB 이하」. 고른 뒤에 알려 주면 사용자는 파일을 찾아 다시 골라야 한다 |
| 미리보기 | 이미지 | — | 파일을 고르면 **저장 전에** 그 자리에서 보인다. 브라우저가 고른 파일을 읽어 그리며 **백엔드를 부르지 않는다** |
| 「등록」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /expend-groups` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다 |
| 실패 안내 | 문구 | — | 등록이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 모달 폼 상단에 뜬다 |

**아이콘을 지우는 자리를 두지 않는다.** 백엔드에 그 동작이 없다 — 두면 누를 수 없는 버튼이 된다.

**수단 등록(2.2)보다 칸이 적다.** 구분·용도에 해당하는 것이 없으며, 기본 유형인지는 서버가 정하고 사용자가 고르지 않는다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「등록」 버튼을 눌렀을 때 | `ExpendGroupCreate` | POST | 이름·사용 여부·아이콘 파일을 함께 보내 유형을 만든다. 파일을 싣는 요청이다 |

**미리보기는 API 를 부르지 않는다.** 브라우저가 고른 파일을 읽어 그리는 화면 조작이며, 서버는 저장 요청이 올 때까지 그 파일을 모른다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록에서 「유형 등록」을 누른다 | 등록 모달을 연 상태로 목록을 그린다 | 빈 등록 폼과 아이콘 제약 문구가 함께 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 아이콘 파일을 고른다 | 브라우저가 그 파일을 읽어 **미리보기를 그린다** | 저장 전에 이미지가 보인다 | 스크립트가 막힌 환경에서는 **미리보기만 사라지고** 선택과 저장은 그대로 동작한다 |
| 이름·사용 여부를 채우고 「등록」을 누른다 | 파일을 고르지 않았으면 **그 칸을 빼고** 보낸다 | 목록을 다시 그린다. 만든 유형이 보인다 | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다 |
| 1MB 를 넘거나 허용되지 않는 형식의 파일로 저장한다 | 백엔드가 **파일 내용으로 판정해** 거절한다 | (해당 없음) | **아이콘 칸 가까이** 허용 형식과 크기를 다시 알린다 |
| 이미 쓰이는 이름으로 저장한다 | 백엔드가 거절한다 | (해당 없음) | **이름 칸 가까이** 안내하며 **삭제된 유형의 이름도 센다**는 것을 함께 적는다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 이름 | 필수. 같은 회원 안에서 겹칠 수 없다 |
| **이름 중복의 범위** | **삭제 표시된 유형의 이름도 겹침으로 센다.** 안내에 이 사실을 함께 적는다 — 적지 않으면 사용자는 삭제한 것과 겹칠 리 없다고 생각해 화면이 잘못됐다고 읽는다. 안내는 **이름 칸 가까이** 붙인다 |
| 사용 여부 | 필수. 「사용」·「사용 안 함」 두 값만 고를 수 있다 |
| 아이콘 파일 | 선택. **`png`·`jpg`·`gif` 세 형식, 1MB 이하** |
| **아이콘 제약을 알리는 시점** | **입력 전부터** 칸 아래에 적고, 거절당하면 **다시** 적는다. 고른 뒤에만 알려 주면 사용자는 파일을 찾아 다시 골라야 하고, 거절 안내에 제약이 없으면 무엇이 허용되는지 모른 채 다른 파일을 시도한다 |
| **형식 판정 주체** | **서버가 파일 내용으로 판정한다.** 확장자만 바꾼 파일은 거절된다. 화면의 파일 선택 필터는 **고르기를 돕는 장치일 뿐 검사가 아니다** — 그 필터를 통과해도 거절될 수 있다 |
| 아이콘 형식·크기 오류 | **아이콘 칸 가까이** 붙이고 허용 형식과 크기를 함께 적는다 |
| 필수 누락 | 모달 폼 상단에 붙인다 |
| 미리보기 | 파일을 고르면 **저장 전에** 보인다. 브라우저가 그리며 API 를 부르지 않는다. **스크립트가 막히면 미리보기만 사라지고 선택과 저장은 그대로 동작해야 한다** — 미리보기가 없으면 올릴 수 없는 화면이 되면 안 된다 |
| 실패 후 착지 | **모달을 연 채로** 목록을 다시 그린다 |
| **실패 후 파일 칸** | **비어 있다.** 브라우저가 파일 입력에 값을 넣는 것을 허용하지 않기 때문이다 — 허용하면 사용자 몰래 파일을 올리는 길이 열린다. **다시 골라야 한다는 것을 안내에 적는다** — 적지 않으면 사용자는 이름만 고쳐 다시 저장하고 아이콘은 올라가지 않은 채로 성공한다 |
| 실패 후 나머지 입력 | 이름과 사용 여부는 사용자가 넣은 값을 되채운다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(2.5)의 템플릿 안에 있다. 별도 주소를 갖지 않는다.
- 수정(2.8)과 칸이 같다. 다른 것은 **빈 파일 칸의 뜻**이며, 등록에서는 「아이콘 없는 유형」이고 수정에서는 「기존 아이콘을 그대로 둔다」이다.
