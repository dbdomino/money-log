## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 회원 목록(1.8) 행의 「수정」 버튼, 또는 브라우저가 `?m=edit&id={아이디}` 가 붙은 주소를 직접 여는 경우 둘이다. 어느 쪽이든 **부모 목록이 함께 그려지고 그 위에 모달이 열린다** |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | **막는다.** 일반 권한(`3`)으로 들어오면 진입 판정이 권한 없음 화면(`/error/forbidden`, 1.6)으로 보낸다 |

**모달을 열기 전에 서버가 대상 회원을 조회한다.** 모달을 여는 일만 브라우저가 하면 열린 모달이 빈 채로 뜨고, 값을 채우려면 브라우저가 다시 요청해야 한다.

| 주소의 상태 | 이 화면이 하는 일 |
|------|------|
| `?m=edit&id={있는 아이디}` | 그 회원을 조회해 모달에 값을 채우고 목록 위에 연다 |
| `?m=edit&id={없는 아이디}` | **오류 화면이 아니라** 모달 없이 목록만 보이고 안내를 띄운다. 낡은 북마크일 뿐이고 목록은 정상이다 |
| 식별자 없이 `?m=edit` | 모달을 열지 않고 목록만 보인다. 누구를 고칠지 모르는 상태다 |

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 회원 목록(1.8)이 평소대로 뒤에 그려진다. 모달을 닫으면 그대로 목록이 남는다 |
| 모달 머리 | 제목 「회원 수정」과 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 모달 폼 | 아이디(읽기 전용)·닉네임·권한·이메일·폰·소개·새 비밀번호를 세로로 놓는다 |
| 모달 바닥 | 「취소」와 「저장」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text (읽기 전용) | — | 수정 대상의 로그인 아이디. **고칠 수 없다.** 백엔드 수정 API 에 아이디를 바꾸는 칸 자체가 없다 |
| 닉네임 | text | 필수 | 현재 닉네임이 채워진 채로 뜬다. 필수라 비울 수 없고, 저장 요청에 언제나 실린다 |
| 권한 | select | 필수 | **「관리자」와 「일반」 두 값만** 고를 수 있고 현재 값이 골라진 채로 뜬다. 자유 입력을 두지 않는다 |
| 이메일 | email | 선택 | 현재 이메일이 채워진 채로 뜬다. 없으면 빈 칸이다. **비우고 저장하면 값이 지워진다** |
| 폰 | tel | 선택 | 현재 폰이 숫자만으로 채워진 채로 뜬다. 하이픈을 넣어도 화면 모듈이 숫자만 남겨 보낸다. **비우고 저장하면 값이 지워진다** |
| 소개 | textarea | 선택 | 현재 소개가 채워진 채로 뜬다. **비우고 저장하면 값이 지워진다** |
| 새 비밀번호 | password | 선택 | **언제나 빈 칸으로 뜬다.** 현재 비밀번호를 채워 보여 주지 않는다. **비우고 저장하면 비밀번호를 바꾸지 않는다** — 다른 칸과 빈 칸의 뜻이 반대다 |
| 「변경할 때만 입력」 안내 | 문구 | 필수 | 새 비밀번호 칸 아래에 언제나 보인다. 비어 있는 것이 정상 상태라는 것을 관리자가 알아야 한다 |
| 비밀번호 규칙 문구 | 문구 | 필수 | 새 비밀번호 칸 아래에 보인다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| 「저장」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /admin/members/{아이디}` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다. 아무것도 저장하지 않는다 |
| 실패 안내 | 문구 | — | 저장이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 모달 폼 상단에 뜬다 |

**정지 상태를 이 모달에서 바꾸지 않는다.** 정지는 목록 행의 「정지」가 확인 다이얼로그를 거쳐 별도 API 로 한다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열리기 전 | `AdminMemberGet` | GET | 대상 회원의 현재 닉네임·권한·이메일·폰·소개를 받아 칸을 채운다 |
| 「저장」 버튼을 눌렀을 때 | `AdminMemberUpdate` | PATCH | 고친 값을 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 `PATCH` 로 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록 행의 「수정」을 누른다 | 주소에 `?m=edit&id={아이디}` 를 실어 목록을 다시 열고, **목록을 그리기 전에** `AdminMemberGet` 으로 그 회원을 조회한다 | 값이 채워진 수정 폼이 목록 위에 뜬다 | 조회가 `2001` 이면 **모달 없이 목록만** 보이고 안내를 띄운다 |
| 닉네임만 바꾸고 「저장」을 누른다 | 새 비밀번호가 비어 있으므로 **요청에 비밀번호를 싣지 않고** 나머지를 보낸다 | 목록을 다시 그린다. 바뀐 닉네임이 목록에 보인다 | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다. 새 비밀번호 칸만 비우고 나머지는 채운다 |
| 이메일을 지우고 「저장」을 누른다 | 이메일이 비었으므로 **요청에 비우라는 값(`null`)을 실어** 보낸다 | 이메일이 지워진다. 목록의 이메일 칸이 빈 칸이 된다 | 위와 같이 모달을 연 채로 다시 그린다 |
| 권한을 바꾸고 「저장」을 누른다 | 고른 권한 값을 실어 보낸다 | 목록의 권한 열이 바뀐다 | 위와 같이 모달을 연 채로 다시 그린다 |
| 주소에 없는 식별자를 친다 | 조회가 `2001` 로 실패한다 | (해당 없음) | 오류 화면이 아니라 목록이 정상으로 뜨고 안내가 보인다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |
| 일반 권한으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 권한 없음 화면(`/error/forbidden`)으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **빈 칸의 뜻 — 새 비밀번호** | 비우면 **바꾸지 않는다.** 요청에 아예 싣지 않는다. 이 칸만 현재 값이 채워지지 않은 채 뜨므로 비어 있는 것이 기본 상태이고, "비웠다"가 아니라 "건드리지 않았다"로 읽는 것이 맞다 |
| **빈 칸의 뜻 — 이메일·폰·소개** | 비우면 **지운다.** 요청에 비우라는 값(`null`)을 실어 보낸다. 세 칸은 현재 값이 채워진 채로 뜨므로 관리자가 지웠다면 지우려는 뜻이다. 이것을 "유지"로 읽으면 지웠는데 그대로 남아 있는 화면이 된다 |
| 닉네임 | 필수라 비울 수 없다. 언제나 요청에 실린다 |
| 아이디 | 고칠 수 없다. 읽기 전용으로 보이며 주소의 식별자로만 쓰인다 |
| 권한 | **「관리자」와 「일반」 두 값만** 고를 수 있다. 그 밖의 값을 보내면 백엔드가 `9001` 로 거절하므로 화면이 고를 수 없게 막는다 |
| 폰 | 하이픈을 넣어도 된다 — 화면 모듈이 숫자만 남겨 보낸다 |
| 새 비밀번호 | 넣었을 때만 규칙을 적용받는다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| `2001` 회원 없음 | 조회에서 나면 모달 없이 목록을 그리며 안내한다. 저장에서 나면 목록을 다시 그리며 안내한다. 어느 쪽도 오류 화면으로 보내지 않는다 |
| `2003` 이메일 중복 | **이메일 칸 가까이** 붙인다 |
| `2004` 비밀번호 규칙 위반 | **새 비밀번호 칸 가까이** 붙인다 |
| `9001` 권한 값 오류 | 모달 폼 **상단**에 붙인다 |
| 실패 후 착지 | **부모 목록으로 튕기지 않고 모달을 연 채로** 목록을 다시 그린다 |
| 실패 후 입력 유지 | **새 비밀번호 칸만 비우고 나머지는 남긴다** |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추는 문구를 만들지 않는다 |
| 백엔드 불통 | 모달로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(1.8)의 템플릿 안에 있다. 별도 주소를 갖지 않고 `?m=edit&id={아이디}` 로만 열린다.
- 빈 칸의 뜻은 본인 정보(1.7)와 같다. 두 화면이 같은 규칙을 쓴다.
- 회원 추가(1.9)와 칸이 다르다. 1.9 에는 **아이디를 입력하는 칸이 있고 비밀번호가 필수**이며, 여기서는 아이디가 읽기 전용이고 비밀번호가 선택이다.
