# [프론트] 회원 추가

> 화면: `AdminMemberCreate` · Phase 1 · 화면번호 1.9  
> 인덱스: [README.md](../README.md) · 상태: **완료**

## 메타

| 항목 | 내용 |
|------|------|
| Phase | 1 |
| 화면 이름 | 회원 추가 |
| 화면번호 | 1.9 |
| 화면 ID | `AdminMemberCreate` |
| 표시방식 | `모달` |
| Method | `GET` |
| URL | `/admin/members?m=create` |
| 템플릿 | `admin/members.html` 안의 추가 모달 조각 |
| 부모 페이지 | 1.8 `/admin/members` |
| 레이아웃 | `main` |
| 권한 | 관리자 |
| activeMenu | `admin-members` |

## 목적

- 관리자가 신규 회원을 등록한다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 회원 목록(1.8)의 「회원 추가」 버튼, 또는 브라우저가 `?m=create` 가 붙은 주소를 직접 여는 경우 둘이다. 어느 쪽이든 **부모 목록이 함께 그려지고 그 위에 모달이 열린다** |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | **막는다.** 일반 권한(`3`)으로 들어오면 진입 판정이 권한 없음 화면(`/error/forbidden`, 1.6)으로 보낸다 |

**모달을 여는 판정은 서버가 한다.** 007 의 모달 판정이 주소의 `m` 값을 보고 이 화면이 아는 값(`create`)일 때만 모달을 연 상태로 그린다. 모르는 값이면 모달 없이 목록만 보인다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 회원 목록(1.8)이 평소대로 뒤에 그려진다. 모달을 닫으면 그대로 목록이 남는다 |
| 모달 머리 | 제목 「회원 추가」와 닫기 버튼을 놓는다 |
| 안내 영역 | 모달 폼 위에 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 모달 폼 | 칸 일곱을 세로로 놓는다. 필수 넷(아이디·비밀번호·닉네임·권한)을 위쪽에 모은다 |
| 모달 바닥 | 「취소」와 「추가」 버튼을 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text | 필수 | 만들 회원의 로그인 아이디. 이미 쓰이고 있으면 `2002` 다. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 비밀번호 | password | 필수 | 관리자가 정하는 임시 비밀번호 평문. **칸 아래에 규칙 문구를 입력 전부터 보인다.** 실패로 다시 그릴 때는 비운다 |
| 닉네임 | text | 필수 | 회원의 닉네임. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 권한 | select | 필수 | **「관리자」와 「일반」 두 값만** 고를 수 있다. 자유 입력을 두지 않는다 — 그 밖의 값을 보내면 백엔드가 `9001` 로 거절한다 |
| 이메일 | email | 선택 | 회원의 이메일. 다른 회원이 쓰고 있으면 `2003` 이다 |
| 폰 | tel | 선택 | 연락처. 하이픈을 넣어도 **화면 모듈이 숫자만 남겨** 보낸다 |
| 소개 | textarea | 선택 | 자기소개 |
| 비밀번호 규칙 문구 | 문구 | 필수 | 비밀번호 칸 아래에 언제나 보인다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| 「추가」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /admin/members` 로 제출한다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫고 목록으로 돌아간다. 아무것도 저장하지 않는다 |
| 실패 안내 | 문구 | — | 추가가 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 모달 폼 상단에 뜬다 |

**비밀번호 확인 칸이 없다.** 백엔드 생성 API 가 확인 값을 받지 않는다. 관리자가 만든 임시 비밀번호를 회원에게 알려 주는 흐름이라 회원가입(1.2)과 다르다 — 1.2 는 본인이 정한 값을 두 번 쳐서 오타를 거른다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「추가」 버튼을 눌렀을 때 | `AdminMemberCreate` | POST | 칸 일곱을 보내 회원을 만든다. 관리자 토큰을 실어 보낸다 |

**모달이 열릴 때는 백엔드를 부르지 않는다.** 새로 만드는 화면이라 미리 가져올 값이 없다. 수정 모달(1.10)과 다른 점이다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록에서 「회원 추가」를 누른다 | 주소에 `?m=create` 를 실어 목록을 다시 열고, 모달 판정이 추가 모달을 연 상태로 그린다 | 빈 추가 폼이 목록 위에 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 칸을 채우고 「추가」를 누른다 | 폰에서 숫자만 남긴 뒤 `AdminMemberCreate` 를 부른다 | 목록을 다시 그린다. 만든 회원이 목록에 보인다 | 오류 화면으로 보내지 않고 **모달을 연 채로** 목록을 다시 그린다. 비밀번호 칸만 비우고 나머지는 사용자가 넣은 값을 채운다 |
| 「취소」를 누르거나 모달을 닫는다 | 모달을 닫고 목록만 남긴다 | 목록이 뜬다 | (해당 없음) |
| 일반 권한으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 권한 없음 화면(`/error/forbidden`)으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 아이디 | 필수. 이미 쓰이고 있으면 `2002` 다 |
| 비밀번호 | 필수. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」. **문구를 입력 전부터 칸 아래에 보인다.** 문구는 `_공통.md` 의 것을 그대로 쓴다 |
| 닉네임 | 필수 |
| 권한 | 필수. **「관리자」와 「일반」 두 값만** 고를 수 있다. 화면이 고를 수 없는 값을 백엔드가 받는 일이 없어야 한다 |
| 이메일 | 선택. 다른 회원과 겹치지 않아야 한다 |
| 폰 | 선택. 하이픈을 넣어도 된다 — 화면 모듈이 숫자만 남겨 보낸다 |
| 소개 | 선택 |
| `2002` 아이디 중복 | **아이디 칸** 아래에 붙인다 |
| `2003` 이메일 중복 | **이메일 칸** 아래에 붙인다 |
| `2004` 비밀번호 규칙 위반 | **비밀번호 칸** 아래에 붙인다 |
| `9001` 권한 값 오류 | 모달 폼 **상단**에 붙인다 |
| 실패 후 착지 | **부모 목록으로 튕기지 않고 모달을 연 채로** 목록을 다시 그린다. 모달을 닫아 버리면 관리자가 채운 일곱 칸이 전부 사라진다 |
| 실패 후 입력 유지 | **비밀번호 칸만 비우고 나머지는 남긴다** |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추는 문구를 만들지 않는다 |
| 백엔드 불통 | 모달로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 이 모달은 부모 목록(1.8)의 템플릿 안에 있다. 별도 주소를 갖지 않고 `?m=create` 로만 열린다.
- 회원가입(1.2)과 칸이 다르다. 1.2 에는 **비밀번호 확인 칸이 있고 권한 칸이 없다**.
