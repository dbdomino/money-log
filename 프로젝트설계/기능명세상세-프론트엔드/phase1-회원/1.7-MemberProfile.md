## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 사이드바의 「본인 정보 수정」 메뉴, 또는 브라우저가 `/member/profile` 을 직접 여는 경우 둘이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다. 이 화면은 세션이 살아 있다는 전제로만 그려진다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 정보를 연다. 관리자도 일반 회원도 같은 화면을 쓴다 |

**진입 판정은 007 이 한다.** 이 화면이 세션을 다시 확인하지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `profile` 이다 |
| 제목 | 본문 상단에 「본인 정보」를 놓는다 |
| 안내 영역 | 폼 위에 저장 완료 안내와 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 입력 폼 | 아이디(읽기 전용)·닉네임·이메일·폰·소개·새 비밀번호를 세로로 놓고 아래에 「저장」 버튼을 둔다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text (읽기 전용) | — | 로그인 아이디. **고칠 수 없다.** 백엔드 수정 API 에 아이디를 바꾸는 칸 자체가 없고, 화면은 그 사실을 사용자에게 보여 줄 뿐이다 |
| 닉네임 | text | 필수 | 현재 닉네임이 채워진 채로 뜬다. 필수라 비울 수 없고, 저장 요청에 언제나 실린다 |
| 이메일 | email | 선택 | 현재 이메일이 채워진 채로 뜬다. 없으면 빈 칸이다. **비우고 저장하면 값이 지워진다** |
| 폰 | tel | 선택 | 현재 폰이 숫자만으로 채워진 채로 뜬다. 하이픈을 넣어도 화면 모듈이 숫자만 남겨 보낸다. **비우고 저장하면 값이 지워진다** |
| 소개 | textarea | 선택 | 현재 소개가 채워진 채로 뜬다. **비우고 저장하면 값이 지워진다** |
| 새 비밀번호 | password | 선택 | **언제나 빈 칸으로 뜬다.** 현재 비밀번호를 채워 보여 주지 않는다. **비우고 저장하면 비밀번호를 바꾸지 않는다** — 다른 칸과 빈 칸의 뜻이 반대다 |
| 「변경할 때만 입력」 안내 | 문구 | 필수 | 새 비밀번호 칸 아래에 언제나 보인다. 비어 있는 것이 정상 상태라는 것을 사용자가 알아야 한다 |
| 비밀번호 규칙 문구 | 문구 | 필수 | 새 비밀번호 칸 아래에 보인다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| 「저장」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /member/profile` 로 제출한다 |
| 저장 완료 안내 | 문구 | — | 저장에 성공했을 때만 폼 위에 보인다 |
| 실패 안내 | 문구 | — | 저장이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 폼 상단에 뜬다 |

**권한을 고르는 자리를 두지 않는다.** 본인은 자기 권한을 바꿀 수 없고, 백엔드 본인 수정 API 에 그 칸 자체가 없다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때 | `MemberGetMe` | GET | 현재 닉네임·이메일·폰·소개·권한을 받아 칸을 채운다 |
| 「저장」 버튼을 눌렀을 때 | `MemberUpdateMe` | PATCH | 고친 값을 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 `PATCH` 로 옮긴다 |

**화면이 열릴 때마다 백엔드에서 받는다.** 값을 세션에 담아 두지 않는다 — 관리자가 그 회원을 고쳤을 때 화면에 옛 값이 남는다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 사이드바에서 「본인 정보 수정」을 누른다 | `MemberGetMe` 로 현재 값을 받아 칸을 채운다. 새 비밀번호 칸은 비워 둔다 | 현재 값이 채워진 폼이 뜬다 | 007 의 오류 화면으로 간다 — 값을 못 받으면 그릴 폼이 없다 |
| 닉네임만 바꾸고 「저장」을 누른다 | 새 비밀번호가 비어 있으므로 **요청에 비밀번호를 싣지 않고** 나머지를 보낸다 | 저장 완료 안내와 함께 갱신된 값이 보인다. 비밀번호는 그대로라 옛 비밀번호로 로그인된다 | 오류 화면으로 보내지 않고 **이 폼을 다시 그린다**. 새 비밀번호 칸만 비우고 나머지는 사용자가 넣은 값을 채운다 |
| 이메일을 지우고 「저장」을 누른다 | 이메일이 비었으므로 **요청에 비우라는 값(`null`)을 실어** 보낸다 | 이메일이 지워진다. 다시 열면 빈 칸이다 | 위와 같이 폼을 다시 그린다 |
| 폰에 하이픈을 넣고 「저장」을 누른다 | 화면 모듈이 숫자만 남겨 보낸다 | 숫자만으로 저장된다 | 위와 같이 폼을 다시 그린다 |
| 새 비밀번호를 넣고 「저장」을 누른다 | 값이 있으므로 요청에 비밀번호를 실어 보낸다 | 비밀번호가 바뀐다. 다음 로그인부터 새 비밀번호를 쓴다 | 위와 같이 폼을 다시 그린다 |
| 미로그인으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 로그인 화면(`/auth/login`)으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **빈 칸의 뜻 — 새 비밀번호** | 비우면 **바꾸지 않는다.** 요청에 아예 싣지 않는다. 이 칸만 현재 값이 채워지지 않은 채 뜨므로 비어 있는 것이 기본 상태이고, "비웠다"가 아니라 "건드리지 않았다"로 읽는 것이 맞다 |
| **빈 칸의 뜻 — 이메일·폰·소개** | 비우면 **지운다.** 요청에 비우라는 값(`null`)을 실어 보낸다. 세 칸은 현재 값이 채워진 채로 뜨므로 사용자가 지웠다면 지우려는 뜻이다. 이것을 "유지"로 읽으면 사용자는 이메일을 지우고 저장했는데 그대로 남아 있는 화면을 보게 된다 |
| 닉네임 | 필수라 비울 수 없다. 언제나 요청에 실린다 |
| 아이디 | 고칠 수 없다. 읽기 전용으로 보이며 요청에 실리지 않는다 |
| 폰 | 하이픈을 넣어도 된다 — 화면 모듈이 숫자만 남겨 보낸다. 브라우저 스크립트에 맡기지 않는다. 스크립트가 막힌 환경에서 하이픈이 그대로 나가 형식 오류로 거절된다 |
| 새 비밀번호 | 넣었을 때만 규칙을 적용받는다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| `2003` 이메일 중복 | **이메일 칸 가까이** 붙인다 |
| `2004` 비밀번호 규칙 위반 | **새 비밀번호 칸 가까이** 붙인다 |
| `9001` 잘못된 요청 | 어느 칸인지 가릴 수 없으므로 **폼 상단**에 붙인다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추는 문구를 만들지 않는다 |
| 실패 후 입력 유지 | **새 비밀번호 칸만 비우고 나머지는 남긴다** |
| 세션 | **닉네임을 바꿔도 로그인 세션은 그대로다.** 세션이 들고 있는 것은 아이디와 권한뿐이고 둘 다 본인 수정으로 바뀌지 않는다. 상단바 표시가 아이디라면 바뀌지 않는 것이 맞다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/member-profile.html` 을 옮긴다. 프로토타입의 예시 값과 "실제 API 호출 없음" 문구는 걷어낸다.
- 빈 칸의 뜻은 관리자 회원 수정(1.10)과 같다. 두 화면이 같은 규칙을 쓴다.
