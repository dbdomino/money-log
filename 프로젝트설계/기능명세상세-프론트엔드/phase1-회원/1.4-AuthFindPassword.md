## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 로그인 화면(1.1) 아래의 「비밀번호 찾기」 링크, 아이디 찾기(1.3)의 「비밀번호 찾기」 링크, 브라우저가 `/auth/find-password` 를 직접 여는 경우, **1.5 에 재설정 표식 없이 들어온 사용자가 안내를 따라 넘어온 경우** 넷이다 |
| 미로그인 | 접근 가능 (로그인 불필요). 비로그인 허용 목록에 들어 있다 |
| 권한 없음 | 해당 없음 — 권한을 요구하지 않는 화면이라 등급으로 막히는 경우가 없다 |

**이 화면은 확인만 한다.** 비밀번호를 정하는 일은 다음 화면(1.5)이 하며, 두 화면이 한 흐름을 이룬다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 브랜드 | 카드 상단에 서비스 로고 `money-log` 를 놓는다. 로그인 화면과 같은 자리다 |
| 단계 안내 | 폼 위에 「확인되면 비밀번호 변경 화면으로 갑니다」를 미리 적는다. 두 단계라는 것을 시작할 때 알리는 편이 낫다 |
| 안내 영역 | 폼 위에 실패 안내를 놓는다. 응답 코드와 백엔드 문구를 함께 보인다 |
| 입력 폼 | 아이디·닉네임 두 칸과 「확인」 버튼을 세로로 놓는다 |
| 보조 링크 | 폼 아래에 「로그인으로」(`/auth/login`) 와 「아이디 찾기」(`/auth/find-id`) 를 둔다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text | 필수 | 로그인 아이디. 확인이 실패해 폼을 다시 그릴 때 사용자가 넣은 값을 그대로 채운다 |
| 닉네임 | text | 필수 | 가입할 때 정한 닉네임. 아이디와 함께 본인임을 확인하는 값이다. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 「확인」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /auth/find-password` 로 제출한다 |
| 단계 안내 | 문구 | 필수 | 「확인되면 비밀번호 변경 화면으로 갑니다」 고정 문구. 언제나 보인다 |
| 실패 안내 | 문구 | — | 확인이 실패했을 때만 폼 상단에 보인다. 응답 코드와 백엔드 문구를 함께 적는다 |
| 「로그인으로」 링크 | 링크 | 필수 | 로그인 화면(`/auth/login`)으로 이동한다 |
| 「아이디 찾기」 링크 | 링크 | 필수 | 아이디 찾기 화면(`/auth/find-id`)으로 이동한다. 아이디까지 잊은 사용자가 이 화면에서 막히지 않게 한다 |

**비밀번호 칸이 없다.** 이 화면은 본인을 확인만 하고, 새 비밀번호는 1.5 에서 받는다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「확인」 버튼을 눌렀을 때 | `MemberFindPassword` | POST | 아이디·닉네임을 보내 그 조합의 회원이 있는지 확인받는다 |

**인증 없이 부른다.** 비밀번호를 잊은 사용자라 로그인할 수 없는 상태다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 이 주소를 연다 | 빈 폼과 단계 안내를 함께 그린다 | 비밀번호 찾기 폼이 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 아이디·닉네임을 넣고 「확인」을 누른다 | `MemberFindPassword` 를 인증 없이 부른다 | 확인된 아이디·닉네임을 **재설정 표식에 담고** 비밀번호 변경 화면(`/auth/reset-password`)으로 보낸다. 사용자가 두 값을 다시 칠 이유가 없다 | 오류 화면으로 보내지 않고 **이 폼을 다시 그린다**. 아이디·닉네임 값은 그대로 채우고 폼 상단에 안내를 보인다 |
| 「로그인으로」·「아이디 찾기」를 누른다 | 해당 화면 주소로 이동한다 | 그 화면이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 아이디 | 필수. 비우고 제출하면 백엔드가 `9001` 로 거절한다 |
| 닉네임 | 필수. 비우고 제출하면 백엔드가 `9001` 로 거절한다 |
| `2001` 아이디·닉네임 불일치 | 폼 상단에 보인다. **아이디와 닉네임 중 무엇이 틀렸는지 가르지 않는다** — 백엔드가 두 경우를 한 코드로 묶은 이유를 화면이 풀지 않는다. 가르면 아이디만 넣어 보며 실재하는 아이디를 추려 낼 수 있다 |
| `1004` 비활성 계정 | 정지된 계정임을 분명히 알린다. 비밀번호를 바꿔도 로그인할 수 없으므로 사용자가 그 사실을 먼저 알아야 한다 |
| `9001` 필수 누락 | 폼 상단에 보인다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않는다 |
| 확인 성공 후 | 아이디·닉네임을 재설정 표식에 담는다. 표식은 **서버 세션**에 두고 주소에 싣지 않는다 — 주소에 실으면 아이디가 주소창·방문 기록·Referer 에 남는다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다 |
