## 목적

- 찾기 성공 후 새 비밀번호를 설정한다.
- 변경 API 성공 후 **같은 카드**에 완료 안내를 보여 주고, 로그인 화면으로 보낸다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 1.4 비밀번호 찾기에서 본인 확인에 성공한 직후에만 정상 진입이다 |
| 미로그인 | 접근 가능 (로그인 불필요). 비로그인 허용 목록에 들어 있다 |
| 권한 없음 | 해당 없음 — 권한을 요구하지 않는 화면이라 등급으로 막히는 경우가 없다 |

**아이디·닉네임을 1.4 에서 넘겨받는다.** 저장 API 가 두 값을 요구하지만 사용자에게 다시 묻지 않는다. 1.4 가 확인에 성공하면서 두 값을 **서버 세션의 재설정 표식**에 담아 두었고, 이 화면은 그것을 읽어 쓴다. 그래서 이 화면에는 아이디 칸도 닉네임 칸도 없다.

**표식 없이 들어오면 폼을 그리지 않고 1.4 로 안내한다.** 주소창에 직접 치거나 낡은 북마크로 들어온 경우다. 폼을 그려 두고 저장에서 실패시키면 사용자는 **비밀번호를 다 고른 뒤에** "처음부터 다시 하세요"를 보게 된다.

| 표식 상태 | 이 화면이 하는 일 |
|------|------|
| 있다 | 폼을 그린다. 확인된 아이디를 화면에 보여 준다 — 누구의 비밀번호를 바꾸는지 알아야 한다 |
| 없다 | 폼을 그리지 않고 비밀번호 찾기(`/auth/find-password`)로 안내한다 |
| 저장에 실패했다 | **표식을 그대로 둔다.** 지우면 규칙에 한 번 어긋난 사용자가 1.4 부터 다시 해야 한다 |
| 저장에 성공했다 | **표식을 지운다.** 남겨 두면 뒤로 가기로 돌아와 다시 바꿀 수 있다 |

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 브랜드 | 카드 상단에 서비스 로고 `money-log` 를 놓는다. 로그인 화면과 같은 자리다 |
| 대상 안내 | 폼 위에 확인된 아이디를 보인다. 누구의 비밀번호를 바꾸는 중인지 알리는 자리다 |
| 안내 영역 | 폼 위에 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 입력 단계 | 새 비밀번호·확인 두 칸과 「변경」 버튼을 세로로 놓는다. 저장에 성공하면 이 영역을 감춘다 |
| 성공 단계 | 같은 카드에 「비밀번호가 변경되었습니다」와 「로그인으로」 버튼을 보인다. 저장에 성공했을 때만 나타난다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 확인된 아이디 | 문구 | 필수 | 표식에서 읽은 아이디. 사용자가 고칠 수 없는 표시용 값이다 |
| 아이디 (숨은 값) | hidden | 필수 | 표식에서 읽어 저장 요청에 함께 싣는다. 사용자가 바꿔도 **백엔드가 저장 시점에 다시 대조하므로** 남의 비밀번호를 바꿀 수 없다 |
| 닉네임 (숨은 값) | hidden | 필수 | 위와 같다. 표식에서 읽어 저장 요청에 싣고, 백엔드가 다시 대조한다 |
| 새 비밀번호 | password | 필수 | 바꿀 비밀번호 평문. **칸 아래에 규칙 문구를 입력 전부터 보인다.** 실패로 다시 그릴 때는 비운다 |
| 새 비밀번호 확인 | password | 필수 | 위와 같은 값. 다르면 백엔드가 `2005` 로 거절한다. 실패로 다시 그릴 때는 비운다 |
| 비밀번호 규칙 문구 | 문구 | 필수 | 새 비밀번호 칸 아래에 언제나 보인다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| 「변경」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /auth/reset-password` 로 제출한다 |
| 실패 안내 | 문구 | — | 저장이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 폼 상단에 뜬다 |
| 성공 안내 | 문구 | — | 저장 성공 시에만 성공 단계에 보인다. 「비밀번호가 변경되었습니다」 |
| 「로그인으로」 버튼 | 링크 버튼 | — | 성공 단계에만 보인다. 로그인 화면(`/auth/login`)으로 이동한다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「변경」 버튼을 눌렀을 때 | `MemberResetPassword` | POST | 표식의 아이디·닉네임과 새 비밀번호 두 칸을 함께 보내 비밀번호를 바꾼다 |

**인증 없이 부른다.** 비밀번호를 잊은 사용자라 로그인할 수 없는 상태다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 1.4 확인 성공으로 넘어온다 | 표식에서 아이디·닉네임을 읽어 숨은 값에 싣고 폼을 그린다. 확인된 아이디를 화면에 보인다 | 입력 단계가 뜬다 | (해당 없음 — 서버 호출이 없다) |
| **표식 없이** 이 주소를 직접 연다 | 폼을 그리지 않는다 | (해당 없음) | 비밀번호 찾기(`/auth/find-password`)로 안내한다 |
| 새 비밀번호 두 칸을 넣고 「변경」을 누른다 | 표식의 아이디·닉네임과 함께 `MemberResetPassword` 를 인증 없이 부른다 | **표식을 지우고** 같은 화면을 성공 단계로 그린다. 완료 문구와 「로그인으로」 버튼이 함께 보인다 | 오류 화면으로 보내지 않고 **입력 단계를 다시 그린다**. 비밀번호 두 칸을 비우고 **표식은 그대로 둔다** |
| 성공 단계에서 기다린다 | 잠시 뒤(약 2초) 로그인 화면(`/auth/login`)으로 옮겨 간다 | 로그인 화면이 뜬다 | (해당 없음) |
| 성공 단계에서 「로그인으로」를 누른다 | 로그인 화면(`/auth/login`)으로 이동한다 | 로그인 화면이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 새 비밀번호 | 필수. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」. **이 문구를 입력 전부터 칸 아래에 보인다.** 문구는 `_공통.md` 의 것을 그대로 쓰고 화면이 새로 쓰지 않는다 |
| 새 비밀번호 확인 | 필수. 위 값과 같아야 한다. 다르면 `2005` 다 |
| 아이디·닉네임 | 사용자가 입력하지 않는다. 표식에서 와서 숨은 값으로 실린다 |
| `2004` 비밀번호 규칙 위반 | **새 비밀번호 칸** 아래에 붙인다. 같은 화면에 머물고 **표식은 살아 있어 곧바로 다시 시도할 수 있다** |
| `2005` 비밀번호 확인 불일치 | **새 비밀번호 확인 칸** 아래에 붙인다. 위와 같이 표식은 그대로 둔다 |
| `2001` 아이디·닉네임 불일치 | 표식의 값이 더는 맞지 않는다는 뜻이다. 이 화면에 머물러도 할 수 있는 일이 없으므로 **1.4 로 안내한다** |
| `1004` 비활성 계정 | 정지된 계정임을 알린다. 비밀번호를 바꿔도 로그인할 수 없다 |
| `9001` 필수 누락 | 폼 상단에 붙인다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추는 문구를 만들지 않는다 |
| 실패 후 입력 유지 | 비밀번호 두 칸은 **언제나 비운다.** 되채우면 평문이 HTML 에 실린다 |
| 자동 이동 | 성공 단계는 잠시 뒤 로그인으로 옮겨 가되 **「로그인으로」 버튼을 함께 둔다** — 자동 이동이 막힌 환경에서 사용자가 갇히지 않게 한다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다 |
