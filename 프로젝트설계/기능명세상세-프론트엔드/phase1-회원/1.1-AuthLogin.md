## 목적

- id·비밀번호로 로그인하고 토큰을 저장한 뒤 가계부로 이동한다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 브라우저가 `/auth/login` 을 직접 여는 경우, 보호 화면에 미로그인으로 접근해 진입 판정이 보낸 경우, 세션이 끝나 밀려난 경우, 가입(1.2) 성공 직후 넘어온 경우, 1.5 비밀번호 변경 완료 후 「로그인으로」를 누른 경우 다섯이다 |
| 미로그인 | 접근 가능 (로그인 불필요). 비로그인 허용 목록에 들어 있다 |
| 권한 없음 | 해당 없음 — 권한을 요구하지 않는 화면이라 등급으로 막히는 경우가 없다 |

**이미 로그인한 사용자는 이 화면을 열지 않는다.** 조회 처리가 세션의 토큰을 보고 월별 가계부(`/ledger`)로 보낸다. 이것은 "로그인 없이 열 수 있는가"(비로그인 허용 목록)와 다른 판단이라 진입 판정이 아니라 이 화면의 조회 처리가 한다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 브랜드 | 카드 상단에 서비스 로고 `money-log` 를 놓는다. 권한 없음 화면(1.6)과 같은 자리다 |
| 안내 영역 | 폼 위에 실패 안내와 세션 만료 안내를 놓는다. 실패 안내는 응답 코드와 백엔드 문구를 함께 보인다 |
| 입력 폼 | 아이디·비밀번호 두 칸과 「로그인」 버튼을 세로로 놓는다 |
| 보조 링크 | 폼 아래에 「회원가입」(`/auth/signup`) · 「아이디 찾기」(`/auth/find-id`) · 「비밀번호 찾기」(`/auth/find-password`) 세 개를 가로로 놓는다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text | 필수 | 로그인 아이디. 가입 직후 넘어왔으면 방금 만든 아이디가 채워진 채로 뜬다. 로그인이 실패해 폼을 다시 그릴 때도 사용자가 넣은 값을 그대로 채운다 |
| 비밀번호 | password | 필수 | 비밀번호 평문. **어떤 경우에도 값을 채워 보내지 않는다** — 실패로 폼을 다시 그릴 때도 빈 칸이다. 평문이 HTML 에 실리면 브라우저 캐시와 방문 기록에 남는다 |
| 「로그인」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /auth/login` 으로 제출한다 |
| 실패 안내 | 문구 | — | 로그인이 실패했을 때만 **폼 상단에** 보인다. 백엔드가 준 응답 코드와 문구를 함께 적는다 |
| 세션 만료 안내 | 문구 | — | 세션이 끝나 밀려났을 때만 폼 위에 보인다. 「다른 곳에서 로그인되어 로그아웃되었습니다」처럼 007 이 실어 보낸 문구를 그대로 쓴다 |
| 「회원가입」 링크 | 링크 | 필수 | 회원가입 화면(`/auth/signup`)으로 이동한다 |
| 「아이디 찾기」 링크 | 링크 | 필수 | 아이디 찾기 화면(`/auth/find-id`)으로 이동한다 |
| 「비밀번호 찾기」 링크 | 링크 | 필수 | 비밀번호 찾기 화면(`/auth/find-password`)으로 이동한다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「로그인」 버튼을 눌렀을 때 | `MemberLogin` | POST | 아이디·비밀번호를 보내 토큰 두 개와 아이디·권한을 받는다 |

**인증 없이 부른다.** 세션에 남아 있던 만료된 토큰을 실어 보내면 로그인 요청 자체가 만료로 거절된다. 화면 모듈의 비인증 통로를 쓴다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 로그인하지 않은 채 이 주소를 연다 | 세션에 토큰이 없음을 확인하고 폼을 그린다 | 로그인 폼이 뜬다 | (해당 없음 — 서버 호출이 없다) |
| **이미 로그인한 채** 이 주소를 연다 | 세션의 토큰을 보고 월별 가계부(`/ledger`)로 보낸다 | 월별 가계부가 뜬다 | (해당 없음) |
| 가입(1.2) 직후 넘어온다 | 넘겨받은 아이디를 아이디 칸에 채우고 폼을 그린다 | 아이디가 채워진 폼이 뜬다 | (해당 없음) |
| 세션이 끝나 밀려난다 | 007 이 실어 보낸 안내 문구를 폼 위에 보인다 | 사유 문구와 함께 폼이 뜬다 | (해당 없음) |
| 아이디·비밀번호를 넣고 「로그인」을 누른다 | `MemberLogin` 을 인증 없이 부른다 | 받은 토큰 두 개와 아이디·권한을 로그인 세션에 담고 월별 가계부(`/ledger`)로 보낸다 | 오류 화면으로 보내지 않고 **이 폼을 다시 그린다**. 아이디는 채우고 비밀번호는 비운다 |
| 「회원가입」·「아이디 찾기」·「비밀번호 찾기」를 누른다 | 해당 화면 주소로 이동한다 | 그 화면이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 아이디 | 필수. 비우고 제출하면 백엔드가 `9001` 로 거절하며, 그 안내가 폼 상단에 뜬다 |
| 비밀번호 | 필수. 비우고 제출하면 백엔드가 `9001` 로 거절한다. 화면은 규칙을 따로 검사하지 않는다 — 로그인은 기존 비밀번호를 확인하는 자리이고 규칙 검사는 저장하는 자리(1.2·1.5·1.7)의 몫이다 |
| `1003` 아이디·비밀번호 불일치 | **폼 상단에만** 보인다. 아이디 칸에도 비밀번호 칸에도 붙이지 않는다 — 칸에 붙이는 순간 그 아이디가 실재하는지가 드러난다. 백엔드가 두 경우를 한 코드로 묶은 이유를 화면이 풀지 않는다 |
| `1004` 비활성 계정 | 반대로 **정지된 계정임을 분명히 알린다.** 아이디가 맞다는 사실이 드러나지만, 정지된 사용자가 이유를 모른 채 비밀번호만 계속 시도하는 쪽이 더 나쁘다 |
| `9001` 필수 누락 | 폼 상단에 보인다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않고, 사용자가 넣은 값을 되비추는 문구도 만들지 않는다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다. 폼 실패와 통신 실패는 사용자가 할 수 있는 일이 다르다 |
| 세션 만료 안내 | 007 이 세션을 버리며 실어 보낸 문구를 그대로 보인다. 화면이 사유를 짐작해 문구를 만들지 않는다 |

## 비고

- 화면 구성은 `화면기획/proto/auth-login.html` 을 옮긴다. 프로토타입의 예시 값과 "실제 API 호출 없음" 문구는 걷어낸다.
- 상단바 로그아웃은 이 화면이 만들지 않는다. 007 의 `layout/main.html` 이 이미 `POST /auth/logout` 폼을 들고 있고, 토큰 비활성화와 세션 버리기의 순서도 007 이 지킨다.
