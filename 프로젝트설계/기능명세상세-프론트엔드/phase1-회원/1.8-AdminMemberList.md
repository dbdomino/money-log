# [프론트] 회원 목록

> 화면: `AdminMemberList` · Phase 1 · 화면번호 1.8  
> 인덱스: [README.md](../README.md) · 상태: **완료**

## 메타

| 항목 | 내용 |
|------|------|
| Phase | 1 |
| 화면 이름 | 회원 목록 |
| 화면번호 | 1.8 |
| 화면 ID | `AdminMemberList` |
| 표시방식 | `페이지` |
| Method | `GET` |
| URL | `/admin/members` |
| 템플릿 | `admin/members.html` |
| 레이아웃 | `main` |

## 목적

- 관리자가 회원 목록을 검색·페이징하고 정지할 수 있다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 사이드바의 「회원 관리」 메뉴, 또는 브라우저가 `/admin/members` 를 직접 여는 경우 둘이다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다. 권한 없음 화면보다 로그인이 먼저다 — 순서가 뒤집히면 미로그인 사용자에게 이 주소가 실재한다는 사실이 드러난다 |
| 권한 없음 | **막는다.** 일반 권한(`3`)으로 들어오면 진입 판정이 권한 없음 화면(`/error/forbidden`, 1.6)으로 보낸다. 사이드바에도 이 메뉴가 그려지지 않는다 |

**권한 판정은 007 이 한다.** 이 화면이 다시 판정하지 않는다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `admin-members` 이며 관리자에게만 그려진다 |
| 제목·추가 버튼 | 본문 상단에 「회원 관리」와 오른쪽에 「회원 추가」 버튼을 놓는다 |
| 검색 영역 | 아이디 칸과 닉네임 칸을 가로로 놓고 「검색」 버튼을 둔다. 아래에 두 칸이 AND 로 묶인다는 설명을 한 줄 적는다 |
| 안내 영역 | 표 위에 실패 안내를 놓는다. 정지 실패와 수정 대상 조회 실패가 여기에 뜬다 |
| 목록 표 | 열 여섯(아이디·닉네임·이메일·권한·상태·관리)을 가진 표를 놓는다 |
| 쪽 이동 | 표 아래에 쪽 번호 링크와 전체 건수를 놓는다 |
| 모달 | 「회원 추가」(1.9)와 「수정」(1.10) 모달을 이 화면 위에 띄운다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 검색어 | text | 선택 | 아이디 부분 일치로 좁힌다. 비워 두면 아이디로 좁히지 않는다 |
| 닉네임 검색어 | text | 선택 | 닉네임 부분 일치로 좁힌다. 비워 두면 닉네임으로 좁히지 않는다 |
| AND 설명 문구 | 문구 | 필수 | 검색 칸 아래에 언제나 보인다. 「두 칸을 함께 넣으면 둘 다 맞는 회원만 나옵니다」. 적지 않으면 관리자는 "또는"으로 기대하고 결과가 비었을 때 데이터가 없다고 읽는다 |
| 「검색」 버튼 | 제출 버튼 | 필수 | 검색어 둘을 `GET /admin/members` 의 질의로 보낸다. **쪽 번호를 싣지 않는다** |
| 「회원 추가」 버튼 | 링크 버튼 | 필수 | 추가 모달을 연다(`?m=create`) |
| 아이디 열 | 표 열 | 필수 | 회원의 로그인 아이디 |
| 닉네임 열 | 표 열 | 필수 | 회원의 닉네임 |
| 이메일 열 | 표 열 | 필수 | 회원의 이메일. 등록하지 않은 회원은 빈 칸이다 |
| 권한 열 | 표 열 | 필수 | 「관리자」 또는 「일반」. **숫자 대신 말로 보인다** — `1`·`3` 은 화면 밖의 값이다 |
| 상태 열 | 표 열 | 필수 | 「활성」 또는 「정지」 |
| 관리 열 | 표 열 | 필수 | 「수정」과 「정지」 버튼을 놓는다 |
| 「수정」 버튼 | 링크 버튼 | 필수 | 그 회원의 수정 모달을 연다(`?m=edit&id={아이디}`) |
| 「정지」 버튼 | 제출 버튼 | 필수 | 확인 다이얼로그를 거쳐 `POST /admin/members/{아이디}/deactivate` 로 보낸다. **링크가 아니다** |
| 쪽 이동 링크 | 링크 | 필수 | 쪽 번호와 **검색어 둘을 함께** 싣는다. 빠뜨리면 쪽을 넘길 때 검색이 풀린다 |
| 전체 건수 | 문구 | 필수 | 검색 조건에 맞는 전체 건수. 현재 쪽의 행 수가 아니다 |
| 실패 안내 | 문구 | — | 정지나 대상 조회가 실패했을 때만 표 위에 보인다 |

**회원이 언제 만들어졌는지를 보여 주는 열을 두지 않는다.** 백엔드 목록 응답에 그 값이 없다. 응답에 없는 값을 열로 두면 빈 칸이 "만들어진 때를 모르는 회원"으로 읽혀 데이터가 잘못된 것처럼 보인다.

**정지된 회원에게 정지를 되돌리는 버튼을 두지 않는다.** 정지를 푸는 API 가 없어 **화면에서 정지 상태를 풀 수 없다.** 누를 수 없는 버튼을 두면 관리자는 언제든 되돌릴 수 있다고 믿고 정지를 누른다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때·검색할 때·쪽을 넘길 때 | `AdminMemberList` | GET | 검색어 둘과 조회 구간을 보내 회원 목록과 전체 건수를 받는다 |
| 확인 다이얼로그에서 정지를 확정했을 때 | `AdminMemberDeactivate` | PATCH | 그 회원을 정지시킨다. 본문 없이 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 `PATCH` 로 옮긴다 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 사이드바에서 「회원 관리」를 누른다 | 검색어 없이 첫 쪽을 조회한다 | 행과 쪽 정보가 그려진다 | 007 의 오류 화면으로 간다 — 목록을 못 받으면 그릴 표가 없다 |
| 아이디 칸에만 검색어를 넣고 「검색」을 누른다 | 아이디 검색어만 실어 조회한다. **쪽 번호를 싣지 않아** 첫 쪽에서 시작한다 | 아이디로 좁혀진 목록이 뜬다 | 007 의 오류 화면으로 간다 |
| 아이디·닉네임에 함께 넣고 「검색」을 누른다 | 두 검색어를 **각각** 실어 조회한다 | 둘 다 맞는 회원만 나온다 | 007 의 오류 화면으로 간다 |
| 쪽 이동 링크를 누른다 | 쪽 번호를 조회 구간으로 환산하고 검색어 둘을 함께 실어 조회한다 | 검색이 유지된 채 다음 쪽이 뜬다 | 007 의 오류 화면으로 간다 |
| 「회원 추가」를 누른다 | 추가 모달을 연 채로 목록을 그린다 | 빈 추가 폼이 모달로 뜬다 | (해당 없음 — 조회가 없다) |
| 「수정」을 누른다 | **목록을 그리기 전에** 그 회원을 조회해 모달에 채운다 | 값이 채워진 수정 폼이 모달로 뜬다 | 조회가 `2001` 이면 **모달 없이 목록만** 보이고 안내를 띄운다. 낡은 북마크일 뿐이고 목록은 정상이다 |
| 「정지」를 누른다 | 확인 다이얼로그를 띄운다. 본문은 이 화면이 넘긴다 | 다이얼로그가 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 다이얼로그에서 정지를 확정한다 | `AdminMemberDeactivate` 를 본문 없이 부른다 | 목록을 다시 그린다. 그 회원의 상태가 「정지」로 바뀐다 | `2001`·`9001` 은 오류 화면으로 보내지 않고 목록을 다시 그리며 안내를 띄운다 |
| 일반 권한으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 권한 없음 화면(`/error/forbidden`)으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 아이디 검색어 | 선택. 부분 일치로 좁힌다 |
| 닉네임 검색어 | 선택. 부분 일치로 좁힌다 |
| **두 검색어를 함께 넣으면** | **둘 다 맞는 회원만** 나온다. 백엔드가 두 조건을 AND 로 묶기 때문이다. 화면에 이 사실을 한 줄로 적는다 |
| 검색 폼과 쪽 번호 | 검색 폼은 **쪽 번호를 싣지 않는다.** 새 검색은 언제나 쪽 번호 없는 요청이 되어 첫 쪽에서 시작한다. 싣고 다니면 3쪽에서 검색했을 때 결과가 한 쪽뿐인데도 3쪽을 요구해 빈 화면이 뜬다 |
| 쪽 이동 링크 | 쪽 번호와 **검색어 둘을 함께** 싣는다. 빠뜨리면 쪽을 넘기는 순간 검색이 풀려 전체 목록으로 돌아간다 |
| 조회 구간 | 007 의 페이징 환산기가 쪽 번호를 백엔드가 요구하는 구간으로 바꾼다. **화면이 직접 계산하지 않는다** — 개수의 배수가 아닌 값이 새어 나가면 목록이 통째로 `9001` 로 실패한다 |
| 전체 쪽 수 | 백엔드가 준 **전체 건수**로 환산한다. 현재 쪽의 행 수로 계산하면 마지막 쪽에서 쪽 수가 줄어든다 |
| 권한 표시 | 「관리자」·「일반」으로 보인다. `1`·`3` 숫자를 그대로 보이지 않는다 |
| 상태 표시 | 「활성」·「정지」로 보인다 |
| 정지 전송 방식 | **`POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는 것만으로 계정이 정지된다 |
| 정지 확인 | 007 의 공통 확인 다이얼로그를 거친다. 본문에 담을 것은 아래 「정지 확인 다이얼로그」에 적는다 |
| `2001` 회원 없음 | 목록을 다시 그리며 안내한다. 오류 화면으로 보내지 않는다 |
| `9001` 이미 정지 상태 | 목록을 다시 그리며 안내한다. 오류 화면으로 보내지 않는다 — 이미 원하는 상태이고 관리자가 할 일이 없다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

### 정지 확인 다이얼로그

다이얼로그는 문구를 만들지 않고 이 화면이 넘긴다. 세 가지를 담는다.

| 담을 것 | 왜 |
|------|------|
| 대상이 누구인지 (아이디·닉네임) | 표의 어느 행을 눌렀는지 다이얼로그만 보고 확인할 수 있어야 한다 |
| **되돌릴 수 없다는 사실** | 화면에서 정지를 푸는 길이 없다. 되돌릴 수 없다는 것은 누르기 전에 보여야 한다 |
| **정지와 로그아웃이 다르다는 것** | 정지된 계정은 **다시 로그인할 수 없다.** 로그아웃은 토큰만 무효로 만들고 다시 로그인할 수 있다 |

**대상이 자기 자신이면 그 사실을 함께 알린다.** 관리자가 자기를 정지하면 다음 요청부터 자기도 막힌다.

## 비고

- 화면 구성은 `화면기획/proto/member-admin-list.html` 을 옮긴다. 프로토타입과 두 곳이 다르다 — **검색이 한 칸이 아니라 두 칸**이고, **만들어진 때를 보여 주는 열과 정지를 되돌리는 버튼이 없다.**
- 추가(1.9)·수정(1.10)은 이 화면 위의 모달이며 별도 주소를 갖지 않는다.
