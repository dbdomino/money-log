## 목적

- 이메일로 회원 id를 조회해 화면에 표시한다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 로그인 화면(1.1) 아래의 「아이디 찾기」 링크, 또는 브라우저가 `/auth/find-id` 를 직접 여는 경우 둘이다 |
| 미로그인 | 접근 가능 (로그인 불필요). 비로그인 허용 목록에 들어 있다 |
| 권한 없음 | 해당 없음 — 권한을 요구하지 않는 화면이라 등급으로 막히는 경우가 없다 |

**로그인한 사용자도 보낸 뒤 되돌리지 않는다.** 1.1·1.2 와 달리 이 화면은 로그인한 사용자가 들어올 이유가 있다 — 곁에 있는 사람의 아이디를 함께 찾아 주는 경우다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 브랜드 | 카드 상단에 서비스 로고 `money-log` 를 놓는다. 로그인 화면과 같은 자리다 |
| 안내 영역 | 폼 위에 실패 안내를 놓는다. 응답 코드와 백엔드 문구를 함께 보인다 |
| 입력 폼 | 이메일 한 칸과 「아이디 찾기」 버튼을 세로로 놓는다 |
| 결과 영역 | 조회에 성공했을 때만 **같은 화면에** 나타난다. 찾은 아이디와, 값이 가려져 왔으면 그 사실을 적는다 |
| 보조 링크 | 폼 아래에 「로그인으로」(`/auth/login`) 와 「비밀번호 찾기」(`/auth/find-password`) 를 둔다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이메일 | email | 필수 | 가입할 때 등록한 이메일. 조회가 실패해 폼을 다시 그릴 때 사용자가 넣은 값을 그대로 채운다 |
| 「아이디 찾기」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /auth/find-id` 로 제출한다 |
| 찾은 아이디 | 문구 | — | 조회 성공 시에만 결과 영역에 보인다. 백엔드가 돌려준 값을 그대로 보이며 **화면이 가공하지 않는다** |
| 가림 안내 | 문구 | — | 백엔드가 아이디를 가려서 돌려줬을 때만 결과 영역에 함께 보인다. 「일부가 가려진 아이디입니다」처럼 값이 완전하지 않다는 것을 알린다 |
| 실패 안내 | 문구 | — | 조회가 실패했을 때만 폼 상단에 보인다. 응답 코드와 백엔드 문구를 함께 적는다 |
| 「로그인으로」 링크 | 링크 | 필수 | 로그인 화면(`/auth/login`)으로 이동한다. 결과를 확인한 사용자가 곧바로 로그인할 수 있게 한다 |
| 「비밀번호 찾기」 링크 | 링크 | 필수 | 비밀번호 찾기 화면(`/auth/find-password`)으로 이동한다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「아이디 찾기」 버튼을 눌렀을 때 | `MemberFindId` | POST | 이메일을 보내 그 이메일로 가입된 아이디와 가림 여부를 받는다 |

**인증 없이 부른다.** 아이디를 잊은 사용자라 로그인할 수 없는 상태다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 이 주소를 연다 | 빈 폼을 그린다. 결과 영역은 보이지 않는다 | 아이디 찾기 폼이 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 이메일을 넣고 「아이디 찾기」를 누른다 | `MemberFindId` 를 인증 없이 부른다 | **같은 화면에** 결과 영역이 나타나고 찾은 아이디가 보인다. 결과 전용 주소로 이동하지 않는다 | 오류 화면으로 보내지 않고 **이 폼을 다시 그린다**. 이메일 값은 그대로 채우고 폼 상단에 안내를 보인다 |
| 결과가 가려진 값으로 온다 | 백엔드가 함께 준 가림 여부를 보고 가림 안내를 결과 옆에 붙인다 | 가려진 아이디와 그 사실이 함께 보인다 | (해당 없음) |
| 「로그인으로」·「비밀번호 찾기」를 누른다 | 해당 화면 주소로 이동한다 | 그 화면이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 이메일 | 필수. 형식이 맞지 않으면 백엔드가 `9001` 로 거절한다. 화면은 형식을 따로 검사하지 않는다 — 두 곳에서 검사하면 규칙이 갈린다 |
| `2001` 회원 없음 | 그 이메일로 가입된 회원이 없다는 안내를 폼 상단에 보인다 |
| `9001` 이메일 형식 오류 | 폼 상단에 보인다 |
| 결과 표시 | 백엔드가 돌려준 아이디를 그대로 보인다. **가려진 아이디를 화면이 풀지 않는다** — 무엇을 얼마나 가릴지는 백엔드가 판단한다 |
| 가림 안내 | 백엔드가 가림 여부를 함께 준다. 가려진 값일 때만 그 사실을 적는다. 적지 않으면 사용자는 가려진 값이 진짜 아이디라고 믿고 그대로 로그인을 시도한다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않는다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/auth-find-id.html` 을 옮긴다. 프로토타입의 예시 값과 "실제 API 호출 없음" 문구는 걷어낸다.
- **결과 전용 주소를 만들지 않는다.** 그 주소에 직접 들어온 사용자에게는 아무 맥락도 없는 아이디가 보인다.
