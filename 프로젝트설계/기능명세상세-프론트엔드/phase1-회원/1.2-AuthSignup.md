## 목적

- 신규 회원 정보를 입력·가입하고 로그인 화면으로 이동한다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 로그인 화면(1.1) 아래의 「회원가입」 링크, 또는 브라우저가 `/auth/signup` 을 직접 여는 경우 둘이다 |
| 미로그인 | 접근 가능 (로그인 불필요). 비로그인 허용 목록에 들어 있다 |
| 권한 없음 | 해당 없음 — 권한을 요구하지 않는 화면이라 등급으로 막히는 경우가 없다 |

**이미 로그인한 사용자는 이 화면을 열지 않는다.** 조회 처리가 세션의 토큰을 보고 월별 가계부(`/ledger`)로 보낸다. 로그인한 사용자가 계정을 또 만들 이유가 없다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 브랜드 | 카드 상단에 서비스 로고 `money-log` 를 놓는다. 로그인 화면과 같은 자리다 |
| 안내 영역 | 폼 위에 실패 안내를 놓는다. 어느 칸인지 가릴 수 없는 실패가 여기에 뜬다 |
| 입력 폼 | 칸 일곱을 세로로 놓고 아래에 「가입」 버튼을 둔다. 필수 넷(아이디·비밀번호·비밀번호 확인·닉네임)을 위쪽에 모은다 |
| 보조 링크 | 폼 아래에 「로그인으로」(`/auth/login`) 하나를 둔다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 아이디 | text | 필수 | 로그인 아이디. 4~20자, 영문·숫자·`_`. 가입이 실패해 폼을 다시 그릴 때 사용자가 넣은 값을 그대로 채운다 |
| 비밀번호 | password | 필수 | 비밀번호 평문. **칸 아래에 규칙 문구를 입력 전부터 보인다.** 실패로 다시 그릴 때는 비운다 |
| 비밀번호 확인 | password | 필수 | 위 비밀번호와 같은 값. 다르면 백엔드가 `2005` 로 거절한다. 실패로 다시 그릴 때는 비운다 |
| 닉네임 | text | 필수 | 화면에 보일 이름. 2~20자. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 이메일 | email | 선택 | 아이디 찾기(1.3)에 쓰이는 값. 다른 회원이 쓰고 있으면 `2003` 이다. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 폰 | tel | 선택 | 연락처. 사용자가 하이픈을 넣어도 **화면 모듈이 숫자만 남겨** 백엔드로 보낸다. 브라우저 스크립트에 맡기지 않는다 |
| 소개 | textarea | 선택 | 자기소개. 실패로 다시 그릴 때 값을 그대로 채운다 |
| 비밀번호 규칙 문구 | 문구 | 필수 | 비밀번호 칸 아래에 언제나 보인다. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」 |
| 「가입」 버튼 | 제출 버튼 | 필수 | 폼을 `POST /auth/signup` 으로 제출한다 |
| 실패 안내 | 문구 | — | 가입이 실패했을 때만 보인다. 코드로 칸을 가를 수 있으면 그 칸 아래에, 아니면 폼 상단에 뜬다 |
| 「로그인으로」 링크 | 링크 | 필수 | 로그인 화면(`/auth/login`)으로 이동한다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 「가입」 버튼을 눌렀을 때 | `MemberSignup` | POST | 칸 일곱을 보내 회원을 만든다. 성공 응답으로 만들어진 아이디·닉네임·권한을 받는다 |

**인증 없이 부른다.** 아직 계정이 없는 사용자의 요청이라 실을 토큰 자체가 없다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 이 주소를 연다 | 세션에 토큰이 없음을 확인하고 빈 폼과 비밀번호 규칙 문구를 함께 그린다 | 가입 폼이 뜬다 | (해당 없음 — 서버 호출이 없다) |
| **이미 로그인한 채** 이 주소를 연다 | 세션의 토큰을 보고 월별 가계부(`/ledger`)로 보낸다 | 월별 가계부가 뜬다 | (해당 없음) |
| 칸을 채우고 「가입」을 누른다 | 폰에서 숫자만 남긴 뒤 `MemberSignup` 을 인증 없이 부른다 | **로그인 화면(`/auth/login`)으로 보내며 방금 만든 아이디를 함께 넘긴다.** 사용자가 같은 값을 두 번 칠 이유가 없다 | 오류 화면으로 보내지 않고 **이 폼을 다시 그린다**. 비밀번호 두 칸만 비우고 나머지 다섯은 사용자가 넣은 값을 그대로 채운다 |
| 「로그인으로」를 누른다 | 로그인 화면(`/auth/login`)으로 이동한다 | 로그인 화면이 뜬다 | (해당 없음) |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 아이디 | 필수. 4~20자, 영문·숫자·`_`. 이미 쓰이고 있으면 `2002` 다 |
| 비밀번호 | 필수. 「8자 이상, 영어 대·소문자·특수문자·숫자 중 3종류 이상」. **이 문구를 입력 전부터 칸 아래에 보인다** — 다 채운 뒤에 규칙을 알려 주면 사용자가 처음부터 다시 친다. 문구는 `_공통.md` 의 것을 그대로 쓰고 화면이 새로 쓰지 않는다 |
| 비밀번호 확인 | 필수. 위 비밀번호와 같아야 한다. 다르면 `2005` 다 |
| 닉네임 | 필수. 2~20자 |
| 이메일 | 선택. 넣으면 다른 회원과 겹치지 않아야 한다 |
| 폰 | 선택. 하이픈을 넣어도 된다 — **화면 모듈이 숫자만 남겨 보낸다.** 저장되는 값은 언제나 숫자만이다 |
| 소개 | 선택. 길이 제한을 화면이 따로 두지 않는다 |
| `2002` 아이디 중복 | **아이디 칸** 아래에 붙인다 |
| `2003` 이메일 중복 | **이메일 칸** 아래에 붙인다 |
| `2004` 비밀번호 규칙 위반 | **비밀번호 칸** 아래에 붙인다 |
| `2005` 비밀번호 확인 불일치 | **비밀번호 확인 칸** 아래에 붙인다 |
| `9001` 필수 누락·형식 오류 | 어느 칸인지 가릴 수 없으므로 **폼 상단**에 붙인다. 엉뚱한 칸에 붙이면 사용자가 맞는 칸을 고치고 또 틀린다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 「비밀번호 `abc` 는 규칙에 맞지 않습니다」처럼 입력값을 되비추는 문구를 만들지 않는다 |
| 실패 후 입력 유지 | **비밀번호 두 칸만 비우고 나머지 다섯은 남긴다.** 비밀번호를 되채우면 평문이 HTML 에 실린다 |
| 백엔드 불통 | 폼으로 되돌리지 않고 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/auth-signup.html` 을 옮긴다. 프로토타입의 예시 값과 "실제 API 호출 없음" 문구는 걷어낸다.
- 관리자 회원 추가(1.9)와 칸이 다르다. 1.9 에는 **비밀번호 확인 칸이 없고 권한 칸이 있다** — 백엔드 생성 API 가 확인 값을 받지 않고 권한을 요구하기 때문이다.
