## 목적

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 둘이다. ① 월별 가계부(5.1) 목록 행의 「수정」 버튼 ② 브라우저가 `/ledger?m=expense-edit&id={id}` 를 직접 여는 경우 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 지출을 고친다. 남의 것을 열 수 없는 것은 백엔드가 보장한다 |

**모달이 열리기 전에 값을 가져온다.** 부모 목록을 그리기 전에 그 지출을 조회해 모달에 싣는다 — 여는 일만 브라우저가 하면 열린 모달이 빈 채로 뜨고 값을 채우려면 다시 요청해야 한다.

**없는 대상이면 모달을 열지 않는다.** 빈 모달을 띄우지 말고 **목록만** 남긴 뒤 안내한다. **없는 것과 남의 것을 가르지 않는다** — 가르면 식별자를 훑어 남의 지출이 실재하는지 알아낼 수 있다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 5.1 의 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「지출 수정」과 닫기(X) |
| 실패 안내 | 모달 폼 상단. 어느 칸인지 가릴 수 없는 실패가 여기 뜬다 |
| **할부 안내** | 할부 건일 때만 보인다. 잠긴 칸의 이유와 **대안**을 적는다 |
| 입력 폼 | 칸 여섯(+할부 건의 잠긴 칸 둘). 아래 표 참고 |
| 모달 푸터 | 「취소」와 「저장」 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 수단 | 선택 | 필수 | **사용 중 수단 목록(지출용)** 으로 채운다. 현재 값이 골라진 채로 뜬다 |
| 지출유형 | 선택 | 필수 | **사용 중 지출유형 목록**으로 채운다. 비울 수 없다 |
| 결제일 | 날짜 | 필수 | `YYYY-MM-DD` |
| 금액 | 숫자 | 필수 | 원 단위 양의 정수. **할부 건이면 그 회차 하나의 금액**이다 |
| 장소 | 문자 | 필수 | 100자 이하 |
| 내용 | 문자 | 필수 | 255자 이하 |
| **할부 개월 수** | 숫자 | — | **할부 건에서 읽기 전용.** 값은 보이되 고칠 수 없다 |
| **시작 연월** | 월 | — | **할부 건에서 읽기 전용.** 값은 보이되 고칠 수 없다 |
| 할부 안내 문구 | 문구 | — | 할부 건일 때만. **왜 잠겼는지와 바꾸는 길**을 적는다 |
| 「저장」 버튼 | 제출 버튼 | 필수 | 고친 값을 보낸다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫는다. 목록은 그대로 남는다 |

### 할부 건은 두 칸이 잠긴다

| 칸 | 할부 건에서 |
|---|---|
| 할부 개월 수 | **읽기 전용** |
| 시작 연월 | **읽기 전용** |
| 금액 · 결제일 · 수단 · 지출유형 · 장소 · 내용 | 고칠 수 있다 |

**화면이 미리 막는다.** 목록 응답이 그 행이 할부인지 알려 주므로, 고칠 수 없는 칸을 열어 두고 저장에서 실패시킬 이유가 없다.

**그래도 서버 실패를 함께 다룬다.** 주소를 직접 쳐서 올 수 있고, **화면이 막는 것과 서버가 막는 것은 서로를 대신하지 않는다.**

### 등록 모달과 다른 점

| | 3.1 등록 | 3.2 수정 |
|---|---|---|
| 결제 방식 토글 | **있다** — 통로가 갈린다 | **없다** — 이미 정해진 건이다 |
| 나가는 통로 | 둘(일시불·할부) | **하나**(지출 수정) |
| 할부 개월 수·시작 연월 | 입력한다 | **잠긴다** |
| 대상 조회 | 없다 | **모달을 열기 전에** 한다 |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열릴 때 | `ExpenseGet` | GET | **목록을 그리기 전에** 그 지출을 조회해 폼에 채운다. 할부인지도 이 응답이 알려 준다 |
| 모달이 열릴 때 | `PaymentMethodListActive` | GET | 수단 칸의 선택지. **지출용**을 가리킨다 |
| 모달이 열릴 때 | `ExpendGroupListActive` | GET | 지출유형 칸의 선택지 |
| 「저장」을 누를 때 | `ExpenseUpdate` | PATCH | 고친 값을 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

**할부 건이어도 개월 수·시작 연월을 싣지 않는다.** 화면이 칸을 잠그지만 주소로 직접 올 수 있고, 실어 보내면 백엔드가 거절한다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록 행의 「수정」을 누른다 | **목록을 그리기 전에** 그 지출을 조회해 폼에 채운다 | 값이 채워진 수정 폼이 뜬다 | **모달 없이 목록만** 보이고 안내를 띄운다 |
| **할부 건**의 「수정」을 누른다 | 위와 같되 개월 수·시작 연월을 **읽기 전용으로** 그리고 안내를 함께 놓는다 | 잠긴 칸과 이유·대안이 보인다 | 위와 같다 |
| 없는 식별자로 모달을 연다 | 조회가 실패하면 모달을 열지 않는다 | (해당 없음) | **빈 모달이 아니라 목록만** 뜨고 안내가 보인다 |
| 식별자 없이 `?m=expense-edit` 만 연다 | 무엇을 조회할지 알 수 없으므로 모달을 열지 않는다 | (해당 없음) | 목록만 뜬다 |
| 값을 고쳐 「저장」을 누른다 | 고친 값을 보낸다 | 목록을 다시 그린다. 그 행과 **합계가 함께** 갱신된다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 |
| **할부 건의 금액만** 바꿔 저장한다 | 그 지출 한 건의 수정으로 보낸다 | **그 회차 하나만** 바뀐다. 할부 전체가 아니다 | 위와 같다 |
| 주소를 직접 쳐서 개월 수를 실어 보낸다 | 화면 모듈이 그 칸을 싣지 않는다. 넘어와도 서버가 거절한다 | (해당 없음) | **개월 수 칸 가까이** 사유와 대안이 보인다 |
| 「취소」를 누르거나 Esc 를 누른다 | 모달을 닫는다 | 목록이 그대로 남는다 | (해당 없음) |
| 미로그인으로 이 주소를 연다 | 부모 페이지의 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | — |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **할부 건의 잠긴 칸** | **개월 수와 시작 연월을 읽기 전용으로** 그린다. 화면이 미리 막는다 — 고칠 수 없는 칸을 열어 두고 저장에서 실패시킬 이유가 없다 |
| **잠긴 이유와 대안** | 둘을 함께 적는다 — ① **개월 수와 시작 연월은 바꿀 수 없다**는 것 ② **바꾸려면 지우고 다시 등록한다**는 것. 대안을 적지 않으면 **사용자는 막혔다고만 읽는다** |
| 할부 금액 수정의 범위 | **그 회차 하나만 바뀐다.** 할부 전체가 아니다 |
| 중도상환과의 구분 | 남은 회차를 한 번에 정리하는 것은 **목록의 「중도상환」**이며 이 모달에 두지 않는다 — 넣으면 금액을 고치러 들어갔다가 할부 전체가 정리되는 사고가 난다 |
| 화면이 막는 것과 서버가 막는 것 | **서로를 대신하지 않는다.** 주소를 직접 쳐서 올 수 있으므로 서버 실패도 함께 다룬다 |
| 보내지 않는 칸 | **할부 건이어도 개월 수·시작 연월을 싣지 않는다.** 실어 보내면 백엔드가 거절한다 |
| **없는 대상** | **모달을 열지 않고 목록만 남긴다.** 빈 모달을 띄우지 않는다 |
| 없는 것과 남의 것 | **가르지 않는다.** 백엔드가 한 코드로 묶었고 화면도 풀지 않는다 — 가르면 식별자를 훑어 남의 지출이 실재하는지 알아낼 수 있다 |
| **선택 목록의 출처** | **사용 중 목록으로만 채운다.** 관리 목록을 쓰면 사용자가 **지운 수단으로 지출을 고치게** 된다 |
| 수단의 용도 | **지출용**을 가리킨다 |
| 지출유형은 하나 필수 | 비우고 저장할 수 없다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다 |
| 지출유형 실패 | **지출유형 칸**에 붙인다 |
| 지출 값 오류 | **모달 폼 상단**이다. 한 코드가 금액·날짜·장소·내용 네 칸을 함께 가리킨다 |
| 할부 변경 거절 | **개월 수 칸**에 붙이고 **대안을 함께** 적는다 |
| 지출을 찾을 수 없음 | 모달 없이 **목록의 안내**로 보인다 |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 사용자가 고친 값을 **되받은 값으로 덮지 않는다** — 덮으면 방금 바꾼 것이 사라진다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/ledger-monthly.html` 의 `modal-expense-edit` 를 옮긴다. 프로토타입에 **할부 안내 문구가 이미 있다** — 잠금 자체는 화면이 새로 더하는 것이다.
- 프로토타입의 모달 푸터에 「삭제」 버튼이 있는데 **이 화면에는 두지 않는다.** 삭제는 목록 행의 버튼이 확인 다이얼로그를 거쳐 처리한다 — 수정 폼을 채우다가 삭제를 누르는 자리를 만들지 않는다.
- 부모는 5.1 월별 가계부다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 등록(3.1)과 칸이 거의 같지만 **결제 방식 토글이 없고** 할부 건의 두 칸이 잠긴다.
