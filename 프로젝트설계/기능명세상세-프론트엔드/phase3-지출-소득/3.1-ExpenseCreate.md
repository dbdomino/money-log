## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 셋이다. ① 월별 가계부(5.1)의 「지출 등록」 버튼 ② 사이드바의 「지출 등록」 메뉴 ③ 브라우저가 `/ledger?m=expense-create` 를 직접 여는 경우 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 지출을 등록한다 |

**별도 주소를 갖지 않는다.** 부모 목록 주소에 어느 모달인지를 실어 열고, **부모 목록이 함께 그려진 뒤 그 위에 뜬다.**

**사이드바의 활성 메뉴가 부모와 같다.** 지출 등록 모달을 열었는데 「월별 목록」 메뉴가 꺼져 보이면 사용자는 다른 화면으로 온 줄 안다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 5.1 의 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「지출 등록」과 닫기(X) |
| 실패 안내 | 모달 폼 상단. 어느 칸인지 가릴 수 없는 실패가 여기 뜬다 |
| 입력 폼 | 칸 여덟(+할부 칸 셋). 아래 표 참고 |
| 모달 푸터 | 「취소」와 「등록」 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 결제 방식 | 선택 | 필수 | **「일시불」 또는 「할부」.** 고른 값에 따라 **나가는 API 자체가 갈린다** |
| 수단 | 선택 | 필수 | **사용 중 수단 목록(지출용)** 으로 채운다. 관리 목록을 쓰지 않는다 |
| 지출유형 | 선택 | 필수 | **사용 중 지출유형 목록**으로 채운다. **비울 수 없는 칸**으로 그린다 |
| 결제일 | 날짜 | 일시불만 | `YYYY-MM-DD`. **할부에는 없다** — 할부는 시작 연월로 회차가 만들어진다 |
| 금액 | 숫자 | 일시불만 | 원 단위 양의 정수. **할부에는 이 칸이 없다** |
| 월 납부액 | 숫자 | 할부만 | 원 단위 양의 정수. **일시불의 「금액」과 칸 이름이 다르다** |
| 할부 개월 수 | 숫자 | 할부만 | **2 이상** |
| 시작 연월 | 월 | 할부만 | `YYYY-MM` |
| 장소 | 문자 | 필수 | 100자 이하 |
| 내용 | 문자 | 필수 | 255자 이하 |
| 「등록」 버튼 | 제출 버튼 | 필수 | 고른 결제 방식에 맞는 통로로 보낸다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫는다. 목록은 그대로 남는다 |

### 결제 방식에 따라 칸이 갈린다

| 사용자가 고른 것 | 금액 칸 | 결제일 | 함께 나가는 것 |
|---|---|:---:|---|
| 일시불 | **금액** | 있다 | — |
| 할부 | **월 납부액** | 없다 | 할부 개월 수 · 시작 연월 |

**한 모달에 두 벌의 칸을 두고 토글로 접는다.** 모달을 둘로 나누지 않는 이유는 사용자에게 **「지출 하나를 넣는 일」** 이기 때문이다 — 나누면 등록 버튼이 둘이 되어 무엇을 고를지 먼저 판단해야 한다.

| 누가 | 무엇을 |
|---|---|
| 브라우저 | 결제 방식에 따라 칸을 **접고 편다.** 입력 중의 편의다 |
| 화면 모듈 | 고른 값을 보고 **통로 자체를 가른다.** 보장이다 |

**접는 것은 편의이고 가르는 것이 보장이다.** 스크립트가 막힌 환경에서 칸이 접히지 않아도 화면 모듈이 올바른 통로로 보낸다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열릴 때 | `PaymentMethodListActive` | GET | 수단 칸의 선택지. **지출용**을 가리킨다. 사용 중인 것만 온다 |
| 모달이 열릴 때 | `ExpendGroupListActive` | GET | 지출유형 칸의 선택지. 사용 중인 것만 온다 |
| **일시불**로 등록을 누를 때 | `ExpenseCreate` | POST | 금액·결제일을 싣는다 |
| **할부**로 등록을 누를 때 | `ExpenseCreateInstallment` | POST | 월 납부액·할부 개월 수·시작 연월을 싣는다 |

**한 폼에서 제출되는 API 가 갈린다.** 이것은 칸 표에 드러나지 않아 여기 적는다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 5.1 에서 「지출 등록」을 누른다 | 부모 목록을 그리고 **선택 목록 둘을 함께 불러** 모달을 연다 | 빈 등록 폼이 뜨고 선택 칸이 채워져 있다 | 선택 목록을 받지 못하면 그 칸이 빈 채로 뜬다. 모달은 그대로 열린다 |
| 결제 방식을 「할부」로 바꾼다 | 브라우저가 금액·결제일 칸을 접고 월 납부액·개월 수·시작 연월 칸을 편다 | 할부 칸이 나타나고 **금액 칸이 사라진다** | (해당 없음 — 서버 호출이 없다) |
| 일시불로 채워 「등록」을 누른다 | **일시불 통로**로 보낸다. 금액 칸 이름이 그쪽이다 | 목록을 다시 그린다. 그 지출이 목록과 **합계에 함께** 나타난다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 |
| 할부로 채워 「등록」을 누른다 | **할부 통로**로 보낸다. 월 납부액·개월 수·시작 연월을 함께 싣는다 | 회차가 만들어지고 목록에 **할부 뱃지**로 뜬다 | 위와 같다 |
| 스크립트가 막힌 채로 제출한다 | 칸이 접히지 않아 양쪽 값이 다 남아 있어도 **고른 결제 방식대로 통로를 가른다** | 위와 같다 | 위와 같다 |
| 지출유형을 비우고 저장한다 | 브라우저가 먼저 막고, 넘어와도 서버가 거절한다 | (해당 없음) | 지출유형 칸에 사유가 보인다 |
| 「취소」를 누르거나 Esc 를 누른다 | 모달을 닫는다 | 목록이 그대로 남는다 | (해당 없음) |
| 미로그인으로 이 주소를 연다 | 부모 페이지의 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | — |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **나가는 통로가 둘이다** | **일시불과 할부가 서로 다른 API 로 나간다.** 한 폼에서 제출되지만 제출 대상 자체가 다르다 — 칸 표만 보고는 알 수 없다 |
| **금액 칸 이름이 다르다** | 일시불은 「금액」, 할부는 「월 납부액」이다. **일시불 폼 그대로 할부를 보내면 형식 오류**다 |
| 할부에 결제일이 없다 | 할부는 **시작 연월**로 회차가 만들어진다. 결제일 칸을 두면 사용자는 첫 회차 날짜를 고르는 줄 안다 |
| 접는 것과 가르는 것 | **접는 것은 브라우저, 가르는 것은 화면 모듈이다.** 스크립트가 막혀 칸이 접히지 않아도 고른 값대로 통로가 갈린다 |
| **선택 목록의 출처** | **사용 중 목록으로만 채운다.** 관리 목록에는 삭제 표시된 것과 사용 안 함이 함께 들어 있어, 쓰면 사용자가 **지운 수단으로 지출을 등록**하게 된다 |
| 수단의 용도 | **지출용**을 가리킨다. 소득용이 섞이면 고른 순간 서버가 용도 불일치로 거절하고, 사용자에게는 자기가 고른 것이 거절된 것으로 보인다 |
| **지출유형은 하나 필수** | 비우고 저장할 수 없다. 칸을 **비울 수 없는 칸으로** 그린다 |
| 할부 개월 수 | **2 이상**이다. 1개월은 할부가 아니다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다. 없는 것인지 용도가 안 맞는 것인지 가르지 않는다 — 사용자가 할 일은 어느 쪽이든 **다른 수단을 고르는 것**이다 |
| 지출유형 실패 | **지출유형 칸**에 붙인다 |
| 지출 값 오류 | **모달 폼 상단**이다. 한 코드가 금액·날짜·장소·내용 네 칸을 함께 가리켜 어느 칸인지 가릴 수 없다 — **짐작해 아무 칸에나 붙이면 사용자가 맞는 칸을 고치고 또 틀린다** |
| 할부 값 오류 | **개월 수 칸**에 붙인다 |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 모달을 닫아 버리면 사용자가 채운 칸이 전부 사라진다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않고 **입력값을 되비추지 않는다** |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/ledger-monthly.html` 의 `modal-expense-create` 를 옮긴다. 프로토타입에는 **어느 API 로 나가는지가 드러나지 않는다** — 결제 방식 선택과 할부 칸은 있지만, 금액 칸 이름이 갈린다는 것과 통로가 둘이라는 것은 표에 없다.
- 부모는 5.1 월별 가계부다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 수정(3.2)과 칸이 거의 같지만 **할부 건의 개월 수·시작 연월이 잠긴다**는 점이 다르다.
- 같은 지출을 **엑셀로 한꺼번에** 넣는 길이 3.5 에 있다.
