## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 셋이다. ① 월별 가계부(5.1)의 「소득 등록」 버튼 ② 사이드바의 「소득 등록」 메뉴 ③ 브라우저가 `/ledger?m=income-create` 를 직접 여는 경우 |

**별도 주소를 갖지 않는다.** 부모 목록 주소에 어느 모달인지를 실어 열고, 부모 목록이 함께 그려진 뒤 그 위에 뜬다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 5.1 의 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「소득 등록」과 닫기(X) |
| 실패 안내 | 모달 폼 상단. 어느 칸인지 가릴 수 없는 실패가 여기 뜬다 |
| 입력 폼 | **칸 넷.** 지출 모달보다 적다 |
| 모달 푸터 | 「취소」와 「등록」 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 수단 | 선택 | 필수 | **사용 중 수단 목록(소득용)** 으로 채운다. 지출 모달과 **다른 용도**를 가리킨다 |
| 금액 | 숫자 | 필수 | 원 단위 양의 정수 |
| 결제일 | 날짜 | 필수 | 입금일. `YYYY-MM-DD` |
| 내용 | 문자 | 선택 | 255자 이하. 비워도 된다 |
| 「등록」 버튼 | 제출 버튼 | 필수 | 소득 등록 요청을 보낸다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫는다. 목록은 그대로 남는다 |

### 지출 모달에 있고 여기 없는 것

| 없는 것 | 왜 |
|---|---|
| **지출유형 칸** | 백엔드가 그 칸을 받지 않는다. 두면 **사용자가 채운 값이 조용히 버려진다** |
| **장소 칸** | 위와 같다 |
| **할부 토글** | 소득에 할부라는 개념이 없다 |

**칸을 두고 버리는 것이 가장 나쁘다.** 사용자는 자기가 적은 것이 저장됐다고 믿는다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열릴 때 | `PaymentMethodListActive` | GET | 수단 칸의 선택지. **소득용**을 가리킨다. 사용 중인 것만 온다 |
| 「등록」을 누를 때 | `IncomeCreate` | POST | 수단·금액·결제일·내용을 싣는다 |

**지출유형 목록을 부르지 않는다.** 소득 모달에 그 칸이 없다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 5.1 에서 「소득 등록」을 누른다 | 부모 목록을 그리고 **소득용 수단 목록을 불러** 모달을 연다 | 빈 등록 폼이 뜨고 수단 칸이 채워져 있다 | 선택 목록을 받지 못하면 그 칸이 빈 채로 뜬다. 모달은 그대로 열린다 |
| 채워 「등록」을 누른다 | 소득 등록 요청을 보낸다 | 목록을 다시 그린다. 그 소득이 목록과 **소득 합계에 함께** 나타난다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 |
| 내용을 비우고 저장한다 | 선택 칸이라 그대로 보낸다 | 내용 없이 등록된다 | (해당 없음) |
| 목록에서 그 소득 행을 본다 | 지출유형·장소 칸을 **빈 칸으로** 그린다 | 지어낸 말이 없다 | (해당 없음) |
| 「취소」를 누르거나 Esc 를 누른다 | 모달을 닫는다 | 목록이 그대로 남는다 | (해당 없음) |
| 미로그인으로 이 주소를 연다 | 부모 페이지의 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | — |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **지출유형·장소 칸이 없다** | **두지 않는다.** 백엔드가 그 칸을 받지 않아, 두면 사용자가 채운 값이 **조용히 버려진다.** 사용자는 자기가 적은 것이 저장됐다고 믿는다 |
| 할부 토글이 없다 | 소득에 할부라는 개념이 없다 |
| **선택 목록의 출처** | **사용 중 수단 목록**으로만 채운다. 관리 목록에는 삭제 표시된 것과 사용 안 함이 함께 들어 있어, 쓰면 사용자가 **지운 수단으로 소득을 등록**하게 된다 |
| **수단의 용도** | **소득용**을 가리킨다. 지출용이 섞이면 고른 순간 서버가 용도 불일치로 거절하고, 사용자에게는 자기가 고른 것이 거절된 것으로 보인다 |
| 내용은 선택 | 비워도 된다. 비우면 저장되지 않을 뿐 거절되지 않는다 |
| 금액 | 원 단위 양의 정수다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다. 없는 것인지 용도가 안 맞는 것인지 가르지 않는다 — 사용자가 할 일은 어느 쪽이든 **다른 수단을 고르는 것**이다 |
| 소득 값 오류 | **모달 폼 상단**이다. 한 코드가 금액·날짜·내용 여러 칸을 함께 가리킨다 |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 모달을 닫아 버리면 사용자가 채운 칸이 전부 사라진다 |
| 목록에서의 표시 | 소득 행의 지출유형·장소는 **빈 칸**이다. 「없음」 같은 말을 채우지 않는다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/ledger-monthly.html` 의 `modal-income-create` 를 옮긴다.
- 부모는 5.1 월별 가계부다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 지출 등록(3.1)과 **칸 수가 다르다.** 지출은 여덟(+할부 셋), 소득은 넷이다 — 같은 모양으로 맞추려 들면 버려지는 칸이 생긴다.
- 같은 소득을 **엑셀로 한꺼번에** 넣는 길이 3.5 에 있다.
