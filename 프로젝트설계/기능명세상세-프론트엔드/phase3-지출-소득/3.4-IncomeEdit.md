## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 둘이다. ① 월별 가계부(5.1) 목록의 소득 행에 있는 「수정」 버튼 ② 브라우저가 `/ledger?m=income-edit&id={id}` 를 직접 여는 경우 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 소득을 고친다. 남의 것을 열 수 없는 것은 백엔드가 보장한다 |

**모달이 열리기 전에 값을 가져온다.** 부모 목록을 그리기 전에 그 소득을 조회해 모달에 싣는다.

**없는 대상이면 모달을 열지 않는다.** 빈 모달을 띄우지 말고 **목록만** 남긴 뒤 안내한다. **없는 것과 남의 것을 가르지 않는다.**

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 5.1 의 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「소득 수정」과 닫기(X) |
| 실패 안내 | 모달 폼 상단. 어느 칸인지 가릴 수 없는 실패가 여기 뜬다 |
| 입력 폼 | **칸 넷.** 등록(3.3)과 같다 |
| 모달 푸터 | 「취소」와 「저장」 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 수단 | 선택 | 필수 | **사용 중 수단 목록(소득용)** 으로 채운다. 현재 값이 골라진 채로 뜬다 |
| 금액 | 숫자 | 필수 | 원 단위 양의 정수 |
| 결제일 | 날짜 | 필수 | 입금일. `YYYY-MM-DD` |
| 내용 | 문자 | 선택 | 255자 이하. **비우면 비운다** |
| 「저장」 버튼 | 제출 버튼 | 필수 | 고친 값을 보낸다 |
| 「취소」 버튼 | 버튼 | 필수 | 모달을 닫는다. 목록은 그대로 남는다 |

### 여기에도 지출유형·장소 칸이 없다

등록(3.3)과 같은 이유다 — **백엔드가 그 칸을 받지 않는다.** 두면 사용자가 채운 값이 조용히 버려진다.

**할부 토글도 없다.** 소득에 할부라는 개념이 없다.

### 등록 모달과 다른 점

| | 3.3 등록 | 3.4 수정 |
|---|---|---|
| 칸 | 넷 | **같다** |
| 대상 조회 | 없다 | **모달을 열기 전에** 한다 |
| 내용을 비우면 | 내용 없이 등록된다 | **내용을 비운다** |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달이 열릴 때 | `IncomeGet` | GET | **목록을 그리기 전에** 그 소득을 조회해 폼에 채운다 |
| 모달이 열릴 때 | `PaymentMethodListActive` | GET | 수단 칸의 선택지. **소득용**을 가리킨다 |
| 「저장」을 누를 때 | `IncomeUpdate` | PATCH | 고친 값을 보낸다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

**지출유형 목록을 부르지 않는다.** 소득 모달에 그 칸이 없다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 소득 행의 「수정」을 누른다 | **목록을 그리기 전에** 그 소득을 조회해 폼에 채운다 | 값이 채워진 수정 폼이 뜬다 | **모달 없이 목록만** 보이고 안내를 띄운다 |
| 없는 식별자로 모달을 연다 | 조회가 실패하면 모달을 열지 않는다 | (해당 없음) | **빈 모달이 아니라 목록만** 뜨고 안내가 보인다 |
| 식별자 없이 `?m=income-edit` 만 연다 | 무엇을 조회할지 알 수 없으므로 모달을 열지 않는다 | (해당 없음) | 목록만 뜬다 |
| 값을 고쳐 「저장」을 누른다 | 고친 값을 보낸다 | 목록을 다시 그린다. 그 행과 **소득 합계가 함께** 갱신된다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 |
| 내용을 지우고 저장한다 | **비우라는 뜻으로** 보낸다 | 내용이 비워진다 | 위와 같다 |
| 「취소」를 누르거나 Esc 를 누른다 | 모달을 닫는다 | 목록이 그대로 남는다 | (해당 없음) |
| 미로그인으로 이 주소를 연다 | 부모 페이지의 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | — |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **지출유형·장소 칸이 없다** | **두지 않는다.** 백엔드가 그 칸을 받지 않아, 두면 사용자가 채운 값이 **조용히 버려진다** |
| 할부 토글이 없다 | 소득에 할부라는 개념이 없다 |
| **없는 대상** | **모달을 열지 않고 목록만 남긴다.** 빈 모달을 띄우지 않는다 |
| 없는 것과 남의 것 | **가르지 않는다.** 백엔드가 한 코드로 묶었고 화면도 풀지 않는다 |
| **선택 목록의 출처** | **사용 중 수단 목록**으로만 채운다. 관리 목록을 쓰면 사용자가 **지운 수단으로 소득을 고치게** 된다 |
| **수단의 용도** | **소득용**을 가리킨다 |
| 내용을 비우는 뜻 | 현재 값이 채워진 채로 뜨는 칸이라, 사용자가 지웠다면 **지우려는 뜻**이다. 「유지」로 읽으면 사용자는 지우고 저장했는데 그대로 남아 있는 화면을 보게 된다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다 |
| 소득 값 오류 | **모달 폼 상단**이다 |
| 소득을 찾을 수 없음 | 모달 없이 **목록의 안내**로 보인다 |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 사용자가 고친 값을 **되받은 값으로 덮지 않는다** |
| 목록에서의 표시 | 소득 행의 지출유형·장소는 **빈 칸**이다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/ledger-monthly.html` 의 `modal-income-edit` 를 옮긴다.
- 부모는 5.1 월별 가계부다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 등록(3.3)과 칸이 같다. 다른 것은 **대상 조회가 앞에 붙는다**는 것과 **내용을 비우는 뜻**이다.
- 삭제는 이 모달에 두지 않는다. 목록 행의 「삭제」가 확인 다이얼로그를 거쳐 처리한다.
