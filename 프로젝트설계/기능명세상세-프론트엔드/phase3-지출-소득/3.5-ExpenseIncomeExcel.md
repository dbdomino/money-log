**한 건씩 넣는 길(3.1·3.3)이 있으면 없어도 되지만, 과거 기록을 옮길 때 쓴다.**

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `excel` 이다 |
| 제목 | 본문 상단에 「엑셀 일괄 등록」 |
| **제약 안내** | **입력 전부터** 보인다. 허용 형식(`.xlsx`)과 한도(300행)를 적는다 |
| 양식 받기 | 「양식 다운로드」 링크. **화면 모듈 주소**로 건다 |
| 업로드 폼 | 파일 칸 하나와 「업로드」 버튼 |
| 결과 영역 | 성공이면 건수, 행 오류면 **표**. 성공과 실패의 **모양이 다르다** |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 제약 안내 | 문구 | 필수 | **올리기 전부터** 보인다. `.xlsx` 만·300행 이하 |
| 「양식 다운로드」 링크 | 링크 | 필수 | **화면 모듈 주소**를 건다. 백엔드 주소를 직접 걸지 않는다 |
| 엑셀 파일 칸 | 파일 | 필수 | 파일 선택 필터가 **`.xlsx` 하나**다 |
| **올리기 전 경고** | 문구 | — | 300행을 넘길 만한 **크기**에 브라우저가 경고한다. **막는 것이 아니라 알리는 것**이다 |
| 「업로드」 버튼 | 제출 버튼 | 필수 | 파일을 실어 보낸다 |
| 성공 건수 | 숫자 | — | 전체·지출·소득 셋 |
| 「가계부 보기」 링크 | 링크 | — | 성공했을 때만. 올린 것이 실제로 들어갔는지 확인할 자리다 |
| **행 오류 표** | 표 | — | 열 셋(행 번호·열·사유). **행 번호 순**이다 |
| 전체 실패 안내 | 문구 | — | 행 오류 표 **위에** 놓는다. **한 행이라도 틀리면 전체가 등록되지 않았다**는 것 |
| 폼 상단 실패 안내 | 문구 | — | 형식·한도·빈 파일 실패가 여기 뜬다. **제약을 다시 적는다** |

### 받고 올리는 두 방향

```
받기:   브라우저 ──주소──> 화면 모듈 ──인증+조회──> 백엔드 ──파일──> 브라우저
올리기: 브라우저 ──파일──> 화면 모듈 ──파일──> 백엔드
```

**어느 방향으로도 브라우저가 백엔드를 직접 부르지 않는다.** 지출유형 아이콘과 같은 규칙이다.

### 앞에서 막는 것과 서버가 막는 것

| 검사 | 누가 | 무엇을 |
|---|---|---|
| 형식 | 브라우저 | 파일 선택 필터를 **`.xlsx` 하나로** 둔다 |
| 형식 | **서버** | 확장자가 아니라 **내용으로** 판정한다 |
| 행 수 | 브라우저 | **크기로 가늠해 경고**한다 |
| 행 수 | **서버** | 정확히 세어 300행 초과를 거절한다 |

**앞에서 막는 것이 검사를 대신하지 않는다.** 브라우저가 행 수를 정확히 세려면 파일을 파싱해야 하는데 **그것은 화면이 할 일이 아니다** — 파싱하면 저장 규칙이 두 곳에 생긴다.

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **허용 형식** | **`.xlsx` 만이다.** 파일 선택 필터를 `.xlsx` 하나로 둔다 — 프로토타입이 `.xls` 를 함께 허용하는데 백엔드는 받지 않아, 그대로 두면 **고를 수는 있는데 거절당하는 형식**이 남는다 |
| 파일 선택 필터의 성격 | **고르기를 돕는 장치일 뿐 검사가 아니다.** 확장자만 바꾼 파일은 서버가 내용으로 판정해 거절한다 |
| **행 수 한도** | **300행**(헤더 제외)이다. 브라우저는 **크기로 가늠해 경고**하고 정확한 판정은 서버가 한다 |
| **올리기 전 경고** | **막는 것이 아니라 알리는 것이다.** 가늠이 틀릴 수 있으므로 사용자가 그래도 올리겠다면 보낸다 |
| **제약을 미리 적는다** | 허용 형식과 한도를 **입력 전부터** 보인다. 올린 뒤에야 알려 주면 사용자는 기다린 시간을 잃는다 |
| **거절 안내에 제약을 다시 적는다** | 형식·한도 실패 안내에 **무엇이 허용되는지**를 함께 적는다 — 모른 채 다른 파일을 시도하게 두지 않는다 |
| **화면이 엑셀을 파싱하지 않는다** | 파싱하면 **저장 규칙이 두 곳에 생긴다.** 행 수는 가늠해 경고하고 판정은 서버가 한다 |
| **양식 링크의 주소** | **화면 모듈 주소**를 건다. 백엔드 주소를 직접 걸지 않는다 — **양식 받기에도 인증이 필요한데 브라우저의 링크는 인증을 붙이지 못한다** |
| 양식 파일 이름 | **받은 이름을 그대로 넘긴다.** 화면이 이름을 지어내면 백엔드가 양식을 바꿀 때 **파일 이름만 옛것으로 남는다** |
| **양식 받기 실패** | **오류 화면으로 간다.** 아이콘과 다른 점이다 — 아이콘은 화면 한 귀퉁이가 비는 것으로 끝나지만, 양식을 못 받으면 사용자가 이 화면에서 할 수 있는 일이 없다 |
| **성공과 실패의 모양** | **다르다.** 성공은 건수 셋이고 실패는 행 번호·열·사유의 목록이다. 한 자리에 섞어 그리지 않는다 |
| 성공 표시 | 전체·지출·소득 **건수 셋**과 **가계부로 가는 길**을 함께 둔다 — 올린 것이 실제로 들어갔는지 확인할 자리가 있어야 한다 |
| **행 오류 표시** | **표로 보인다.** 칸 하나짜리 폼이라 붙일 칸이 없고, 오류가 여럿이라 한 줄로 보일 수 없다 |
| 행 오류의 순서 | **행 번호 순**이다. 사용자가 엑셀을 열어 **위에서부터 고치기** 때문이다 |
| **전체 실패임을 알린다** | 표 **위에** 적는다. **한 행이라도 틀리면 전체가 등록되지 않는다** — 화면이 「몇 건은 들어갔다」고 말하지 않는다 |
| **중복 행** | **경고하지 않는다.** 그대로 등록되는 것이 계약이며, 화면이 임의로 막으면 같은 금액을 두 번 쓴 사용자가 기록하지 못한다 — 같은 날 같은 금액을 두 번 쓰는 일은 흔하다 |
| 실패 안내 문구 | 백엔드가 준 문구와 행 오류를 그대로 쓴다. 화면이 문구를 새로 만들지 않는다 |
| **올린 파일의 바이트** | **로그에 넘기지 않는다.** 엑셀은 아이콘보다 크고, 로그로 가면 파일이 부풀고 **거래 내역이 그대로 남는다** |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

### 양식 시트의 열

| 열 | 내용 |
|----|------|
| A | 구분 (지출 / 소득) |
| B | 결제일 `YYYY-MM-DD` |
| C | 금액 |
| D | 수단 (본인 사용 중 수단) |
| E | 지출유형 (지출일 때) |
| F | 장소 (지출일 때) |
| G | 내용 |

**행 오류의 「열」은 이 표의 열을 가리킨다.** 사용자가 엑셀을 열었을 때 어느 칸인지 바로 찾을 수 있어야 한다.

## 비고

- 화면 구성은 `화면기획/proto/ledger-excel.html` 을 옮긴다. 프로토타입과 **두 곳이 다르다** — 파일 선택 필터가 `.xls` 를 함께 허용하고, 결과 표가 **성공 행까지 함께** 보인다. 그대로 두면 고를 수는 있는데 거절당하는 형식이 남고, 「몇 건은 들어갔다」로 읽히는 표가 남는다.
- **전체가 등록되지 않는 것이 계약이다.** 성공 행을 표에 섞지 않는다.
- 같은 지출·소득을 한 건씩 넣는 길이 3.1·3.3 에 있다.
- 결과 확인은 5.1 월별 가계부에서 한다. 이 화면은 그 목록을 쓰지 않는다.
- 실패 응답에서 행 오류를 꺼내려면 **백엔드 호출 통로의 실패 예외가 봉투의 값을 통째로 들고 올라와야** 한다. 코드와 문구만으로는 이 화면이 표를 그릴 수 없다.
