## 목적

- 연·월을 골라 그 달의 **고정지출 내역 목록**을 본다.
- 내역 1건의 금액·결제일·내용·수단을 그 달에 한해 바꾼다.
- 고정지출 관리 쪽 변경(신규 등록·수정·삭제)을 그 달 내역에 **버튼으로 반영**한다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 연·월 선택 | 조회할 연도·월. 변경 시 목록 재조회 |
| 내역 목록 | 그 달의 고정지출 내역. 직접 수정된 행은 표시(배지 등)로 구분 |
| 반영 버튼 | 「고정지출 반영」 — 관리 테이블 기준으로 그 달 재작성 |
| 단건 수정 폼 | 목록 행 선택 시 열림 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `year` / `month` | select | ✅ | 조회 연·월 |
| `amount` | number | ❌ | 단건 수정 — 그 달 금액 |
| `paymentDate` | date | ❌ | 단건 수정 — 그 달 결제일(그 달 안이어야 함) |
| `content` | text | ❌ | 단건 수정 — 그 달 내용 |
| `paymentMethodId` | select | ❌ | 단건 수정 — 그 달 수단 |
| `overwriteModified` | checkbox | ❌ | 재작성 — 직접 수정한 행까지 되돌릴지. 기본 **해제** |

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 모달 열림 · 연·월 변경 | `FixedExpenseMonthlyList` | GET | 그 달 내역 목록 (없으면 서버가 생성) |
| 단건 저장 | `FixedExpenseMonthlyUpdate` | PATCH | 그 달 1건 수정 |
| 「고정지출 반영」 클릭 | `FixedExpenseMonthlySync` | POST | 그 달 재작성. 응답의 목록으로 화면 갱신 |

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 연·월 선택 | `FixedExpenseMonthlyList` 호출 | 목록 표시 | `3403` → 연·월 안내 |
| 행 수정 후 저장 | 바뀐 필드만 PATCH | 그 행 갱신, 「수정됨」 표시 | `3405` → 재작성 안내 · `3401` → 입력 안내 |
| 「고정지출 반영」 클릭 | 확인 후 POST | 추가·갱신·삭제 건수 안내 + 목록 갱신 | 오류 문구 표시 |
| 「직접 수정분도 되돌리기」 체크 후 반영 | `overwriteModified=true`로 POST | 그 달 전체가 관리 값으로 | 오류 문구 표시 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| `paymentDate` | 선택한 연·월 안의 날짜여야 함 |
| `amount` | 0보다 커야 함 |
| `overwriteModified` | 체크 시 "직접 수정한 값이 사라집니다" 확인 |
| 빈 목록 | "이 달에 해당하는 고정지출이 없습니다" |

## 비고

- 고정지출 **관리(설정)** 수정은 4.5 `FixedExpenseEdit`이고, 이 화면은 **그 달 내역**만 다룬다.
- 관리 설정을 바꿔도 이미 열어본 달·지난 달은 자동으로 따라오지 않는다. 그래서 「고정지출 반영」 버튼이 있다.
- 상세 작성 시 [_TEMPLATE.md](../_TEMPLATE.md) 섹션을 채운다.
