## 목적

- 연·월을 골라 그 달의 **고정지출 내역 목록**을 본다.
- 내역 1건의 금액·결제일·내용·수단을 **그 달에 한해** 바꾼다.
- 고정지출 설정 쪽 변경(신규 등록·수정·삭제)을 그 달 내역에 **「고정지출 반영」으로** 맞춘다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 둘이다. ① 고정지출 설정 목록(4.2) **상단의 「월별 내역」 버튼** ② 브라우저가 `/fixed-expenses?m=monthly` 를 직접 여는 경우. **수정 모달(4.5)의 파급 범위 안내**에서 오는 길도 여기로 닿는다 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 내역을 본다 |

### 대상 식별자를 붙이지 않는다

**그 달 전체를 보는 화면이다.** 특정 고정지출 하나를 여는 것이 아니라서 모달 값에 **대상
식별자를 싣지 않는다** — `?m=monthly` 다.

**단건 수정에 들어갈 때만** `id` 가 붙는다.

**그래서 「월별 내역」 버튼이 목록 행이 아니라 화면 상단에 있다**(4.2). 행마다 두면 「이
고정지출의 월별」로 읽히고, 열어 보면 그 달 전체가 나와 사용자는 화면이 잘못 열린 것으로
생각한다 — **버튼의 위치가 곧 범위의 선언이다.**

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 4.2 의 설정 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「월별 고정지출 내역」과 닫기(X) |
| 연·월 선택 | 조회할 연·월. **바뀌면 다시 조회한다** |
| 상단 합계 | 그 달 고정지출 합계. **필터와 무관한 그 달 전체 기준** |
| 반영 영역 | **「고정지출 반영」 버튼**과 **「직접 수정분도 되돌리기」 체크박스** |
| 반영 결과 | 반영 뒤에만 보인다. **추가·갱신·삭제·보존 네 건수** |
| 안내 영역 | 실패 안내와 성공 안내 |
| 내역 목록 | 열 일곱(이름·수단·유형·결제일·그 달 금액·상태·관리) |
| 단건 수정 폼 | **같은 모달이 편집 상태로** 열릴 때만 보인다 |
| 확인 다이얼로그 | 반영이 쓴다. 007 의 공통 다이얼로그이며 본문은 이 화면이 넘긴다 |

| 요소 | 타입 | 필수 | 설명 |

| **「직접 수정분도 되돌리기」** | 체크박스 | 선택 | **기본 꺼짐.** 모달이 열릴 때마다 꺼진 상태로 시작한다 |

| **그 달 금액** 열 | 표 열 | 필수 | 원 단위. 오른쪽 정렬. **「기본 금액」이 아니다** |
| **상태** 열 | 표 열 | 필수 | **「수정됨」 뱃지.** 직접 고친 행에만 |
| 관리 열 | 표 열 | 필수 | 「수정」 |

| 그 달 결제일 (편집) | 날짜 | — | **그 달 안**이어야 한다 |

| 그 달 수단 (편집) | 선택 | — | **사용 중 수단 목록(지출용)** 으로 채운다 |
| 빈 목록 안내 | 문구 | — | 그 달 대상이 없을 때만 |
| 반영 결과 | 문구 | — | **추가·갱신·삭제·보존** 네 건수 |

**이름과 지출유형은 편집 칸에 두지 않는다** — 그것은 4.5 에서 바꾼다.

### 프로토타입에서 옮길 것이 거의 없다

프로토타입의 `modal-fx-monthly` 는 **연·월·금액 세 칸짜리 단건 수정 폼**이다. 확정 계약의 이
화면은 **그 달 목록 + 단건 수정 + 반영 버튼 + 되돌리기 체크박스**다.

| 프로토타입 | 이 화면 |
|---|---|
| 제목이 「월별 금액 수정」 | **「월별 고정지출 내역」** — 하나를 고치는 화면이 아니다 |
| 연·월·금액 세 칸 | **그 달 목록**(열 일곱) |
| 반영 버튼 없음 | **「고정지출 반영」과 되돌리기 체크박스** |
| 「수정됨」 표시 없음 | **상태 열에 뱃지** |

**가져오는 것은 모달 껍데기뿐이고 나머지는 새로 만든다.** 프로토타입이 만들어질 때는 월별
내역이 「설정 하나의 그 달 금액을 덮어쓰는 일」로 보였고, 확정 계약에서 **그 달 전체를
다루는 화면**이 됐다.

## 설정이 아니라 그 달에 잡힌 값이다

| | 4.2~4.5 설정 | **4.6 이 화면** |
|---|---|---|
| 무엇인가 | 매달 이만큼 나간다는 **기준값** | **그 달에 실제로 잡힌 값** |
| 금액의 이름 | **「기본 금액」** | **「그 달 금액」** |
| 고치면 | 미래 달로 번진다 | **그 달에서 끝난다** |

**같은 「금액」으로 적지 않는다.** 하나로 읽히면 사용자는 "고쳤는데 지난달이 안 바뀐다"를
버그로 신고한다.

## 그 달 행은 열어 볼 때 만들어진다

```
4.6 을 연다
   │
   ├─ 그 달 행이 있다 ─→ 그대로 보인다
   │
   └─ 없다 ─→ 서버가 적용 기간에 걸리는 설정을 펼쳐 만들고, 그 목록을 돌려준다
```

**화면은 그 달을 열 뿐이고 만들라고 따로 요청하지 않는다.** 만드는 규칙(적용 기간·말일 보정)이
백엔드에 있고, 화면이 따로 요청하면 **같은 판단이 두 곳에 생긴다.**

**조회가 쓰기를 겸하는 유일한 호출이다.**

**한 번도 열지 않은 달은 통계(6.2)의 고정지출 합계가 0 이다.** 그 달을 채우려면 이 화면이나
가계부를 먼저 연다 — 012 와 맞물리는 지점이다.

## 「수정됨」이 반영의 전제다

직접 고친 행을 **뱃지로 구분해** 보인다.

**구분이 없으면 반영을 누를 때 무엇이 보존되는지 알 수 없다.** 「직접 수정분도 되돌리기」가
무엇을 되돌리는지도 이 표시를 봐야 이해된다.

**되돌릴 수 있는 표시라 위험을 알리는 색을 쓰지 않는다** — 009 의 「삭제됨」과 다른 점이다.
반영으로 다시 설정 값이 될 수 있다.

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **모달 값에 식별자 없음** | `?m=monthly` 다. **그 달 전체를 보는 화면**이라 특정 고정지출을 가리키지 않는다 — **단건 수정에 들어갈 때만** `id` 가 붙는다 |
| 연·월의 기본값 | 주소에 없으면 **이번 달**이고 **서버 시각으로 정한다.** 브라우저 시각을 믿으면 시차가 있는 사용자가 다른 달을 본다 |
| 연·월 변경 | **바뀌면 다시 조회한다.** 세션에 두지 않아 뒤로 가기와 새 탭에서도 같은 달이 뜬다 |
| **조회가 쓰기를 겸한다** | 그 달 행이 없으면 **서버가 만든다.** 화면은 그 달을 열 뿐이고 **만들라고 따로 요청하지 않는다** — 만드는 규칙이 백엔드에 있고, 따로 요청하면 같은 판단이 두 곳에 생긴다 |
| 열지 않은 달의 통계 | **한 번도 열지 않은 달은 통계(6.2)의 고정지출 합계가 0 이다.** 그 달을 채우려면 이 화면이나 가계부를 먼저 연다 |
| **금액의 이름** | **「그 달 금액」**이다. 4.2~4.5 의 **「기본 금액」과 다르다** — 같은 말로 부르면 사용자는 하나로 읽는다 |
| **결제일 보정** | 매달 결제일이 그 달 말일보다 크면 **서버가 말일로 맞춘다.** 화면은 **받은 날짜를 그대로** 보이고 스스로 계산하지 않는다 |
| **「수정됨」 표시** | 직접 고친 행을 **뱃지로 구분**한다. 구분이 없으면 **반영 시 무엇이 보존되는지 알 수 없다** |
| 뱃지의 색 | **되돌릴 수 있는 표시라 위험 색을 쓰지 않는다** — 009 의 「삭제됨」과 다르다. 반영으로 다시 설정 값이 될 수 있다 |
| **상단 합계** | **그 달 전체 기준**이며 화면이 목록을 다시 더하지 않는다 — 010 의 가계부에서 정한 것과 같은 규칙이다 |
| 그 달 대상 없음 | **「이 달에 해당하는 고정지출이 없습니다」**를 보인다. 적용 기간이 그 달을 포함하지 않으면 나오지 않는다는 것이 이유이며, 빈 목록만 두면 불러오지 못한 것으로 읽는다 |
| **편집으로 바꿀 수 있는 것** | **금액·결제일·내용·수단 넷뿐**이다. **이름과 지출유형은 여기서 바꾸지 않는다** — 그것은 4.5 다 |
| **결제일 범위** | **그 달 안**이어야 한다. 화면이 칸 가까이 먼저 적고 밖의 날짜는 서버가 거절한다 |
| 편집의 수단 선택지 | **사용 중 수단 목록(지출용)** 으로 채운다. 등록(4.3)과 같다 |
| **모달을 겹치지 않는다** | 주소에 대상과 연·월을 실어 **같은 모달을 편집 상태로** 다시 연다. 007 의 모달 스크립트는 **Esc 가 전부 닫는 구조**라, 겹치면 위의 것만 닫으려 해도 **둘 다 닫히고 사용자가 고치던 값이 사라진다** |
| 편집 실패 착지 | **그 달과 대상이 유지된 채** 돌아온다 |
| **아직 만들어지지 않은 달** | 오류로 끝내지 않고 **「먼저 그 달을 열라」**는 길을 준다. 그 달을 여는 것이 곧 만드는 일이므로 **사용자가 할 일은 한 번 더 여는 것뿐**이다 |
| **반영의 확인** | 007 의 공통 확인 다이얼로그를 거친다. **본문은 체크박스 상태에 따라 갈린다** |
| **반영 결과** | **추가·갱신·삭제·보존 네 건수**를 보인다. **「보존」이 특히 중요하다** — 그 숫자가 **직접 고친 값이 살아남았다는 증거**이고, 되돌리기를 켰을 때 0 이 되는 것으로 무엇이 달랐는지 읽힌다 |
| 반영 뒤 갱신 | **응답의 목록과 합계로 갱신하고 다시 조회하지 않는다** |
| **되돌리기 기본값** | **꺼짐**이다. **모달이 열릴 때마다 꺼진 상태로 시작한다** — 이전에 켰던 것이 남아 있으면 다음 반영에서 모르고 지나간다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

### 반영 확인 다이얼로그 — 본문이 갈린다

**범위가 다르므로 문구도 다르다.** 같은 문구를 쓰면 **두 겹이 한 겹이 된다.**

| 되돌리기 | 담을 것 |
|---|---|
| **꺼짐** (기본) | ① 어느 달인지 ② 설정 기준으로 다시 만든다 ③ **직접 고친 행은 보존된다** |
| **켜짐** | 위 셋에 더해 ④ **「직접 수정한 값이 사라진다」** |

### 안전장치가 두 겹이다

| 겹 | 장치 |
|---|---|
| 1 | 체크박스가 **기본 꺼짐**이고 모달을 열 때마다 꺼진 상태로 시작한다 |
| 2 | 켠 채 누르면 **확인 문구가 달라진다** |

**한 겹이면 실수로 켠 것을 알아챌 자리가 없다.**

### 무엇이 일어나나 (반영)

| 대상 | 처리 |
|---|---|
| 적용 기간에 걸리는데 내역이 없는 것 | **추가** |
| 내역이 있고 직접 고치지 않은 것 | 설정 값으로 **갱신** |
| 내역이 있고 **직접 고친 것** | **보존** (되돌리기를 켜면 갱신) |
| 적용 기간이 그 달을 더는 포함하지 않는 것 | **삭제** |

**설정을 고쳤을 때 지난 달이 따라오지 않는 것**(4.5)의 **유일한 해결책**이다.

## 비고

- 화면 구성은 `화면기획/proto/fixed-expense-list.html` 의 `modal-fx-monthly` 에서 **모달 껍데기만** 가져온다. 프로토타입은 연·월·금액 세 칸짜리 단건 수정 폼이고 이 화면은 **그 달 목록**이라 옮길 것이 거의 없다.
- 부모는 4.2 고정지출 설정 목록이다. **「월별 내역」 버튼이 그 화면 상단에 있다.**
- **설정을 만들고 고치는 것은 4.2~4.5 다.** 이 화면은 **그 달에 잡힌 값**을 다룬다.
- **012 와 맞물린다** — 한 번도 열지 않은 달은 통계의 고정지출 합계가 0 이다.
- 가계부(5.1)의 고정지출 행도 이 내역에서 나온다. 그쪽은 읽기만 한다.
