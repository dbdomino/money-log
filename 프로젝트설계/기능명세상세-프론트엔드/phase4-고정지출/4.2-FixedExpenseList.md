## 목적

- 고정지출 설정 목록을 페이징으로 본다.
- 설정을 등록·수정·삭제하고, 그 달 내역(4.6)으로 가는 길을 둔다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 둘이다. ① 사이드바의 「고정지출 설정 목록」 메뉴 ② 브라우저가 `/fixed-expenses` 를 직접 여는 경우. **가계부(5.1)의 고정지출 행에서 오는 길**도 여기로 닿는다 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 고정지출을 연다. 본인 것만 보이는 것은 백엔드가 보장한다 |

**진입 판정은 007 이 한다.** 이 화면이 세션을 다시 확인하지 않는다.

**010 이 읽기만 하던 것을 만드는 곳이다.** 월별 가계부의 고정지출 행에는 수정·삭제가 없고
대신 이 화면으로 오는 안내가 있다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `fixed-list` 다 |
| 제목·상단 버튼 | 본문 상단에 「고정지출」과 오른쪽에 **「월별 내역」·「고정지출 등록」** 둘을 놓는다 |
| 안내 영역 | 표 위에 실패 안내와 성공 안내를 놓는다. 삭제 결과와 모달 대상 조회 실패가 여기에 뜬다 |
| 목록 표 | 열 일곱(이름·수단·유형·기본 금액·결제일·적용 기간·관리)을 가진 표를 놓는다 |
| 쪽 넘기기 | 표 아래에 놓는다. 007 의 페이징 환산기가 낸 값으로 만든다 |
| 모달 | 등록(4.3)·상세(4.4)·수정(4.5)·**월별 내역(4.6)** 넷을 이 화면 위에 띄운다 |
| 확인 다이얼로그 | 삭제가 쓴다. 007 의 공통 다이얼로그이며 본문은 이 화면이 넘긴다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 「고정지출 등록」 버튼 | 링크 버튼 | 필수 | 등록 모달을 연다(`?m=create`) |
| **「월별 내역」 버튼** | 링크 버튼 | 필수 | 그 달 **전체** 내역 모달을 연다(`?m=monthly`). **행마다 두지 않는다** — 아래 「왜 상단에 두나」 참고 |
| 이름 열 | 표 열 | 필수 | 고정지출 이름. 사용자가 붙인 값이다 |
| 수단 열 | 표 열 | 필수 | 수단 이름. **조회 시점 현재 이름**이며 화면이 저장된 값으로 덮어쓰지 않는다 |
| 유형 열 | 표 열 | 필수 | 지출유형 이름. 위와 같은 규칙이다 |
| **기본 금액** 열 | 표 열 | 필수 | 원 단위. 오른쪽 정렬. **「그 달 금액」이 아니다** — 그냥 「금액」으로 적으면 4.6 의 값과 같은 것으로 읽힌다 |
| 결제일 열 | 표 열 | 필수 | 「매달 N일」. 1~31 |
| **적용 기간** 열 | 표 열 | 필수 | 「2026-01 ~ 2026-12」. **프로토타입에 없어 더한 열**이다 |
| 관리 열 | 표 열 | 필수 | 「상세」·「수정」·「삭제」 셋을 놓는다 |
| 「상세」 버튼 | 링크 버튼 | 필수 | 그 설정의 상세 모달을 연다(`?m=detail&id={식별자}`) |
| 「수정」 버튼 | 링크 버튼 | 필수 | 그 설정의 수정 모달을 연다(`?m=edit&id={식별자}`) |
| 「삭제」 버튼 | 제출 버튼 | 필수 | 확인 다이얼로그를 거쳐 삭제 요청을 보낸다. **링크가 아니다** |
| 쪽 이동 | 링크 | 필수 | 007 의 페이징 환산기가 낸 쪽 번호로 만든다 |
| 빈 목록 안내 | 문구 | — | 행이 없을 때만 표 안에 보인다 |
| 실패 안내 | 문구 | — | 응답 코드와 백엔드 문구를 함께 적는다. 화면이 문구를 새로 만들지 않는다 |

### 프로토타입과 세 곳이 다르다

화면 구성은 `화면기획/proto/fixed-expense-list.html` 을 옮기되 **세 곳을 고친다.**

| 프로토타입 | 이 화면 | 왜 |
|---|---|---|
| 도구줄에 **상태 필터**(전체·진행·완료·중도상환) | **없다** | **백엔드에 상태 개념 자체가 없다.** 목록은 조회 구간만 받는다 — 그대로 옮기면 **고를 수는 있는데 아무것도 걸러지지 않는 필터**가 남는다 |
| 열에 **주기·다음 결제일·상태** | **적용 기간** 열 | 백엔드가 주지 않는 값이다. 「진행 중」이 뜻하려던 것은 **적용 기간이 지금을 포함하는가**이며, 시작·종료를 보이면 사용자가 읽는다 |
| 관리 열에 상세·수정·**월별** | 상세·수정·**삭제** | 삭제가 없으면 **지울 방법이 없는 목록**이다. 월별은 그 달 **전체**를 보는 화면이라 행에 두면 「이 고정지출의 월별」로 읽힌다 |

**「중도상환」은 할부(010)의 개념이다.** 고정지출에는 그 개념이 없는데 프로토타입이 두 기능을
섞었다. 프로토타입의 확인 다이얼로그가 「중도상환 확인」인 것도 같은 이유이며, 이 화면에서
그 자리는 **삭제 확인**이다.

### 화면이 「진행 중」을 계산하지 않는다

적용 기간이 지금을 포함하는지 **화면이 판단해 상태로 보이지 않는다.** 계산 규칙이 화면에
숨고, 백엔드가 나중에 상태를 도입하면 **두 규칙이 갈린다.**

**쪽 넘기기가 있어 더 그렇다.** 화면이 한 쪽만 받아 거르면 **다음 쪽에 있는 「진행 중」이
빠진다** — 쪽이 나뉜 목록에서 화면이 거르면 언제나 이 문제가 난다.

### 왜 「월별 내역」을 상단에 두나

4.6 은 **그 달 전체**를 보는 화면이고 특정 고정지출 하나를 여는 것이 아니다. 행마다 두면
**「이 고정지출의 월별」로 읽히고**, 열어 보면 그 달 전체가 나와 사용자는 화면이 잘못 열린
것으로 생각한다.

**버튼의 위치가 곧 범위의 선언이다.**

### 쪽 넘기기가 있다

**009·010 의 목록과 다르다.** 백엔드가 조회 구간을 **필수로** 받으며 시작점이 개수의 배수가
아니면 목록이 통째로 실패한다.

007 의 **페이징 환산기**를 쓴다 — 008 의 관리자 회원 목록에 이어 두 번째다. 환산기는 쪽
번호에서만 시작점을 만들므로 어긋난 값이 생길 경로가 없다.

**사용자가 시작점을 직접 넣는 칸을 두지 않는다.**

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때 · 쪽을 넘길 때 | `FixedExpenseList` | GET | 본인 고정지출 설정을 쪽 단위로 받는다. 수단·유형 이름과 쪽 정보가 함께 온다 |
| 확인 다이얼로그에서 삭제를 확정했을 때 | `FixedExpenseDelete` | DELETE | 그 설정을 지운다. **월별 내역도 함께 사라진다.** 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |

**모달이 부르는 API 는 4.3~4.6 이 갖는다.** 이 화면은 모달의 부모일 뿐이며, 모달을 여는
요청에서 대상 조회와 선택 목록 조회가 함께 일어난다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 사이드바에서 「고정지출 설정 목록」을 누른다 | 첫 쪽을 조회한다. 시작점은 007 의 환산기가 만든다 | 행과 적용 기간이 그려진다 | 007 의 오류 화면으로 간다 — 목록을 못 받으면 그릴 표가 없다 |
| 쪽을 넘긴다 | 쪽 번호에 개수를 곱해 시작점을 만들어 다시 조회한다 | 겹치는 행 없이 이어진다 | 위와 같다 |
| 「고정지출 등록」을 누른다 | 등록 모달을 연 채로 목록을 그린다. **선택 목록 둘**을 함께 부른다 | 빈 등록 폼이 모달로 뜬다 | 선택 목록을 받지 못하면 그 칸이 빈 채로 뜬다 |
| 「상세」를 누른다 | **목록을 그리기 전에** 그 설정을 조회해 모달에 채운다 | 값이 읽기 전용으로 보인다 | **모달 없이 목록만** 보이고 안내를 띄운다 |
| 「수정」을 누른다 | 위와 같이 조회해 수정 폼에 채운다 | 값이 채워진 수정 폼이 뜬다 | 위와 같다 |
| **「월별 내역」을 누른다** | 그 달 내역 모달을 연다. **대상 식별자를 싣지 않는다** | 그 달 전체 내역이 보인다 | 4.6 이 다룬다 |
| 「삭제」를 누른다 | 확인 다이얼로그를 띄운다. 본문은 이 화면이 넘긴다 | 다이얼로그가 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 다이얼로그에서 삭제를 확정한다 | 삭제 요청을 보낸다 | 목록을 다시 그린다. 그 행이 사라지고 **월별 내역도 함께** 사라진다 | 오류 화면으로 보내지 않고 목록을 다시 그리며 안내를 띄운다 |
| 009 에서 수단 이름을 바꾼 뒤 목록을 다시 연다 | 받은 값을 그대로 보인다 | **새 이름**이 보인다 | (해당 없음) |
| 모달에서 저장이 실패한다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 | (해당 없음) | 사용자가 채운 값이 남은 채 사유가 보인다 |
| 미로그인으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **상태 필터** | **두지 않는다.** 백엔드에 상태 개념이 없어 그대로 옮기면 **아무것도 걸러지지 않는 필터**가 남는다. 009 에서 「누를 수 있는데 언제나 실패하는 버튼을 두지 않는다」로 정한 것과 같은 판단이다 |
| **적용 기간 표시** | 「2026-01 ~ 2026-12」로 보인다. **「진행 중」을 화면이 계산해 보이지 않는다** — 계산 규칙이 화면에 숨고, 쪽이 나뉜 목록에서 화면이 거르면 **다음 쪽의 「진행 중」이 빠진다** |
| **금액 열의 이름** | **「기본 금액」**으로 적는다. 그냥 「금액」이면 4.6 의 **「그 달 금액」과 같은 것으로 읽히고**, 사용자는 "고쳤는데 지난달이 안 바뀐다"를 버그로 읽는다 |
| **이름 표시** | **받은 값 그대로**다. 수단·유형 이름은 **조회 시점 현재 값**이며 고정지출에 이름 컬럼이 없다 — 수단 이름을 바꾸면 이 목록도 새 이름으로 보인다. **화면이 저장된 값으로 덮어쓰지 않는다** |
| 010 과 이름 규칙이 반대 | 지출·소득(3.1~3.4)은 **등록 당시 스냅샷**이라 덮어쓰면 안 됐고, 고정지출은 **현재 이름**이라 옛 이름을 들고 있으면 안 된다. **화면이 할 일은 양쪽 다 같다 — 받은 값 그대로** |
| **관리 열** | **상세·수정·삭제 셋**이다. 「월별」을 행에 그리지 않는다 — 그 달 **전체**를 보는 화면이라 행에 두면 범위가 잘못 읽힌다 |
| 「월별 내역」의 자리 | **화면 상단 버튼 하나**다. **버튼의 위치가 곧 범위의 선언**이다 |
| 삭제 전송 방식 | **`POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는 것만으로 실행된다 |
| **삭제 확인 본문** | 셋을 담는다 — ① 어느 고정지출인지 ② **월별 내역이 지난 달 것까지 함께 사라진다** ③ **되돌릴 수 없다**. 아래 「삭제 확인 다이얼로그」 참고 |
| 쪽 넘기기 | **007 의 페이징 환산기**를 쓴다. 시작점이 개수의 배수가 아니면 목록이 통째로 실패하므로 **쪽 번호에서만** 시작점을 만든다 |
| 시작점 입력 | **사용자가 직접 넣는 칸을 두지 않는다.** 없는 길은 어긋날 일도 없다 |
| 고정지출 없음 | 목록을 다시 그리며 안내한다. 오류 화면으로 보내지 않는다 |
| 없는 것과 남의 것 | **가르지 않는다.** 백엔드가 한 코드로 묶었고 화면도 풀지 않는다 — 가르면 식별자를 훑어 남의 고정지출이 실재하는지 알아낼 수 있다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않고 **입력값을 되비추지 않는다** |
| 백엔드 불통 | 007 의 오류 화면으로 간다. 빈 목록으로 그리지 않는다 — 빈 목록과 「가져오지 못한 목록」이 똑같이 보이면 사용자는 자기 데이터가 없어졌다고 읽는다 |

### 삭제 확인 다이얼로그

다이얼로그는 문구를 만들지 않고 이 화면이 넘긴다. 세 가지를 담는다.

| 담을 것 | 왜 |
|---|---|
| 대상이 무엇인지 (고정지출 이름) | 표의 어느 행을 눌렀는지 다이얼로그만 보고 확인할 수 있어야 한다 |
| **월별 내역이 지난 달 것까지 함께 사라진다** | **009 의 수단·지출유형과 다르다.** 그쪽은 삭제 표시라 행이 남고 과거 내역의 이름도 살아 있었다. 고정지출은 **물리 삭제**이고 **내역이 따라 사라진다** — 적지 않으면 사용자는 「설정만 지우는 것」으로 읽고 **지난 기록이 날아간 뒤에야 안다** |
| **되돌릴 수 없다** | 화면에서 푸는 길이 없다 |

### 설정과 그 달 내역은 다른 것이다

이 화면이 다루는 것은 **「매달 이만큼 나간다」는 기준값**이고, 4.6 이 다루는 것은 **그 달에
실제로 잡힌 값**이다.

| | 4.2 이 화면 | 4.6 월별 내역 |
|---|---|---|
| 무엇인가 | **기준값** | **그 달에 잡힌 값** |
| 금액의 이름 | **「기본 금액」** | **「그 달 금액」** |
| 고치면 | **미래 달로 번진다**(4.5) | **그 달에서 끝난다** |

**같은 「금액」으로 부르지 않는다.** 하나로 읽히면 사용자는 "고쳤는데 지난달이 안 바뀐다"를
버그로 신고한다.

## 비고

- 화면 구성은 `화면기획/proto/fixed-expense-list.html` 을 옮긴다. 프로토타입과 **세 곳이 다르다** — 상태 필터가 있고, 열에 주기·다음 결제일·상태가 있으며, 관리 열에 삭제가 없고 「월별」이 있다.
- 등록(4.3)·상세(4.4)·수정(4.5)·월별 내역(4.6)은 이 화면 위의 모달이며 별도 주소를 갖지 않는다.
- **4.1 은 없다.** 고정지출 화면은 4.2 부터 센다.
- 목록+모달의 공통 모양은 2.1 수단 목록이 세운 것을 따른다. **다른 점은 쪽 넘기기가 있다는 것과 모달이 넷이라는 것**이다.
- **가계부(5.1)의 고정지출 행은 읽기만 한다.** 만들고 고치는 곳이 이 화면이다.
