## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 셋이다. ① 고정지출 설정 목록(4.2)의 「고정지출 등록」 버튼 ② 사이드바의 「고정지출 등록」 메뉴 ③ 브라우저가 `/fixed-expenses?m=create` 를 직접 여는 경우 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 고정지출을 만든다 |

**별도 주소를 갖지 않는다.** 부모 목록 주소에 어느 모달인지를 실어 열고, **부모 목록이 함께
그려진 뒤 그 위에 뜬다.**

**사이드바의 활성 메뉴가 부모와 같다.** 등록 모달을 열었는데 「고정지출 설정 목록」 메뉴가
꺼져 보이면 사용자는 다른 화면으로 온 줄 안다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 부모 목록 | 모달 뒤에 4.2 의 목록이 그대로 그려져 있다 |
| 모달 헤더 | 「고정지출 등록」과 닫기(X) |
| 실패 안내 | 모달 폼 상단. 어느 칸인지 가릴 수 없는 실패가 여기 뜬다 |
| 입력 폼 | **칸 열.** 아래 표 참고 |
| 모달 푸터 | 「취소」와 「저장」 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 이름 | 문자 | ✅ | 고정지출 이름(예: 월세). 목록에서 이 값으로 구분한다 |
| 수단 | 선택 | ✅ | **사용 중 수단 목록(지출용)** 으로 채운다. 관리 목록을 쓰지 않는다 |
| 지출유형 | 선택 | ✅ | **사용 중 지출유형 목록**으로 채운다 |
| **기본 금액** | 숫자 | ✅ | 원 단위 양의 정수. **매달 이만큼 나간다는 기준값**이며 4.6 의 「그 달 금액」과 다르다 |
| 매달 결제일 | 숫자 | ✅ | **1~31.** 범위를 입력 전에 적는다 |
| 내용 | 문자 | ✅ | |
| **적용 시작 연** | 숫자 | ✅ | **정수 한 칸** |
| **적용 시작 월** | 숫자 | ✅ | **정수 한 칸.** 1~12 |
| **적용 종료 연** | 숫자 | ✅ | 정수 한 칸 |
| **적용 종료 월** | 숫자 | ✅ | 정수 한 칸. 1~12 |
| 「저장」 버튼 | 제출 버튼 | ✅ | 등록 요청을 보낸다 |
| 「취소」 버튼 | 버튼 | ✅ | 모달을 닫는다. 목록은 그대로 남는다 |

**열 칸이 전부 필수다.** 하나라도 비우면 거절된다.

### 적용 기간은 정수 네 칸이다

| 기능 | 형식 | 예 |
|---|---|---|
| 3.1 할부 등록(010) | **문자열 한 칸** | `2026-01` |
| **4.3 고정지출(이 화면)** | **정수 네 칸** | `2026` · `1` · `2026` · `12` |

**같은 저장소 안에서 형식이 갈린다.** 한쪽 규칙을 다른 쪽에 옮기면 **등록이 형식 오류로
막힌다.**

**화면이 쪼개거나 합치지 않는다.** 입력 칸도 넷이고 보내는 값도 넷이다 — 한 칸으로 받아
화면이 쪼개면 **쪼개는 자리가 또 하나의 규칙**이 되고, 010 을 본 사람이 그쪽 형식으로 보낼
위험이 남는다.

**할부가 문자열인 이유**는 그 값이 「기간의 끝」이 아니라 **첫 회차가 떨어지는 한 지점**이고
개월 수와 함께 읽히는 단일 좌표라서다. 고정지출은 **시작·종료 두 쌍**이라 네 칸이 된다.

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **적용 기간의 형식** | **연과 월을 각각 정수로 보낸다.** 문자열 `YYYY-MM` 이 아니다 — 010 의 할부만 문자열을 쓰며, **한쪽 규칙을 다른 쪽에 옮기면 등록이 형식 오류로 막힌다** |
| 적용 기간을 쪼개지 않음 | **입력 칸도 넷이고 보내는 값도 넷이다.** 한 칸으로 받아 화면이 쪼개면 쪼개는 자리가 또 하나의 규칙이 된다 |
| 필수 칸 | **열 칸 전부 필수**다. 하나라도 비우면 거절된다 |
| **결제일 범위** | **1~31** 이다. 입력 칸에 최소·최대를 걸고 **범위를 칸 가까이 먼저 적는다** — 올린 뒤에야 알려 주면 사용자는 기다린 시간을 잃는다 |
| 화면이 막는 것과 서버가 막는 것 | **서로를 대신하지 않는다.** 주소를 직접 쳐서 올 수 있으므로 서버 실패도 함께 다룬다 |
| **선택 목록의 출처** | **사용 중 목록으로만 채운다.** 009 의 관리 목록에는 **삭제 표시된 것과 사용 안 함이 함께** 들어 있어, 쓰면 사용자가 **지운 수단으로 고정지출을 만들게** 된다 |
| 수단의 용도 | **지출용**을 가리킨다. 소득용은 선택지에 없다 |
| 종료가 시작보다 앞섬 | **화면이 미리 가리지 않는다.** 서버가 판정하며 사유가 폼 상단에 보인다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다. 없는 것인지 타인 것인지 가르지 않는다 — 사용자가 할 일은 어느 쪽이든 **다른 수단을 고르는 것**이다 |
| 지출유형 실패 | **지출유형 칸**에 붙인다 |
| **값 오류와 용도 불일치** | **한 코드가 둘을 겸한다** — 결제일·금액·기간 오류와 **수단 용도 불일치**가 같은 코드로 온다. 코드만으로는 어느 칸인지 가릴 수 없어 **폼 상단**에 두고 **서버 문구를 그대로** 보인다 |
| 용도 불일치의 문구 | 서버 문구가 **「지출용 수단을 고르라」**를 말해 준다. 화면이 **「수단이 없다」로 바꿔 적지 않는다** — 수단은 실재하고 목록에도 보인다 |
| 왜 상단인가 | 짐작해 결제일 칸에 붙이면 **수단을 잘못 고른 사용자가 결제일을 고치고 또 틀린다** |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 모달을 닫아 버리면 사용자가 채운 칸이 전부 사라진다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. **입력값을 되비추지 않는다** |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

### 등록에는 파급 안내가 없다

4.5 수정 모달에는 **「미래 달에만 반영된다」**는 안내가 있는데 **이 화면에는 두지 않는다** —
새로 만드는 것에는 **따라올 과거가 없다.**

다만 **그 달 내역이 바로 생기지는 않는다.** 적용 기간에 걸리는 달이라도 그 달 내역은
**4.6 을 열거나 가계부를 열 때** 만들어진다.

## 비고

- 화면 구성은 `화면기획/proto/fixed-expense-list.html` 의 `modal-fx-create` 를 옮긴다. 프로토타입에 **적용 기간이 이미 네 칸**으로 되어 있다 — 형식이 갈린다는 사실만 문서에 적으면 된다.
- 부모는 4.2 고정지출 설정 목록이다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 수정(4.5)과 칸이 같지만 **파급 범위 안내가 없다**는 점이 다르다.
- 여기서 만든 설정의 **그 달 내역**은 4.6 에서 보고 고친다.
