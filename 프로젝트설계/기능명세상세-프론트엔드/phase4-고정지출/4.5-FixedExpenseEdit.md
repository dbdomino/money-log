## 목적

- 고정지출 기본값을 수정한다.
- **그 수정이 어느 달까지 번지는지** 저장 전에 알린다.

## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 둘이다. ① 고정지출 설정 목록(4.2) 행의 「수정」 버튼 ② 브라우저가 `/fixed-expenses?m=edit&id={id}` 를 직접 여는 경우. 상세 모달(4.4)의 「수정」 링크도 여기로 온다 |
| 미로그인 | **막는다.** 부모 페이지의 진입 판정이 로그인 화면으로 보낸다 |
| 권한 없음 | 해당 없음 — 남의 것을 열 수 없는 것은 백엔드가 보장한다 |

**모달이 열리기 전에 값을 가져온다.** 부모 목록을 그리기 전에 그 설정을 조회해 모달에
싣는다 — 여는 일만 브라우저가 하면 열린 모달이 빈 채로 뜨고 값을 채우려면 다시 요청해야
한다.

**없는 대상이면 모달을 열지 않는다.** 빈 모달을 띄우지 말고 **목록만** 남긴 뒤 안내한다.
**없는 것과 남의 것을 가르지 않는다.**

| | 4.3 등록 | 4.5 수정 |
|---|---|---|
| 칸 | 열 | **같다** |
| 대상 조회 | 없다 | **모달을 열기 전에** 한다 |
| **파급 범위 안내** | **없다** — 따라올 과거가 없다 | **있다.** 저장 전에 보인다 |

## 수정은 미래 달로 번진다

**응답에 드러나지 않는 부작용이다.** 기본값을 고치면 백엔드가 **미래 달이면서 사용자가 직접
고치지 않은 월별 내역**을 함께 갱신한다.

| 달 | 따라오나 |
|---|:---:|
| 미래 달 · 직접 고치지 않음 | **✅ 바뀐다** |
| 미래 달 · **직접 고침** | ❌ 그대로 |
| 이번 달 · 지난 달 | ❌ 그대로 |

### 파급 범위를 저장 전에 알린다

모달에 **셋을 적는다.**

| 담을 것 | 왜 |
|---|---|
| **미래 달 중 직접 고치지 않은 내역에만 반영된다** | 이 기능에서 **가장 오해하기 쉬운 지점**이다. 안내가 없으면 사용자는 **지난달이 안 바뀐 것을 버그로 신고한다** |
| **직접 고친 달은 그대로다** | 4.6 에서 「수정됨」으로 지켜 둔 값이 보존된다는 뜻이며, 그쪽의 반영과 이어지는 개념이다 |
| **지난 달을 맞추려면 4.6 의 반영을 쓴다** | 제약만 적고 길을 적지 않으면 사용자는 **막혔다고만 읽는다** |

**저장 뒤가 아니라 저장 전이다.** 뒤에 알리면 "그럴 줄 알았으면 안 고쳤다"가 되고 되돌릴
방법도 마땅치 않다.

**길을 모달 안에 둔다.** 안내를 읽은 그 자리에서 4.6 으로 갈 수 있어야 한다 — 닫고
찾아가게 하면 무엇을 하려 했는지 잊는다.

### 화면이 건수를 계산하지 않는다

**"3건이 바뀝니다" 같은 숫자를 내지 않는다.** 그 숫자를 내려면 월별 내역을 전부 뒤져야 하고,
**판정 규칙이 화면과 백엔드 두 곳에 생긴다.**

**규칙을 말로 적는다.**

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 목록 행의 「수정」을 누른다 | **목록을 그리기 전에** 그 설정을 조회해 폼에 채운다 | 값이 채워진 수정 폼과 **파급 범위 안내**가 함께 뜬다 | **모달 없이 목록만** 보이고 안내를 띄운다 |
| 모달이 열린 직후를 본다 | — | **저장 전에** 「미래 달에만 반영된다」가 보이고 **4.6 으로 가는 길**이 함께 있다 | (해당 없음) |
| 없는 식별자로 모달을 연다 | 조회가 실패하면 모달을 열지 않는다 | (해당 없음) | **빈 모달이 아니라 목록만** 뜨고 안내가 보인다 |
| 식별자 없이 `?m=edit` 만 연다 | 무엇을 조회할지 알 수 없으므로 모달을 열지 않는다 | (해당 없음) | 목록만 뜬다 |
| 금액을 바꿔 「저장」을 누른다 | 고친 값을 보낸다. **적용 기간도 정수 네 칸**으로 싣는다 | 목록을 다시 그린다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 |
| 저장 뒤 **미래 달** 내역을 연다(4.6) | — | **새 금액**이다 | (해당 없음) |
| 저장 뒤 **지난 달** 내역을 연다 | — | **옛 금액 그대로**다 | (해당 없음) |
| 어떤 달을 직접 고친 뒤 설정을 또 바꾼다 | — | 그 달은 **바뀌지 않는다** | (해당 없음) |
| 지난 달을 맞추고 싶다 | 안내의 길을 따라 4.6 으로 간다 | 「고정지출 반영」으로 그 달이 설정 기준으로 맞춰진다 | (해당 없음) |
| 결제일에 32 를 넣어 저장한다 | 화면이 먼저 막고, 넘어와도 서버가 거절한다 | (해당 없음) | **1~31** 임이 안내된다 |
| 「취소」를 누르거나 Esc 를 누른다 | 모달을 닫는다 | 목록이 그대로 남는다 | (해당 없음) |
| 미로그인으로 이 주소를 연다 | 부모 페이지의 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | — |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| **파급 범위 안내** | **저장 전에** 보인다. 셋을 적는다 — ① **미래 달 중 직접 고치지 않은 내역에만 반영된다** ② **직접 고친 달은 그대로다** ③ **지난 달을 맞추려면 4.6 의 반영을 쓴다** |
| 왜 저장 전인가 | 뒤에 알리면 **"그럴 줄 알았으면 안 고쳤다"**가 되고 되돌릴 방법도 마땅치 않다 |
| **대안을 함께 적는다** | 제약만 적고 길을 적지 않으면 사용자는 **막혔다고만 읽는다.** 009 의 「사용 안 함으로 돌리라」, 010 의 「지우고 다시 등록하라」와 같은 성격이다 |
| 길의 자리 | **모달 안**이다. 안내를 읽은 그 자리에서 갈 수 있어야 한다 |
| **건수를 계산하지 않는다** | "몇 건이 바뀝니다"를 내려면 월별 내역을 전부 뒤져야 하고 **판정 규칙이 두 곳에 생긴다.** 규칙을 말로 적는다 |
| **적용 기간의 형식** | **연과 월을 각각 정수로 보낸다.** 등록(4.3)과 같으며 문자열 `YYYY-MM` 이 아니다 — 010 의 할부만 문자열을 쓴다 |
| **금액의 이름** | **「기본 금액」**이다. 4.6 의 **「그 달 금액」과 다르다** — 같은 말로 부르면 사용자는 하나로 읽는다 |
| **결제일 범위** | **1~31** 이다. 입력 전에 적고 칸에도 최소·최대를 건다 |
| **선택 목록의 출처** | **사용 중 목록으로만 채운다.** 관리 목록을 쓰면 사용자가 **지운 수단으로 고정지출을 고치게** 된다 |
| 수단의 용도 | **지출용**을 가리킨다 |
| 삭제 표시된 수단을 쓰던 설정 | **설정은 그대로 열린다** — 이미 걸린 참조는 유지된다. 다만 **다른 수단으로 바꾸려 할 때** 삭제된 것은 고를 수 없다 |
| **없는 대상** | **모달을 열지 않고 목록만 남긴다.** 빈 모달을 띄우지 않는다 |
| 없는 것과 남의 것 | **가르지 않는다.** 가르면 식별자를 훑어 남의 고정지출이 실재하는지 알아낼 수 있다 |
| 실패가 붙는 자리 | 어느 칸인지 아는 실패는 그 칸 아래, 가릴 수 없는 실패는 **모달 폼 상단**이다 |
| 수단 실패 | **수단 칸**에 붙인다 |
| 지출유형 실패 | **지출유형 칸**에 붙인다 |
| **값 오류와 용도 불일치** | **한 코드가 둘을 겸한다.** 코드만으로 칸을 가릴 수 없어 **폼 상단**에 두고 **서버 문구를 그대로** 보인다 — 짐작해 붙이면 사용자가 맞는 칸을 고치고 또 틀린다 |
| 고정지출을 찾을 수 없음 | 모달 없이 **목록의 안내**로 보인다 |
| **모달 제출 실패** | **모달을 연 채로** 부모 목록을 다시 그린다. 사용자가 고친 값을 **되받은 값으로 덮지 않는다** — 덮으면 방금 바꾼 것이 사라진다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 입력값을 되비추지 않는다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |

## 비고

- 화면 구성은 `화면기획/proto/fixed-expense-list.html` 의 `modal-fx-edit` 를 옮긴다. **파급 범위 안내는 프로토타입에 없어 새로 더한다** — 응답에 드러나지 않는 부작용이라 적지 않으면 구현자도 사용자도 모른다.
- 부모는 4.2 고정지출 설정 목록이다. **모달 제출 실패도 그 목록을 다시 그린다.**
- 등록(4.3)과 칸이 같지만 **대상 조회가 앞에 붙고 파급 범위 안내가 더해진다.**
- **지난 달을 맞추는 길은 4.6 의 「고정지출 반영」 하나뿐이다.**
