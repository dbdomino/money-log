## 진입

| 항목 | 내용 |
|------|------|
| 진입 경로 | 셋이다. ① **로그인에 성공하면 이 주소로 착지한다** ② 사이드바의 「월별 목록」 메뉴 ③ 브라우저가 `/ledger` 를 직접 여는 경우 |
| 미로그인 | **막는다.** 진입 판정이 로그인 화면(`/auth/login`)으로 보낸다 |
| 권한 없음 | 해당 없음 — 로그인한 회원이면 등급과 무관하게 자기 가계부를 연다. 본인 것만 보이는 것은 백엔드가 보장한다 |

**진입 판정은 007 이 한다.** 이 화면이 세션을 다시 확인하지 않는다.

**로그인 직후 착지가 이 화면이다.** 008 이 로그인 성공 시 이 주소로 보내므로, 여기가 사용자가 가장 먼저 보는 화면이다. 목록 조회가 실패해도 **빈 목록과 합계 0 으로 그린다** — 여기서 오류 화면으로 가면 로그인하자마자 오류를 만난다.

## 화면 구성

### 영역

| 영역 | 설명 |
|------|------|
| 사이드바·상단바 | 로그인 후 레이아웃이 제공한다. 사이드바의 활성 메뉴는 `ledger` 다 |
| 제목·등록 버튼 | 본문 상단에 「월별 가계부」와 오른쪽에 「소득 등록」·「지출 등록」 버튼을 놓는다. 둘 다 이 화면 위의 모달을 연다 |
| 도구줄 | 연·월과 **필터 여섯**(수단·지출유형·시작일·종료일·검색어·종류)과 **정렬 둘**(기준·방향)을 놓는다. 프로토타입에는 연·월·검색어 셋뿐이라 나머지를 더한다 |
| 상단 요약 | 지출 합계·소득 합계·잔액 셋을 가로로 놓는다. **필터와 무관한 그 달 전체 값**이다 |
| 안내 영역 | 표 위에 실패 안내와 성공 안내를 놓는다. 삭제·중도상환·모달 대상 조회의 결과가 여기에 뜬다 |
| 목록 표 | 열 일곱(일자·구분·수단·유형·내용·금액·관리)을 가진 표를 놓는다 |
| 모달 | 지출 등록(3.1)·지출 수정(3.2)·소득 등록(3.3)·소득 수정(3.4) 넷을 이 화면 위에 띄운다 |
| 확인 다이얼로그 | 삭제와 중도상환이 각각 쓴다. 007 의 공통 다이얼로그이며 본문은 이 화면이 넘긴다 |

### 입력·표시 요소

| 요소 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| 「지출 등록」 버튼 | 링크 버튼 | 필수 | 지출 등록 모달을 연다(`?m=expense-create`) |
| 「소득 등록」 버튼 | 링크 버튼 | 필수 | 소득 등록 모달을 연다(`?m=income-create`) |
| 연 선택 | 선택 | 필수 | 조회할 연도. **주소에 없으면 서버 시각의 이번 해**다 |
| 월 선택 | 선택 | 필수 | 조회할 월(1~12). **주소에 없으면 서버 시각의 이번 달**이다 |
| 수단 필터 | 선택 | 선택 | 그 수단의 행만 남긴다. 선택지는 **사용 중 수단 목록**으로 채운다 |
| 지출유형 필터 | 선택 | 선택 | 그 유형의 행만 남긴다. 선택지는 **사용 중 지출유형 목록**으로 채운다 |
| 시작일 필터 | 날짜 | 선택 | 그 달 안에서 결제일을 더 좁힌다. 이 날짜 **이상**(포함) |
| 종료일 필터 | 날짜 | 선택 | 그 달 안에서 결제일을 더 좁힌다. 이 날짜 **이하**(포함) |
| 검색어 필터 | 문자 | 선택 | **내용과 장소** 두 칸을 부분 일치로 본다. 칸 아래에 그 사실을 한 줄로 적는다 |
| 종류 필터 | 다중 선택 | 선택 | 지출·할부·소득·고정지출. **여러 개를 함께 고를 수 있다** — 한 값만 보내면 「지출과 할부만」 같은 조합을 만들 수 없다 |
| 정렬 기준 | 선택 | 선택 | **결제일과 금액 둘뿐**이다. 기본은 결제일 |
| 정렬 방향 | 선택 | 선택 | 오름차순·내림차순. 기본은 내림차순 |
| 「필터 적용」 버튼 | 제출 버튼 | 필수 | 고른 조건을 주소에 실어 이 화면을 다시 연다 |
| 지출 합계 | 숫자 | 필수 | 백엔드가 준 그 달 지출 합계 **그대로**. 화면이 목록을 다시 더하지 않는다 |
| 소득 합계 | 숫자 | 필수 | 백엔드가 준 그 달 소득 합계 그대로 |
| 잔액 | 숫자 | 필수 | 소득 합계 − 지출 합계. **응답에 없어 화면이 두 값을 뺀다** |
| 일자 열 | 표 열 | 필수 | 그 행의 결제일 `YYYY-MM-DD` |
| 구분 열 | 표 열 | 필수 | **뱃지.** 지출 · 할부 · 소득 · 고정지출 넷을 다른 모양으로 보인다 |
| 수단 열 | 표 열 | 필수 | 수단 이름. **받은 값 그대로**이며 화면이 다시 조회해 덮어쓰지 않는다 |
| 유형 열 | 표 열 | 필수 | 지출유형 이름. **소득 행은 빈 칸**이고 지어낸 말을 채우지 않는다 |
| 내용 열 | 표 열 | 필수 | 내용. 장소가 있으면 함께 보인다. **할부 행은 회차를 함께** 적는다(「3/12」) |
| 금액 열 | 표 열 | 필수 | 원 단위. 오른쪽 정렬 |
| 관리 열 | 표 열 | 필수 | **행 종류마다 다르다.** 아래 「행이 열 수 있는 것」 참고 |
| 「수정」 버튼 | 링크 버튼 | — | 지출·할부·소득 행에만 그린다. 그 건의 수정 모달을 연다 |
| 「삭제」 버튼 | 제출 버튼 | — | 지출·할부·소득 행에만 그린다. 확인 다이얼로그를 거친다. **링크가 아니다** |
| 「중도상환」 버튼 | 제출 버튼 | — | **할부 행에만** 그린다. 확인 다이얼로그를 거친다 |
| 고정지출 안내 | 문구 | — | 고정지출 행의 관리 열에 놓는다. 고정지출 설정 화면으로 가는 길과 **왜 여기서 고칠 수 없는지**를 함께 적는다 |
| 빈 목록 안내 | 문구 | — | 행이 없을 때만 표 안에 보인다. 합계 0 과 함께 뜬다 |
| 실패 안내 | 문구 | — | 응답 코드와 백엔드 문구를 함께 적는다. 화면이 문구를 새로 만들지 않는다 |

### 행이 열 수 있는 것

| 종류 | 수정 | 삭제 | 중도상환 |
|---|:---:|:---:|:---:|
| 지출 | ✅ | ✅ | ❌ |
| 할부 | ✅ (개월 수·시작 연월 잠김) | ✅ | **✅** |
| 소득 | ✅ | ✅ | ❌ |
| 고정지출 | **❌** | **❌** | ❌ |

**행 종류마다 열 수 있는 것이 다르다.** 표만 보고는 알 수 없어 여기 적는다 — 적지 않으면 모든 행에 같은 버튼이 그려진다.

### 종류마다 비는 칸이 다르다

| 종류 | 지출유형 | 장소 | 할부 회차 | 고정지출 이름 |
|---|:---:|:---:|:---:|:---:|
| 지출 | 있다 | 있다 | — | — |
| 할부 | 있다 | 있다 | **있다** | — |
| 소득 | **없다** | **없다** | — | — |
| 고정지출 | 있다 | **없다** | — | **있다** |

**뱃지가 먼저 오는 이유가 이 표다.** 종류를 알아야 그 행에 왜 빈 칸이 있는지 읽힌다.

### 쪽 넘기기가 없다

백엔드 목록이 조회 구간을 받지 않고 **한 달치를 전부** 돌려주며 합계도 함께 온다. 007 의 페이징 환산기를 쓰지 않는다 — 쪽을 나누면 합계와 목록의 기준이 갈린다.

## 호출 API

상세 필드: [기능명세상세-백엔드](../../기능명세상세-백엔드/README.md)

| 시점 | API 이름 | Method | 용도 |
|------|----------|--------|------|
| 화면이 열릴 때 | `LedgerMonthlyList` | GET | 그 달의 지출·할부·소득·고정지출을 한 목록으로 받는다. 합계도 함께 온다. **조회 구간을 싣지 않는다** |
| 도구줄에 선택지를 채울 때 | `PaymentMethodListActive` | GET | 수단 필터의 선택지. **사용 중인 것만** 온다 |
| 도구줄에 선택지를 채울 때 | `ExpendGroupListActive` | GET | 지출유형 필터의 선택지. 사용 중인 것만 온다 |
| 확인 다이얼로그에서 지출 삭제를 확정했을 때 | `ExpenseDelete` | DELETE | 그 지출을 지운다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |
| 확인 다이얼로그에서 소득 삭제를 확정했을 때 | `IncomeDelete` | DELETE | 그 소득을 지운다. 브라우저는 `POST` 로 보내고 화면 모듈이 옮긴다 |
| 확인 다이얼로그에서 중도상환을 확정했을 때 | `ExpenseSettleInstallmentRemainder` | PATCH | 그 할부 그룹의 **남은 회차를 한 번에** 정리한다. 본문을 싣지 않는다 |

**모달이 부르는 API 는 3.1~3.4 가 갖는다.** 이 화면은 모달의 부모일 뿐이며, 모달을 여는 요청에서 대상 조회와 선택 목록 조회가 함께 일어난다.

## 동작

| 사용자 행동 | 프론트 처리 | 성공 시 | 실패 시 |
|-------------|-------------|---------|---------|
| 로그인에 성공한다 | 008 이 이 주소로 보낸다. 연·월이 없으므로 **서버 시각의 이번 달**로 조회한다 | 추가 조작 없이 이번 달 목록과 합계가 뜬다 | 빈 목록과 합계 0 으로 그린다. **오류 화면으로 가지 않는다** |
| 사이드바에서 「월별 목록」을 누른다 | 위와 같다 | 위와 같다 | 위와 같다 |
| 연·월을 바꿔 「필터 적용」을 누른다 | 연·월을 주소에 실어 다시 연다. **걸어 둔 필터가 함께 실린다** | 그 달의 목록과 합계가 뜨고 필터가 유지된다 | 위와 같다 |
| 필터를 걸고 「필터 적용」을 누른다 | **비어 있는 조건은 싣지 않는다.** 빈 값을 보내면 백엔드가 「그 값으로 걸러 달라」로 읽어 결과가 통째로 빈다 | 목록만 좁혀지고 **상단 합계는 그대로**다 | 위와 같다 |
| 필터 결과가 0건이다 | 빈 목록임을 알린다 | **필터가 풀리지 않는다.** 사용자가 건 조건이다 | (해당 없음) |
| 「지출 등록」·「소득 등록」을 누른다 | 등록 모달을 연 채로 목록을 그린다. **선택 목록 둘**을 함께 부른다 | 빈 등록 폼이 모달로 뜬다 | 선택 목록을 받지 못하면 선택 칸이 빈 채로 뜬다 |
| 행의 「수정」을 누른다 | **목록을 그리기 전에** 그 지출·소득을 조회해 모달에 채운다 | 값이 채워진 수정 폼이 뜬다 | **모달 없이 목록만** 보이고 안내를 띄운다. 빈 모달을 띄우지 않는다 |
| 행의 「삭제」를 누른다 | 확인 다이얼로그를 띄운다. 본문은 이 화면이 넘긴다 | 다이얼로그가 뜬다 | (해당 없음 — 서버 호출이 없다) |
| 다이얼로그에서 삭제를 확정한다 | 삭제 요청을 보낸다 | 목록을 다시 그린다. 그 행과 **합계에서 함께** 빠진다 | 오류 화면으로 보내지 않고 목록을 다시 그리며 안내를 띄운다 |
| 할부 행의 「중도상환」을 누른다 | 확인 다이얼로그를 띄운다 | 다이얼로그가 뜬다 | (해당 없음) |
| 다이얼로그에서 중도상환을 확정한다 | 본문 없이 중도상환 요청을 보낸다 | 남은 회차가 정리되고 목록이 갱신된다 | **정리할 회차가 없으면** 오류 화면이 아니라 목록의 안내로 사유가 보인다 |
| 고정지출 행의 관리 열을 본다 | 버튼을 그리지 않고 안내만 놓는다 | 고정지출 설정 화면으로 가는 길이 보인다 | (해당 없음) |
| 모달에서 저장이 실패한다 | 실패를 칸에 갈라 붙이고 **모달을 연 채로** 목록을 다시 그린다 | (해당 없음) | 사용자가 채운 값이 남은 채 사유가 보인다 |
| 미로그인으로 이 주소를 연다 | 진입 판정이 막는다 | (해당 없음) | 로그인 화면으로 보내진다 |
| 백엔드에 닿지 못한다 | 007 의 오류 화면으로 간다 | (해당 없음) | 빈 목록으로 그리지 않는다 — 「닿지 못함」과 「거래 없음」은 다르다 |

## 검증·안내

| 대상 | 규칙·문구 |
|------|-----------|
| 연·월의 기본값 | 주소에 없으면 **이번 달**이고, **서버 시각으로 정한다.** 브라우저 시각을 믿으면 시차가 있는 사용자가 다른 달을 본다 |
| 행 종류 표시 | **뱃지로 먼저 보인다.** 지출·할부·소득·고정지출 넷이 서로 다른 모양이다. 영문 값(`EXPENSE`·`INSTALLMENT`·`INCOME`·`FIXED`)을 그대로 내보내지 않는다 |
| **비는 칸** | **빈 채로 둔다.** 소득 행의 지출유형·장소, 소득·고정지출 행의 장소가 그렇다. 「없음」 같은 말을 채우면 **「비어 있는 값」과 「없는 항목」이 구분되지 않는다** |
| 할부 행의 회차 | 「3/12」처럼 **함께 적는다.** 적지 않으면 사용자는 같은 지출이 여러 번 들어간 줄 안다 |
| **이름 규칙** | **화면이 이름을 다시 조회해 덮어쓰지 않는다.** 고정지출 행만 조회 시점 현재 이름이고 나머지 셋은 등록 당시 스냅샷이다 — 수단 이름을 바꾼 뒤 열면 고정지출 행만 새 이름으로 보이는데 **버그가 아니라 설계다.** 맞추려 들면 **과거 기록이 사후에 바뀐다** |
| 이름 규칙의 안내 | **사용자에게 설명하지 않는다.** 목록에 「이 이름은 스냅샷입니다」 같은 주석을 달면 읽기 어려워진다. 이 규칙은 문서에 남기고 화면은 조용히 지킨다 |
| **상단 합계** | **백엔드가 준 값 그대로**이며 화면이 목록을 다시 더하지 않는다. **필터와 무관하다** — 필터를 걸면 목록의 합과 상단 합계가 달라지는데 그것이 의도다. 맞추려 하면 「필터를 걸었는데 이번 달 지출이 줄어드는」 화면이 되고, 사용자는 자기가 쓴 돈이 줄었다고 읽는다 |
| 잔액 | 소득 합계에서 지출 합계를 뺀다. **응답에 없다.** 같은 기준의 두 값을 빼는 것이라 필터와 무관하다는 성질이 유지된다 |
| 거래가 없는 달 | **합계 0 과 빈 목록 안내가 함께** 보인다. 목록만 비어 있으면 사용자는 불러오지 못한 것으로 읽는다 |
| **고정지출 행** | **수정·삭제·중도상환을 그리지 않는다.** 여기서 지우면 그 달 내역만 사라질지 설정 전체가 사라질지 사용자가 알 수 없다 — **되돌릴 수 없는 동작의 범위가 불분명한 버튼**이다. 만들고 고치는 것은 고정지출 설정 화면(4.2~4.5)이다 |
| 고정지출 행의 안내 | **왜 이 행만 버튼이 없는지 적는다.** 적지 않으면 화면이 고장 난 것으로 읽힌다. 고정지출 설정 화면으로 가는 길을 함께 둔다 |
| **중도상환 버튼** | **할부 행에만 그린다.** 일반 지출 행에 두면 사용자는 자기 지출이 할부인 줄 안다 |
| 중도상환의 성격 | **수정도 삭제도 아니다.** 그 지출 한 건을 고치는 일이 아니라 여러 회차를 함께 바꾸는 일이라 **수정 모달 안에 넣지 않는다** — 넣으면 금액을 고치러 들어갔다가 할부 전체가 정리되는 사고가 난다 |
| 중도상환 확인 본문 | 셋을 담는다 — ① 어느 할부인지 ② **남은 회차가 한 번에 정리된다**는 것 ③ **되돌릴 수 없다**는 것 |
| 정리할 회차가 없음 | 오류 화면이 아니라 **목록의 안내**로 보인다. 이미 다 낸 할부이고 사용자가 할 일이 없다 |
| 삭제 전송 방식 | **`POST` 로 보낸다.** 되돌릴 수 없는 동작을 링크로 두면 브라우저가 미리 불러오는 것만으로 실행된다 |
| 삭제 확인 본문 | 셋을 담는다 — ① 대상이 무엇인지(일자·금액·내용) ② **되돌릴 수 없다**는 것 ③ **합계에서도 빠진다**는 것 |
| **검색어가 보는 칸** | **내용과 장소 둘이다.** 그 사실을 검색 칸 아래에 한 줄로 적는다 — 적지 않으면 사용자는 내용만 검색되는 줄 알고 장소로 찾기를 포기한다 |
| **종류 필터** | **여러 값을 함께 고를 수 있다.** 백엔드가 콤마로 받는다. 한 값만 보내면 「지출과 할부만」 같은 조합을 만들 수 없다 |
| **정렬 기준** | **결제일과 금액 둘뿐이다.** 백엔드가 그 둘만 받아 수단·지출유형 정렬은 부를 방법이 없다. 두 기준 모두 오름차순·내림차순을 고를 수 있다 |
| 정렬을 화면이 하지 않음 | **받은 목록을 스스로 다시 정렬하지 않는다.** 지금은 한 달치를 전부 받아 괜찮아 보이지만 그 가정이 화면 코드에 숨고, 쪽 넘기기가 생기는 순간 깨진다 |
| 빈 조건 | **비어 있는 조건은 요청에 싣지 않는다.** 빈 값을 보내면 백엔드가 「그 값으로 걸러 달라」로 읽어 결과가 통째로 빈다 |
| **필터 유지** | 연·월을 바꿔도 **필터가 주소에 남는다.** 연·월만 바꾼 주소를 만들면 나머지가 그대로 실린다 |
| 필터가 0건일 때 | **필터를 풀지 않는다.** 사용자가 건 조건이다. 빈 목록임을 알리기만 한다 — 자동으로 풀면 사용자는 자기가 무엇을 걸었는지 잃는다 |
| 화면 상태를 두는 곳 | **주소다.** 세션에 두면 뒤로 가기와 새 탭에서 다른 목록이 뜬다 |
| 목록 조회 실패 | **빈 목록과 합계 0 으로 그린다.** 로그인 직후 착지라 여기서 터지면 사용자는 로그인하자마자 오류를 만난다 |
| 백엔드 불통 | 007 의 오류 화면으로 간다 |
| 실패 안내 문구 | 백엔드가 준 문구를 그대로 쓴다. 화면이 문구를 새로 만들지 않는다 |

### 도구줄이 프로토타입과 다르다

프로토타입의 도구줄에는 **연·월·검색어 셋뿐**이다. 이 화면은 여기에 **다섯을 더한다.**

| 더하는 것 | 왜 |
|---|---|
| 수단 필터 | 「이 카드로 얼마를 썼나」가 한 달 기록에서 가장 자주 찾는 것 중 하나다 |
| 지출유형 필터 | 유형별로 보는 길이 없으면 목표금액·통계와 기준이 갈린다 |
| 날짜 범위(시작일·종료일) | 그 달 안에서 며칠 구간만 보는 길이다 |
| 종류 필터 | **고정지출만·일반 내역만** 보는 길이다. 네 종류가 한 목록에 섞여 있어 이것이 없으면 걸러 볼 방법이 없다 |
| 정렬(기준·방향) | 「이번 달에 제일 많이 쓴 것」이 금액 정렬이고, 백엔드는 처음부터 그것을 지원하고 있었다 |

그대로 옮기면 **거를 수 없는 목록**이 된다.

## 비고

- 화면 구성은 `화면기획/proto/ledger-monthly.html` 을 옮긴다. 프로토타입과 **두 곳이 다르다** — 도구줄에 필터 다섯이 없고, 행마다 관리 버튼이 「수정」 하나로 같다. 그대로 옮기면 거를 수 없는 목록이 되고, 고정지출 행에도 수정 버튼이 생긴다.
- 지출 등록(3.1)·지출 수정(3.2)·소득 등록(3.3)·소득 수정(3.4)은 이 화면 위의 모달이며 별도 주소를 갖지 않는다.
- 엑셀 일괄 등록(3.5)은 독립 페이지다. 같은 지출·소득을 다른 입구로 넣는 화면이며 이 목록을 쓰지 않는다.
- **고정지출 행을 만들고 고치는 것은 4.2~4.5 다.** 이 화면은 읽기만 한다.
- 목록+모달의 공통 모양은 2.1 수단 목록이 세운 것을 따른다. **다른 점은 자원이 둘이고 상세 모달이 없다**는 것이다 — 목록에 값이 다 보여 따로 읽을 자리가 필요 없다.
