공통 래퍼: [_공통.md § 응답 래퍼](../_공통.md#응답-래퍼)

### 성공 (`resCode: 200`) — `data`

FixedExpense 전체 + 아래 두 이름 필드

| 필드 | 타입 | 설명 |
|------|------|------|
| `paymentMethodName` | string | 수단의 **현재** 이름 (스냅샷 아님). `tbl_fixed_expense`에 이름 컬럼이 없어 조회 시점에 수단 행에서 읽는다 |
| `expendGroupName` | string | 지출유형의 **현재** 이름 (스냅샷 아님). 위와 같은 규칙이다 |

**이름을 저장하지 않는다.** 고정지출은 "지금 유효한 설정"이라 수단 이름을 바꾸면 이 응답도 새 이름으로 바뀐다. 이미 일어난 일을 기록하는 지출·소득(3.1·3.7)이 등록 당시 이름을 스냅샷으로 남기는 것과 **정반대**다.

### 실패 — 대표 `resCode`

| resCode | 조건 |
|---------|------|
| 1001 | 로그인 필요 |
| 3003 | 수단이 없거나 타인 소유이거나 사용 중이 아님 |
| 3103 | 지출유형이 없거나 타인 소유이거나 사용 중이 아님 |
| 3401 | 결제일이 1~31 밖, 금액이 0 이하, 시작·종료 월이 1~12 밖, 종료 연월이 시작 연월보다 앞섬, 또는 수단의 용도가 `EXPENSE`가 아님 |

**수단 용도 불일치는 `3003`이 아니라 `3401`이다.** `3003`은 "그 수단을 쓸 수 없다"이고 용도 불일치는 "값을 잘못 골랐다"다 — 수단은 실재하며 사용자가 목록에서 볼 수 있으므로 존재를 감출 이유가 없다. 판정 순서는 **참조(`3003`/`3103`) → 용도(`3401`) → 값(`3401`)**이다.

### 성공

**Request**

```http
POST /api/v1/fixed-expenses HTTP/1.1
Host: localhost:8081
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

  "paymentMethodId": 1,

    "paymentMethodId": 1,
    "paymentMethodName": "국민카드",

    "paymentDayOfMonth": 5,
    "content": "원룸 월세",
    "expendGroupId": 2,
    "expendGroupName": "주거",
    "startYearMonth": "2026-01",
    "endYearMonth": "2026-12"
  }
}
```

## 비고

- 등록 시점에는 **고정지출 관리 행 1건만** 만든다. 적용 기간 전체의 월별 내역을 미리 만들지 않는다.
- 월별 고정지출 내역은 그 달을 **처음 조회할 때** 이 설정에서 만들어진다 ([4.5](./4.5-FixedExpenseMonthlyList.md)).
- 이미 지나간·이미 열어본 달에도 반영하려면 [4.9 `FixedExpenseMonthlySync`](./4.9-FixedExpenseMonthlySync.md)를 호출한다.
- `LedgerMonthlyList`에 `type=FIXED`로 포함.
