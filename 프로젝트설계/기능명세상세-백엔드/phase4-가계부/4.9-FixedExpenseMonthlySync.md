# [백엔드] 월별 고정지출 내역 수동 재작성

> API: `FixedExpenseMonthlySync` · Phase 4 · 기능번호 4.9  
> 인덱스: [README.md](../README.md)

## 메타

| 항목 | 내용 |
|------|------|
| Phase | 4 (가계부·고정지출) |
| 기능 이름 | 월별 고정지출 내역 수동 재작성 |
| 기능번호 | 4.9 |
| API 이름 | `FixedExpenseMonthlySync` |
| Method | `POST` |
| URL | `/api/v1/fixed-expenses/monthly/sync` |
| 권한 | 로그인 |
| Content-Type | `application/json` |

## 요청

지정한 연·월의 월별 고정지출 내역을 **고정지출 관리 테이블 기준으로 다시 맞춘다.** 화면의 "고정지출 반영" 버튼이 호출하는 API다.

### Path Variables

없음 (Body only) — POST 규칙: Path·Query 사용하지 않는다.

### Body

| 필드 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `year` | number | ✅ | 재작성할 연도 |
| `month` | number | ✅ | 재작성할 월 1~12 |
| `overwriteModified` | boolean | ❌ | 사용자가 직접 고친 행(`modified=true`)까지 관리 테이블 값으로 되돌릴지. 기본 `false`(**보존**) |

`overwriteModified`를 생략하면 `false`로 본다.

### Headers

| 이름 | 필수 | 설명 |
|------|:----:|------|
| `Authorization` | ✅ | `Bearer <accessToken>` |
| `Content-Type` | ✅ | `application/json` |

## 동작

그 연·월에 대해 아래를 **한 트랜잭션**으로 처리한다.

| 대상 | 처리 |
|------|------|
| 적용 기간에 걸리는데 내역이 없는 고정지출 (신규 등록분 포함) | **추가** |
| 내역이 있고 `modified = false` | 관리 테이블 현재 값으로 **갱신** |
| 내역이 있고 `modified = true` | 기본 **보존**. `overwriteModified=true`면 갱신하고 `modified=false`로 되돌림 |
| 적용 기간이 그 연·월을 더는 포함하지 않는 내역 | **삭제** |
| 관리 테이블에서 삭제된 고정지출의 내역 | 관리 행 삭제 시 이미 함께 사라짐 |

## 응답

### 성공 (`resCode: 200`) — `data`

| 필드 | 타입 | 설명 |
|------|------|------|
| `year` | number | |
| `month` | number | |
| `createdCount` | number | 새로 만든 내역 수 |
| `updatedCount` | number | 관리 값으로 갱신한 내역 수 |
| `deletedCount` | number | 없앤 내역 수 |
| `keptCount` | number | 직접 수정 행이라 손대지 않은 수 |
| `total` | number | 재작성 후 그 달 고정지출 합계 |
| `list` | array (object[]) | 재작성 후 목록. [4.5](./4.5-FixedExpenseMonthlyList.md) `list[]`와 동일 구조 |

### 실패 — 대표 `resCode`

| resCode | 조건 |
|---------|------|
| 1001 | 로그인 필요 |
| 3403 | year·month 범위 오류 |

## 비고

- **왜 필요한가**: 월별 고정지출 내역은 그 달을 **처음 조회할 때 한 번** 만들어진다([4.5](./4.5-FixedExpenseMonthlyList.md)). 이미 연 달에 고정지출을 새로 등록·수정·삭제해도 그 달 내역은 자동으로 따라오지 않으므로, 사용자가 버튼으로 다시 맞출 경로가 필요하다.
- **자동 반영과의 차이**: 고정지출 관리 수정([4.4](./4.4-FixedExpenseUpdate.md))은 **아직 오지 않은 달**의 `modified=false` 행만 자동으로 따라간다. 이 API는 **지정한 한 달**만 대상으로 하고, **지난 달에도** 쓸 수 있다.
- **되돌리기**: `overwriteModified=true`는 그 달의 직접 수정분을 전부 관리 테이블 값으로 되돌린다. 화면에서 확인을 받고 호출하는 것을 전제한다.
- `year`·`month`는 **Body**로 받는다 (2.1 「HTTP Method 규칙」 — POST는 Path·Query 미사용). 같은 형태의 선례: `StatisticsMonthlySave` (`POST /statistics/monthly/save`).
- 대상은 **로그인 회원 본인의** 고정지출뿐이다.
- 재작성 결과 목록을 함께 돌려주므로, 호출 후 [4.5](./4.5-FixedExpenseMonthlyList.md)를 다시 부를 필요는 없다.
