### 성공 (`resCode: 200`) — `data`

| 필드 | 타입 | 설명 |
|------|------|------|
| `year` | number | 조회 연도 |
| `month` | number | 조회 월 |
| `total` | number | 그 달 고정지출 합계 |
| `list` | array (object[]) | 월별 고정지출 내역 |

#### `list[]` 요소

| 필드 | 타입 | 설명 |
|------|------|------|
| `fixedExpenseId` | number | 고정지출 관리 PK. `year`·`month`와 함께 이 행의 식별자 |
| `year` | number | |
| `month` | number | |
| `fixedExpenseName` | string | 고정지출 이름 (관리 테이블 **현재** 값) |
| `amount` | number | 그 달 금액 |
| `paymentDate` | string | 그 달 결제일. `YYYY-MM-DD`. 매달 결제일이 그 달 말일보다 크면 **말일로 보정된 값** |
| `content` | string | 그 달 내용 |
| `paymentMethodId` | number | 그 달 수단 |
| `paymentMethodName` | string | 수단의 **현재** 이름 (스냅샷 아님) |
| `expendGroupId` | number | 그 달 지출유형 |
| `expendGroupName` | string | 지출유형의 **현재** 이름 (스냅샷 아님) |
| `modified` | boolean | 이 달 값을 사용자가 직접 고쳤으면 `true` |

### 실패 — 대표 `resCode`

| resCode | 조건 |
|---------|------|
| 1001 | 로그인 필요 |
| 3403 | year·month 누락·범위 오류 |

## 비고

- **첫 조회 시 생성(lazy)**: 그 연·월의 내역 행이 아직 없으면, 고정지출 관리 테이블에서 **적용 기간(시작~종료 연월)에 걸리는 건**을 복사해 만든 뒤 돌려준다. 같은 달을 다시 조회해도 행이 늘어나지 않는다(동시 요청 포함).
- 적용 기간 **밖**의 연·월은 그 고정지출의 내역을 만들지 않는다. 기간에 걸리는 고정지출이 하나도 없으면 `list`는 빈 배열이다.
- 이 API는 **월별 고정지출 내역만** 돌려준다. 일반 지출·소득은 [3.x 지출·소득 목록] 또는 [4.8 `LedgerMonthlyList`](./4.8-LedgerMonthlyList.md)에서 조회한다.
- 이미 만들어진 달에 고정지출을 **새로 등록·수정·삭제**해도 그 달 내역은 자동으로 따라오지 않는다. 다시 맞추려면 [4.9 `FixedExpenseMonthlySync`](./4.9-FixedExpenseMonthlySync.md)를 호출한다.
- 이름(고정지출·수단·지출유형)은 스냅샷이 아니라 **조회 시점의 현재 값**이다.
