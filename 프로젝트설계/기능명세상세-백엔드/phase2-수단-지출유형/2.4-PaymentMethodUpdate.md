## 응답

공통 래퍼: [_공통.md § 응답 래퍼](../_공통.md#응답-래퍼)

### 성공 (`resCode: 200`) — `data`

PaymentMethod 전체 필드 (갱신 후)

### 실패 — 대표 `resCode`

| resCode | 조건 |
|---------|------|
| 1001 | 로그인 필요 |
| 3003 | 수단 없음 — 본인 소유가 아닌 경우 포함 |
| 3001 | type 값 오류(`CARD`·`ACCOUNT` 밖) 또는 purpose 값 오류(`EXPENSE`·`INCOME` 밖) |
| 3005 | purpose 변경 불가 — 이 수단을 참조하는 지출·소득·고정지출이 1건 이상 있음 |
| 9001 | 잘못된 요청 |

## 비고

- **과거 지출·소득 내역**의 `paymentMethodName` 스냅샷은 수정해도 변경되지 않음. 등록 당시 이름을 보존하는 것이 목적이라, 3월에 "국민카드"로 적힌 지출은 카드 이름을 바꿔도 그대로 남는다.
- `deleted=true` 수단도 수정 가능 (이름 정리 등).
- **`purpose` 변경은 참조 0건일 때만 허용한다.** 그 수단을 가리키는 지출(`tbl_expense`)·소득(`tbl_income`)·고정지출(`tbl_fixed_expense`, `tbl_fixed_expense_monthly`)이 한 건이라도 있으면 `3005`로 거절한다. 지출용으로 쓰던 카드를 소득용으로 바꾸면 이미 그 카드로 적힌 지출 내역이 "소득 수단으로 낸 지출"이 되어 월별 집계와 통계의 수단별 요약이 어긋나기 때문이다.
- 이 검사는 **애플리케이션의 몫**이다. `purpose`는 수단 쪽 컬럼이라 DB CHECK으로는 다른 테이블의 참조 건수를 볼 수 없다.
- `purpose`를 omit 하면 기존 값이 유지되며 위 검사도 수행하지 않는다. PATCH omit 규칙 그대로다.
