| 항목 | 내용 |

| 기능 이름 | 월별 통계 조회 |

## 요청

### Path Variables

| 이름 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `year` | number | ✅ | 조회 연도 |
| `month` | number | ✅ | 조회 월 1~12 |

### Query Parameters

| 이름 | 타입 | 필수 | 설명 |
|------|------|:----:|------|
| `view` | string | ❌ | 조회 모드. 생략 또는 `saved` = **저장본 우선**. `live` = 저장본 무시하고 **지금 데이터로 최신 계산** (DB 미변경) |

`view`에 `saved`·`live` 이외 값 → `3603`.

> Path(`year`/`month`) + Query(`view`) 혼용은 **본 API만** 허용. `view`는 모드 스위치용 옵션이다.

### Headers

| 이름 | 필수 | 설명 |
|------|:----:|------|
| `Authorization` | ✅ | `Bearer <accessToken>` |

### Body

없음

| 필드 | 타입 | 설명 |
|------|------|------|
| `year` | number | 조회 연도 |
| `month` | number | 조회 월 |
| `source` | string | `SAVED` (DB 저장본) \| `CALCULATED` (실시간·최신 계산) |
| `savedAt` | string \| null | 해당 월 **마지막 저장** 시각 ISO-8601. 저장본이 없으면 `null`. `view=live`여도 저장본이 있으면 시각을 내려 **저장 여부 표시**에 쓴다 |
| `incomeTotal` | number | 월 소득 합계 |
| `expenseTotal` | number | 월 지출 합계 (일반+할부+고정) |
| `fixedVsRegularRatio` | object | 고정 vs 일반 지출 비율 |
| `fixedVsRegularRatio.fixedAmount` | number | 고정지출 합계 |
| `fixedVsRegularRatio.regularAmount` | number | 일반·할부 지출 합계 |
| `fixedVsRegularRatio.fixedPercent` | number | 고정 비율 (0~100) |
| `fixedVsRegularRatio.regularPercent` | number | 일반 비율 (0~100) |
| `weeklyExpenses` | array | 주별 지출 |
| `weeklyExpenses[].weekIndex` | number | 주차 (1부터) |
| `weeklyExpenses[].weekStart` | string | 주 시작일 `YYYY-MM-DD` (월요일 기준, 1일≠월요일이면 첫 주는 1일부터) |
| `weeklyExpenses[].weekEnd` | string | 주 종료일 |
| `weeklyExpenses[].amount` | number | 해당 주 지출 합계 |
| `expendGroupSummaries` | array | 유형별 요약 (**0원 유형 제외**) |
| `expendGroupSummaries[].expendGroupId` | number | |
| `expendGroupSummaries[].expendGroupName` | string | |
| `expendGroupSummaries[].amount` | number | 유형별 지출 합계 |
| `expendGroupSummaries[].target` | number | 목표금액 (월별 우선, 없으면 기본) |

| `paymentMethodSummaries[].paymentMethodId` | number | |
| `paymentMethodSummaries[].paymentMethodName` | string | |
| `paymentMethodSummaries[].amount` | number | 해당 수단 지출 합계 |

## 비고

- **기본(`view` 생략 / `saved`)**: 저장본이 있으면 `source=SAVED`, 없으면 가계부·고정지출·목표로 계산 (`CALCULATED`). 과거 월 **보존**용.
- **`view=live`**: 저장본을 무시하고 **지금** 지출·소득·고정지출·목표로 다시 계산. `source`는 항상 `CALCULATED`. **DB 스냅샷은 바꾸지 않음**. 저장 확인은 기본 조회, 최신 비교·갱신 미리보기는 `live`.
- `view=live`인데 해당 월 저장본이 있으면 `savedAt`에 마지막 저장 시각을 내려, 프론트가 「저장본 있음 / 지금 최신 계산」을 구분할 수 있게 한다.
- 스냅샷을 DB에 반영·덮어쓰려면 [`StatisticsMonthlySave`](./5.6-StatisticsMonthlySave.md).
- 주별 지출: **월요일 시작**. 해당 월 1일이 월요일이 아니면 첫 주는 1일~첫 일요일. 마지막 주는 말일에서 끊는다.
- `status` 기준은 **확정값**이다 — 사용률 **90% 미만** `UNDER`, **90 이상 110 이하** `OK`, **110% 초과** `OVER`. `tbl_statistics_expend_group.status`가 `NOT NULL`이고 `ck_stat_group_status`가 이 세 값만 허용하므로 채우지 않거나 다른 문자열을 넣으면 저장이 통째로 실패한다. 목표가 0원이면 사용률이 0이라 `UNDER`다. 기준이 나중에 바뀌어도 **이미 저장된 행은 다시 계산하지 않는다**(FR-523).
- **수단별 요약은 유형별과 정반대다.** 유형별은 그 달 지출이 0원인 유형을 **빼지만**(FR-521) 수단별은 0원도 **넣는다**(FR-521a). 다만 0원 행의 대상은 "회원 소유 수단 전부"가 아니라 **저장 시점 사용 중인 `EXPENSE` 수단만**이다 — 전부로 읽으면 버린 카드의 0원 행이 매달 쌓인다.
